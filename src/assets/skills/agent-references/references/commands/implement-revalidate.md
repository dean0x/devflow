# Implement: re-validation

Read by `/implement` when the user asks to re-validate (D-CMD-REF-HAND).

## Continuation path

When the user explicitly asks to re-validate, re-check, or re-run quality gates after making their own changes:

1. **Branch safety check**: If on a protected branch (main, master, develop, etc.), run all of Phase 1, through its **Fresh base.** step, to create/switch to a work branch; "Phase 1 ran" below means all of it ran. If already on a work branch, skip Phase 1 and resolve `{worktree}` as its docs root does: `git -C "{start}" rev-parse --show-toplevel`, else the start directory.
2. **Skip Phase 2** — no Code agent needed, user already made changes. With no Code report, Phase 4 keeps Harden at every level: the `harden-scope` skip never applies on this path.
3. **Record BASE_BRANCH**: unless Phase 1 ran, read the PR's base name (`baseRefName`) and fork flag in one Bash call, `cd "{worktree}" && F="$(mktemp)" && echo "F=$F" && gh pr view --json isCrossRepository --jq .isCrossRepository; G=$?; gh pr view --json baseRefName --jq .baseRefName > "$F"; echo "gh=$G,$?"`; `{name file}` is the printed `F=` path, and `gh` failed when either status printed in `gh=` is not 0. If `gh` failed and its output shows that no PR applies (none for the branch, `gh` missing or logged out, or no GitHub remote), the name is the remote default branch; fill the file: `F="{name file}"; git -C "{worktree}" for-each-ref --format='%(symref:lstrip=3)' refs/remotes/origin/HEAD > "$F"`; when the file reads as empty (a file whose only content is an empty line is empty), `main` if `git -C "{worktree}" rev-parse --verify --quiet main` succeeds, otherwise `master` the same way; write a literal name with the Write tool, after a Read of the file. If the Write tool fails, treat the value as missing; never write it with a shell command. Read `{name file}` with the Read tool: its one line is the name. Stop the run, after `rm -- "{name file}"`, if `gh` failed and its output does not show that no PR applies, or the file is empty after every fallback. Stop the run, after `rm -- "{name file}"`, unless the name matches `^(?![-#]|origin\/|(?:@|(?:FETCH_|ORIG_|MERGE_)?HEAD)$)(?!.*\.\.)[A-Za-z0-9._\/+@,#-]{1,200}$` (judge the match by reading; never pass the value to a command), naming only the allowed set, never the name (ASCII letters, digits and `._/+@,#-`, at most 200; no leading `-` or `#`, no `origin/` prefix, no `..`, not `@` or a HEAD name). Phases 3-7 run `{branch_diff}` from `BASE_REF`, the fork point.
   Unless Phase 1 ran (its `BASE_REF` stands), run `F="{name file}"; trap 'rm -- "$F"' EXIT; cd "{worktree}" && X=<isCrossRepository, else false> && node "$HOME/.devflow/scripts/resolve-base.cjs" pr --name-stdin --cross "${X}" < "$F"; echo "exit=$?"` when gh returned a PR, else `F="{name file}"; trap 'rm -- "$F"' EXIT; cd "{worktree}" && node "$HOME/.devflow/scripts/resolve-base.cjs" local --name-stdin < "$F"; echo "exit=$?"`. Handle its line as the fresh base step does. Output other than one `BASE_REF=` line (40 or 64 hex, or `none`) with `exit=0` counts as `REASON=resolver-unavailable`: stop, with the fix `re-run; if it repeats, run devflow init`.
4. **Take GATE_LEVEL**: unless Phase 1 ran, run the Phase 1 **Resolve the settings line** step once for this worktree, and take `GATE_LEVEL` from the line it accepts, or from its fail-closed line when it accepts none. Phase 6 passes `GATE_LEVEL` to Validate. Then, from that same line, the accepted one or the fail-closed one, set `COMPLIANCE_FRAMEWORKS` as Phase 1 defines it and `COMPLIANCE_DIRECTIVE` by the Phase 1 **Set the compliance directive** step; Phases 5-7 pass `COMPLIANCE_DIRECTIVE` to their Fix spawns. Run the Phase 1 **Resolve the evidence policy once per run** step, then take `REVIEW_PUBLICATION` from that same line by the Phase 1 **Resolve `REVIEW_PUBLICATION` per worktree:** step and the Phase 1 **Evidence stub:** step; Phase 11 passes `REVIEW_PUBLICATION` as the value resolved in Phase 1.
5. **Run Phases 3-8** — Polish (at `full`), Self-Review, Alignment, the one full Validate, QA Testing and the conditional Re-Validate, on the branch diff.
6. **Proceed to Phase 9** (Open PR), **Phase 11** (Evidence) and **Phase 12** (Report).

If the user prompt does NOT match re-validation, proceed with the full pipeline below.
