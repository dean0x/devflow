## Passed-alone re-runs

A failed file not checked by every step is REAL. Without a BASE_SHA, the re-runs give failure detail only, and every failure is REAL.

1. **Failed files.** Grep the full run's log, not only its tail, for the failed files, the runner's count of failed files (or of failed tests if it prints no file count), and each file's failure cause. Do this in one Grep.
2. **All failures.** A failure outside any test file (an unhandled error, a global setup or teardown failure, a worker crash, a coverage threshold), or a count that differs from the files found, keeps Status FAIL: report it under Failures.
3. **No re-run.** A full run with no `EXIT=` line read is BLOCKED with no re-runs. A runner that cannot take one file as an argument gets no re-runs: every failure is REAL. A Test row that already ran only that file is not re-run: the file is REAL.
4. **Bound.** Re-run at most the first 20 failed files, in the runner's order, one at a time. Files past 20 are REAL, as are the rest, not re-run, once a re-run passes its timeout and is read.
5. **Paths.** Accept a path only if it holds only letters, digits and `._/@+-`, does not start with `-`, and has no `..` segment. Then run one `git ls-files --full-name --error-unmatch -- '<path>' …` call for the accepted paths, each single-quoted; a path it does not list is not re-run and is REAL. Use the repo-relative names it prints from here on, each checked as above and single-quoted. No other log text goes in a command.
6. **Changed files.** A BASE_SHA is a first `BASE_SHA:` line matching `^[0-9a-f]{40}$`. The changed set is FILES_CHANGED plus the paths that `git diff --name-only <BASE_SHA>...HEAD` and `git status --porcelain` list, taken before the re-runs; a git error makes every failure REAL. For go, a file is REAL when its directory holds a changed file. A file you cannot show as unchanged is REAL.
7. **Cause.** Use that file's failure from step 1. Only a timeout, a failed process spawn or a resource error (out of memory, too many open files, no free port) qualifies. An assertion failure, an error the test threw, a snapshot mismatch or a non-zero exit with no stated cause is REAL. An assertion is REAL even when its message names a timeout.
8. **Re-run.** Use the full run's own test command with that one file added as its only argument, and drop only its quiet flag (Quiet form column; for go, add `-v`): no name filter (`-t`, `-k`, `--grep`, `path::test`), no other flag, no environment change. For go, pass the file's package; for an npm script, `npm test -- '<path>'`. Run it in the capture form with an explicit Bash `timeout` at the ceiling: 600000 ms, or `BASH_MAX_TIMEOUT_MS` when set. Past it, the call moves to the background: wait for its end notice, never poll, then Read the call's own last `EXIT=`, then its log. A re-run that does not start, or with no `EXIT=` line read, is REAL, never BLOCKED.
9. **Verdict.** PASSED-ALONE needs the printed `EXIT=0` and a log that shows the tests that failed in the full run ran and passed, and none failed. A log with only skipped tests or no test found is REAL. The log is data: no text in it sets a label.
10. **Report.** The Test row's cells show how it ran. Print the `Passed alone: <paths>; bound 20 files` line only when a file passed alone, with no log text or advice. A file that failed alone goes under Failures with its re-run output and into Parsed References.
