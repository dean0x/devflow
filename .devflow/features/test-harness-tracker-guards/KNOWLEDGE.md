# Test Harness - Git-Agent Guard Modes, Command-Agent Seam, Tracker and PR-Host Guards

## Rules

- **KB-INV-1** `git.md` is the single `**Input:**` and producer contract authority: seam Directions 1, 2 and 3 and every `'sole'` lookup read a git.md-only corpus.
- **KB-INV-2** A guard literal that moves out of `git.md` is reclassified from `'sole'` to `'union'` one literal at a time, each paired with a known-bad sibling (`sinkCorpusWithoutPrHost()` or `seedPrHostFile`) proving that dropping what it widened TO turns the guard red.
- **KB-INV-3** D4 degradation evidence stays `'sole'` over `git.md`: a clause living only in a loadable reference is one a spawn can decline to load.
- **KB-INV-4** `references/pr/` is a peer tree to each provider tree in every scan (`provider-scope`, `single-authority`, `reference-reachability`, `schema-scope`, `reference-overlay`): widened, not duplicated, with provenance proof that a `pr/` entry was actually read.
- **KB-INV-5** The PR-host tree is provider-NEUTRAL: no jira or linear literal may reach it, because it loads for every third-provider user.
- **KB-INV-6** Each normative sentence lives once: `SHARED_LITERAL_REGISTRY`, `MCP_SHARED_LITERAL_REGISTRY` and `TRACKER_CONTRACT_LITERAL_REGISTRY` hold a sentence to one home, and `NEUTRAL_STEPS` proves moved steps are byte-identical across providers while keeping their gating conditions.
- **KB-INV-7** The `~/.devflow/tracker/{provider}.md` schema has one WRITER (the Tracker agent's embedded template) and one READER (`tracker/_contract.md`); `TRACKER_SCHEMA_SECTIONS` lives once in `helpers.ts` and both arms import it.
- **KB-INV-8** The D11 bypass guard reads a recipe the way a shell parses it: continuations are joined before matching and every shape is bounded to ONE command.
- **KB-INV-9** The Tracker agent is spawned only by the SessionStart hook, so its spawn-fence count in the seam test is a CEILING of zero.
- **KB-INV-10** No text every spawn loads carries a GitHub-specific signal: `PROVIDER_DETECTORS` are labelled word-bounded regexes checked over the cross-cutting sections, whose label set equals a NAMED list.
- **KB-AP-1** Never blanket-widen a suite to make it green after a prompt split; widen a corpus only where its literal provably moved.
- **KB-AP-2** Never point a `'sole'` lookup at the sink corpus: the throw on a duplicated anchor is the signal, not a bug.
- **KB-AP-3** Never type a corpus-multiplicity literal that a provider addition changes: derive it from the registry (`TRACKER_OP_DECLARING_FILES`).
- **KB-AP-4** Never search the consumer (compiled commands) for a producer signal: seam Direction 3 reads `git.md`, the emitter.
- **KB-AP-5** Never fold the legacy DEGRADED-reason registries together, or scope them by basename: each literal is excused only in the tree that emits it, scoped by PATH PREFIX.
- **KB-AP-6** `gitAuthorityCorpus()` stays un-widened: its authored-preload scan surface is a written non-goal, not an oversight.
- **KB-AP-7** A step-label guard keyed on `4b.` must name its op section and corpus: the label exists in several files.
- **KB-AP-8** A stand-in provider name that can be registered silently becomes real: use the deliberately unregisterable `probe-provider` with its own absence guard.
- **KB-AP-9** No prompt rule that stops or reports DEGRADED for a missing tracker contract: only install corruption could cause it (`collectMissingContractRules`).
- **KB-AP-10** `create-release` stays inline in `git.md`: moving its `gh release create` step into a reference would trip the Jira and Linear forbidden-transport guards.

## Overview

Three tracker providers (github, jira, linear) are covered by the same guard shape, and a fourth tree, `references/pr/` (`PR_HOST_OPS`, under no provider: pull requests stay on GitHub whatever the tracker is), converges, is reachable-scanned and is single-authority-scanned by the SAME test files as the three provider trees. `provider-scope`'s `PROVIDER_OWNED_PATHS`/`FORBIDDEN_SCOPES`, `single-authority.test.ts`'s `providerReferenceCorpus()`, `reference-reachability.test.ts`'s reachability set, `schema-scope.test.ts`'s scoped-exemption registry and `installer/reference-overlay.test.ts`'s converge-not-merge arms all treat `pr/` as a peer subtree, not a special case.

The section-boundary rule is fence-aware (core mechanics in `test-harness`): `manage-debt`'s successor-issue body and `ensure-traceable-issue`'s heredoc and D3-template headings are the shipped cases that depend on it, so every union-mode guard reaches the recipes below them and `git-agent.test.ts` needs no file-scoped workaround for either. The domain content these files pin belongs to `tracker-feature`, `tracker-references` and `installer-shadowing`.

## Guard-Mode Classification in git-agent.test.ts

When a monolithic prompt splits (the tracker providers, the PR/review op bodies moving from `dist/agents/git.md` into provider-independent `references/pr/{op}.md`, the provider-neutral step move), the harness reclassifies every guard literal that moved from `'sole'` to `'union'` mode one at a time, each paired with a known-bad probe proving the widening is honest rather than a "make it green" pass. `git-agent.test.ts` names three module-scoped helpers for this, built on the memoised `cachedSinkCorpus()`:

- `gitPlusPrHostCorpus()`: `git.md` UNION exactly the `references/pr/` tree, and nothing else. Used only by DETECTION guards, where the corpus decides WHICH ops are the subject (AC-0.6b's remote-I/O sweep). The full sink corpus would detect `setup-task` as remote-I/O through its unrelated PROVIDER mechanics, silently changing the guard's subject.
- `sinkCorpusWithoutPrHost()`: the sink corpus with the `references/pr/` tree filtered out; it throws if filtering removes nothing (an empty filter means the tree the build should have emitted is missing, and every probe built on it would be vacuous). This is the known-bad probe every `'sole'`-to-`'union'` reclassification is checked against: a widening is only honest if dropping what it widened TO turns the guard red. Without it, `'union'` is indistinguishable from `'sole'` on a corpus that still contains the literal somewhere, and the classification collapses into "widen everything until green".
- `seedPrHostFile(op, transform)`: a copy of the sink corpus with one `references/pr/{op}.md` entry's content replaced by `transform(content)`. It seeds a defect (a dropped D11 clause, a smuggled `{title}` placeholder) into exactly one PR-host file and drives the live guard's own predicate over the result, proving a per-op containment claim reports the SEEDED op and not its sibling.

Every literal the PR-host split moved carries a paired positive/negative test built on these: the post-review-summary and post-resolution-summary 60000-character caps; resolve-review-threads' `<=50` bound and fetch-review-threads' `<=2-page` bound (each pinned by step literals only the PR-host half carries, namely the loop sentence, the step-1 `bounds:` wording and the cursor-correctness trap, because `git.md`'s own Output enum and purpose line still spell the bare tokens); the review/resolution dedup marker FORM; ensure-pr-ready's D11 scrub; and the containment negative arm's `{body}/{description}/{title}` check. All are `extractOpSection(cachedSinkCorpus(), op, 'union')` reads with a `sinkCorpusWithoutPrHost()` (or `seedPrHostFile`) known-bad sibling.

Four shared rules are named once, at describe scope, so the live guard and its probe read the identical rule rather than two copies that could drift: `isPostingSection(sec)` (does a section post a body via `--body-file` or `-F body=@`?), `d10Reaches(corpus, op, literal)` (the D10 per-op containment predicate), `REMOTE_PLACEHOLDER_RE` (`/\{body\}|\{description\}|\{title\}/`, the remote-body placeholder the summary and reply ops' negative arm forbids) and `summaryComposeSurface(corpus, op)` (the surface that negative arm scans: the op's section across every corpus file, mode `'union'`, so its probe exercises the arm's corpus choice and not only its regex). That live arm also pins an in-scope witness, the `60000` cap every compose template states and none of those ops' `git.md` sections does, so a scope that shrinks back to `git.md` goes red instead of passing an absence check over less text. `D10_FAIL_CLOSED_LITERAL` (`'treat as PUBLIC'`) is likewise named once so the D10 per-op literal table and its probe cannot restate it apart. D4 evidence (`**Degradation (D4):**` / `TRACEABILITY: DEGRADED`) stays `'sole'` over `git.md` even inside the widened detection guard: the wider corpus only decides which ops count as remote-I/O in the first place.

**The provider-neutral step move (D-NEUTRAL-STEP-MOVE).** Provider-neutral step text left `git.md` for each provider's reference, and the literals it carried were reclassified one at a time. `setup-task`'s conventions-commit steps are read per provider reference in `'union'` mode, each provider's section checked on its own, with a probe that mutates only the GitHub reference and requires jira and linear to stay silent; the Output trailer naming `CONVENTIONS_COMMIT` stays `'sole'`. `post-wave-report`'s `<external-thread>` literal sits in `MOVED_EXTERNAL_THREAD_OPS` with a tripwire that fails if the literal comes back to `git.md`. `create-release` deliberately stays inline: its `gh release create` step would trip the Jira and Linear forbidden-transport guards (a probe seeds it into a reference), and it keeps `create-release` in the remote-I/O detection set.

The same discipline governs the rest of this family: the `'sole'`/`'union'` mode-naming rule, `gitAuthorityCorpus()`'s deliberately un-widened scope, `PR_HOST_LEGACY_REASONS` staying a separate registry from `GIT_AGENT_LEGACY_REASONS`, and the byte budget's recorded `LOADED_SET_WRITTEN_EXCLUSIONS` rule all classify one literal at a time and never widen to make a suite green.

**Corpus multiplicity is derived, never typed.** `git-agent.test.ts`'s `fetch-issue` union-match-count assertion is `TRACKER_OP_DECLARING_FILES = 1 + VARIANT_MODULES.filter(mod => mod.subdir.startsWith('tracker/')).length`, derived from the module registry, so registering a provider raises the expected count automatically instead of turning a correct guard red with a message that reads like an extractor regression.

**The operation roster.** `GIT_OPERATION_ROSTER` and `collectOperationNames` live in a SECOND top-level describe at the tail of `tests/git-agent.test.ts`. They name the property (which operations the agent declares) rather than counting guard declarations; the collector reads `## Operation: <name>` headings in file order and a non-vacuity test seeds a rename.

### collectCrossCuttingSections / PROVIDER_DETECTORS (git-agent.test.ts)

A named collector local to `git-agent.test.ts`, not `tests/helpers.ts`. `collectCrossCuttingSections(text)` walks `collectUnfencedH2(text)` and buckets everything before the first `## Operation:` heading as `'(header)'`, then every remaining unfenced heading that is not itself an `## Operation:` line, by label, to end of file or the next such heading. `PROVIDER_DETECTORS` is a small table of `{ label, pattern, justification }` rows, each pattern a **labelled, word-boundary-bounded regex** rather than a bare substring test.

The live guard asserts TWO things over the real `git.md`: the cross-cutting label set equals the NAMED list `['(header)', 'Output', 'Principles', 'Boundaries']` (`Output` is the report-cap section of the Git agent), and `collectProviderDetectors` returns empty (no GitHub-specific signal survives in text every spawn loads whatever provider it resolved to). A paired known-bad probe seeds a synthetic operation body with the SAME heading both fenced and unfenced, proving the fence-awareness is live in both directions.

### Inline-body scan (joinContinuations / INLINE_BODY_SHAPES / matchInlineBodyShapes / collectInlineBodyOffenders / inlineBodyCorpus)

The D11 bypass guard (`tests/git-agent.test.ts`) reads a shell recipe the way a shell parses it, not the way a human skims it. `joinContinuations(text)` replaces every backslash-newline-indent with a single space BEFORE matching. `INLINE_BODY_SHAPES` names five posting forms independently: `long-flag`, `short-flag` (verb-restricted to `create|comment|review|close|reopen|edit`), `api-field`, `unscrubbed-file`, `unscrubbed-api-file`. `IN_COMMAND` (a character class excluding backticks, newlines, `|`, `;` and `&`) bounds every shape to ONE command. `matchInlineBodyShapes(text)` folds continuations then returns every shape name that fires. `collectInlineBodyOffenders(corpus)` is the named collector, parameterised on the corpus so the live guard, the shape-table probe and the known-bad posting probe all drive the SAME predicate. `inlineBodyCorpus()` is the whole installed prompt surface: every declared agent via `resolveAllAgents()` ∪ `gitAgentSinkCorpus()` (git.md plus every generated reference, `pr/` included by construction) ∪ every skill `.md` ∪ every compiled command ∪ every rule, deduped by path, returning agent and generated counts for provenance. The shapes' non-goals are written down, not inferred from a green run; `KNOWN_GITHUB_API_INLINE_BODIES` (for `references/github-api.md` inline bodies) is empty, and the empty array is the declaration point for any future named exception.

### Tracker schema and mechanics collectors (helpers.ts)

`~/.devflow/tracker/{provider}.md` (one conventions file per provider) has a WRITER, the Tracker agent's embedded template, and a READER, the provider resolution and tracker input contract in `tracker/_contract.md` (which left git.md's always-loaded preamble). `TRACKER_SCHEMA_SECTIONS` lives once in `tests/helpers.ts`, built through `requireSchemaOracle` (which throws at import when `collectSchemaOracleDefects` finds the oracle unusable), and is imported by `tests/tracker-agent.test.ts` (writer arm) and `tests/tracker/schema-scope.test.ts` (reader arm). `collectTrackerTemplate(content)` addresses the embedded template fence BY TAG (`tracker-md-template`). `collectTrackerTemplateHeadings(template)` lists its `##`/`###` headings. `collectTrackerSchemaRows(content)` parses the agent's own schema/shape-check table, splitting on UNESCAPED pipes only; `tests/tracker/hostile-values.test.ts`'s payload matrix drives the corresponding shape-check cell this collector returns directly, so the agent's own table is the single authority a hostile payload is checked against.

`TOOL_CALL_MECHANICS_CLAIMS` / `collectMissingMechanicsClaims` is the shared claim table for AC-3.3, AC-3.11 and section 14.3, parameterised on a `ProviderRefVocabulary` (`refToken`/`refNoun`) so jira's and linear's generated mechanics are checked against the SAME clause text with only the vocabulary substituted. `PER_ITEM_FETCH_SHAPES` / `collectPerItemFetchVerbs` is the analogous shared table for the per-item-fetch negative. All of these tables live in `helpers.ts` rather than in any one provider's suite, since the claim is the SAME claim per provider.

## Command-Agent Seam Test (tests/seams/command-agent-input.test.ts)

The seam test pins the command-to-agent input contract. It checks three directions against the compiled command corpus (`DIST_FILES`):

1. **Forward**: every `KEY:` value passed in a Git fence is declared in that op's `**Input:**` line in `git.md` (sole corpus; git.md is the single authority).
2. **Reverse**: every non-optional `**Input:**` identifier for an op that has at least one caller fence is passed by at least one caller.
3. **Producer, PER OPERATION**: every entry in `ISSUE_CAPTURE_CONTRACT` names one or more `producerOps`, and `collectMissingProducers()` checks each `(label, op)` pair independently.

**Ops with callers vs. without.** Most `## Operation:` sections in `git.md` have a live caller fence in `dist/commands/` (`update-pr-evidence` joined via `/implement`'s Phase 10b spawn); the reverse-direction floor is `seam-ops-with-callers` and the op-to-section map floor is `seam-op-section-map`. The ops without a caller fence: `learn-conventions` (invoked internally by setup-task, not by any command fence); `check-ci-status` (no command spawns it, because `ci-wait.cjs` replaced the Git CI re-spawn, and the op stays defined as the authority for the `**Status**:` enum `ci-wait.cjs` is pinned to and for check-merge-readiness step 3); and `create-release`, `gather-release-evidence`, `backlink-shipped-issues` and `associate-release`, all named only in the `release` command's prose, never in an `Agent(...)` spawn fence.

**`ISSUE_CAPTURE_CONTRACT` keys.** `ISSUE_CONTENT`, `ACCEPTANCE_CRITERIA`, `ISSUE_REF`, plus the three `### Handoff Values` keys `ISSUE_ID`, `ISSUE_PR_LINK` and `ISSUE_BRANCH_TOKEN`. `issue-capture-contract-size` counts KEYS; the check itself ranges over `(key, op)` PAIRS.

**The three Handoff Values are single-issue-only.** Their `producerOps` name only `setup-task` and `fetch-issue`; `fetch-issues-batch` deliberately does NOT emit them. The `- **Branch token**:` value IS the branch name each op returns (`{branch-name}` for setup-task under `## Task Setup: {branch-name}`, `{suggested-branch}` for fetch-issue under `### Suggested Branch`), never an opaque `{token}`; `tests/seams/pr-link-handoff.test.ts`'s `collectBranchTokenDefects` pins both per-op mappings and the absence of the retired placeholder.

**`'sole'` vs `'union'` corpora, by direction.** Directions 1/2 (`gitCorpus`) and Direction 3's `collectMissingProducers` both read `git.md` ALONE, because `git.md` is the single contract authority; the generated references also open with a `## Operation:` anchor, so a union corpus would make every lookup match twice. Direction 3 must search `git.md` (the emitter), never `DIST_FILES` (the consumer), and it slices a `git.md` BODY rather than calling `extractOpSectionFromCorpus`: both known-bad probes drive `collectMissingProducers` with a mutated copy of the body, and a corpus-shaped signature would push the mutation into a fixture instead of the input under test.

`parseInputIdentifiers(section)` scopes to the `**Input:**` line only. Language-tagged fences are recipe fences and are excluded. Excluded keys: `OPERATION`, `COMPLIANCE`, `WORKTREE_PATH`, `PRODUCES`/`REQUIRES`, `D9`. **`**Produces:**` and `**Requires:**`** in command sources name principal upstream state for phase ordering (DAG annotations), not spawn fields, and are explicitly excluded from the key checks.

**The `OPERATION:` anchor regex** for compiled fences is `/^[ \t]*"?OPERATION: (\S+)/m`, allowing leading whitespace and an optional opening double quote. A column-0 anchor (`/^OPERATION: /m`) matches zero of the Git spawn fences in `dist/commands/` (a vacuity failure).

**`fencesScanned` carries a THIRD tracked type, `['Tracker', 0]`, as a CEILING rather than a floor**: the Tracker agent is spawned only by the SessionStart hook's directive, never by a compiled command, so its count must stay exactly 0.

## Gotchas

**KB-AP-2: `'sole'` throwing on a duplicated anchor is a signal, not a bug.** `git.md` operations also have same-named `## Operation:` anchors in the generated references: once per registered provider, plus once under `references/pr/` for the PR-host ops. A `'sole'` call accidentally pointed at a sink-wide corpus throws; that is the mechanism working.

**KB-AP-7: `4b.` step labels span files.** `git.md` carries one numbered `4b.` (`setup-task`'s conventions commit); `ensure-pr-ready`'s `4b.` lives in each `tracker/{provider}/ensure-pr-ready.md`, and `pr/ensure-pr-ready.md` carries its PR-host half unnumbered. A guard that keys off `4b.` must name its op section and corpus.

**KB-AP-6: `gitAuthorityCorpus()`'s scan surface is a written non-goal (GAP-25's Guard 7b).** It reads `dist/agents/git.md ∪ src/assets/skills/git/**`, the AUTHORED preload surface only, not the sink corpus. Widening it was rejected for the same reason a blanket `'union'` widening is rejected: the property under test is scoped to the text a spawn PRELOADS, and a joined corpus would prove the literal exists somewhere while losing the scope that makes the count mean anything.

**KB-AP-8: a synthetic provider name can silently become real.** `tests/installer/reference-overlay.test.ts`'s fixture provider (`EXTRA_PROVIDER_MANIFEST`) is the deliberately unregisterable `probe-provider`, with its own guard asserting it stays absent from the real manifest, because an earlier fixture literally named `jira` became a real provider mid-Phase-3 and silently inverted what its arms proved.

**KB-AP-9: no prompt stop rules for install corruption.** A rule telling a spawn to stop or report DEGRADED when the tracker contract is missing guards a failure only a corrupted install can cause; ask "why would it be missing?" first. `collectMissingContractRules` holds this.
