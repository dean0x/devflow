# Uninstall Scope & Install-Artifact Cleanup

## Rules

- **KB-AP-1** Uninstall never removes all of `~/.devflow/`: only `scripts/` is Devflow-owned; shadows, conventions and config are user content. `resolveDevflowDirCleanup` plus `removeDevFlowInstallArtifacts` enforce the boundary.
- **KB-AP-2** Call `enumerateUserDevFlowContent` BEFORE any removal: the files may be gone by the time a confirmation prompt is shown.
- **KB-AP-3** Never `process.exit()` on a cancel or decline path after `removeAllDevFlow` ran: it leaves `manifest.json` behind. Cancel and decline fall through to `removeDevFlowInstallArtifacts`; `resolveProjectDataCleanup` maps cancel to preserve.
- **KB-AP-4** Never put a name in both `userContentPaths` (via `enumerateUserDevFlowContent`) and `installArtifactPaths`: the prompt would call it user content, then delete it regardless of the answer. A test enforces disjointness.
- **KB-AP-5** A dry-run test never exercises only the pure helper: `runDryRunPhase` (full mode) must go through `enumerateDryRunExtras`, or preview and removal diverge unseen.
- **KB-AP-6** `artifact.isDir` is checked by strict `=== true`; `recursive: artifact.isDir` hands `undefined` to `fs.rm`, whose `TypeError` on directories the per-item catch swallows silently.
- **KB-AP-7** Never skip the containment precondition before each `fs.rm` in the artifact loop (`''`, `..`-prefixed or absolute relative path means skip): a path collapsing to `''` would wipe all of `~/.devflow`.
- **KB-AP-8** Never kill the relay: before removing `proxy.pid`, check the process with `process.kill(pid, 0)` and warn with a manual kill hint.
- **KB-AP-9** Selective uninstall retains assets on behalf of the MANIFEST's installed plugins, never the whole registry (`D-RETAIN-FROM-MANIFEST`), and the dry run and the real removal always receive the same list.
- **KB-AP-10** A settings stripper never matches by marker word or by file name alone: hooks end in `/scripts/hooks/run-hook <marker>`, the statusLine ends in `/.devflow/scripts/hud.sh` (or the legacy `statusline.sh`).
- **KB-AP-11** The project-data step never touches `DEVFLOW_TRACKED_PATHS` (name AND kind must match) and never follows a symlinked `.devflow`.
- **KB-AP-12** A legacy local-scope removal never follows a link under `<repo>/.claude` or `<repo>/.devflow`: each target passes the `ChangeGuard`.
- **KB-AP-13** `removeManagedSettings`'s path override is a parameter, never an env var: the function can run `sudo rm` / `sudo cp`, and an env-selectable target would let anyone controlling the environment redirect a root write.
- **KB-AP-14** No sudo path goes through a shell: every call is `execFileSync('sudo', [...])` with argv.
- **KB-INV-1** Install artifacts are removed on every path (confirm, decline, cancel, non-interactive, `--keep-docs`); user content survives every path but a confirmed full-directory rm.
- **KB-INV-2** `resolveDevflowDirCleanup` returns `'artifacts-only'` unless its four preconditions hold, and always under `--keep-docs`; it never throws.
- **KB-INV-3** `installArtifactPaths` is the single source of truth for both the removal loop and the dry-run preview.
- **KB-INV-4** A local-only uninstall never touches HOME, and an explicit `--scope local` where no legacy install can exist exits 1 before any phase runs.
- **KB-INV-5** `removeManagedDenyList` is the one implementation behind both `devflow security --disable` and `devflow init --security none`; it classifies, never throws.
- **KB-INV-6** A selective `uninstall --plugin` drops the named plugins from `manifest.plugins` through `removeManifestPlugins` (`src/core/manifest.ts`, `D-UNINSTALL-DROPS-PLUGIN`) behind the `mayChange` guard, so a plain re-init does not install them again; `knownPlugins` stays, and it also re-stamps the installed `/code-review` language-focus line from the plugins that remain.

## Overview

Uninstall is the inverse of the install pipeline plus a boundary around what is user content. It runs as phases in `src/cli/commands/uninstall.ts` (dry run, selective, full, cleanup) over injectable seams, and shares `sweepOrphanedAssets` with the installer. One install scope exists machine-wide; the `local` scope survives only to remove installs the retired `init --scope local` left in repositories. The managed security deny-list removal that `devflow security --disable` and `devflow init --security none` share is documented at the end.

## Exports and Detection

- `removeAllDevFlow`, `removeSelectedPlugins`, `isDevFlowInstalled`, `enumerateUserDevFlowContent`, `removeDevFlowInstallArtifacts`, `installArtifactPaths`, `enumerateDryRunExtras`, `sweepDevflowNamespaces`, `resolveDevflowDirCleanup`, `resolveProjectDataCleanup`, `resolveProjectDataPlan`, `partitionProjectData`, the phase runners and `userContentPaths` are all exported for direct testing.
- **`isDevFlowInstalled(claudeDir)`** detects via `commands/devflow/` (exists), OR `agents/devflow/` (exists), OR any `devflow:`-prefixed skill dir in `skills/`. Keying off `commands/devflow/` alone misses commandless-plugin installs where agents and skills are still present.

## Scope: One Install, Legacy Local Cleanup (`D-SCOPE-RETIRED`, `D-LEGACY-LOCAL-CLEANUP`)

`init` installs machine-wide only (`getInstallationPaths()` takes no scope). `uninstall` still knows `UninstallScope = 'user' | 'local'` solely to remove installs the retired `init --scope local` left in repos: the private `legacyLocalInstallPaths(gitRoot)` is the only place a `<repo>/.claude` / `<repo>/.devflow` path is derived.
- A local-only uninstall never touches HOME: the settings strip edits `<repo>/.claude/settings.json`, `removeAmbientHook(json, { purgeLegacyRule: false })` skips the `~/.claude/rules/devflow/commands.md` purge (also on `runSelectivePhaseForScope({ scope: 'local' })`), and `runCleanupPhase` returns before its machine-wide steps (security deny list, safe-delete) unless `scopesToUninstall` includes `user`.
- **Links (`D-CLI-NO-SYMLINK`).** A repository can commit enough of `.claude` to be detected, and `.claude`, `.devflow` or anything inside them may be a symbolic link. Every local-scope removal and settings rewrite (`removeAllDevFlow`, `removeSelectedPlugins`, `sweepDevflowNamespaces`, `removeDevFlowInstallArtifacts`, the selective phase's `/code-review` re-stamp, the agent-model revert and both settings strips) first passes the `ChangeGuard` from `legacyLocalChangeGuard`: a target with a link anywhere from `<gitRoot>/.claude` or `<gitRoot>/.devflow` down to it, itself included, is skipped, the link kept, and one warning per link names it; a swept folder is checked as a whole, since `fs.rm` only unlinks a link it is given. The user scope's guard passes everything. Pinned by `tests/uninstall-legacy-local.test.ts` (its TP-14, TP-48 and the `D-CLI-NO-SYMLINK` arms).
- **`uninstall --scope local` refuses where no legacy local install can exist.** `legacyLocalInstallPaths(gitRoot)` returns `null` when the git root's `.claude` / `.devflow` resolve (realpath-compared through `isSameLocation`, in `src/core/same-location.ts`, shared with init) onto the machine-wide `getInstallationPaths()` directories (a repo rooted at HOME, e.g. a dotfiles repo), and `scopeInstallPaths('local', null)` is `null` outside a repo. An explicit `--scope local` with a `null` result logs `No legacy project-local install here` and exits 1 before any phase runs, so the cleanup phase can never reach the cwd (HOME); auto-detection in that repo finds only `user`. Pinned by the two HOME-rooted tests in `tests/uninstall-legacy-local.test.ts`.

## Removal

- **`removeAllDevFlow(claudeDir, devflowScriptsDir, verbose, mayChange?)`** removes `commands/devflow/`, `agents/devflow/`, `rules/devflow/`, `devflowScriptsDir`, and skill dirs via two separate passes: **prefixed** (`devflow:name`) for every skill in `getAllSkillNames() ∪ LEGACY_SKILL_NAMES`; **bare** (name or `devflow-name`) for `LEGACY_SKILL_NAMES` only — `~/.claude/skills/` is shared, so a bare dir matching a live-registry skill name is by construction foreign to Devflow. A skill's whole prefixed directory (including any `references/` the overlay wrote into `devflow:git`) goes with it; there is no separate reference cleanup.
- **`revertExternalAgents`** runs BEFORE `removeSelectedPlugins` (on the full path, before `removeAllDevFlow`), stripping GPT model lines from installed agent frontmatter while the files are present. **Known limitation:** on the selective path it reverts EVERY installed agent, not only those being removed; surviving agents lose GPT frontmatter assignments until the next `devflow init`.
- **`sweepDevflowNamespaces(claudeDir, verbose)`** is a registry-diff sweep of all Devflow-owned namespaces (`agents/devflow/`, `commands/devflow/`, `skills/` `devflow:*` entries), called by `removeSelectedPlugins` after the per-plugin removals to prune retired asset names (renamed or deleted from the registry) without the caller knowing the full registry. `knownNames` spans ALL plugins per asset type, so assets of non-selected plugins are never swept. Failures always warn (a swept-but-not-removed agent keeps loading in Claude Code); removals are logged only under `verbose`.
- **`resolveInstalledPlugins(devflowDir)`** (async) reads the manifest's `plugins` array and returns the matching `PluginDefinition`s, falling back to the whole registry when there is no manifest or nothing matches. `computeAssetsToRemove(selectedPlugins, installedPlugins)` retains assets on behalf of THAT list, not the registry (`D-RETAIN-FROM-MANIFEST`): with plugin-scoped skills the two disagree, and retaining from the registry would keep a removed plugin's skills alive because some plugin the user never installed also declares them. Skills are retained across the CLOSURE (`skills ∪ requires`) of the remaining plugins. `runDryRunPhase` REQUIRES `installedPlugins`; `runSelectivePhaseForScope` and `removeSelectedPlugins` take it optionally — the dry run and the real removal must be given the SAME list or they describe different outcomes.

## The `~/.devflow` Boundary

- After `removeAllDevFlow`, the scope decides the rest of `devflowDir`, in `resolveDevflowDirCleanup(opts)`, a **pure exported function** (like `resolveSecurityRemovalDecision`; no I/O). Four preconditions must hold: `basename(devflowDir) === '.devflow'`, `devflowDir !== homeDir`, `devflowDir !== '/'`, `devflowDir.startsWith(homeDir + sep)`. Any failure returns `'artifacts-only'` (never throws). With `keepDocs` it returns `'artifacts-only'` regardless of `isTTY` or user content, suppressing the full-cleanup prompt. It returns `'artifacts-only'` or `'prompt'`.
- **`installArtifactPaths(devflowDir)`** is the exported pure source of truth returning `ReadonlyArray<{ relPath; isDir?; isPrefix? }>` for every Devflow-owned install artifact under `devflowDir` (`manifest.json` is removed by a separate step at the top of `removeDevFlowInstallArtifacts`). It lists `migrations.json`, `agent-models.json`, `costs/` (dir), the proxy files (`proxy.json`, `proxy-routing.json`, `proxy.pid`, `.proxy-spawn.lock/` dir), `logs/` (dir), the cache dir (resolved via `hudCacheDir(devflowDir)`), the tracker runtime files, and the CLAUDE.md import audit stamp. The tracker runtime files are `.tracker.processing` (the Tracker agent's global claim file), every `.tracker.{provider}.attempts` (`TRACKER_ATTEMPTS_NAMES`, derived from the registry), the legacy single `.tracker.attempts`, `.tracker.enabled` (the machine provider sentinel) and the `.tracker-staged.` prefix entry (`isPrefix`, a SIGKILL-stranded staging file): machine state with no user-authored content, disjoint from the conventions. The audit entries are `.claude-md-audit` (`CLAUDE_MD_AUDIT_STAMP_FILE`, imported from `src/core/claude-md-audit.ts`) and its `.claude-md-audit.tmp.` prefix entry (`CLAUDE_MD_AUDIT_STAMP_TMP_PREFIX`: the `<stamp>.tmp.<pid>` sibling a SIGKILL strands between write and rename) — machine state the SessionStart hook and `devflow init` write, holding paths, existence flags and finding keys but nothing the user authored. The audit script itself (`claude-md-audit.cjs`) ships in `~/.devflow/scripts/`, which `removeAllDevFlow` removes wholesale, so it has no entry and a neighbouring `.claude-md-audit-notes` file is never matched. `agent-models.json` is an artifact because stale per-agent overrides would silently re-apply to renamed or deleted agents on reinstall; `migrations.json` is an artifact so migrations (including `canonicalise-agent-keys-v1`) re-run cleanly on reinstall.
- **`enumerateUserDevFlowContent(devflowDir)`** walks `userContentPaths(devflowDir)` (called BEFORE any removal) and returns human-readable labels for what exists: `skills/` and `rules/` (shadows), `preference-profile.md`, `tracker/` (the inferred per-provider issue-tracker conventions, `D-TRACKER-PER-PROVIDER-CONVENTIONS`, the code-site label OD-15), the legacy `tracker.md` and every `tracker.md.{provider}.bak` an earlier release left (the migration leaves an unplaceable `tracker.md` in place and nothing moves or deletes a backup), `learning.json`, and `hud.json`. `agent-models.json` is NOT listed. **The conventions' classification as user content is conditional**, recorded as a live reversal obligation at the code site: they are safe to preserve only because the Git agent refuses to trust a stale file whose frontmatter `provider:` disagrees with the resolved provider (`TRACEABILITY: DEGRADED (tracker configuration mismatch (conventions file))`, no tracker call) — the same "silently" test that governs `agent-models.json`'s artifact classification, applied in the opposite direction. If that guard is dropped or softened, the conventions entries must move to `installArtifactPaths` in the same change (full mechanics: `tracker-feature` KB).
- **Hard classification invariant:** user content (survives unless explicitly confirmed) and the artifact list (removed on every path) must be **DISJOINT**. `agent-models.json` and `migrations.json` are artifacts; `hud.json` is user state; the conventions (`tracker/`, legacy `tracker.md`, `tracker.md.{provider}.bak`) are user state while the `.tracker.*` runtime files are artifacts. `tests/uninstall-logic.test.ts` enforces it: `(9c)` compares the residue after an artifact-only removal with the user-authored allow-list (which includes `tracker`, `tracker.md` and `tracker.md.jira.bak`), and `(9f)` checks that every enumerated user-content item survives an artifacts-only pass.
- **`enumerateDryRunExtras(claudeDir, devflowDir)`** (exported async, extracted from the dry-run loop body) enumerates what is on disk: whole Claude directories (`commands/devflow`, `agents/devflow`, `rules/devflow`, `devflowDir/scripts`), skill removal candidates via the same split-pass approach as `removeAllDevFlow`, `manifest.json`, and every artifact from `installArtifactPaths(devflowDir)`. Coverage matches `removeAllDevFlow` exactly, so the preview cannot diverge from the real removal.
- **`removeDevFlowInstallArtifacts(devflowDir, verbose)`** removes (non-fatally per item) `manifest.json`, then every entry of `installArtifactPaths(devflowDir)`. Before removing `proxy.pid` it reads the PID and checks the process with `process.kill(pid, 0)`; if it is alive it warns with a manual kill hint and **never kills the relay**. The **containment precondition** inside the loop computes `path.relative(devflowDir, fullPath)` before each `fs.rm` and **skips the removal** (no throw) when the result is `''`, starts with `'..'`, or is absolute — a derived relative path (for example from `hudCacheDir`) collapsing to `''` would otherwise recursively wipe all of `~/.devflow`. It is production code, not only a test, to keep the invariant load-bearing.
- **User-scope prompt path:** confirm → `fs.rm(devflowDir, {recursive: true, force: true})`; decline OR cancel → falls through to `removeDevFlowInstallArtifacts`. `process.exit()` is never called here. `resolveProjectDataCleanup(answer: boolean | symbol) => boolean` is the pure mapping: `true` only on explicit confirmation, a cancel symbol (Ctrl-C) maps to `false` (preserve) and the uninstall continues.
- **Settings cleanup** calls `applyDisableToSettings(parsedSettings, managedPort)` in one parse-mutate-serialize pass; `managedPort` is read from `proxy.json` (falling back to `DEFAULT_PROXY_PORT`), so only the `ANTHROPIC_BASE_URL` for Devflow's managed port is stripped.

## Phase Runners

Extracted from the `.action()` body for independent testability:
- **`runDryRunPhase(opts)`** — selective mode derives the plan from `computeAssetsToRemove` + `formatDryRunPlan`; full mode calls `enumerateDryRunExtras` per scope (the production enumeration path). It also lists the project-data removals; `uninstall --dry-run` does not list the `/code-review` re-stamp (a rewrite, not a removal).
- **`runSelectivePhaseForScope(opts)`** — reverts external agent frontmatter, calls `removeSelectedPlugins` (which calls `sweepDevflowNamespaces`), re-stamps the installed `/code-review` from the plugins that remain (`restampInstalledCommands` under the `mayChange` guard; learning-variants KB), drops the removed names from `manifest.plugins` (`removeManifestPlugins`, KB-INV-6; a quiet no-op with no usable manifest or none of the names listed, and a failed write only warns), and cleans the ambient hook if the ambient plugin is removed. **Selective uninstall never strips flags:** `stripFlags` runs only in `runCleanupPhase` on full uninstall, so flag state persists in `settings.json` when individual plugins are removed.
- **`runFullPhaseForScope(opts)`** — reverts external agents, calls `removeAllDevFlow`, then scope-aware `devflowDir` cleanup (local: always artifacts-only; user: the `resolveDevflowDirCleanup` gate → prompt or artifacts-only). It takes an injected `isTTY` instead of reading `process.stdin.isTTY`.
- **`runCleanupPhase(opts)`** — post-loop extras on full uninstall: the project-data step, `.claudeignore`, `settings.json` hooks/flags, the security deny list and the safe-delete shell function. It calls `stripFlags` directly (no record argument), removing all flag-managed keys including `attribution` when its current value is the devflow-managed shape `{"commit":"","pr":""}` (shape guard via `settingDeleteGuard`; a custom attribution value is never deleted). It takes injected `cwd`, `isTTY` and an optional `confirm: ConfirmPrompt` (default `p.confirm`; every confirm in the phase goes through it), so prompt gates are testable without touching developer files.

## Project-data Step (`D-UNINSTALL-CARVE-OUT`)

`resolveProjectDataPlan({ gitRoot, homeDir, machineDevflowDir })` targets `<gitRoot>/.devflow`, never `<cwd>/.devflow`, and skips (`no-git-root` | `home-root` | `machine-dir` | `symlink` | `absent`) outside a repo, when the git root is HOME, when the root's `.devflow` is the machine-wide devflow directory, or when it is a symbolic link to anywhere else (`lstat` after the machine-dir comparison; never followed, so neither the link nor its target is touched). Both comparisons go through `isSameLocation` (realpaths: macOS `/var` → `/private/var`, a symlinked HOME). `formatProjectDataSkip(reason, gitRoot)` is the one skip message (machine-dir/home-root and symlink; null for no-git-root/absent) that `runCleanupPhase` and `runDryRunPhase` both print. `partitionProjectData` keeps `DEVFLOW_TRACKED_PATHS` (`features/`, `conventions.md`, `policy.json`, `project.json`, exported from `post-install.ts` beside the gitignore block; name AND kind must match, so a file named `features` is removed) and removes the rest. The private `runProjectDataStep` logs `formatProjectDataPlan` (what is removed, what is kept) before one confirm; `--keep-docs`, non-TTY, decline and cancel change nothing, and `.devflow/` itself is removed only when nothing tracked was in it. Pinned by the project-data tests (TP-26/TP-27) and the symlinked-`.devflow` describe in `tests/uninstall-logic.test.ts`, which also pins that every path the gitignore block re-includes is in `DEVFLOW_TRACKED_PATHS`.

## Exact Ownership of Hooks and HUD (`D-EXACT-HOOK-OWNER`, `D-HUD-EXACT-OWNER`)

Every stripper `runCleanupPhase` calls on `settings.json` (`removeAmbientHook`, `removeMemoryHooks`, `removeCaptureHooks`, `removeDreamHook`, `removeContextHook`, `applyProxyTeardownToSettings`) identifies devflow's hooks through `src/targets/claude-code/hooks.ts` — the command ENDS in `/scripts/hooks/run-hook <marker>` (or a named legacy ending) — and removes single hooks, so a user hook that mentions a marker word, and a devflow hook's siblings in its matcher group, survive uninstall. `isDevFlowStatusLine` (`src/cli/commands/hud.ts`) claims a statusLine only when its command ends in `/.devflow/scripts/hud.sh` or the legacy `/.devflow/scripts/statusline.sh`. init's settings pass (`addHudStatusLine` / `removeHudStatusLine`), `init --hud-only`, `hud --enable/--disable` and uninstall's `runCleanupPhase` all converge through it, so a foreign statusLine (for example `~/.claude/statusline.sh`, `/opt/devflow/...`) survives each (`tests/hud.test.ts`, TP-23).

## Managed Security Deny-List Removal (`security.ts`, `D-MANAGED-REMOVAL-REMEDY`)

`removeManagedDenyList(rootDir, verbose, managedPath?)` is the ONE implementation `devflow security --disable` and `devflow init --security none` both call, so "none" means none in every location. It classifies the outcome as a `ManagedDenyRemoval` discriminated union (`removed | absent | no-devflow-entries | failed`) rather than a boolean, gated on `detectDenyState`'s parse-safe signal (a corrupt or Devflow-free managed file is classified `no-devflow-entries` / `absent` before reaching `removeManagedSettings`, which parses without a guard) and never throws. `describeManagedDenyRemoval(outcome)` renders the one user-facing line both callers print; a `failed` outcome names no command (pointing `devflow security --disable`'s own failure back at itself would be circular) and tells the user to re-run interactively and accept the sudo prompt, or edit the file as an administrator. `removeManagedSettings`'s `managedPathOverride` is the test seam both this function and `installManagedSettings` share.

## Anti-Patterns

- **KB-AP-1** Only `~/.devflow/scripts/` is Devflow-owned; `~/.devflow/skills/`, `rules/` and config are user-owned. The cleanup/artifacts split is the boundary.
- **KB-AP-2** `enumerateUserDevFlowContent` needs the files present, so it runs before the removal block.
- **KB-AP-3** `removeAllDevFlow` has already run when a cancel or decline arrives; an early exit leaves a stale `manifest.json`. `runAttributionStep` likewise never calls `process.exit`; callers own the cancel idiom.
- **KB-AP-4** A name in both lists makes the confirmation prompt untruthful.
- **KB-AP-5** The original helper-only test (`installArtifactPaths` in isolation) missed a real divergence: bare legacy skill dirs and `agent-models.json` appeared in the preview but not in the production removal. The fix routes full-mode `runDryRunPhase` through `enumerateDryRunExtras`, which derives from `installArtifactPaths` and the same skill-candidate sets as `removeAllDevFlow`; the test now exercises `runDryRunPhase` directly.
- **KB-AP-9** The registry keeps a removed plugin's skills alive when some plugin the user never installed declares them; the manifest's installed list does not.

## Gotchas

- **KB-AP-6** Per-item failure isolation can mask systematic TypeErrors: the proxy-artifact removal depends on `artifact.isDir === true` (strict equality), because `recursive: artifact.isDir` passes `undefined` for entries with no `isDir`.
- **KB-INV-1** `migrations.json` is an artifact, so migrations re-run cleanly on reinstall; a failed `canonicalise-agent-keys-v1` write is not retried by the runner (init-seed KB).
- **`revertExternalAgents` on the selective path reverts ALL agents**, not only those being removed; the surviving agents lose GPT frontmatter until the next `devflow init`.
- **Selective uninstall does not rewrite `manifest.json`**, so `manifest.plugins` still lists a removed plugin and a later `init --plugin=X` or full re-init reinstalls it consistently with disk.
- **An explicit `--scope local` in a HOME-rooted repository exits 1** by design; auto-detection finds only `user`.
