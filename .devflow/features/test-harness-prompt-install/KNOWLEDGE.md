# Test Harness - Prompt-Corpus Doctrine Guards and Install-Level Regression Net

## Rules

- **KB-INV-1** A prompt doctrine is held by a guard over the compiled corpus with a named collector, known-bad probes driven through that same collector, and loud corpus reads (a missing file or root fails, never skips).
- **KB-INV-2** Rosters are derived, never listed: the report-cap roster comes from `DEVFLOW_PLUGINS` less the hook-spawned agents, decision receivers from `resolveAllAgents()`, and spawn liveness counts DISTINCT agent types, not sites.
- **KB-INV-3** `DECISIONS_CONTEXT` goes only to agent types whose source lists it among their inputs, and the `LEARNING=off` gate sentence precedes the ledger-locate call and index read in every host.
- **KB-INV-4** No spawn argument list or workflow `agent(` options object in the prompt corpus carries `model=` or `model:`: a spawn's model outranks the installed frontmatter where `devflow agents` writes a user's override.
- **KB-INV-5** Each learning variant equals the compiled host resolved on or off by an INDEPENDENT line scanner (not the build's splitter), and no `<!-- learning:... -->` marker survives in any `dist/**/*.md`.
- **KB-INV-6** Install snapshots and the hook matrix move only through `npm run test:golden:update -- install-snapshot`, in a fixture-only `test(snapshot):` commit whose PR body justifies each hunk.
- **KB-INV-7** Every CLI toggle's writes stay inside its write-set-fence row's allowlist, and coverage is held to the CLI's own definitions (`devflow --help`, every `--enable`/`--disable`/`--set`), not to the table.
- **KB-INV-8** The same non-interactive init lands the same machine side in every location (`INIT_LOCATIONS`), and per-repo writes land only at the checkout toplevel.
- **KB-INV-9** No learning-ledger ID reaches committed text (`no-ledger-citations`): ledger IDs are machine-local, so committed text states a decision in words.
- **KB-INV-10** A live-`claude` test generates its session UUID before spawning (`--session-id <uuid>`), waits after SIGTERM, retries at most `MAX_SPAWN_ATTEMPTS`, and stays excluded from routine integration runs.
- **KB-AP-1** A live-`claude` test prompt must stay read-only: a spawned Git agent once made a real empty commit.
- **KB-AP-2** Never run `init` or a hook against the real HOME or a real repo: a QA-agent run once wiped a real `~/.claude`; build the env with `sandboxEnv` and echo the resolved HOME first.
- **KB-AP-3** Never use spawn SITE counts as a doctrine's liveness floor: a legitimate prompt trim lowers sites (source plus compiled copy) but not types.
- **KB-AP-4** A test green alone and red under the full suite has an unsized timeout, not a flaky branch: size slow arms from a measurement taken alone instead of labelling them flakes.
- **KB-AP-5** Never build a recording PATH farm per test: the first exec of a new executable (and of `node` behind it) stalls on macOS after a fork-heavy run; build once per file and warm in `beforeAll`.
- **KB-AP-6** Simulating a missing tool by subtracting it from `PATH` is platform-dependent: build farms from explicit wrappers.
- **KB-AP-7** `heredoc-quoting` exclusions are pinned as `file:line`: a comment added above an excluded heredoc moves it, so re-pin in the same change.
- **KB-AP-8** The percent-based auto-compact override is out of scope in every spelling and letter case anywhere under `src/`.
- **KB-AP-9** A prompt scan must never read a stale build: `no-config-read` fails when `dist/` is older than its sources instead of scanning it.

## Overview

These checks hold the agent and command prompts to the doctrines the token-diet waves set, and prove the install itself is stable. Each follows the Guard Conventions in `test-harness` (a named collector, known-bad probes driven through that same collector, loud corpus reads). The doctrine each pins is owned elsewhere: `dynamic-workflow-engine` for the foreground run, gate ownership and bind-once input, `ambient-orchestrator` for the charter checks in `tests/agent-name-guards.test.ts`.

## Prompt-Corpus Doctrine Guards

- **`tests/guards/running-commands-parity.test.ts`**: the Code, Validate and Test bodies each carry exactly one `## Running commands` block, byte-identical, within a 1,400-byte target (`BLOCK_MAX_BYTES`) and stating every normative element: foreground under a Bash timeout, the capture-then-tail form that echoes `LOG=` first, no backgrounding or polling, BLOCKED on an overrun, the 90% split and the `bash-max-timeout-ms` remedy. `_engine.mds`'s `build_execution_doctrine()` renders the same text, each `dynamic-build.mds` prompt site names the block exactly once in source and in the compiled command (`running-commands-site-count`), and `test.md`'s dev-server section follows the block as a section of its own, where the dev server is started in the background, with Monitor named nowhere outside the block's prohibition.
- **`tests/guards/gate-ownership.test.ts`**: the gate bodies (Code, Simplify, Evaluate, Scrutinize, Test, Validate; `gate-ownership-body-count`) each carry one `**Gate ownership:**` line pinned as text; all but Validate say that only Validate runs the full suite; Simplify and Evaluate instruct no build, test or lint command; the TDD skill says "affected tests" and defines the term once. The rows are pinned as text on purpose: a reworded row must change the guard.
- **`tests/guards/report-cap.test.ts`**: every roster agent's Output section ends with a `Report cap:` line (at most about 1,500 tokens, longer material to a `mktemp` file, the exempt fields named). The roster is DERIVED from `DEVFLOW_PLUGINS`, less the hook-spawned `learning` and `tracker`, so a new agent without a line fails instead of slipping past a stale list (`report-cap-roster-count`). Exempt fields were taken from what each spawning command parses, not from the agent's own template; sections are read fence-aware (the Design, Review and Diagnose templates carry `## ` lines inside fences). `git` is on the roster: its `## Output` section sits after every operation and before `## Principles` and ends in the cap line, its exempt-field record lists what the commands parse from the per-operation templates, `check-ci-status`'s `**Status**:` is exempt as the enum `ci-wait.cjs` is pinned to, and a probe drops the cap line and then one exempt field.
- **`tests/commands/report-caps.test.ts`**: the built-in Explore and Plan spawns a command writes as prose carry their own cap WITH a token figure ("at most|under|no more than N tokens"; "keep it short" bounds nothing), counted in the compiled commands against per-command minimums in `REQUIRED_CAPS` (explore, debug, plan).
- **`tests/guards/arguments-once.test.ts`** + **`tests/install-bound-input.test.ts`**: over `dist/commands` at most one `$ARGUMENTS` placeholder per command (literal and positional spellings counted together, none positional), exactly one in each `TRACKER_PARTIAL_ADOPTERS` host, each between `<command-input>` lines, and exactly the `INPUT_BOUND_COMMANDS` set (the adopters plus explore, release and research; a set, not a count) carries one. The install test repeats the count on the INSTALLED commands after one real `init` into a sandbox HOME and checks the installed charter, because the install is the last step that could change a command's text. Ceiling `arguments-once-max`.
- **`tests/commands/knowledge-preload.test.ts`**: the Knowledge agent preloads `devflow:feature-knowledge` and holds no Skill tool, and no compiled command (the write-back partial, `/research`) tells it to load that skill.
- **`tests/guards/spawn-no-hardcoded-model.test.ts`**: no `Agent(` argument list and no workflow `agent(` options object under `src/assets/{commands,agents,skills,mds}` or `dist/{commands,agents}` carries `model=` or `model:`; argument text is read with string and template bodies blanked. Hook scripts are outside it by design. Reach arms require every root to contribute files and the spawn-holding roots to contribute sites, and the liveness count is `SPAWNED_AGENT_TYPE_FLOOR` DISTINCT spawned agent types (`spawn-no-model-agent-type-floor`), not sites: consolidating a spawn lowers the site count but not the type count, so no legitimate prompt trim can break the floor, and a type leaves the count only when no prompt spawns that agent at all.

## Learning, Decisions, KB-Shape and Review-Gating Guards

- **Learning variants (`tests/learning/`).** `learning-variants.test.ts` holds the splitter (`src/core/learning-variants.ts`): exact-byte assertions on every happy arm and one known-bad probe per refusal kind (nesting, second `off`, unopened `end`, unclosed arm, empty arm, stray or malformed marker). `learning-variants-build.test.ts` builds a FIXTURE host with arms under a throwaway `DEVFLOW_MDS_ROOT` and holds the real `dist/learning-off/` to `LEARNING_VARIANT_HOSTS` in both directions, with no marker in any `dist/**/*.md`. `learning-variants-arms.test.ts` holds the arms the prompts really carry: each variant equals the compiled host resolved on or off by an INDEPENDENT line scanner; an on arm is learning text and an off arm never is, bar an on/off pair differing only in a list or step number; nothing under `dist/learning-off` holds a learning token except the pinned settings-grammar line; an off agent's frontmatter is its on frontmatter minus the `apply-decisions` preload; no status-line sampler anchor sits inside an arm. The install side (`learning-variants-install.test.ts` against temp trees and the real installer, `-install-e2e.test.ts` driving the built CLI under `sandboxEnv`, HOME seeded with `~/.claude` and the first assertion on installed bytes) is mutation-checked; `requires-closure` reasons over the on variant, `provider-scope` scans `dist/learning-off/{agents,commands}`, and `code-preload.test.ts` has an off arm.
- **Decisions seam (`tests/decisions/decisions-seam.test.ts`, D-DECISIONS-DECLARED-ONLY).** `DECISIONS_CONTEXT` goes only to agent types whose source lists it among their inputs (computed from `resolveAllAgents()`, never typed): every Code spawn passes it, a site that passes it names a declared type, and every unfenced prose sentence giving it away names a declared receiver, with a literal classification table whose stale rows fail. Spawn sites come from `collectCodeSpawnSites(file, text, agentType = 'Code')`, which validates the type name and reads five shapes (fenced spawn, one-line prose spawn, "Spawn a T agent" prose, a workflow template literal with other options allowed, and the engine partial's pseudo-form `T(agentType:"T", ...)`), so that pseudo-form counts as a Code site in dynamic-build for the compliance-lens and OPERATION guards. `CODE_SITE_FLOOR` and `DECISIONS_HOST_COUNT` are test-local constants.
- **Feature-knowledge delivery and shape.** `tests/guards/feature-knowledge-delivery.test.ts` (D-KB-DELIVERY-TIERS, D-KB-LEGACY-FALLBACK): each selected KB reaches an agent as a `--- Feature knowledge: {slug} ---` block (`KB:` path, `Rules:` bullets with IDs, `Headings:` index); the `LOAD_HOSTS` (the commands calling `knowledge_load()` plus `release`) carry the format, the Bash heading listing and the legacy `Rules ({section name}):` label and never the word "Grep"; a spawn line keeps the input name `FEATURE_KNOWLEDGE:` and names its tier's variable (`FEATURE_KNOWLEDGE_RULES` for Evaluate and Scrutinize; none for Validate, Git, Test). `tests/guards/kb-shape.test.ts` (D-KB-RULES-SHAPE) holds the wording in the `feature-knowledge` skill, the Knowledge agent and the write-back prompt: Rules first after the title, stable `KB-AP-n`/`KB-INV-n` IDs, a 30,000-character target and 40,000 ceiling, index lines of at most 300 characters and descriptions of at most 220, "curate, never truncate", the legacy fallback and the refresh rule stated once. The charter's Feature knowledge bullet is held by `collectCharterKnowledgeDefects` in `agent-name-guards.test.ts`.
- **Handoff and quiet form.** `tests/guards/handoff-sections.test.ts` (D-HANDOFF-CAP): `## Phase {N} Implementation Summary` sections of at most 8,192 bytes, each written once by the Code agent that finished the phase; the Code agent, `/implement`'s Handoff Protocol and the dynamic commands' shared convention must agree. `tests/guards/validate-quiet-form.test.ts` (D-VALIDATE-QUIET-FORM): the Validation Order table's Quiet form column per row, one fallback sentence (re-run only the failing test verbosely, never the suite) OUTSIDE the byte-identical `## Running commands` block, and one quiet-form bullet in each of the language rules.
- **`/code-review` gating and the language stamp.** `tests/guards/code-review-diff-gating.test.ts` (D-DIFF-CLASS-GATE, D-DIFF-FILE-ONCE, and the prompt side of D-LANGUAGE-FOCUS-STAMP, in both learning variants): classification order and both fail-safes, exact reduced focus sets, one `diff.patch` per worktree written by redirect, `DIFF_FILE`/`DIFF_RANGE` spawn keys, every `git ... diff` either the `--name-only` listing or a redirect into a patch file, no `test -f` probe in any compiled command, and `/dynamic-build` carrying none of it. The installer side is `tests/installer/language-stamp.test.ts` (injected temp dirs: the pure `installedLanguageFocuses`, the line rewrite, install, partial install, the `uninstall --plugin` re-stamp, and the converge CARRYING the installed stamp rather than re-stamping) and `language-stamp-e2e.test.ts` (built CLI under `sandboxEnv`); `skill-references` holds the stamp paragraph's canonical focus names (`language-gate-focuses`, equal to what `renderLanguageStamp(installedLanguageFocuses(DEVFLOW_PLUGINS))` writes) and `claude-dir` no longer expects a Claude-directory probe in `/code-review`.
- **Compaction and import audit.** `tests/guards/no-autocompact-pct-override.test.ts`: the percent-based auto-compact override is out of scope in every form, so no spelling of its name (any letter case) appears anywhere under `src/`, with a reach arm naming a sentinel per surface class. `tests/session-start-compact.test.ts` holds Sections 5 and 6 of `session-start-context` (the resume directive, pinned by `compact-directive-max-chars`, and the CLAUDE.md import-audit fast path and stamp) through PATH farms of recording `jq`/`node` wrappers; `tests/core/claude-md-audit.test.ts` holds the audit script and its facade.

## Corpus-Wide Text Guards

- **`tests/guards/no-ledger-citations.test.ts`**: no learning-ledger ID (the ADR or PF prefix followed by three digits) reaches committed text, because the ledger is gitignored and numbered per machine. It reads the worktree as git lists it (tracked plus untracked-unignored files; binary files skipped). A FULL BAN reports an ID wherever it sits in `src/**`, `scripts/**`, the root `vitest*.config.ts` files, `docs/**`, the root prose (`CLAUDE.md`, `README.md`, `CONTRIBUTING.md`, `.devflow/conventions.md`, `.release/RELEASE-FLOW.md`), `.devflow/features/index.md`, every feature `KNOWLEDGE.md` and `tests/fixtures/numeric-floors.json`. In `tests/**/*.ts` only commentary is read (comments, `describe`/`it`/`test` titles and `expect(value, message)` messages, pulled out by a strings-first lexer so a `//` inside a string is never a comment): an ID in a citation shape (after `applies`, `avoids`, `per` or `see`, opening or closing a parenthesis or bracket, or possessive) is always reported, and any other ID is reported unless the same file holds it as data outside its commentary. `CHANGELOG.md`, the golden fixtures, the install-snapshot goldens and `.devflow/learning/**` are excluded everywhere; placeholders carry no three digits and pass. Non-vacuity: seeded probes drive the same `collectLedgerViolations` collector the live arms use (a red probe per full-ban root and per test-arm shape; green probes for placeholders, data, Jira-style keys, longer numbers, strings, regex literals and excluded paths), and per-root reach checks (`SCANNED_AREAS`, each `ROOT_PROSE` file, and an extractor check that real comments, titles and messages come out of the tests corpus) fail an arm that would pass over nothing.
- **`tests/guards/claude-dir.test.ts`** (D-CLAUDE-DIR-PROMPTS): no compiled command, agent, reference, skill or rule reads a path under the home `.claude` directory, or the bare directory without the installer's rule (`CLAUDE_CONFIG_DIR` when absolute, else `$HOME/.claude`); red probes plus a behavioural run of the sanctioned line. `tests/skill-references.test.ts` Format 3 holds that compiled commands name no skill by install path; its non-vacuity comes from an extractor probe and the stamp paragraph, and its companion-skill check reads all five catalog intent rows, "(none)" included, and holds each to its compiled command in both directions (`collectCompanionDrift`).
- **`tests/guards/docs-root.test.ts`** (D-DOCS-ROOT): every `.devflow/docs` path in a compiled command is rooted at `{worktree}` (`_partials/_docs_root.mds`), relative only in an agent field that travels with `WORKTREE_PATH`, or a named live exemption; `tests/commands/partials-root.test.ts` runs the resolution on real git.
- **`tests/guards/settings-atomic-write.test.ts`** (D-SETTINGS-ATOMIC): every `settings.json` write under `src/` goes through `writeSettingsFileAtomic`.
- **`tests/guards/no-config-read.test.ts`**: no prompt reads `project.json` or `config.json` itself; the scan covers compiled commands, agents, references, skills, rules, the ambient charter and every directive a hook emits, and it fails when `dist/` is older than its sources rather than scan a stale build.
- **`tests/guards/heredoc-quoting.test.ts`**: an unquoted `<<EOF` heredoc scan over the prompt corpus; its frozen exclusions are `file:line`, so a comment added above an excluded heredoc moves it and the guard reports both a "new" heredoc and a stale exclusion.
- **`tests/hook-log-paths.test.ts`** (D-LOG-DIR-CAP, hook side): `devflow_log_dir` and the debug trace's folder creation prune to the cap under a temp HOME; the shell cap is pinned equal to `MAX_HOOK_LOG_DIRS`.

## Install-Level Regression Net

### Install snapshots and the hook matrix (tests/install-snapshot.test.ts)

`tests/install-snapshot-helpers.ts` is the one capture/normalise/render path, shared by the test and by `scripts/update-golden.ts install-snapshot` (which writes `tests/fixtures/golden/install-snapshot-{github,jira-hipaa,all-off}.txt` and `hook-matrix.txt` from the BUILT CLI; `--only <config>` narrows it, and the matrix is written only with `github`). Each sandbox is one `mkdtemp` root: `home/` (seeded `.claude/`), `repo/` (one commit) with `repo/sub/`, `wt/` (a real `git worktree add`), `nongit/`, `bin/` (a fake `claude` that logs into the sandbox) and `tmp/` (the hooks' TMPDIR). Child envs come from `sandboxEnv` with SHELL deleted: with a known SHELL, init writes a safe-delete block into the shell profile whenever the platform trash tool is on PATH, which is a machine fact.

Normalisation (D-SNAPSHOT-NORMALISE): sandbox paths in logical and realpath forms plus the dash-joined log slug, ISO timestamps, and the manifest `version` when it equals package.json's (so a golden survives a release bump). Walks record kind + owner exec bit only, sorted. A golden's sections are baseline, install (walks, `settings.json` with `permissions.deny` collapsed to a count, manifest, repo config), `re-init` (an LCS line diff from the first init, which AC-3 wants as `(none)`), and uninstall (keep list, removed baseline entries, settings). The matrix declares one `it` per golden cell at collection time; its first test proves the cell set equals installed hooks × four locations, `memory-worker` cells are `it.skip` by name, and every cell restores the sandbox byte-for-byte so cells are order-independent. Spawn budget (D-SPAWN-BUDGET): github and jira-hipaa run init, re-init and uninstall in-process; `all-off` is covered only by TP-8, which regenerates it into a temp `--out-dir` and byte-compares the whole file. A golden mismatch means install behaviour changed: fix the source, or regenerate in a fixture-only `test(snapshot):` commit whose PR body justifies each hunk. The `all-off` argv is held to every `--no-*` switch `init` accepts, read from the imported `initCommand.options` rather than a spawn, through `noSwitchDrift`, so a new `--no-x` fails by name.

CI's `macos-bash32-hooks` job (`.github/workflows/ci.yml`) re-runs the shell-hook suites (`shell-hooks`, `shell-hooks-helpers`, `shell-hooks-tracker`, `capture-hooks`, `queue-append`) and `install-snapshot.test.ts` (the hook matrix) with `/bin/bash` 3.2 first on PATH. A step fails the job unless `bash --version` reports 3.2, and vitest runs with `--no-file-parallelism`, one file at a time, because these suites spawn hundreds of hook processes and in parallel on a 3-core runner the load alone times tests out.

### Write-set fence and the init location matrix

These complete the regression net the one-install-scope decision required before any scope change, alongside the install snapshots. Both run the BUILT CLI (`npm run build` first) in `install-snapshot-helpers` sandboxes under `sandboxEnv`'s temp HOME, with a fake `claude` first on PATH.

- **`tests/write-set-fence.test.ts` (D-WRITE-SET-FENCE).** `FENCE_ROWS` holds one row per CLI toggle action (every `--enable`, `--disable` and `--set` a command defines, plus the state-clearing and read-only actions beside them), each with an `allow` list (`<HOME>/...`, `<REPO>/...`, `<SANDBOX>/...`, a trailing `/**` admitting a subtree), `mustWrite` (a toggle that silently stopped writing fails) and an optional `seed`. The rows run once, in table order, against ONE sandbox installed by `init --recommended --security user`; around each, the whole sandbox (HOME, repo, subdirectory, worktree, non-git dir, TMPDIR, the fake claude's call log; `.git` excluded) is walked with contents and every added, modified or removed path must be allowed. The table leaves each toggle flipped back, so every row starts from the installed state. Coverage is held to the CLI's own definitions: every top-level command in `devflow --help` has a row or a reason in `UNFENCED_COMMANDS`, and every `--enable`/`--disable`/`--set` option a command defines has a row or a reason in `UNFENCED_ACTIONS`. Row count and fenced-command count are floors (`write-fence-row-count`, `write-fence-command-count`); the allowlist size is a ceiling (`write-fence-allowlist-size`). The `learning --enable` and `--disable` rows allow the manifest plus ONE token, `LEARNING_VARIANT_SURFACE`, which the check expands to the converge's own roster (D-LEARNING-VARIANT-FENCE): the `.md` files under `dist/learning-off/{commands,agents}` matched file by file, never as a `commands/**` or `agents/**` subtree, plus the learning-gated skill directory, so a stray write to any other agent, command or skill still fails, and an absent roster directory throws instead of yielding an empty roster that would fence the toggle to the manifest alone. `allowlistSize` counts entries as declared, before expansion (D-ALLOWLIST-COUNTING): the roster-derived surface is one entry because its members come from the build and a new arm needs no edit here, while every hand-written path still counts one each; a probe shows a second hand-written entry takes the footprint past the ceiling and fails it (the ceiling was raised once, from 11 to 12, on the maintainer's authorisation).
- **`tests/init-location-invariance.test.ts` (D-INIT-LOCATION-INVARIANCE).** The same non-interactive init (the github install-snapshot argv) runs once per `INIT_LOCATIONS` entry, each in a fresh sandbox: repo root, subdirectory, linked worktree, non-git directory, a repository path with a space, a symlinked HOME, and a HOME that is itself a repository. The machine side (every entry under HOME, `settings.json` and the manifest, normalised) must equal the root run's in every location, and per-repository writes land only at the checkout's toplevel: none in a subdirectory, none outside git, none at a HOME repository (D-INIT-NOT-HOME). The space sits in the repository path only: a HOME with a space is not a supported layout (hook commands carry HOME unquoted). `init-location-count` is its floor.

## Live and CLI-Spawning Tests

**Subagent skill preload (`tests/integration/subagent-skill-preload.test.ts`)** spawns real `claude` CLI sessions. The suite is skipped when `claude` is absent (CI skips it); prompts must stay read-only; session identity is deterministic (`runClaudeAndWait` generates a UUID before spawning and passes `--session-id <uuid>`); there is a 3-second post-SIGTERM wait and one bounded retry (`MAX_SPAWN_ATTEMPTS`). It is excluded from routine integration runs by `exclude` in `vitest.integration.config.ts`, and the only way back in is `DEVFLOW_INTEGRATION_ALL` set to an explicit affirmative spelling (`0`, `false`, `no` and `off` are not opt-ins).

**Clause (ii) file-residue (`tests/integration/clause-ii-file-residue.test.ts`)** mechanises the file-residue half of the prefix-shippability clause (ii) acceptance criterion: it packs the real tarball, installs into a scratch `$HOME`, creates a throwaway git repo, runs `devflow init --recommended`, and asserts `git status --porcelain` has no `??` (untracked) entries.

**CLI-spawning config tests (`init-review-publication.test.ts`, `feature-toggle-config.test.ts`).** Both spawn the real compiled CLI against a throwaway `$HOME` AND a throwaway git repo (`mkdtempSync`, never the real ones) and both follow the timeout convention in `test-harness`. `feature-toggle-config.test.ts` proves each `devflow {memory,learning,knowledge} --enable/--disable`'s OWN write path preserves unmanaged config keys (D-CONFIG-PRESERVE-UNMANAGED) by a real file round trip; `tests/core/feature-config-managed-write.test.ts` is its unit-level sibling, driving `mergeManagedConfig`/`updateFeature` directly without a spawn. The two are deliberately paired because a direct call exercises an input path no user actually has.

## Anti-Patterns

**KB-AP-1, KB-AP-2: tests that can hurt the machine.** A live-`claude` prompt that can write, or an `init` spawned unscoped, turns a test into an incident (an empty commit; a wiped `~/.claude`). Read-only prompts and `sandboxEnv`-scoped spawns are the controls; they are not optional politeness.

**KB-AP-3: counting sites.** A floor on how many places spawn an agent breaks when a prompt is trimmed legitimately. Count the distinct spawned agent types instead (`SPAWNED_AGENT_TYPE_FLOOR`).

## Gotchas

**KB-AP-4, KB-AP-5: full-suite load timeouts.** Under the whole `npm test`, arms in `compliance-e2e`, `eager-memory-refresh` and `shell-hooks` hit vitest's 5 s default `testTimeout` (most of their `it(...)` calls carry none), and the failing arm differs from run to run; each file passes alone. That is the green-alone, red-under-load signature of an unsized timeout, not evidence against the branch under test. Confirm by running the one file on its own, and when a file keeps recurring size its slow arms from a measurement taken alone (about 4x the measured time, floored at 20_000 ms) rather than labelling them flakes. macOS adds a second cause: the first exec of a newly written executable, and of `node` behind it, is held for seconds by a security scan after a fork-heavy run, so a hook test that builds a PATH farm per test pays it many times over. The fix is structural, not a bigger default: `tests/session-start-compact.test.ts` builds its four PATH farms (jq and node present or absent) once per file, warms every wrapper in `beforeAll` under a 120_000 ms hook timeout, resets only the recording logs per test, and restores a cached wrapper a test edits inside `finally`; its node-spawning cases carry `NODE_RUN_MS` (the hook allowance plus a stall allowance), the `claude-md-audit` hook-CLI cases carry a 30_000 ms timeout, and the `shell-hooks-tracker` TP-40 differentials call `primeAuditStamp` first so Section 6 costs the same in the baseline and the measured run.

**KB-AP-6: PATH subtraction.** Removing a tool by subtracting it from `PATH` behaves differently per platform; the compact-hook suite builds PATH farms from recording wrappers so "tool absent" is explicit.

**KB-AP-7: frozen `file:line` exclusions.** The `heredoc-quoting` guard names its excluded heredocs by file and line; any edit above one needs the pins re-set in the same change.
