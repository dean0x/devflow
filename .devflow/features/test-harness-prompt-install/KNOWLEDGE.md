# Test Harness - Prompt-Corpus Doctrine Guards and Install-Level Regression Net

## Rules

- **KB-INV-1** A prompt doctrine is held by a guard over the compiled corpus with a named collector, known-bad probes driven through that same collector, and loud corpus reads (a missing file or root fails, never skips).
- **KB-INV-2** Rosters are derived, never listed: the report-cap roster comes from `DEVFLOW_PLUGINS` less the hook-spawned agents, decision receivers from `resolveAllAgents()` (`test-harness-text-guards` KB-INV-3), and spawn liveness counts DISTINCT agent types, not sites.
- **KB-INV-4** No spawn argument list or workflow `agent(` options object in the prompt corpus carries `model=` or `model:`: a spawn's model outranks the installed frontmatter where `devflow agents` writes a user's override.
- **KB-INV-6** Install snapshots and the hook matrix move only through `npm run test:golden:update -- install-snapshot`, in a fixture-only `test(snapshot):` commit whose PR body justifies each hunk.
- **KB-INV-7** Every CLI toggle's writes stay inside its write-set-fence row's allowlist, and coverage is held to the CLI's own definitions (`devflow --help`, every `--enable`/`--disable`/`--set`), not to the table.
- **KB-INV-8** The same non-interactive init lands the same machine side in every location (`INIT_LOCATIONS`), and per-repo writes land only at the checkout toplevel.
- **KB-INV-10** A live-`claude` test generates its session UUID before spawning (`--session-id <uuid>`), waits after SIGTERM, retries at most `MAX_SPAWN_ATTEMPTS`, and stays excluded from routine integration runs.
- **KB-INV-11** No Code-family body (Code, Fix, Refactor; curation on or off) carries a `Skill(...)` call, a `DOMAIN` input or compliance text: the compliance instruction reaches a spawn only through the command's `COMPLIANCE_DIRECTIVE`, which is empty when the resolved lens is off.
- **KB-INV-12** An agent mode's long template is read by explicit path from the reference-only `agent-references` skill, which no agent preloads and no plugin requires; a guard on what a mode's spawn sees reads the body plus that reference.
- **KB-INV-13** A spawn guard admits the built-in `Plan` type by exact name for `subagent_type` only, through the closed one-entry `BUILT_IN_SPAWN_TYPES` compared before any case folding or hyphen stripping: `plan`, `PLAN`, `general-purpose` and `agentType: "Plan"` stay reported, and a new entry needs a recorded decision.
- **KB-INV-14** The /plan level reference and the compiled gate-level block are closed shapes: text outside the decided lines, rule needles and `BLOCK_ITEMS` fails, so added prose cannot hide between rows.
- **KB-INV-15** The Validate lint pack runs only when the first `GATE_LEVEL:` line is exactly `lean`, last, after the table commands that exist pass; only `/implement` Phase 6 passes Validate `GATE_LEVEL` and `BASE_SHA`, and the re-validation path takes the level from Phase 1's settings step unless Phase 1 ran.
- **KB-INV-16** `validation-fix` never edits the lint pack, its config, its build-file entry or any `.gitattributes`, and never silences the linter, to clear a match; no other agent body names the pack.
- **KB-INV-17** /implement and /resolve read their level reference only at `standard` or `lean`, once per run, through one closed `**Gate level.**` block; a failed read, bad heading or bad row applies no row (in /resolve, in no worktree), keeps `GATE_LEVEL` and says `level reference unreadable: no level rows applied`, so /implement's lean lint pack still runs; the floor lines are pinned word for word in both builds, and in /resolve Global Triage, Batch FIX_NOW, Fix and Manage Debt never take `skip` (a row or Rules bullet that breaks that is malformed).
- **KB-INV-18** Every fenced spawn (`Agent(subagent_type="X"` or `agentType: "X"`) of /implement and /resolve is pinned by sha256 in both builds, so a level block cannot edit a spawn; a failure names the heading and agent type and prints the repin command (`test-harness-goldens-budgets`).
- **KB-INV-19** The resolver suites name every call the script makes by its exact argv (`siteOf`, `LOCAL_ARGV`, `SITES` in `resolve-base-process.test.ts`): an argv that matches no listed site is `unknown` and the control asserts `unknown` is never reached, so a new local git call fails until it is listed and driven through both modes.
- **KB-INV-20** In `base-ref-guard.test.ts` the `reason-fix-table` rule derives the REASONs that need a fix from the resolver's `REASON_NOTES` (stop or degraded, less `fetch-failed` and `usage`) and holds every copy equal to the `ensure-pr-ready` 5b sentence (`CANONICAL_FIX_TABLE`). The text one command or Git op states alone has one owner, that command's own guard, never a copy here.
- **KB-INV-21** A skipped Polish phase leaves its inputs and outputs whole: `{branch_diff}` is defined once in /implement's Phase 3 prose, before the Polish spawn and outside every fence, no later Requires line names the Polish output, and /self-review, /debug and /dynamic-build keep Polish and pass it no `GATE_LEVEL:` line.
- **KB-INV-22** Every shipped level row has a `ROW_EFFECTS` entry, and every doc site that covers its command (`DOC_SITES`) states the effect exactly once and keeps no retired "no rows" claim; a level-scoped site (`DocSite.level`, the two init hints) is read by its level's cell (`levelCell`): it owes a row's effect only when that cell is not `-` and must not state it when it is.
- **KB-INV-23** The `pass level` Grammar cell puts `GATE_LEVEL: {GATE_LEVEL}` first in every spawn prompt of the phase, right after a leading `OPERATION:` line; each agent spawned there without an `OPERATION:` line declares an optional `GATE_LEVEL` input read from prompt line 1 only (`collectPassLevelInputDefects`; Evaluate's Level scope: `collectEvaluateLevelDefects`). At `standard` and `lean` the Phase 5 `single-pass` row and bullet run Evaluate once and Fix at most once: COMPLETE sets `MISALIGNED (fixed once, not re-checked)`, any other Fix report goes to the user (`collectSinglePassDefects`); `collectFullLoopDefects` pins the `full` loop.
- **KB-AP-1** A live-`claude` test prompt must stay read-only: a spawned Git agent once made a real empty commit.
- **KB-AP-2** Never run `init` or a hook against the real HOME or a real repo: a QA-agent run once wiped a real `~/.claude`; build the env with `sandboxEnv` (the evidence suites use `scopedEnv`, see Live and CLI-Spawning Tests) and echo the resolved HOME first.
- **KB-AP-3** Never use spawn SITE counts as a doctrine's liveness floor: a legitimate prompt trim lowers sites (source plus compiled copy) but not types.
- **KB-AP-4** A test green alone and red under the full suite has an unsized timeout, not a flaky branch: size slow arms from a measurement taken alone, never label them flakes.
- **KB-AP-5** Never build a recording PATH farm, fake executable or hook program per test: the first exec of a new executable (and of `node` behind it) stalls on macOS after a fork-heavy run; build once per file and warm in `beforeAll` (the resolver suites do, for every fake and for `node`).
- **KB-AP-6** Simulating a missing tool by subtracting it from `PATH` is platform-dependent: build farms from explicit wrappers.
- **KB-AP-10** A /plan gate-skip text scan (`GATE_SKIP`) cannot hold a gate floor alone: it misses "does not run" wording, so the closed shapes report that, and it covers the gate-level block only (other phases say `skip Gate 0 questions`).
- **KB-AP-11** A test never names a literal `src/assets/agents/` path in code or composes `agentsDir()` with an agent `.md` filename on one line (`literal-agent-paths` skips comment lines only): read an agent body through `resolveAgentSource(name)`.
- **KB-AP-12** An agent-specific bound never goes into the shared `## Running commands` block, byte-identical across the Code, Fix, Refactor, Validate and Test bodies and the engine (`running-commands-parity`): it goes in that agent's own section (Validate's `## Lint pack`).
- **KB-AP-13** A deliberate edit of a moved reference section re-pins its length and SHA-256 in `command-reference-move.test.ts` in the same commit; a step inserted in `implement-revalidate.md` renumbers the step `tests/evidence/implement-flow.test.ts` finds by list number.
- **KB-AP-14** Row safety in a level reference is a tripwire over known words, not a proof: a removal verb (`REMOVAL_STEMS`, `REMOVAL_PHRASES`) counts when a floor name or protected phase number stands in the same cell or bullet, its name included, and a bare negation (`REMOVAL_WORDS`, "does not run") only within `NEAR_WORDS` words of one in one sentence; a farther negation ("Do not wait for the CI gate."), a cap with no removal word and a removal in unknown words pass, so read a new row against the floor by hand. The one exemption is a spec's `exemptRemoval` (`{ phase, name, line, floorName }`; only /implement's `harden-scope` has one): the bullet's name, byte-equal line and `appliedBy(name)` exactly `{phase}` must all match; only that floor name then leaves the removal-verb arm (the negation arm, ACTION and other floor names stay active); any other cell in the exempt phase's row than `-` or `apply: harden-scope` is a defect.
- **KB-AP-15** The doc-site check proves a phrase, not which command it names: a site that covers both commands and names one passes for both.
- **KB-AP-16** A level-guard probe never appends a row or bullet: `withRows` replaces them, and `seed()` fails when nothing changes but replaces only the first match: a probe on the shipped reference uses `seedOnce` (asserts one occurrence), or a repeated phrase lands in the Grammar.

## Overview

These checks hold the agent and command prompts to the doctrines the token-diet waves set, and prove the install itself is stable. Each follows the Guard Conventions in `test-harness` (KB-INV-1). The doctrines they pin are owned by the knowledge bases in Related.

The curation-variant, decisions-seam, feature-knowledge shape and delivery, handoff and quiet-form, `/code-review` gating, compaction and import-audit guards and the corpus-wide text guards (ledger citations, `claude-dir`, docs root, atomic settings writes, config reads, heredoc quoting, hook log paths) moved to `test-harness-text-guards` with KB-INV-3, KB-INV-5, KB-INV-9, KB-AP-7, KB-AP-8 and KB-AP-9.

## Install-Level Regression Net

### Install snapshots and the hook matrix (tests/install-snapshot.test.ts)

`tests/install-snapshot-helpers.ts` is the one capture/normalise/render path, shared by the test and by `scripts/update-golden.ts install-snapshot` (which writes `tests/fixtures/golden/install-snapshot-{github,jira-hipaa,all-off}.txt` and `hook-matrix.txt` from the BUILT CLI; `--only <config>` narrows it, and the matrix is written only with `github`). Each sandbox is one `mkdtemp` root: `home/` (seeded `.claude/`), `repo/` (one commit) with `repo/sub/`, `wt/` (a real `git worktree add`), `nongit/`, `bin/` (a fake `claude` that logs into the sandbox) and `tmp/` (the hooks' TMPDIR). Child envs come from `sandboxEnv` with SHELL deleted: with a known SHELL, init writes a safe-delete block into the shell profile when the platform trash tool is on PATH (a machine fact).

Normalisation (D-SNAPSHOT-NORMALISE): sandbox paths in logical and realpath forms plus the dash-joined log slug, ISO timestamps, and the manifest `version` when it equals package.json's. Walks record kind + owner exec bit only, sorted. A golden's sections are baseline, install (walks, `settings.json` with `permissions.deny` collapsed to a count, manifest, repo config), `re-init` (an LCS line diff from the first init, which AC-3 wants as `(none)`), and uninstall (keep list, removed baseline entries, settings). The matrix declares one `it` per golden cell at collection time; its first test proves the cell set equals installed hooks × four locations, `memory-worker` cells are `it.skip` by name, and every cell restores the sandbox byte-for-byte so cells are order-independent. Spawn budget (D-SPAWN-BUDGET): github and jira-hipaa run init, re-init and uninstall in-process; `all-off` is covered only by TP-8, which regenerates it into a temp `--out-dir` and byte-compares the file. A golden mismatch means install behaviour changed (KB-INV-6). The `all-off` argv is held to every `--no-*` switch `init` accepts, read from the imported `initCommand.options` rather than a spawn, through `noSwitchDrift`, so a new `--no-x` fails by name. A new file under `agent-references/references/commands/` adds one line to each of the three snapshots (`implement-levels.md` and `resolve-levels.md` did).

CI's `macos-bash32-hooks` job (`.github/workflows/ci.yml`) re-runs the shell-hook suites (`shell-hooks`, `shell-hooks-helpers`, `shell-hooks-tracker`, `capture-hooks`, `queue-append`) and `install-snapshot.test.ts` (the hook matrix) with `/bin/bash` 3.2 first on PATH. A step fails the job unless `bash --version` reports 3.2; vitest runs with `--no-file-parallelism` because parallel hook processes on a small runner time tests out.

### Write-set fence and the init location matrix

Both complete the regression net that the one-install-scope decision required before any scope change. They run the BUILT CLI (`npm run build` first) in `install-snapshot-helpers` sandboxes under `sandboxEnv`'s temp HOME, with a fake `claude` first on PATH.

- **`tests/write-set-fence.test.ts` (D-WRITE-SET-FENCE).** `FENCE_ROWS` holds one row per CLI toggle action (every `--enable`, `--disable` and `--set` a command defines, plus the state-clearing and read-only actions beside them), each with an `allow` list (`<HOME>/...`, `<REPO>/...`, `<SANDBOX>/...`, a trailing `/**` admitting a subtree), `mustWrite` (a toggle that silently stopped writing fails) and an optional `seed`. The rows run once, in table order, against ONE sandbox installed by `init --recommended --security user`; around each, the whole sandbox (HOME, repo, subdirectory, worktree, non-git dir, TMPDIR, the fake claude's call log; `.git` excluded) is walked with contents and every added, modified or removed path must be allowed. The table leaves each toggle flipped back, so every row starts from the installed state. Coverage (KB-INV-7): every top-level command in `devflow --help` has a row or a reason in `UNFENCED_COMMANDS`, every `--enable`/`--disable`/`--set` option one in `UNFENCED_ACTIONS`. The `curation --enable` and `--disable` rows allow the manifest plus ONE token, `CURATION_VARIANT_SURFACE`, which the check expands to the converge's own roster (the curation-variant fence): the `.md` files under `dist/curation-off/{commands,agents}` matched file by file, never as a subtree, plus the curation-gated skill directory, so a stray write to any other agent, command or skill still fails; an absent roster directory throws rather than fence the toggle to the manifest alone. `allowlistSize` counts entries as declared, before expansion (D-ALLOWLIST-COUNTING): the roster-derived surface is one entry, and each hand-written path counts one.
- **`tests/init-location-invariance.test.ts` (D-INIT-LOCATION-INVARIANCE).** The same non-interactive init (the github install-snapshot argv) runs once per `INIT_LOCATIONS` entry, each in a fresh sandbox: repo root, subdirectory, linked worktree, non-git directory, a repository path with a space, a symlinked HOME, and a HOME that is itself a repository. The machine side (every entry under HOME, `settings.json` and the manifest, normalised) must equal the root run's (KB-INV-8); per-repository writes land only at the toplevel: none in a subdirectory, none outside git, none at a HOME repository (D-INIT-NOT-HOME). The space sits in the repository path only: a HOME with a space is not a supported layout (hook commands carry HOME unquoted). `init-location-count` is its floor.

## Live and CLI-Spawning Tests

**Live `claude` tests (`tests/integration/subagent-skill-preload.test.ts`, `tests/integration/ambient-activation.test.ts`)** spawn real `claude` CLI sessions. `vitest.integration.config.ts` excludes both at glob time, so a command-line path does not bring them back; the only way in is `DEVFLOW_INTEGRATION_ALL` set to `1`, `true` or `yes`. A file skips with a printed reason when `claude` or a credential is absent. Each file builds a temp HOME and a temp git repository with `createSpawnContext` (`tests/integration/helpers.ts`), installs devflow into that HOME with `init --security user` and memory and curation off, and spawns with `--permission-mode dontAsk`, an allow list, a deny list and `--strict-mcp-config`. `tests/guards/integration-spawn.test.ts` refuses a `claude` spawn under `tests/` without `env` and `cwd`, and refuses the permission-skip flag and the mode that turns permission checks off. Prompts stay read-only (KB-AP-1); `runClaudeAndWait` follows KB-INV-10.

**Clause (ii) file-residue (`tests/integration/clause-ii-file-residue.test.ts`)** mechanises the file-residue half of the prefix-shippability clause (ii): it installs the packed tarball into a scratch `$HOME` and a throwaway git repo, runs `devflow init --recommended` and asserts `git status --porcelain` has no `??` entries.

**CLI-spawning config tests (`init-review-publication.test.ts`, `feature-toggle-config.test.ts`).** Both spawn the real compiled CLI against a throwaway `$HOME` AND a throwaway git repo (`mkdtempSync`). `feature-toggle-config.test.ts` proves each `devflow {memory,curation,knowledge} --enable/--disable`'s OWN write path preserves unmanaged config keys (D-CONFIG-PRESERVE-UNMANAGED) by a real file round trip; `tests/core/feature-config-managed-write.test.ts` is its unit-level sibling, calling `mergeManagedConfig`/`updateFeature` with no spawn.

**Resolver suites (`tests/evidence/resolve-base.test.ts`, `tests/evidence/resolve-base-process.test.ts`).** Both drive `resolve-base.cjs` through `main()` in-process (real git or a recording stub); the first also runs the real script under `process.execPath`, and the process file holds the fetch argv and environment, the group-kill backstop and the local bounds. What no single file shows:

- **The site-aware stub** (KB-INV-19). `siteOf` matches a local site only when the argv after the `-c core.fsmonitor=false` override equals a `LOCAL_ARGV` entry, and names the fetch by its subcommand. `SITES` gives each local site, its modes and the `FETCH` value of its stop line (`skipped` before the fetch, `ok` after). Every site in both modes is driven with a timeout and a signal kill and must give `resolver-unavailable` with `NOTE=stop`. An answered git error exit gives `resolver-unavailable` at the format check, the origin URL, the tip reads and the chosen-base check. Only the merge-base reads and the ancestry check keep their own reason, `no-merge-base`. A control pins that the sites reached equal `SITES` plus the fetch.
- **The run budget** is tested through the injectable `now` clock, which the stub advances per call: each call gets the smaller of its own bound (`LOCAL_TIMEOUT_MS`, `FETCH_TIMEOUT_MS`) and the time left, none starts once the budget is spent, and `RUN_BUDGET_MS` sits between the fetch bound and the Bash tool limit.
- **Warm-up and timeouts.** `beforeAll` writes and runs each AC-12 program (the hook, `upload.sh`, `fsmonitor.sh`, the fake ssh programs, the hung `git`) once (the first-launch stall of KB-AP-5); `resolve-base.test.ts` warms `node` the same way. Both take `SUBPROCESS_TIMEOUT_MS` from `tests/evidence/seam.ts`. Each AC-12 sentinel has a positive control: a plain git command in the same repository runs it.

**Evidence-suite spawn env.** The suites under `tests/evidence/` and `tests/evidence-policy/` build every spawn env with `scopedEnv(home, extra?)` from `tests/evidence-policy/scripted-shim.ts`, not `sandboxEnv`: `process.env` less `INHERITED_LEAKS` (gh and GitHub tokens, `GH_REPO`, `GH_HOST`, the `GIT_DIR` family), with HOME, USERPROFILE and XDG_CONFIG_HOME under `home`, a null global git config, no system config and a fixed commit identity; `extra` wins. It keeps the `GIT_SSH*` and `*_ASKPASS` variables, so a test that depends on their absence deletes them (`cleanEnv` in `resolve-base-process.test.ts`). A `spawnSync`, `execFileSync` or `execSync` call that skips `scopedEnv(` or a `cwd` fails the `spawn environment hygiene` tests (`collectUnscopedSpawns`).

## Anti-Patterns

Each anti-pattern is explained in its Rules bullet; the ones that need more are under Gotchas.

## Gotchas

**KB-AP-4, KB-AP-5: full-suite load timeouts.** Under the whole `npm test`, arms in `compliance-e2e`, `eager-memory-refresh` and `shell-hooks` hit vitest's 5 s default `testTimeout`, a different arm each run, while each file passes alone. Confirm by running the file alone; size its slow arms at about 4x that measurement, floored at 20_000 ms. For the PATH-farm cause the fix is structural, not a bigger default: `tests/session-start-compact.test.ts` builds its four PATH farms (jq and node present or absent) once per file, warms every wrapper in `beforeAll`, resets only the recording logs per test, and restores a cached wrapper a test edits inside `finally`; its node-spawning cases carry `NODE_RUN_MS` (the hook allowance plus a stall allowance), and the `claude-md-audit` hook-CLI cases carry their own timeout.
