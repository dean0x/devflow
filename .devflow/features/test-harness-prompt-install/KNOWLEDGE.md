# Test Harness - Prompt-Corpus Doctrine Guards and Install-Level Regression Net

## Rules

- **KB-INV-1** A prompt doctrine is held by a guard over the compiled corpus with a named collector, known-bad probes driven through that same collector, and loud corpus reads (a missing file or root fails, never skips).
- **KB-INV-2** Rosters are derived, never listed: the report-cap roster comes from `DEVFLOW_PLUGINS` less the hook-spawned agents, decision receivers from `resolveAllAgents()`, and spawn liveness counts DISTINCT agent types, not sites.
- **KB-INV-3** `DECISIONS_CONTEXT` goes only to agent types whose source lists it among their inputs, and the `LEARNING=off` gate sentence precedes the ledger-locate call and index read in every host.
- **KB-INV-4** No spawn argument list or workflow `agent(` options object in the prompt corpus carries `model=` or `model:`: a spawn's model outranks the installed frontmatter where `devflow agents` writes a user's override.
- **KB-INV-5** Each learning variant equals the compiled host resolved on or off by an INDEPENDENT line scanner (not the build's splitter), and no `<!-- learning:... -->` marker survives in any `dist/**/*.md`.
- **KB-INV-6** Install snapshots and the hook matrix move only through `npm run test:golden:update -- install-snapshot`, in a fixture-only `test(snapshot):` commit whose PR body justifies each hunk.
- **KB-INV-7** Every CLI toggle's writes stay inside its write-set-fence row's allowlist, and coverage is held to the CLI's own definitions (`devflow --help`, every `--enable`/`--disable`/`--set`), not to the table.
- **KB-INV-8** The same non-interactive init lands the same machine side in every location (`INIT_LOCATIONS`), and per-repo writes land only at the checkout toplevel.
- **KB-INV-9** No learning-ledger ID reaches committed text (`no-ledger-citations`): ledger IDs are machine-local, so committed text states a decision in words.
- **KB-INV-10** A live-`claude` test generates its session UUID before spawning (`--session-id <uuid>`), waits after SIGTERM, retries at most `MAX_SPAWN_ATTEMPTS`, and stays excluded from routine integration runs.
- **KB-INV-11** No Code-family body (Code, Fix, Refactor; learning on or off) carries a `Skill(...)` call, a `DOMAIN` input or compliance text: the compliance instruction reaches a spawn only through the command's `COMPLIANCE_DIRECTIVE`, which is empty when the resolved lens is off.
- **KB-INV-12** An agent mode's long template is read by explicit path from the reference-only `agent-references` skill, which no agent preloads and no plugin requires; a guard on what a mode's spawn sees reads the body plus that reference.
- **KB-INV-13** A spawn guard admits the built-in `Plan` type by exact name for `subagent_type` only, through the closed one-entry `BUILT_IN_SPAWN_TYPES` compared before any case folding or hyphen stripping: `plan`, `PLAN`, `general-purpose` and `agentType: "Plan"` stay reported, and a new entry needs a recorded decision.
- **KB-INV-14** The /plan level reference and the compiled gate-level block are closed shapes: text outside the decided lines, rule needles and `BLOCK_ITEMS` fails, so added prose cannot hide between rows.
- **KB-AP-1** A live-`claude` test prompt must stay read-only: a spawned Git agent once made a real empty commit.
- **KB-AP-2** Never run `init` or a hook against the real HOME or a real repo: a QA-agent run once wiped a real `~/.claude`; build the env with `sandboxEnv` and echo the resolved HOME first.
- **KB-AP-3** Never use spawn SITE counts as a doctrine's liveness floor: a legitimate prompt trim lowers sites (source plus compiled copy) but not types.
- **KB-AP-4** A test green alone and red under the full suite has an unsized timeout, not a flaky branch: size slow arms from a measurement taken alone instead of labelling them flakes.
- **KB-AP-5** Never build a recording PATH farm per test: the first exec of a new executable (and of `node` behind it) stalls on macOS after a fork-heavy run; build once per file and warm in `beforeAll`.
- **KB-AP-6** Simulating a missing tool by subtracting it from `PATH` is platform-dependent: build farms from explicit wrappers.
- **KB-AP-7** `heredoc-quoting` exclusions are pinned as `file:line`: a comment added above an excluded heredoc moves it, so re-pin in the same change.
- **KB-AP-8** The percent-based auto-compact override is out of scope in every spelling and letter case anywhere under `src/`.
- **KB-AP-9** A prompt scan must not read a stale build: `no-config-read` and `claude-dir` fail when a compiled prompt is older than its own host (a command also against the command partials). A shared agent-partial edit is not detected, so run `npm run build:mds` after it.
- **KB-AP-10** A gate-skip text scan cannot hold a gate floor alone: it misses "does not run" wording, so the closed shapes report that, and it covers the gate-level block only (other phases say `skip Gate 0 questions`).

## Overview

These checks hold the agent and command prompts to the doctrines the token-diet waves set, and prove the install itself is stable. Each follows the Guard Conventions in `test-harness` (a named collector, known-bad probes driven through that same collector, loud corpus reads). The doctrine each pins is owned elsewhere: `dynamic-workflow-engine` for the foreground run, gate ownership and bind-once input, `ambient-orchestrator` for the charter checks in `tests/agent-name-guards.test.ts`.

## Corpus-Wide Text Guards

- **`tests/guards/no-ledger-citations.test.ts`**: no learning-ledger ID (the ADR or PF prefix followed by three digits) reaches committed text, because the ledger is gitignored and numbered per machine. It reads the worktree as git lists it (tracked plus untracked-unignored files; binary files skipped). A FULL BAN reports an ID anywhere in `src/**`, `scripts/**`, the root `vitest*.config.ts` files, `docs/**`, the root prose (`CLAUDE.md`, `README.md`, `CONTRIBUTING.md`, `.devflow/conventions.md`, `.release/RELEASE-FLOW.md`), `.devflow/features/index.md`, every feature `KNOWLEDGE.md` and `tests/fixtures/numeric-floors.json`. In `tests/**/*.ts` only commentary is read (comments, `describe`/`it`/`test` titles and `expect(value, message)` messages, pulled out by a strings-first lexer so a `//` inside a string is never a comment): an ID in a citation shape (after `applies`, `avoids`, `per` or `see`, in parentheses or brackets, or possessive) is always reported, and any other ID is reported unless the same file holds it as data outside its commentary. `CHANGELOG.md`, the golden and install-snapshot fixtures and `.devflow/learning/**` are excluded; placeholders carry no three digits and pass. Seeded probes drive the same `collectLedgerViolations` collector the live arms use (a red probe per full-ban root and per test-arm shape; green probes for placeholders, data, Jira-style keys, longer numbers, strings, regex literals and excluded paths), and reach checks (`SCANNED_AREAS`, each `ROOT_PROSE` file, an extractor check on real comments, titles and messages) fail an arm that would pass over nothing.
- **`tests/guards/claude-dir.test.ts`** (D-CLAUDE-DIR-PROMPTS): an allowlist over the full prompt corpus (compiled commands, agents, references, skills, rules, learning-off builds, the compaction line). Per file, each sanctioned resolution line (the installer's rule: `CLAUDE_CONFIG_DIR` when absolute, else `$HOME/.claude`) and each file-scoped rule prose is removed; the residue is reported for the variable name, a path into the home Claude directory (a project-local `.claude/` path is a negative control), an unrooted install path, and a `d=` or `for d in` reassignment. Each `$d/` use needs the sanctioned line earlier on the same line, because each Bash call is a fresh shell. A new read site needs a `SITE_ROWS` row; new rule prose needs a file-scoped `ALLOWED_RULE_PROSE` entry. /plan's two reads are held by `collectPlanDirReadDefects`. Its dist currency check compares each compiled prompt with its own host only (KB-AP-9). It adds liveness checks and a behavioural run of the sanctioned line. `tests/skill-references.test.ts` Format 3 holds that compiled commands name no skill by install path (non-vacuity: an extractor probe and the stamp paragraph); its companion-skill check holds all five catalog intent rows, "(none)" included, to the compiled command both ways (`collectCompanionDrift`).
- **`tests/guards/docs-root.test.ts`** (D-DOCS-ROOT): every `.devflow/docs` path in a compiled command is rooted at `{worktree}` (`_partials/_docs_root.mds`), relative only in an agent field that travels with `WORKTREE_PATH`, or a named live exemption; `tests/commands/partials-root.test.ts` runs the resolution on real git.
- **`tests/guards/settings-atomic-write.test.ts`** (D-SETTINGS-ATOMIC): every `settings.json` write under `src/` goes through `writeSettingsFileAtomic`.
- **`tests/guards/no-config-read.test.ts`**: no prompt reads `project.json` or `config.json` itself; the scan covers compiled commands, agents, references, skills, rules, the ambient charter and every directive a hook emits, and it fails when a compiled prompt is older than its own host rather than scan a stale build (KB-AP-9).
- **`tests/guards/heredoc-quoting.test.ts`**: an unquoted `<<EOF` heredoc scan over the prompt corpus; its frozen exclusions are `file:line`, so a comment added above an excluded heredoc moves it and the guard reports both a "new" heredoc and a stale exclusion.
- **`tests/hook-log-paths.test.ts`** (D-LOG-DIR-CAP, hook side): `devflow_log_dir` and the debug trace's folder creation prune to the cap under a temp HOME; the shell cap is pinned equal to `MAX_HOOK_LOG_DIRS`.

## Install-Level Regression Net

### Install snapshots and the hook matrix (tests/install-snapshot.test.ts)

`tests/install-snapshot-helpers.ts` is the one capture/normalise/render path, shared by the test and by `scripts/update-golden.ts install-snapshot` (which writes `tests/fixtures/golden/install-snapshot-{github,jira-hipaa,all-off}.txt` and `hook-matrix.txt` from the BUILT CLI; `--only <config>` narrows it, and the matrix is written only with `github`). Each sandbox is one `mkdtemp` root: `home/` (seeded `.claude/`), `repo/` (one commit) with `repo/sub/`, `wt/` (a real `git worktree add`), `nongit/`, `bin/` (a fake `claude` that logs into the sandbox) and `tmp/` (the hooks' TMPDIR). Child envs come from `sandboxEnv` with SHELL deleted: with a known SHELL, init writes a safe-delete block into the shell profile whenever the platform trash tool is on PATH, which is a machine fact.

Normalisation (D-SNAPSHOT-NORMALISE): sandbox paths in logical and realpath forms plus the dash-joined log slug, ISO timestamps, and the manifest `version` when it equals package.json's (so a golden survives a release bump). Walks record kind + owner exec bit only, sorted. A golden's sections are baseline, install (walks, `settings.json` with `permissions.deny` collapsed to a count, manifest, repo config), `re-init` (an LCS line diff from the first init, which AC-3 wants as `(none)`), and uninstall (keep list, removed baseline entries, settings). The matrix declares one `it` per golden cell at collection time; its first test proves the cell set equals installed hooks × four locations, `memory-worker` cells are `it.skip` by name, and every cell restores the sandbox byte-for-byte so cells are order-independent. Spawn budget (D-SPAWN-BUDGET): github and jira-hipaa run init, re-init and uninstall in-process; `all-off` is covered only by TP-8, which regenerates it into a temp `--out-dir` and byte-compares the whole file. A golden mismatch means install behaviour changed: fix the source, or regenerate in a fixture-only `test(snapshot):` commit whose PR body justifies each hunk. The `all-off` argv is held to every `--no-*` switch `init` accepts, read from the imported `initCommand.options` rather than a spawn, through `noSwitchDrift`, so a new `--no-x` fails by name.

CI's `macos-bash32-hooks` job (`.github/workflows/ci.yml`) re-runs the shell-hook suites (`shell-hooks`, `shell-hooks-helpers`, `shell-hooks-tracker`, `capture-hooks`, `queue-append`) and `install-snapshot.test.ts` (the hook matrix) with `/bin/bash` 3.2 first on PATH. A step fails the job unless `bash --version` reports 3.2, and vitest runs with `--no-file-parallelism`, one file at a time, because these suites spawn hundreds of hook processes and in parallel on a 3-core runner the load alone times tests out.

### Write-set fence and the init location matrix

These complete the regression net the one-install-scope decision required before any scope change, alongside the install snapshots. Both run the BUILT CLI (`npm run build` first) in `install-snapshot-helpers` sandboxes under `sandboxEnv`'s temp HOME, with a fake `claude` first on PATH.

- **`tests/write-set-fence.test.ts` (D-WRITE-SET-FENCE).** `FENCE_ROWS` holds one row per CLI toggle action (every `--enable`, `--disable` and `--set` a command defines, plus the state-clearing and read-only actions beside them), each with an `allow` list (`<HOME>/...`, `<REPO>/...`, `<SANDBOX>/...`, a trailing `/**` admitting a subtree), `mustWrite` (a toggle that silently stopped writing fails) and an optional `seed`. The rows run once, in table order, against ONE sandbox installed by `init --recommended --security user`; around each, the whole sandbox (HOME, repo, subdirectory, worktree, non-git dir, TMPDIR, the fake claude's call log; `.git` excluded) is walked with contents and every added, modified or removed path must be allowed. The table leaves each toggle flipped back, so every row starts from the installed state. Coverage is held to the CLI's own definitions: every top-level command in `devflow --help` has a row or a reason in `UNFENCED_COMMANDS`, and every `--enable`/`--disable`/`--set` option a command defines has a row or a reason in `UNFENCED_ACTIONS`. Row count and fenced-command count are floors (`write-fence-row-count`, `write-fence-command-count`); the allowlist size is a ceiling (`write-fence-allowlist-size`). The `learning --enable` and `--disable` rows allow the manifest plus ONE token, `LEARNING_VARIANT_SURFACE`, which the check expands to the converge's own roster (D-LEARNING-VARIANT-FENCE): the `.md` files under `dist/learning-off/{commands,agents}` matched file by file, never as a subtree, plus the learning-gated skill directory, so a stray write to any other agent, command or skill still fails; an absent roster directory throws rather than fence the toggle to the manifest alone. `allowlistSize` counts entries as declared, before expansion (D-ALLOWLIST-COUNTING): the roster-derived surface is one entry because the build supplies its members, while each hand-written path counts one; a probe shows a second hand-written entry fails the ceiling.
- **`tests/init-location-invariance.test.ts` (D-INIT-LOCATION-INVARIANCE).** The same non-interactive init (the github install-snapshot argv) runs once per `INIT_LOCATIONS` entry, each in a fresh sandbox: repo root, subdirectory, linked worktree, non-git directory, a repository path with a space, a symlinked HOME, and a HOME that is itself a repository. The machine side (every entry under HOME, `settings.json` and the manifest, normalised) must equal the root run's in every location, and per-repository writes land only at the checkout's toplevel: none in a subdirectory, none outside git, none at a HOME repository (D-INIT-NOT-HOME). The space sits in the repository path only: a HOME with a space is not a supported layout (hook commands carry HOME unquoted). `init-location-count` is its floor.

## Live and CLI-Spawning Tests

**Live `claude` tests (`tests/integration/subagent-skill-preload.test.ts`, `tests/integration/ambient-activation.test.ts`)** spawn real `claude` CLI sessions. `vitest.integration.config.ts` excludes both at glob time, so a command-line path does not bring them back; the only way in is `DEVFLOW_INTEGRATION_ALL` set to `1`, `true` or `yes` (`0`, `false`, `no` and `off` are not opt-ins). A file skips with a printed reason when `claude` or a credential is absent. Each file builds a temp HOME and a temp git repository with `createSpawnContext` (`tests/integration/helpers.ts`), installs devflow into that HOME with `init --security user` and memory and learning off (no capture hooks in the temp settings), and spawns with `--permission-mode dontAsk`, an allow list, a deny list and `--strict-mcp-config`, never the skip flag. `tests/guards/integration-spawn.test.ts` refuses a `claude` spawn under `tests/` without `env` and `cwd`, and refuses the skip flag and `bypassPermissions`. Prompts stay read-only; `runClaudeAndWait` generates a UUID before spawning (`--session-id <uuid>`), waits 3 seconds after SIGTERM and retries once (`MAX_SPAWN_ATTEMPTS`).

**Clause (ii) file-residue (`tests/integration/clause-ii-file-residue.test.ts`)** mechanises the file-residue half of the prefix-shippability clause (ii) acceptance criterion: it packs the real tarball, installs into a scratch `$HOME`, creates a throwaway git repo, runs `devflow init --recommended`, and asserts `git status --porcelain` has no `??` (untracked) entries.

**CLI-spawning config tests (`init-review-publication.test.ts`, `feature-toggle-config.test.ts`).** Both spawn the real compiled CLI against a throwaway `$HOME` AND a throwaway git repo (`mkdtempSync`, never the real ones) and both follow the timeout convention in `test-harness`. `feature-toggle-config.test.ts` proves each `devflow {memory,learning,knowledge} --enable/--disable`'s OWN write path preserves unmanaged config keys (D-CONFIG-PRESERVE-UNMANAGED) by a real file round trip; `tests/core/feature-config-managed-write.test.ts` is its unit-level sibling, driving `mergeManagedConfig`/`updateFeature` directly without a spawn. The two are deliberately paired because a direct call exercises an input path no user actually has.

## Anti-Patterns

Each anti-pattern is explained in its Rules bullet; the ones that need more are under Gotchas.

## Gotchas

**KB-AP-4, KB-AP-5: full-suite load timeouts.** Under the whole `npm test`, arms in `compliance-e2e`, `eager-memory-refresh` and `shell-hooks` hit vitest's 5 s default `testTimeout`, a different arm each run, while each file passes alone: an unsized timeout, not a branch defect. Confirm by running the file alone; when it recurs, size its slow arms from a measurement taken alone (about 4x, floored at 20_000 ms). macOS adds a second cause: the first-exec stall after a fork-heavy run, which a per-test PATH farm pays many times over. The fix is structural, not a bigger default: `tests/session-start-compact.test.ts` builds its four PATH farms (jq and node present or absent) once per file, warms every wrapper in `beforeAll`, resets only the recording logs per test, and restores a cached wrapper a test edits inside `finally`; its node-spawning cases carry `NODE_RUN_MS` (the hook allowance plus a stall allowance), the `claude-md-audit` hook-CLI cases carry their own timeout, and the `shell-hooks-tracker` TP-40 differentials call `primeAuditStamp` first so Section 6 costs the same in the baseline and the measured run.

**KB-AP-6, KB-AP-7: environment and frozen pins.** The compact-hook suite builds PATH farms from recording wrappers so "tool absent" is explicit; `heredoc-quoting` names its excluded heredocs by file and line, so any edit above one re-sets the pins in the same change.
