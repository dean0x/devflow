# Test Harness - Prompt-Corpus Doctrine Guards and Install-Level Regression Net

## Rules

- **KB-INV-1** A prompt doctrine is held by a guard over the compiled corpus with a named collector, known-bad probes driven through that same collector, and loud corpus reads (a missing file or root fails, never skips).
- **KB-INV-2** Rosters are derived, never listed: the report-cap roster comes from `DEVFLOW_PLUGINS` less the hook-spawned agents, decision receivers from `resolveAllAgents()` (`test-harness-text-guards` KB-INV-3), and spawn liveness counts DISTINCT agent types, not sites.
- **KB-INV-4** No spawn argument list or workflow `agent(` options object in the prompt corpus carries `model=` or `model:`: a spawn's model outranks the installed frontmatter where `devflow agents` writes a user's override.
- **KB-INV-6** Install snapshots and the hook matrix move only through `npm run test:golden:update -- install-snapshot`, in a fixture-only `test(snapshot):` commit whose PR body justifies each hunk.
- **KB-INV-7** Every CLI toggle's writes stay inside its write-set-fence row's allowlist, and coverage is held to the CLI's own definitions (`devflow --help`, every `--enable`/`--disable`/`--set`), not to the table.
- **KB-INV-8** The same non-interactive init lands the same machine side in every location (`INIT_LOCATIONS`), and per-repo writes land only at the checkout toplevel.
- **KB-INV-10** A live-`claude` test generates its session UUID before spawning (`--session-id <uuid>`), waits after SIGTERM, retries at most `MAX_SPAWN_ATTEMPTS`, and stays excluded from routine integration runs.
- **KB-INV-11** No Code-family body (Code, Fix, Refactor; curation on or off) carries a `Skill(...)` call, a `DOMAIN` input or compliance text: the compliance instruction reaches a spawn only through the command's `COMPLIANCE_DIRECTIVE`, which is empty when the resolved lens is off.
- **KB-INV-12** An agent mode's long template is read by explicit path from the reference-only `agent-references` skill, which no agent preloads and no plugin requires; a guard on what a mode's spawn sees reads the body plus that reference.
- **KB-INV-13** A spawn guard admits the built-in `Plan` type by exact name for `subagent_type` only, through the closed one-entry `BUILT_IN_SPAWN_TYPES` compared before any case folding or hyphen stripping: `plan`, `PLAN`, `general-purpose` and `agentType: "Plan"` stay reported, and a new entry needs a recorded decision.
- **KB-INV-14** The /plan level reference and the compiled gate-level block (outside every curation and compliance arm, so in all four builds) are closed shapes: text outside the decided lines, rule needles and `BLOCK_ITEMS` fails, so added prose cannot hide between rows.
- **KB-INV-15** The Validate lint pack runs only when the first `GATE_LEVEL:` line is exactly `lean`, last, after the table commands that exist pass; only `/implement` Phase 6 and, at `lean`, Phase 8 pass Validate `GATE_LEVEL` and `BASE_SHA`, and the re-validation path takes the level from Phase 1's settings step unless Phase 1 ran.
- **KB-INV-16** `validation-fix` never edits the lint pack, its config, its build-file entry or any `.gitattributes`, and never silences the linter, to clear a match; no other agent body names the pack.
- **KB-INV-17** /implement and /resolve read their level reference only at `standard` or `lean`, once per run, through one closed `**Gate level.**` block; a failed read, bad heading or bad row applies no row (in /resolve, in no worktree), keeps `GATE_LEVEL` and says `level reference unreadable: no level rows applied`, so /implement's lean lint pack still runs; the floor lines are pinned word for word in both builds, and in /resolve Global Triage, Batch FIX_NOW, Fix and Manage Debt never take `skip` (a row or Rules bullet that breaks that is malformed).
- **KB-INV-18** Every fenced spawn (`Agent(subagent_type="X"` or `agentType: "X"`) of /implement and /resolve is pinned by sha256 in both builds, so a level block cannot edit a spawn; a failure names the heading and agent type and prints the repin command (`test-harness-goldens-budgets`).
- **KB-INV-19** The resolver suites name every call the script makes by its exact argv (see the site-aware stub below): an argv that matches no listed site is `unknown` and the control asserts `unknown` is never reached, so a new local git call fails until it is listed and driven through both modes.
- **KB-INV-20** In `base-ref-guard.test.ts` the `reason-fix-table` rule derives the REASONs that need a fix from the resolver's `REASON_NOTES` (stop or degraded, less `fetch-failed` and `usage`) and holds every copy equal to the `ensure-pr-ready` 5b sentence (`CANONICAL_FIX_TABLE`). The text one command or Git op states alone has one owner, that command's own guard, never a copy here.
- **KB-INV-21** A skipped Polish phase leaves its inputs and outputs whole: `{branch_diff}` is defined once in /implement's Phase 3 prose, before the Polish spawn and outside every fence, no later Requires line names the Polish output, and /self-review and /debug keep Polish and pass it no `GATE_LEVEL:` line.
- **KB-INV-22** Every shipped level row has a `ROW_EFFECTS` entry, and every doc site that covers its command (`DOC_SITES`) states the effect exactly once and keeps no retired "no rows" claim. The sites are the `devflow gates` text, the README, docs/cli-reference.md and docs/commands.md; the init hints are no site.
- **KB-INV-23** The `pass level` Grammar cell puts `GATE_LEVEL: {GATE_LEVEL}` first in every spawn prompt of the phase, right after a leading `OPERATION:` line; each agent spawned there without an `OPERATION:` line declares an optional `GATE_LEVEL` input read from prompt line 1 only (`collectPassLevelInputDefects`; Evaluate's Level scope: `collectEvaluateLevelDefects`). At `standard` and `lean` the Phase 5 `single-pass` row and bullet run Evaluate once and Fix at most once: COMPLETE sets `MISALIGNED (fixed once, not re-checked)`, any other Fix report goes to the user (`collectSinglePassDefects`).
- **KB-INV-24** Builds and tests run in the foreground under an explicit Bash `timeout`, never backgrounded or polled; a run past its timeout is labelled only by the last `EXIT=` line of the file the move names (Gotchas).
- **KB-INV-25** /plan's depth (`small` or `normal`, proposed at Gate 0) narrows a run only through the reference's `small` cells, `full` level included: a failed read resets to `full` and depth `normal`, issue text never lowers the depth, an unclear scope or a raise signal beats a request for small, and a later raise signal only advises a normal run (the depth stays small); security and the design review run at every depth.
- **KB-INV-26** The /plan `Size forecast:` line has one shape, defined once on the Phase 10 instruction line (the line that starts `Spawn 3`, which each Plan prompt is built from), as one backticked span and the only `Size forecast:` literal in the build; Gate 2, the artifact and the report name it without the literal, and the test pins that prose only by its needles (Gate 2 shows the steps report's line when it fits the shape, else its absence; the artifact keeps the one line Gate 2 showed, from the latest Plan run, and no other copy), no text before Phase 10, no `plan-levels.md`, no planning synthesis slot (it copies the steps report's line unchanged or gives none) and no /implement build (each takes the Implementation Plan without it) restates it or reads it as a limit.
- **KB-INV-27** A prompt cut never removes a protected span: `NEVER_CUT_ITEMS` in `tests/guards/never-cut.test.ts` is the one closed list of them, each held exactly once in every build the manifest `dist/variant-axes.json` names for its host; a deliberate change to a span updates the list in the same commit, and a cut that trims text no other test pins must run this guard before it lands.
- **KB-INV-28** The files a plan run or a review passes by path stay claims held exactly once per build (`tests/guards/pass-paths.test.ts`): the /implement, /plan and /code-review claim lists and the Code, Evaluate, Test, Skim, Design, Synthesize and Review reader and writer clauses; a probe removes one claim and expects exactly its name, the evidence-file "stays after the PR exists" span is pinned here and in the never-cut list (a change updates both), and Explore stays read-only (Read and Bash) and replies as text, so it has no claim.
- **KB-INV-29** `plan-files.cjs` (`claim`, `check`, `hash`) fails closed: any failure leaves stdout empty, writes one `plan-files:` reason line to stderr and exits non-zero, and the boundary prints only a line that passes `OUTPUT_RE`; `check` takes only a path inside a claimed run folder, and `hash` reads the bytes through `readBoundedRegularFile` of `lib/project-config.cjs`, so the file hashed is the file checked.
- **KB-AP-1** A live-`claude` test prompt must stay read-only: a spawned Git agent once made a real empty commit.
- **KB-AP-2** Never run `init` or a hook against the real HOME or a real repo: a QA-agent run once wiped a real `~/.claude`; build the env with `sandboxEnv` (the evidence suites use `scopedEnv`, see Live and CLI-Spawning Tests) and echo the resolved HOME first.
- **KB-AP-3** Never use spawn SITE counts as a doctrine's liveness floor: a legitimate prompt trim lowers sites (source plus compiled copy) but not types.
- **KB-AP-4** A test green alone and red under the full suite has an unsized timeout, not a branch defect: PASSED-ALONE gets the gate through but is no repair, so size slow arms from a measurement taken alone, never label them flakes.
- **KB-AP-5** Never build a recording PATH farm, fake executable or hook program per test: the first exec of a new executable (and of `node` behind it) stalls on macOS after a fork-heavy run; build once per file and warm in `beforeAll` (the resolver suites do).
- **KB-AP-6** Simulating a missing tool by subtracting it from `PATH` is platform-dependent: build farms from explicit wrappers.
- **KB-AP-10** A /plan gate-skip text scan (`GATE_SKIP`) cannot hold a gate floor alone: it misses "does not run" wording, so the closed shapes report that, and it covers the gate-level block only (other phases say `skip Gate 0 questions`).
- **KB-AP-11** A test never names a literal `src/assets/agents/` path in code or composes `agentsDir()` with an agent `.md` filename on one line (`literal-agent-paths` skips comment lines only): use `resolveAgentSource(name)`.
- **KB-AP-12** An agent-specific bound never goes into the shared `## Running commands` block, byte-identical across the Code, Fix, Refactor, Validate and Test bodies (`running-commands-parity`): it goes in that agent's own section (Validate's `## Lint pack`).
- **KB-AP-13** A deliberate edit of a moved reference section re-pins its length and SHA-256 in `command-reference-move.test.ts` in the same commit; edit `implement-revalidate.md` in place, as an inserted step renumbers the steps `tests/evidence/implement-flow.test.ts` finds by list number. Step 4 keeps `**Resolve the settings line**` and lowercase `unless Phase 1 ran` once each (lint-pack probes seed the first match) and the label `**Take GATE_LEVEL**` (a regex); a reference carries no `devflow:<skill>` token (requires-closure scans references).
- **KB-AP-14** Row safety in a level reference is a tripwire over known words, not a proof: a removal verb (`REMOVAL_STEMS`, `REMOVAL_PHRASES`) counts when a floor name or protected phase number stands in the same cell or bullet, its name included, and a bare negation (`REMOVAL_WORDS`, "does not run") only within `NEAR_WORDS` words of one in one sentence; a farther negation ("Do not wait for the CI gate."), a cap with no removal word and a removal in unknown words pass, so read a new row against the floor by hand. The one exemption is a spec's `exemptRemoval` (`{ phase, name, line, floorName }`; only /implement's `harden-scope` has one): the bullet's name, byte-equal line and `appliedBy(name)` exactly `{phase}` must all match, and only that floor name then leaves the removal-verb arm; any cell in the exempt phase's row but `-` or `apply: harden-scope` is a defect.
- **KB-AP-15** The doc-site check proves a phrase, not which command it names: a site that covers both commands and names one passes for both.
- **KB-AP-16** A level-guard probe never appends a row or bullet (`withRows` replaces them); `seed()` fails when nothing changes but replaces only the first match, so a probe on the shipped reference uses `seedOnce` (asserts one occurrence) or a repeated phrase lands in the Grammar.
- **KB-AP-17** Never trust a byte cut to leave a rule alone: a cut that trims a prompt can drop a span no test pins, and a build with a switch off can lack a span only its on build carries; add the span to `NEVER_CUT_ITEMS` under the build set that holds it (`implement (compliance on)` is the set for text only the compliance-on builds carry).
- **KB-AP-18** Never read a vitest failure through `| tail` or `| head`: vitest writes failures to stderr, so the pipe filters nothing; run with `--reporter=json --outputFile=<file>` and read the file with jq.
- **KB-AP-19** A hand edit of an evidence-file TP line keeps its scenario within the length bound of `TP_LINE_RE` (`pr-evidence.cjs`) and free of `/`: the parser refuses the line otherwise.

## Overview

These checks hold the agent and command prompts to the doctrines the token-diet waves set, and prove the install itself is stable. Each follows the Guard Conventions in `test-harness` (KB-INV-1); Related owns the doctrines.

The curation-variant, decisions-seam, feature-knowledge, handoff, `/code-review` gating, compaction, import-audit and corpus-wide text guards (ledger citations, `claude-dir`, docs root, settings writes, config reads, heredocs, hook log paths) moved to `test-harness-text-guards` with KB-INV-3, KB-INV-5, KB-INV-9 and KB-AP-7 to KB-AP-9.

## Prompt-Corpus Doctrine Guards

- **`tests/guards/running-commands-parity.test.ts`**: the Code, Fix, Refactor, Validate and Test bodies (the Code variants share `_partials/_code.mds`) each carry exactly one `## Running commands` block, byte-identical, within `BLOCK_MAX_BYTES` and stating every normative element. The doctrine is KB-INV-24. An agent's own rule sits outside it (KB-AP-12): `test.md`'s dev-server section follows the block, names Monitor nowhere outside the block's prohibition.
- **`tests/guards/gate-ownership.test.ts`**: the gate bodies (Code, Fix, Refactor, Polish, Evaluate, Harden, Test, Validate; `gate-ownership-body-count`) each carry one `**Gate ownership:**` line pinned as text; all but Validate say that only Validate runs the full suite; Polish and Evaluate instruct no build, test or lint command; the TDD skill says "affected tests" and defines the term once.
- **`tests/guards/report-cap.test.ts`**: every roster agent's Output section ends with a `Report cap:` line (a token cap, a `mktemp` file for longer material, exempt fields named). The roster is DERIVED from `DEVFLOW_PLUGINS` less the hook-spawned `curate` and `tracker` (`report-cap-roster-count`). Exempt fields (`EXEMPT_MARKERS`) come from what each spawning command parses, not the agent's template (Validate's include its `Passed alone:` and `Lint pack:` lines); sections are read fence-aware. `git` is on the roster with the fields its templates give the commands.
- **`tests/commands/report-caps.test.ts`**: the Explore (devflow's override of the built-in) and the built-in Plan spawns a command writes as prose carry their own cap WITH a token figure ("at most|under|no more than N tokens"; "keep it short" bounds nothing), counted in the compiled commands against per-command minimums in `REQUIRED_CAPS` (explore, debug, plan).
- **`tests/guards/arguments-once.test.ts`** + **`tests/install-bound-input.test.ts`**: over `dist/commands` at most one `$ARGUMENTS` placeholder per command (literal and positional spellings counted together, none positional), exactly one in each `TRACKER_PARTIAL_ADOPTERS` host, each between `<command-input>` lines, and exactly the `INPUT_BOUND_COMMANDS` set (the adopters plus explore, release and research) carries one. The install test repeats the count on the commands INSTALLED by one real `init` into a sandbox HOME, and checks the installed charter. Ceiling `arguments-once-max`.
- **`tests/commands/knowledge-preload.test.ts`**: the Knowledge agent preloads `devflow:feature-knowledge` and holds no Skill tool, and no compiled command tells it to load that skill.
- **`tests/guards/core-rules-digest.test.ts`**: `omitClaudeMd` drops CLAUDE.md AND `~/.claude/rules/**`, so the omitting set is DERIVED from the `AGENT_CONFIG` rows (`OMIT_CLAUDE_MD_DIGESTS`), never listed; each such body carries exactly its row's digest lines, byte for byte, as bullets under one `## Core rules` heading, and each line's phrases still appear verbatim under `src/assets/rules/`, so a digest cannot keep a rule devflow dropped.
- **`tests/guards/scan-in-code.test.ts`**: each compiled Code variant, curation on and off, carries one conditional `Security scan` block (written once in the shared `_code.mds` partial; scan only when the session offers a code-scanning tool, each changed file once by absolute path, `Security scan: unavailable` otherwise) that names no scanner product; Harden and Polish each carry the one line saying scanning runs in Code, and deny every MCP tool (`MCP_DENY_AGENTS` in the config table is the only place a denylist may hold the `mcp__*` wildcard).
- **`tests/guards/preload-cleanup.test.ts`**: an agent preloads only what its body reads on every spawn. A table of dropped and kept preloads (Knowledge, Tracker, Synthesize, Triage) is checked against the compiled agents, and Triage's inline security-finding paragraph is held by a named collector.
- **`tests/guards/docs-framework-authority.test.ts`**: `devflow:docs-framework` is the one authority for names under `.devflow/docs/`. Every path family a compiled command names appears in the skill; every `branch_slug` derivation and every `handoff-*` / `evidence-*` spelling agrees.
- **`tests/commands/design-plan-discovery.test.ts`** and **`tests/commands/synthesize-base-dir.test.ts`**: `/code-review` and `/bug-analysis` list the flat `/plan` layout only, newest first and bounded, with the glob checked against what `/plan`'s compiled text writes, and each Synthesize mode's command spawn passes the base-dir field its mode's reference writes through (`REVIEW_BASE_DIR`, `ANALYSIS_BASE_DIR`, `RESEARCH_BASE_DIR`).
- **`tests/guards/worktree-support-split.test.ts`**: the discovery algorithm lives in the skill's `references/discovery.md`, and `/code-review` and `/resolve` load the skill and the reference only when `git worktree list` shows more than one worktree.
- **`tests/guards/spawn-no-hardcoded-model.test.ts`** (KB-INV-4): the scan covers `src/assets/{commands,agents,skills,mds}` and `dist/{commands,agents}`, reading argument text with string and template bodies blanked. - **`tests/guards/implement-resolve-level*.test.ts`** (KB-INV-17, KB-INV-21 to KB-INV-23, KB-AP-14 to KB-AP-16): the block reads `implement-levels.md` (at the start of Phase 3, which the re-validation path also reaches) or `resolve-levels.md` (in Step 0d; each row applies per worktree at its own level, except in a global phase, which takes the strictest level in the run). - **`tests/evidence/implement-flow.test.ts`**: the re-validation path is held by `collectRevalidatePublicationDefects` (step 4's three Phase 1 pointers in order, no `auto` fallback in the reference), `collectRevalidateTargetFormDefects` (one form, `the Phase 1 <label> step`, for its five targets) and `collectRevalidatePhase1RunDefects` (step 1's all-of-Phase-1 reading and labels, each `unless Phase 1 ran` copy at its anchor).
- **`tests/guards/implement-resolve-full-fences.test.ts`** (KB-INV-18, KB-INV-23): the sha256 of every fenced spawn (`Agent(subagent_type="X"` or `agentType: "X"`) in both builds of both commands (`PINNED_FENCES`). A digest cannot see prose, so `collectFullLoopDefects` holds each line of the `full` Phase 5 re-check loop once in both builds.
- **`tests/guards/never-cut.test.ts`** (KB-INV-27, KB-AP-17): `NEVER_CUT_ITEMS` entries carry `name` (the rule, said as the defect that reports it lost), `source` (the file under `src/assets` where a change is made), `text` (one exact span) and `builds` (a `BuildSetName`: `implement`, `implement (compliance on)`, `plan`, `code`, `evaluate` or `docs-framework`). `collectNeverCutDefects` reports each build whose text holds a span other than exactly once and each item whose set holds no build. Builds come from `compiledBuilds` (with `Build` and `emittedKeys`, in `tests/helpers.ts`, shared with pass-paths), which reads the host's emitted keys from `dist/variant-axes.json` (a missing manifest, host or build file throws and names `npm run build:mds`, in both guards), so a new variant cannot escape; Evaluate and the docs-framework skill install as is: one build each. A green run proves the files carry the text and not that a model follows it.

## Install-Level Regression Net

### Install snapshots and the hook matrix (tests/install-snapshot.test.ts)

`tests/install-snapshot-helpers.ts` is the one capture/normalise/render path, shared by the test and by `scripts/update-golden.ts install-snapshot` (which writes `tests/fixtures/golden/install-snapshot-{github,jira-hipaa,all-off}.txt` and `hook-matrix.txt` from the BUILT CLI; `--only <config>` narrows it, and the matrix is written only with `github`). Each sandbox is one `mkdtemp` root: `home/` (seeded `.claude/`), `repo/` (one commit) with `repo/sub/`, `wt/` (a real worktree), `nongit/`, `bin/` (a fake `claude`) and `tmp/` (the hooks' TMPDIR). Child envs come from `sandboxEnv` with SHELL deleted: with a known SHELL, init writes a safe-delete block into the shell profile when a trash tool is on PATH.

Normalisation: sandbox paths in logical and realpath forms plus the dash-joined log slug, ISO timestamps, and the manifest `version` when it equals package.json's. Walks record kind + owner exec bit only, sorted. A golden's sections are baseline, install (walks, `settings.json` with `permissions.deny` collapsed to a count, manifest, repo config), `re-init` (an LCS diff from the first init, `(none)` when nothing changed) and uninstall (keep list, removed baseline entries, settings). The matrix declares one `it` per golden cell at collection time; its first test proves the cell set equals installed hooks × four locations, `memory-worker` cells are `it.skip` by name, and every cell restores the sandbox byte-for-byte. Spawn budget: github and jira-hipaa run init, re-init and uninstall in-process; `all-off` is covered only by TP-8, which regenerates it into a temp `--out-dir` and byte-compares it. `noSwitchDrift` holds the `all-off` argv to every `--no-*` switch `initCommand.options` lists, so a new `--no-x` fails by name. A new file under `agent-references/references/` adds one line to each of the three snapshots, two when its folder is new.

CI's `macos-bash32-hooks` job (`.github/workflows/ci.yml`) re-runs the shell-hook suites (`shell-hooks`, `shell-hooks-helpers`, `shell-hooks-tracker`, `capture-hooks`, `queue-append`) and `install-snapshot.test.ts` (the hook matrix) with `/bin/bash` 3.2 first on PATH. A step fails the job unless `bash --version` reports 3.2; vitest runs with `--no-file-parallelism` (parallel hook processes time out on a small runner).

### Write-set fence and the init location matrix

Both run the BUILT CLI (`npm run build` first) in `install-snapshot-helpers` sandboxes under a temp HOME, with a fake `claude` first on PATH.

- **`tests/write-set-fence.test.ts`.** `FENCE_ROWS` holds one row per CLI toggle action (every `--enable`, `--disable` and `--set` a command defines, plus the state-clearing and read-only actions beside them), each with an `allow` list (`<HOME>/...`, `<REPO>/...`, `<SANDBOX>/...`, a trailing `/**` admitting a subtree), `mustWrite` (a toggle that silently stopped writing fails) and an optional `seed`. Coverage (KB-INV-7) is held through `UNFENCED_COMMANDS` and `UNFENCED_ACTIONS`. The `curation --enable` and `--disable` rows allow the manifest plus ONE token, `CURATION_VARIANT_SURFACE`, which the check expands to the converge's own roster (the curation-variant fence): the `.md` files under `dist/curation-off/{commands,agents}` matched file by file, never as a subtree, plus the curation-gated skill directory, so a stray write to any other agent, command or skill still fails; an absent roster directory throws rather than fence the toggle to the manifest alone. `allowlistSize` counts entries as declared, before expansion: the roster-derived surface is one entry, and each hand-written path counts one.

**Resolver suites (`tests/evidence/resolve-base.test.ts`, `tests/evidence/resolve-base-process.test.ts`).** Both drive `resolve-base.cjs` through `main()` in-process (real git or a recording stub); the first also runs the real script under `process.execPath`; the process file holds the fetch argv and environment, the group-kill backstop and the local bounds.

- **The site-aware stub** (KB-INV-19). `siteOf` matches a local site only when the argv after the `-c core.fsmonitor=false` override equals a `LOCAL_ARGV` entry, and names the fetch by its subcommand. `SITES` gives each local site, its modes and the `FETCH` value of its stop line (`skipped` before the fetch, `ok` after). ## Gotchas

**KB-AP-4, KB-AP-5: full-suite load timeouts.** Under the whole `npm test`, arms in `compliance-e2e`, `eager-memory-refresh` and `shell-hooks` hit vitest's default `testTimeout`, a different arm each run, while each file passes alone (the PASSED-ALONE label is in `test-harness-text-guards`). A timeout reported as a failed assertion stays REAL: size slow arms at about 4x a measurement taken alone, floored at 20_000 ms. `tests/session-start-compact.test.ts` fixes the first-exec stall structurally: its four PATH farms are built once per file and warmed in `beforeAll`, and its node-spawning cases carry `NODE_RUN_MS`.

**KB-AP-18: reading a failing run.** Write the json report to a scratch path and read `testResults[].assertionResults[]` with jq for the failure messages.

### KB-INV-24: build execution doctrine, the shared `## Running commands` block

The Code variants (one copy, from `tail()` in `src/assets/agents/_partials/_code.mds`), Validate and Test bodies each carry one byte-identical block, held by `tests/guards/running-commands-parity.test.ts`. The block text is the one source: a prompt that runs builds or tests names "your Running commands block" and never copies it. Its rules: run in the foreground under an explicit Bash `timeout` (ceiling 600000 ms, or `BASH_MAX_TIMEOUT_MS`; `devflow flags --set bash-max-timeout-ms=<ms>` raises it); capture then tail in ONE call, echoing the log path first, so the last `EXIT=` line is the result, never a grep count; never background or poll (no `sleep` turns, sentinel files or Monitor; Test's dev server is the one background process, in its own section after the block); a run past its timeout moves to the background, so make no tool call until its end notice, then Read the last `EXIT=` line of the file the move names (not `$LOG`), which alone sets the label, and with none read the run is BLOCKED with its duration and log path; prefer the scoped command, never re-run a command whose inputs did not change, never wrap a build or test in `sh -c`, `bash -c`, `python3 -c` or `node -e`.

Why foreground is safe (`docs/reference/platform-assumptions.md` holds each row with its drift symptom): the stall watchdog fires after about 600 s of model-stream silence after a tool result returns, never while a tool runs; a call that reaches its timeout moves to the background and finishes, and the end notice re-invokes the waiting agent (probed in an Agent-tool subagent only); the platform refuses a leading `sleep`. A sub-agent killed for model silence leaves uncommitted work in its worktree: inspect `git status` there, resume the same task, and never wait on a sub-agent without a deadline.
