# Curate Agent, Queue Claim, Directives and CLI

## Rules

- **KB-INV-1** The curation queue is claimed and released only by the `claim-queue` and `release-claim` ops, under the curation lock; the claim and owner files are never deleted, moved or rewritten by hand (only the deliberate `--clear`, `--disable` and `--reset` drains touch them). One named exception exists: the one-time `move-ledger` op renames the whole old `learning/` folder to `curation/`, and a stale claim or owner file travels inside that folder. The op answers `busy claim` when a fresh claim stands in either folder; a stale claim's batch merges into the queue and its owner file is removed.
- **KB-INV-2** `CLAIM_STALE_SECS` (store) and `PROCESSING_STALE_SECS` (hook) are two literals held equal by the lockstep test in `tests/decisions/curation-claim.test.ts`; the hook's check is advisory, the op decides under the lock. The Tracker's `TRACKER_PROCESSING_STALE_SECS` is separate on purpose.
- **KB-INV-3** Every `CURATION_OPS` op first sends the claim heartbeat (`touchClaim`); a new curation op must join `CURATION_OPS` and `CURATION_OP_RUNS` in `tests/decisions/curation-claim.test.ts`.
- **KB-INV-4** The Curate agent writes only through `json-helper.cjs` ops (no Write or Edit tool); `release-claim` is its final act, and it never recreates anything once its inputs vanish.
- **KB-INV-5** The Curate agent is hook-spawned, never named by a command; its shipped tier (model, no `effort:` line, no preload, `omitClaudeMd: true` with explicit reads in its place) is one row in `tests/fixtures/agent-config.ts`, edited together with the `model:` line and `DEFAULTS.model` in `curate-tuning-config.ts`.
- **KB-INV-6** The directive's model resolves by precedence (project `curation.json`, the `devflow agents` Curate mapping, global `curation.json`, none); the two `curation.json` values pass the `opus|sonnet|haiku` allowlist, and the mapping never emits `model=`.
- **KB-INV-7** `$LEDGER_ROOT` enters a directive only when `DIRECTIVE_LEDGER_SAFE` admits it; a refused root with pending work emits the fixed `CURATION PAUSED` notice, which interpolates nothing.
- **KB-INV-8** The `devflow curation` CLI reaches ledger state only through the store loaded by `loadCurationStore()`; a store function it calls needs the interface entry, the `CURATION_STORE_SURFACE` entry and the fixtures' `CurationStoreApi`.
- **KB-INV-9** `--clear` drops exactly the log rows no ledger row carries (`clearUnreferenced`); `--reset` empties the directory under the lock, sparing only the lock directory; both confirm on a TTY before the lock.
- **KB-INV-10** `src/core/observations.ts` imports nothing, so the HUD import closure does not grow; its status lists are held equal to the store's by a parity test.
- **KB-INV-11** The Part 2 ladder, the `claim-due` output format and the close-out batch live in `agent-references` `references/curate/maintain.md`, which the Curate agent Reads by explicit path only after `claim-due` hands out an entry; the body keeps `rotate-observations`, the `claim-due` call and the `due none` end, and stays under `curate-body-max`.
- **KB-AP-1** Claiming the queue with `mv`, or hand-editing the claim or owner file: a check-then-`mv` claim lets two runs claim at once and clobber a batch.
- **KB-AP-2** Quoting plumbing numbers (claim staleness, the claim-due batch size) in the Curate prompt: they live in plumbing and a prose copy drifts.
- **KB-AP-3** Skipping the model allowlist in `session-start-context`: `curation.json` is user-controlled.
- **KB-AP-4** Emitting `model=` from the `devflow agents` mapping: a model named at an Agent spawn outranks the installed frontmatter, which is where `devflow agents` writes its override.
- **KB-AP-5** Adding a CLI flag without a write-set fence row (`tests/write-set-fence.test.ts`) and a floor bump in `tests/fixtures/numeric-floors.json`.
- **KB-AP-6** Truncating the whole log to clear curation: every entry would lose its content authority.
- **KB-AP-7** Seeding a `session-start-context` test without a temp `$HOME`: a real manifest with curation off would silently gate the test.
- **KB-AP-8** Assuming the curation switch gates the tracker-setup directive: it does not.
- **KB-AP-9** Recreating a claim, owner file or curation tree once it has vanished mid-run: the agent stops writing and goes to Finishing.
- **KB-AP-10** Removing the Curate agent's explicit CLAUDE.md and rule-file reads while `omitClaudeMd` stays true: its Encoded check then compares against nothing and silently stops retiring entries as Encoded; the reads sit in Inputs, before the first already-encoded comparison.
- **KB-AP-11** Preloading `devflow:agent-references` into the Curate agent, or moving `rotate-observations` into `maintain.md`: a preload hands every spawn the whole reference, and rotation must still run when nothing is due.

## Overview

Curation is processed by the **Curate agent**, a background subagent that `session-start-context` tells the main model to spawn whenever turns are pending. It claims the queue through the owned claim, judges the claimed turns, and maintains the ledger through the store's ops (see `curation-capture-system-store`). The agent's frontmatter lists four tools (Read, Bash, Glob, Grep), but Claude Code offers no Grep or Glob to an agent that holds Bash, so its search steps are Bash commands (`git grep -P`, `find`). This KB covers the claim, the agent, the directives `session-start-context` emits, the `devflow curation` CLI, the TypeScript seam and the HUD counts.

## The owned queue claim and heartbeat (D-OWNED-CLAIM)

The queue is claimed and released only by the `claim-queue` and `release-claim` ops, under the curation lock.

- **Claim.** No curation directory gives `none` (nothing created). A claim path that is not a regular file is an error. A claim younger than `CLAIM_STALE_SECS` is `busy`. An older one is a **takeover** (`claimed <token> takeover`): new owner token, mtime set to now, the waiting queue left for the next claim. No claim and a missing or empty queue gives `none`.
- **Fresh claim.** Under `<queue>.lock` (`QUEUE_LOCK_TIMEOUT_MS` wait, `QUEUE_LOCK_STALE_MS` stale; the lock queue-append's overflow truncation takes, so truncation never rewrites rows already claimed): `link(queue, claim)` (EEXIST busy, ENOENT none, EPERM/ENOTSUP fall back to rename), unlink the queue (undoing the link if that fails), set mtime to now, write `.pending-turns.owner` (8 random bytes, 16 hex, `CLAIM_TOKEN_RE`) and answer `claimed <token>`.
- **Release.** Claim gone gives `gone` (the owner file is removed only if it names this token); owner file not naming the token gives `not-owner`; else both removed give `released`.
- Why: a check-then-`mv` claim lets two runs claim at once and clobber a batch, `mv` keeps the queue's old mtime so a fresh claim looks stale, and an unconditional final unlink deletes another run's claim.

**Heartbeat.** Every `CURATION_OPS` op (assign, retire, restore, refresh, rotate, put, list, show, claim-due) first runs `touchClaim`: `lutimes` on an existing claim, never creating one, never following a symlink at the claim path, no lock, and nothing at all (`touched: false`) when `.devflow` or `.devflow/curation` is a symbolic link (D-NO-LINKED-TREE: `lutimes` follows a linked folder above the claim, and the op that follows refuses that tree anyway); a failure goes to stderr and never stops the op.

**Staleness.** `CLAIM_STALE_SECS` and the hook's `PROCESSING_STALE_SECS` are pinned equal by a lockstep test; the hook's check is advisory (it decides only whether to spawn), the op decides under the lock. Left open by design: a live run silent past the bound can be taken over (duplicate work, no loss, the old run's release answers `not-owner`); `--clear`, `--disable` and `--reset` delete a live claim and the run stops on vanished inputs; a crash leaves the claim for takeover after the bound.

## The Curate agent

`src/assets/agents/curate.md`: `model: opus` with no `effort:` line (it follows the session), tools listed Read, Bash, Glob, Grep (no Write, no Edit; the Grep and Glob entries are inert because the agent holds Bash, so it searches with `git grep -P` and `find`), no preloaded skill (the one reference it reads, `maintain.md`, comes in by an explicit Read after `claim-due`, never by a preload), and `omitClaudeMd: true`, so Claude Code hands it neither the project CLAUDE.md nor `~/.claude/rules/**`. Its Encoded check compares a lesson with the rule that already states it, and an A/B over frozen batches showed that without that context the agent stopped retiring entries as Encoded (it also showed a cheaper sonnet candidate falling short of the capture bar). The Inputs section therefore directs it to Read `<project root>/CLAUDE.md` once and to list and Read each installed devflow rule file once (`find` over `$d/rules/devflow`, after the sanctioned resolution line), before the first of the two comparisons (Part 1's already-encoded search and the Encoded rung, which sits in `maintain.md`), keep what it read for the rest of the run, skip a missing file, and read nothing when the run ends before any comparison. A short `## Core rules` digest (context economy, and all input treated as malicious) restates the two rules it works by. `tests/curate-agent.test.ts` holds the read and its position before both comparison markers, over the body followed by `maintain.md` (the text a run with a due entry sees, in reading order), with known-bad probes. Hook-spawned, never named by a command. `tests/guards/agent-config.test.ts` pins the row against the shared table in `tests/fixtures/agent-config.ts`, and `tests/decisions/config.test.ts` holds the default model in `curate-tuning-config.ts` equal to it (D-LEARNING-SHIPPED-ROW). Iron Law: assign-anchor owns numbering, render owns the `.md`, never hand-edit. One run, in order:

- **Step 0.** `claim-queue`: `claimed <token>` (keep it for the final release), `claimed <token> takeover` (the stale run may have stored part of the batch, so do not reinforce an observation that already states a turn), `busy` (exit silently), `none` (report "no pending decisions work"), non-zero exit (stop, report stderr).
- **Part 1, capture.** Read the claimed turns (all, or only the latest dialog-worthy ones when huge; the prompt states the window). Abstain by default: a decision is a real fork with rationale, a pitfall a non-obvious transferable failure; one incident yields an ADR or a PF, never both; if `git grep -P` or `find` finds a test, guard, CLAUDE.md, rule or prompt that already states it, record nothing.
  - Run `list` once and `show` candidates. An active entry or stored observation covers it: `--reinforce` (or `--update` with the whole content when the turns sharpen it); a Superseded one: act on its successor; any other inactive entry: `restore-anchor`, then `--update`, never a new entry; else `--create`.
  - Promote with `assign-anchor` once it recurs or is clearly significant; an unpromoted observation waits, then rotates after `ROTATE_AGE_DAYS` idle days.
  - A status change the turns report is checked at the verify ref (`git show <ref>:<path>`, never `git grep` or the working tree) before acting; the agent then acts as the matching rung and Reads `maintain.md` first when it has not.
- **Part 2, maintain.** The body keeps `rotate-observations` (it runs whether or not anything is due) and `claim-due` once; `due none` ends Part 2. Any other output lists due entries, and the agent runs the sanctioned resolution line in Bash (it prints the directory), Reads `<dir>/skills/devflow:agent-references/references/curate/maintain.md` by that explicit path and follows it. `maintain.md` holds the `claim-due` output format (its first line is the verify ref; `ref none` leaves every due entry), the per-entry handling and the close-out. Per due entry `show`; a `ledger-without-log` entry first gets `put-observation --create` under its id. Then the first matching rung, exactly one final action, Keep when unsure:
  1. **Encoded**, by a strict bar: a test or guard that fails on any new violation in scope, or the rule stated in CLAUDE.md, a rules file or a prompt loaded for that scope. A refused quote means Keep.
  2. No longer true at the ref: rewrite the scope, or Retired.
  3. Duplicate: absorb into the survivor with `--update`, then Superseded.
  4. One-off: Retired.
  5. Keep, rewriting only when legacy-v1, wrong or vague (read a v1 entry's `ledger-only-content` flags first).
  - `maintain.md` also carries the retire-by-status stdin shapes and closes with one `refresh-anchor … --verified` batch of the kept entries (active v2 only; if refused, drop the named anchors and run once more).
- **Heartbeat and vanished inputs.** Every op refreshes the claim; at the Part 1 to Part 2 boundary and after each maintained entry the agent runs `touch -c <claim> && test -f <claim>` (the `test -f` fails once the claim is gone). If that fails, or an op answers `no .devflow/curation/ under …`, stop writing, go to Finishing, never recreate anything.
- **Finishing.** `release-claim <token>` is the FINAL act (`not-owner`, `gone` or a no-curation-dir refusal is noted in the summary); never delete, move or rewrite the claim or owner file. End with a 1 to 3 line summary, the run's only visibility surface.

The body carries the entry format with a good and a bad example and quotes the ops' stdout forms (the `claim-due` form is in `maintain.md`). Neither file states plumbing numbers (claim staleness, the claim-due batch size): they live in plumbing and a prose copy drifts. Only the rotation and verify-age days stay; the rotation window is pinned over the body plus `maintain.md` by `tests/decisions/curation-retire.test.ts`.

**The reference skill (`agent-references`).** `src/assets/skills/agent-references/` is reference-only: `user-invocable: false` and `disable-model-invocation: true`, never named in an agent's `skills:` list or a plugin `requires`, and registered in `devflow-core-skills` (always installed). It holds `references/curate/maintain.md` for this agent, `references/synthesize/{mode}.md` for Synthesize and `references/commands/{name}.md` for text a command keeps out of its own text (D-CMD-REF-HAND), which that command Reads by explicit path when its condition holds: a rare branch for /implement, and for /code-review the level table, read on every non-`full` run. The agent body is held under the `curate-body-max` ceiling in `tests/fixtures/numeric-floors.json` (lowered, never raised), asserted in `tests/guards/agent-references.test.ts`; the flags and the no-preload rule are held in `tests/guards/skill-description-caps.test.ts`. Curate stays on Opus and keeps its explicit CLAUDE.md and rule reads in the body's Inputs, ahead of both comparisons.

## session-start-context directives

The hook assembles `additionalContext` from numbered sections. Section 1 (the decisions TL;DR, the Index line and the pass rule, which tells the model to hand each agent a slice of the index) belongs to the decisions delivery route and is in `curation-capture-system-delivery`. The rest:

- **Carve-out** (before Section 1): the hook sources `ensure-root-gitignore` (the `.devflow/` carve-out) unless `df_no_symlink_below` finds `.devflow` a symbolic link (the marker would land in the folder the link names); the skip is logged once through `log()` and context injection goes on. `hook-log-init` is sourced before the carve-out, so `ensure-root-gitignore`'s own skips (a linked root `.gitignore`, a legacy copy it could not write, a linked marker) reach the log too: with memory and curation both off, this is the only hook that reaches the carve-out.
- **Section 2** emits `--- CURATION MAINTENANCE ---` when the queue is non-empty or `.pending-turns.processing` is stale (at least `PROCESSING_STALE_SECS`); a fresh claim suppresses it. The queue, the batch and the project `curation.json` are read through `df_file_below "$LEDGER_ROOT"`, so one a link leads to counts as absent: a linked queue or stale batch sends no agent to it, and a linked `curation.json` does not choose the model. The check is advisory: a spawn that loses the race exits on `busy`. `$LEDGER_ROOT` is embedded only when `DIRECTIVE_LEDGER_SAFE` (positive shape `^[A-Za-z0-9/._+-]+$`, `+` for Claude Code's `feat+x` worktrees) admits it; a refused root with pending work emits the fixed `--- CURATION PAUSED ---` notice, which interpolates nothing. The spawn is `subagent_type="Curate"`, `run_in_background: true`, prompt "Process the pending curation queue per your agent instructions. Project root: $LEDGER_ROOT".
  - **Model resolution (D-LEARNING-MODEL-PRECEDENCE)**: four layers, the first that supplies one decides. (1) A valid project `curation.json` `model`, which emits `model="<value>"`. (2) The `devflow agents` Curate mapping, `agents.curate.model` in `$HOME/.devflow/agent-models.json` (else `agents.learning.model`, the key the agent carried before it was renamed), which emits no `model=` so the installed frontmatter decides. (3) A valid global `curation.json` `model`, which emits `model=`. (4) None, again no `model=`. Layers 1 and 3 pass the `opus|sonnet|haiku` allowlist (curation.json is user-controlled) and an invalid value falls through.
  - **Layer 2 detail.** It counts only when `agents.curate.model`, or failing that `agents.learning.model`, is a JSON **string** that is a model name by the rule `readAgentMapping` keeps a model by (`MODEL_NAME_RE` in `src/core/agent-frontmatter.ts`: a letter or digit, then letters, digits, `.`, `_` or `-`, within the length bound), read through `json_string_field_file` so the number `42` is not the name `"42"`; its value is never interpolated into the directive, only its validity decides precedence. Anything `readAgentMapping` would drop (a number, boolean, object, array, empty or out-of-charset string) supplies no model, so the layer reads as absent and the lookup falls through to the global file rather than honouring a mapping for a model nothing will run. An effort-only mapping entry supplies no model; a missing, unreadable or malformed `agent-models.json` reads as absent; a dormant external mapping model still decides, since the hook does not know the proxy state. The name test spells its character sets out because a range such as `A-Za-z` matches accented letters in a UTF-8 locale on bash 3.2, and the value is read with a trailing sentinel so a trailing newline fails the test instead of being stripped.
  - **No `opus` fallback in the hook.** The shipped tier lives in `agents/curate.md`, and `DEFAULTS.model` in `curate-tuning-config.ts` is that same tier (D-LEARNING-SHIPPED-ROW), held equal to the Curate row of the shared agent-config table, so a change of the shipped tier edits the row, the `model:` line and that default together. Layer 2 sends no model because a model named at an Agent spawn outranks the installed frontmatter, which is where `devflow agents` writes a user's override; the no-hardcoded-model guard scans commands, agents, skills and reference modules, and hook directives sit outside it by design (the Tracker directive pins its model; this one emits one only under the precedence above).
- **Section 3, tracker setup** (`--- TRACKER SETUP ---`, not gated by the curation switch, so disabling curation does not disable the issue tracker):
  - The machine provider comes from the `.tracker.enabled` sentinel (provider name on one line, read with `read`, zero forks), overridden by committed `project.json` or narrowed by personal `config.json` only when a bounded read shows a `"tracker"` key (one fork of `resolve-settings.cjs`; a git-tracked `config.json` is ignored, D-PERSONAL-UNTRACKED). Then a POSITIVE `jira|linear` allowlist (never `!= github`) and a skip when `~/.devflow/tracker/$P.md` exists.
  - `tracker_gates_open()` runs cheapest first: attempt cap, git marker, `source` in {startup, clear}, claim freshness, path shape, and the counter increment must land. GitHub and a learned provider fork nothing.
  - `.tracker.{provider}.attempts` is one decimal-integer line (absent, malformed or zero-padded counts as 0 and is self-healed; an over-long digit run counts as `TRACKER_ATTEMPTS_MAX`); the hook increments on emission, the agent deletes it only on a successful write and the claim file last. The section is capped at `TRACKER_SECTION_MAX_CHARS` (the numeric-floors ceiling `tracker-section-max-chars`).
  - The Tracker agent (`tracker.md`, `model: sonnet`) has the same claim and heartbeat shape with its own `TRACKER_PROCESSING_STALE_SECS` bound; provider selection and schema belong to the `tracker-feature` KB.
- **Section 4** (D-LEGACY-LOCAL-NOTICE): one line asking the user, once, to run `devflow uninstall --scope local` when `<root>/.claude/settings.json` registers a devflow hook (a command ending in `/scripts/hooks/run-hook <marker>`).
- **Sections 5 and 6** have nothing to do with curation and add no exit path. Section 5 (D-COMPACT-RESUME-DIRECTIVE): on a positive `compact` case of the SessionStart `source` (read with `cwd` in one `json_extract_cwd_field` subprocess), one fixed single-quoted line, capped by the numeric-floors ceiling `compact-directive-max-chars`, is appended to the context, telling the model to re-read a running devflow command from the phase in progress. Section 6 (D-CLAUDE-MD-IMPORT-AUDIT, D-AUDIT-STAMP): an audit of CLAUDE.md `@path` imports by `claude-md-audit.cjs`, reported in a top-level `systemMessage` that never enters the model's context, with a stamp at `~/.devflow/.claude-md-audit` that makes an unchanged start free of forks.

## devflow curation CLI (`src/cli/commands/curation.ts`)

A thin router (status, list, show, configure, reset, clear, restore, enable, disable). It reads and writes the log, ledger and rendered files only through the store loaded by `loadCurationStore()` (`--configure` and the queue drain write their own files directly, each only past `firstSymbolicLink`, D-CLI-NO-SYMLINK), and locates the ledger with `getLedgerRoot()` (the main checkout from a linked worktree). Writers wait at most `LOCK_WAIT_MS` for the lock and answer `The curation store is busy: another run holds its lock. Nothing was <cleared|restored|reset>; try again in a moment.` (exit 1). A writer facing a linked `.devflow` or `.devflow/curation` answers the store refusal instead (`<op>: <folder> is a symbolic link, not a directory; nothing was changed`, exit 1; D-NO-LINKED-TREE).

**The old folder.** The command is `devflow curation`; `devflow learning`, `init --learning` and `init --no-learning` are unknown to commander (exit 1) and no alias exists. The data moved from `.devflow/learning/` to `.devflow/curation/` (hub KB, KB-INV-17). Read-only subcommands act only when the new folder is absent and the old one is present: `--status` prints the state line then the HUD pointer line (exit 0; `Curation: run devflow init, or open Claude Code in this project after it`, or `Curation: move refused, see the hook log` when the skip marker stands), `--list` prints it as info (exit 0) and `--show` prints it as an error (exit 1). With both folders present they read normally. Every writing subcommand (`--restore` after its id check, `--clear`, `--reset` before its no-data test, project-scope `--configure`) first calls `prepareToWrite`: a skew between the installed hook scripts and the running CLI (`installedScriptsSkew`) refuses even with no old folder; then `runSharedMove` runs when the old folder is present. A busy answer prints `Another run is moving this project's curation data. Nothing was <undone>; try again in a moment.`; a refused or failed move prints its reason and `Nothing was <undone>.`; both exit 1. `--status` also prints one `Backup: <path>: N pending row(s) in the backup` line for each of the first `MOVE_MAX_BACKUPS` `.devflow/learning.backup-*` folders, and one line that counts the rest (`backupPendingRows` in the move module, read-only and link-safe).

- **`--status`**: `Curation: enabled|disabled` (+ `Effective here:`), `Entries: A active (n decisions, m pitfalls), I inactive (Status k, …)`, `Legacy v1 entries: v of A active`, `Observations: L in the log, U not yet promoted`, and a warning when lines were skipped. Reads only, no scope check, no path printed; outside git `Entries: not in a git project`.
- **`--list`** prints exactly the `list` op's text; **`--show <id>`** prints the `show` JSON with every DEL, C1, directional, line-separator and bidi character escaped as `\uXXXX`, so a terminal shows it as written. Both read the cwd outside git; no curation directory gives `No curation data in this project yet.`
- **`--restore <id>`** needs a git root and an entry id and calls `restoreAnchor`: `Restored <anchor> (<status>); it is due for review again.`
- **`--clear`** (D-CLEAR-UNREFERENCED): TTY confirm, then `clearUnreferenced` drops exactly the log rows no ledger row carries, whatever their age or status, and keeps every row an entry carries. It refuses while the ledger holds a malformed line (that line may carry a row it would drop), never writes the ledger, archive or rendered files, and with nothing to drop writes nothing. Only after it succeeds does the CLI drain the queue, claim and owner file (through a linked `.devflow` or `.devflow/curation` it deletes nothing: the success line then omits "drained the curation queue" and a warning names the link, D-CLI-NO-SYMLINK). Truncating the whole log would orphan every entry, each losing its content authority.
- **`--reset`** (D-RESET-UNDER-LOCK): no curation directory gives `No curation data to reset.`, nothing created. The TTY confirmation comes BEFORE the lock; `resetCuration` then empties the directory under the lock, sparing only the lock directory, and removes the emptied directory after the release, only if nothing arrived meanwhile (removing the lock with the directory would let a release delete the lock of a writer that recreated the tree). It removes everything: queue, claim, owner and tuning config included. A `.devflow` or `.devflow/curation` that is a symbolic link is refused with nothing removed (`not-a-directory`, by `withDecisionsLock`, D-NO-LINKED-TREE), since emptying it would empty the directory it leads to; a link inside the directory is removed, never what it points to. `resetCuration` carries no check of its own.
- **`--enable/--disable`** write both manifest keys, `curation` and the mirror `learning` (hub KB, KB-INV-15), then converge the installed prompts onto it through `applyCurationToggle` (the curation-on or curation-off commands and agents, and the `devflow:apply-decisions` skill, with the `devflow agents` mapping reapplied when an agent was rewritten; see `curation-capture-system-delivery`). The converge warns on a skip (no readable manifest, or a manifest version that is not the running CLI's) or a failure and never changes the exit code; when it changed something it prints one `Installed prompts:` line. When the converge succeeds, the command tries the shared move once (a busy answer is no error). Among the toggles only disable drains this project's queue (`drainDisabledCurationQueue`: queue, claim and owner in the new and the old folder, and the pending rows of the backups a move left, meaning their queue, claim, private and overflow files; their ledger files, swept files and owner file stay, so a later re-enable cannot merge the rows back). Through a linked `.devflow`, ledger folder, backup folder or backup queue file it deletes nothing and warns, the switch still turned off and the exit code 0. `--clear` drains the same three files in the new and the old folder only (`drainCurationQueue`), and `devflow init` runs the disable drain where curation is off.
- **`--configure`** writes `curation.json` at the ledger root (project) or `~/.devflow` (global; its scope hint says a `devflow agents` Curate mapping takes precedence over the global file); the project file is written only when `.devflow`, `curation/` and `curation.json` are all not links, else `Project config not written: <link> is a symbolic link, and devflow writes nothing through one` and exit 1 (D-CLI-NO-SYMLINK). The model picker marks as Recommended the model the Curate agent ships with, read from its frontmatter through `loadShippedAgentDefaults` (`curateModelOptions`, D-LEARNING-SHIPPED-ROW), never from a list of its own.

## TypeScript seam, status lists and HUD

**D-LEARNING-STORE-SEAM.** `loadCurationStore(dir = scriptsDir())` loads `hooks/lib/curation-store.cjs` with evidence-policy's `loadScript` and shape-checks it against `CURATION_STORE_SURFACE` (`satisfies Record<keyof CurationStoreModule, SurfaceKind>`: `INACTIVE_STATUSES`, `ANCHOR_ID_RE`, `readCurationState`, `buildListing`, `readListing`, `formatListing`, `showByKey`, `restoreAnchor`, `clearUnreferenced`, `resetCuration`). It never throws (`not-found` and `unusable` map to "curation store not found|failed to load — reinstall devflow-kit"). The interfaces are transcribed from the store's JSDoc and are the TS side's only shape authority, so a store function the CLI calls needs the interface entry, the surface entry and the fixtures' `CurationStoreApi`. The CLI loads the package copy while hooks and ops run `~/.devflow/scripts`, so the two can differ until `devflow init`. The move module has its own seam, `loadCurationMove` (`src/core/curation-move.ts`), checked against `CURATION_MOVE_SURFACE` (`moveLedger`, `sweepLedgerBackups`, `backupPendingRows`, `backupQueueFiles`) with interfaces transcribed from its JSDoc, and the same package-copy skew.

`src/core/observations.ts` mirrors the status lists (D201) and imports nothing, so the HUD import closure does not grow (the install goldens list `core/observations.js`); a parity test pins it equal to the store's lists. The HUD component (D309) counts ledger rows with `anchor_id` set and `isActiveDecisionsStatus`, from `decisions-ledger.jsonl` and never the rendered markdown, silent on malformed lines, and it reads the ledger only through `readBoundedLedger` (see the links KB), showing no counts otherwise. When it has no counts (no ledger, or zero) and the old folder is still there, it shows a pointer instead: `Curation: run devflow init, or open Claude Code in this project after it`, or `Curation: move refused, see the hook log` when the skip marker exists (`gatherMoveNotice` and `formatMoveNotice` in `src/core/curation-move-notice.ts`, which the CLI shares; the busy marker is never read); it never reads the old ledger. `gatherLedgerCurationCounts` uses `getLedgerRoot` inside the git-status `Promise.all` (a tight time budget).

## Anti-Patterns

- **KB-AP-1, claiming by `mv`**: `mv` keeps the queue's old mtime, so a fresh claim looks stale; an unconditional final unlink deletes another run's claim. Use only the two ops (the deliberate `--clear`, `--disable` and `--reset` drains are the exceptions).
- **KB-AP-4, honouring the Curate mapping with `model=`**: see the layer 2 detail; the installed frontmatter must decide.

## Gotchas

- **KB-INV-2**: the staleness is two literals (`CLAIM_STALE_SECS` and the hook's `PROCESSING_STALE_SECS`); change both. The Tracker's bound is separate.
- **KB-AP-7**: every `session-start-context` test seeds a temp `$HOME` (the hooks read `$HOME/.devflow` only).
- **KB-AP-5**: new CLI flags need a write-set fence row (`tests/write-set-fence.test.ts`) and a floor bump in `tests/fixtures/numeric-floors.json`; the fence runs the built CLI. Spawn-backed curation tests need spawn-sized timeouts under full-suite load.
- **KB-AP-8**: Section 3 is not gated by the curation toggle.
- **The CLI package copy and the installed copy of the store can differ** until `devflow init` (the seam loads the package copy).
