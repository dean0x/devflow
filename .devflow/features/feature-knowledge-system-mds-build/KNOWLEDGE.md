# MDS Build Pipeline

## Rules

- **KB-INV-1** `src/assets/` is the source of truth and every compiled artifact lands under `dist/`, never `src/`. `npm run build:cli` alone produces no installable agents or references; `build:mds` (or `build`) is required, and `build:mds` never wipes `dist/`.
- **KB-INV-2** The output-dir allowlist (`ALLOWED_OUTPUT_DIRS` in `mds-variants.ts`) is closed: one `HostVariant` per directory, and `resolveOutputDir` is the only gate on where the build may write. Gated modules and the learning-off tree add no destination.
- **KB-INV-3** `mds-variants.ts` and `learning-variants.ts` are pure, zero-I/O and return `Result`. `build-mds.ts` owns every filesystem call and the single `process.exit`, reached from `main()` after the loop, so refusals aggregate and `dist/` is never left half-updated.
- **KB-INV-4** Variant dispatch is an exhaustive `switch` over `HostVariant` with a `never` default, never a comparison of a resolved path against a re-derived constant. A new variant breaks every dispatch until handled; that friction is intended.
- **KB-INV-5** Every destination is planned before anything is written. A destination claimed by two hosts disqualifies every claimant, and the build errors naming all of them.
- **KB-INV-6** Frontmatter strips run on the compiler's OUTPUT, after `compileFile`, one strip per variant, each verified at both ends. A build key present but valueless hard-fails during discovery.
- **KB-INV-7** Outputs are written to a PID-scoped temp file and renamed. The prune runs only after a zero-error build, is keyed on files actually written, and leaves non-`.md` entries alone.
- **KB-INV-8** Every walk and sweep is bounded (`MAX_WALK_DEPTH`, `MAX_REFERENCE_SWEEP_DEPTH`). The build throws on a breach rather than truncating; the installer's sweep reports into `failed` instead.
- **KB-INV-9** Dist-first resolution has one owner: `agentSourceDirs()` and `commandSourceDirs(learning)` in `src/core/assets.ts`, spelled most-preferred first. Consumers take the list as-is and never re-spell it (`tests/guards/agent-source-precedence.test.ts`).
- **KB-INV-10** No test writes the real `dist/`: every spawned build is scoped by `DEVFLOW_MDS_ROOT`, proved by `collectSpawnScoping`; whole-corpus assertions share one memoised `buildCommittedTree()` spawn. `cwd:` is not a scope.
- **KB-AP-1** Only `{{…}}` interpolates in MDS. Single-brace `{x}` ships as literal text and `\{x\}` ships its backslashes; both compile with no error or warning, so only the lost-expansion and backslash-leak guards catch them.
- **KB-AP-2** Learning arms are whole-line markers that never nest; a mid-line, mis-cased or unbalanced marker fails the build. A blank line a paragraph needs goes INSIDE the arm that owns it, and a native conditional stays banned in the agent-host corpus until the planned migration.
- **KB-AP-3** A blank line between a command host's `@import` block and its body reaches the output: the body starts on the next line.
- **KB-AP-4** A verbatim move of prose between `.mds` files is not semantics-preserving: the destination slices by its own grammar (heading level, the `<!-- op: -->` marker regex), so an ordinary heading can become a section terminator.
- **KB-AP-5** Never re-write a hand-authored prompt when converting it to a host: `git mv`, add the steering block, `cmp` against the original or golden. End every host source in a single newline.
- **KB-AP-6** `output-name:` is refused on a reference module (it has no basename to name) and there is no templating key; never hardcode a destination outside the allowlist to route around the `typo?` refusal.
- **KB-AP-7** No agent has both a hand-authored `.md` and a generator `.mds` (the resolver would silently pick a winner), and no `\{`/`\}` sequence may leak into `dist/agents/`.
- **KB-AP-8** The agent-host scope fence is narrowed visibly or not at all: a legalised construct is named in `LEGALISED_IN_PHASE2`, never silently dropped from the forbidden list.
- **KB-AP-9** The build's printed census lines are parsed by tests; never reword them.
- **KB-AP-10** The `dist/` staleness check compares a fresh build of committed `src/` against whatever `dist/` the tree holds. It proves "nobody rebuilt" and "hand-edited", not that the bytes were reviewed.

## Overview

`scripts/build-mds.ts` is the single compiler for every `.mds` host kind. `npm run build:mds` produces three output kinds plus a variant tree: command hosts to `dist/commands/`, agent generator hosts to `dist/agents/`, reference-module sources to `dist/skills/git/references/` (one file per operation or named document), and `dist/learning-off/{commands,agents}/` holding the learning-off variant of every host that carries a learning arm. `npm run build` is `build:cli` plus `build:mds`.

This KB owns the pipeline: discovery (including the deferred/gated census bucket), destination validation, frontmatter strips, variant expansion and section splitting, the learning-variant split and the prune, for all variants. Neighbours own other sides of the same compiler. `feature-knowledge-system-reference-modules` owns the reference-module registry, kinds, gate and manifests. `tracker-references` owns what the reference files contain (operation mechanics, byte-budget formula, the installer's overlay into `devflow:git`). `tracker-feature` owns the provider dimension (selection, what opens the `_mcp.mds` gate, the contract text). `dynamic-workflow-engine` owns what the compiled commands must say. `installer-shadowing` owns how the installer and the learning toggle consume `dist/learning-off/`. The `feature-knowledge-system` hub covers the knowledge partials, which are themselves MDS sources.

## Host Kinds and Manifests

The roster lives in `tests/fixtures/mds-manifest.ts` as named sets, not counts. It is the single source every count-literal test compares against in both directions, and the build's printed counts are asserted against it; floors only rise.

- **Command hosts** `MDS_COMMAND_HOSTS` = the knowledge-workflow hosts (`KNOWLEDGE_COMMAND_HOSTS`), the dynamic hosts and `release`. Every command is a compiled host; none is a static `.md`, and `DIST_COMMAND_FILES` names the same set.
- **Generator hosts** `MDS_GENERATOR_HOSTS`: `git` first, then the agents that take `DECISIONS_CONTEXT` (plus Skim's `LEARNING` input) so their learning arms can build into the off variant: code, design, diagnose, knowledge, research, review, scrutinize, skim, triage. Hand-authored agents (`evaluate`, `learning`, `simplify`, `synthesize`, `test`, `tracker`, `validate`) stay `.md`.
- **Reference-module sources** `MDS_REFERENCE_MODULES` (see the reference-modules KB).
- **Partials** declare no `output-dir:` and are skipped: `MDS_PARTIALS` under `_partials/`, plus `MDS_REFERENCE_PARTIALS` (`_common.mds`, `_steps.mds`) outside it; `ALL_MDS_PARTIALS` is the union the build prints. `ALL_MDS_HOSTS` is filenames only (reference modules excluded by construction); `ALL_DISCOVERED_HOSTS` is everything `output-dir:` finds, gated or not. `LEARNING_VARIANT_HOSTS` / `LEARNING_OFF_FILES` name the hosts with an arm; `SETTINGS_BLOCK_HOSTS` and `SETTINGS_BLOCK_HOSTS_LEARNING_OFF` name those carrying the settings block, and those that keep it with learning off.

Reference modules write nowhere near `dist/commands/`, so `DIST_COMMAND_FILES` is unaffected by them. The `_` prefix is enforced structurally: `validateOutputName` refuses a leading underscore, so a partial can never become a one-file host, while a `'contract'` module's op name requires one under its own rule. The deferred census count is a live measurement, not a constant: it reads zero while a tool-call-backed provider is registered and one, naming `_mcp.mds`, for a registry with every `MCP_BACKED_PROVIDER_SUBDIRS` entry removed; both readings are asserted by the non-vacuity arms.

## Pipeline

1. **Walk.** From the repo root, skipping `IGNORE_DIRS` (`node_modules`, `dist`, `.git`, `.devflow`, `.claude`, `.release`, `tmp`, `tests`, `coverage`). `tests` and `coverage` are skipped so a fixture or coverage `.mds` can never compile into the real `dist/`; the skip is by directory name, so it holds under `DEVFLOW_MDS_ROOT` too (a fixture host planted at `<tmpRoot>/tests/` is invisible). `DEVFLOW_MDS_ROOT` redirects the whole walk for negative-path tests. The recursion is bounded by `MAX_WALK_DEPTH` (root is depth 0) and **throws** on breach: a host skipped for depth would compile nothing while the build still printed its counts and exited 0. `readdirSync` tolerates `ENOENT`/`ENOTDIR` (an entry can vanish between a parent's readdir and the descent) and rethrows everything else.
2. **Discover and bucket.** Each path is first checked against `deferredReferenceModuleSources()`: a module the registry knows but whose gate is shut goes to `deferred`, never becoming a `HostEntry` or a counted partial. Otherwise the FIRST `---…---` block is read with a scalar regex (`readFrontmatterKey`; the build must not gain a YAML dependency): a non-empty `output-dir:` makes it a host, else a partial. `BUILD_KEYS` (`output-dir`, `output-name`) is the one list of keys the build consumes; it drives this read and the command-host strip, so a key the build reads can never leak into an artifact. A bare build key returns `''` (not null), so a `?? basename` fallback would not fire; discovery therefore hard-fails (`output-dir: is empty …`) rather than hide the authoring mistake, before any plan or write, leaving `dist/` untouched.
3. **Validate the destination** with `resolveOutputDir(root, declared)`: containment (`isContainedIn`), then backslash rejection (declarations are POSIX-spelled; `path.posix.normalize` leaves `\`, so `dist\commands` would pass the canonical check on win32), then canonical spelling (POSIX-normalised, no trailing slash: `dist/commands/`, `./dist/agents` and `dist/skills/../commands` are refused), then the allowlist. It returns `{ variant, abs }`, where `variant` is the `HostVariant` (`'commands' | 'agents' | 'skill-refs'`) the matching allowlist entry declares and selects the strip strategy in step 5. The four errors (`escapes-root`, `backslash-separator`, `non-canonical`, `not-allowlisted`) render through an exhaustive switch and are thrown for aggregation.
4. **Plan** (`planHost`) through an exhaustive switch on the variant into `planSingleFile` (commands, agents) or `planReferenceModule` (skill-refs), each returning a `HostPlan`, a union discriminated on `variant`. The one-file arm carries `dest` plus a `learningOffDest`, planned for every one-file host but deliberately NOT claimed by `destsOf`: it is written only after the split, in its own tree, so two hosts can collide on it only by colliding on `dest` first. The fan-out arm carries `outputs: readonly PlannedReference[]`, each pairing a `dest` with its `(module, op)` pair, so there are no parallel arrays and no arm reads a field the other owns. `destsOf(plan)` is the uniform "every file this host claims" view for the claims loop, the contested-destination filter and the prune's claimed set. `planSingleFile` validates the emitted name (source basename, or `output-name:`) with `validateOutputName` (charset `^[a-z0-9][a-z0-9._-]{0,63}$`, refusing `.`/`..` and separators). `planReferenceModule` refuses `output-name:` outright, finds the module with `referenceModuleFor` (against `resolveVariantModules()`, the gated registry, never raw `VARIANT_MODULES`), expands it with `expandVariants([mod])` and re-validates each path segment by segment (`validateContractOutputName` for `'contract'` modules), then asserts that no expanded destination escapes the output directory (a belt-and-braces check that cannot fire after the segment validation). A source declaring the skill-refs directory but absent from the registry is refused with no basename fallback. All destinations go into one `Map<destAbs, HostEntry[]>` across the whole plan pass.
5. **Compile, then strip** (`stripFrontmatterFor`, exhaustive over the variant). The compiler emits a byte-0 frontmatter block verbatim, so slicing it afterwards is safe. `commands`: `stripBuildKeys` removes each `BUILD_KEYS` line from the single real block, every other key byte-untouched (no YAML round-trip). `agents`: `stripGeneratorFrontmatter` removes the ENTIRE first block and promotes the second, verified before (a leading block exists) and after (a second block is what the slice exposes), because a single-block host, the shape of every hand-authored agent, would otherwise ship headerless while the build reported success. `skill-refs`: `stripReferenceFrontmatter` also removes the one leading block but verifies the OPPOSITE postcondition, that no second block follows, because a reference ships as plain markdown and a two-block habit would leak `output-dir:` into every emitted file.
6. **Split learning variants** (commands and agents). `materializeOutputs` splits the stripped body with `splitLearningVariants` (D-LEARNING-VARIANTS): the on-variant is the artifact at the host's own path, and only when the body has an arm is a learning-off variant planned for `dist/learning-off/{commands,agents}/{name}.md`. The split runs on compiled text, so it costs no `compileFile` call and nothing against the per-module compile-time guard. Each refusal (`nested-arm`, `repeated-off`, `unopened-end`, `unclosed-arm`, `empty-arm`, `stray-marker`) is rendered by `learningSplitRefusal` with the host and a quoted neighbouring content line; line numbers count the COMPILED output, since a marker from a partial has no line in the host.
7. **Split reference sections** (skill-refs). `materializeOutputs` refuses any body containing a learning marker (sections ship as written, so a marker would reach the installed reference as text), then calls `splitVariantSections<T extends OperationNamed>(body, entries)`. The entries are the plan's own `{dest, op}` records, so exactly one `VariantSection<T>` (the caller's fields plus `content`) comes back per entry: the destination travels with its content, with no lookup structure or non-null assertion. The splitter walks `<!-- op: NAME -->` markers and drops any module-level preamble before the first, since it belongs to no operation and would otherwise be duplicated into every file; `_linear.mds`'s `## Known Unknowns` section, written for a human reading the source, is emitted nowhere for this reason. It is bidirectional: `unknown-section` (a marker names an op the registry lacks) and `missing-section` (the registry names an op the body never marks) both refuse, and `empty-section` (GAP-44) is a third, independent refusal, because a marker with a blank body compiles cleanly and would ship a zero-byte reference with no build signal.
8. **Write** each output to `{dest}.{pid}.tmp`, then `renameSync` (per-file atomic, the temp cleaned on rename failure). The PID scoping keeps concurrent builds off one staging path, and the rename closes the ENOENT window a delete-then-write has for parallel vitest readers.
9. **Report.** Any compile error fails the build, so no stale command ever ships. It prints `N partial(s) skipped (no output-dir:)`, `N reference module(s) deferred (generation gated)` (naming each held-back source as `deferred: {source} (no registered provider needs it yet)`), `N host(s) to compile:` and, after the prune, `N learning-off variant(s) written`; these four are parsed by `tests/build-mds-generator-hosts.test.ts` (AC-1.8) and by the non-vacuity arm in `tests/packaging.test.ts`. The deferred count is subtracted from the partial arithmetic explicitly (`totalCount - hosts.length - deferred.length`), so a gated module cannot move the partial count for a reason that is not a roster change. There is no separate "references emitted" line: a fan-out folds into the `compiled: {source} → {dest}` line as `{outDir}/ (N file(s))`, and a learning-off variant renders as `{on dest} + {learning-off dest}`.
10. **Prune** (`main()`, only after zero errors), in order, each keyed on `writtenDests`, the files actually written, not the planned ones (a learning-off variant is planned for every one-file host but written only for one with an arm): `pruneOrphanCommands` (`pruned: {path} (no command host)`), `pruneOrphanAgents` (`(no generator host)`), `pruneOrphanReferences` and `pruneOrphanLearningOff` (`(no reference module)`, `(no learning arm)`), all through the shared `pruneOrphans` helper bounded by `MAX_REFERENCE_SWEEP_DEPTH`. The reference and learning-off sweeps are recursive by necessity: the reference tree is nested (`tracker/{provider}/{op}.md` plus flat `tracker/_contract.md` and `tracker/_mcp.md`), and a host that loses its last arm would otherwise leave its old variant for a learning-off machine to install in place of the real prompt. The pruned directories are gitignored and outrank their `src/` counterparts in every consumer that resolves from them, so a leftover would install in preference to audited source on every `devflow init`. `dist/commands/` is pruned too, because every command is a host and "no host claims it" means orphan (a renamed host's old output would otherwise install as a command no source declares). A refused build prunes nothing. `COMMANDS_OUTPUT_DIR`, `AGENTS_OUTPUT_DIR`, `SKILL_REFS_OUTPUT_DIR` and `LEARNING_OFF_OUTPUT_DIR` name the targets even when no host of a kind is planned, the case where every file is an orphan and the target cannot be derived from the plan.

The depth bound has two postures for one breach (`depth > MAX_REFERENCE_SWEEP_DEPTH`, root counted as 0): the build's `pruneOrphans` **throws** (a generated tree that deep is a build bug and `dist/` is the build's own tree to fail), while the installer's `sweepOrphanedReferences` **reports** the unswept subtree into `failed`, so one bad subtree never aborts an install.

**Test coverage of the prune.** `tests/build-mds-generator-hosts.test.ts` has a describe for `dist/agents/` (delete-and-report, claimed survives, refused build prunes nothing, non-`.md` survives) with a sibling case for an unclaimed `dist/commands/*.md`, and the describe `dist/skills/git/references orphan prune` (unclaimed and nested files pruned, claimed and non-`.md` files survive, descent at the bound succeeds and one past it fails without pruning). It also asserts that root-level planted files in the references tree are pruned: the build sweeps the whole generated tree root-included, unlike the installer's prune, which narrows to the wholly-generated `CONVERGED_SUBTREES` (`references/tracker/**` and `references/pr/**`; D-CONVERGED-SUBTREES in `src/targets/claude-code/installer.ts`) because the installed skill dir mixes generated and hand-authored sources at the references root.

## Dist as a Shipping Area

`dist/agents/` carries three properties held by `tests/guards/dist-agents.test.ts`: source and output parity in both directions, failing loudly (never a silent `catch { return }` on a missing build); no leaked escape sequences; no agent with both a `.md` and a `.mds` source.

The dist-first precedence has exactly one owner, `agentSourceDirs()` in `src/core/assets.ts`, a non-empty tuple spelled most-preferred first (`[compiledAgentsDir(), agentsDir()]`). With `learning` false it puts `learningOffDir('agents')` in front, and `commandSourceDirs(learning)` does the same for `dist/commands`, so a host with an arm installs its off variant and a host with none falls through to its one compiled file (the install and converge side belongs to `installer-shadowing`). Order is invisible to the type system, since a list spelled the other way still typechecks and silently inverts the answer. Consumers: the installer's agent-source loop (first hit wins; a miss throws naming every candidate path plus a `build:mds` hint) and `loadShippedAgentDefaults(dirs = agentSourceDirs(), opts)`, which walks first-wins over a per-directory `readDirDefaults(dir)`, tolerates a missing directory on every entry, and deliberately reads the learning-on order because model and effort are the same in both variants. The test resolver `resolveAgentSource` in `tests/helpers.ts` reads the same order but is a different resolver with a stricter contract: only its dist side tolerates ENOENT, and a missing src file throws with a build hint. `compiledSkillRefsDir()` is the analogous accessor for `dist/skills/git/references/`, reading `SKILL_REFS_OUTPUT_DIR` off the allowlist rather than re-spelling it; the installer's reference overlay (owned by `tracker-references` and `installer-shadowing`) consumes it, and the overlay's own unit-shape rule tells the flat `tracker/_contract.md` and `_mcp.md` apart from provider subdirectories, while this build's registry decides only the generated shape.

## Constraints

- **Allowlist.** `ALLOWED_OUTPUT_DIRS` holds the commands, agents and skill-refs entries; the third is deliberate (D-SKILLREFS-ALLOWLIST), since the alternative (writing references through a path composed outside `resolveOutputDir`) would make the allowlist a partial gate. A gated module still resolves to the same skill-refs variant (only its `subdir` and op-name rule differ), and the learning-off tree is written by the splitter's own path function, not declared by a host. Adding a *directory* means a table entry: `satisfies` forces it to declare a `HostVariant`, and `_EveryVariantHasADirectory` is the reverse compile-time proof (a variant with no entry fails to typecheck). Widening the union breaks every exhaustive dispatch until handled.
- **Agent-host scope fence** (AC-1.2, `tests/guards/dist-agents.test.ts`). The guard forbids `@if` conditionals, a `variants:` key, the `tracker-<provider>.md` token, the `{provider}.md` templated name, and `@import`/`@define` inside a compiled AGENT host; the generated reference tree is driven by the typed `VARIANT_MODULES` registry, not by a template or conditional. Two constructs were deliberately legalised and named in `LEGALISED_IN_PHASE2`: the literal strings `expandVariants(` and `(module, op)`, which live in `mds-variants.ts` and `build-mds.ts`, the guard's own corpus. A later legalisation must update that list, and the guard's own test proves the fence still forbids a floor of constructs afterwards. The corpus is every generator-host `.mds` plus those two files; `learning-variants.ts` sits outside it, and the learning markers are HTML comments, so they pass.

## Anti-Patterns

**KB-AP-6, adding a destination.** A host declaring an unlisted `output-dir:`, even a sensible-looking one, is refused with the `typo?` message by design. The only way to add a destination is the allowlist table. `output-name:` decouples a filename from a `commands`/`agents` host's basename; on a reference module it is refused rather than ignored, because filenames come from the module's `ops` roster and a key read on two variants and silently dropped on the third is the authoring trap the refusal avoids. Variant expansion is registry-driven, not frontmatter-templated, and `name-template:` stays unclaimed.

## Gotchas

**KB-AP-1, brace syntax.** Since `@mdscript/mds` 0.4.4 (the 0.2.0-era single-brace form is gone), `{{name}}`, `{{helper()}}` and `{{alias.helper()}}` interpolate. A single-brace `{helper()}` is emitted as literal call text, in prose, inline code and every fence kind (column-0, indented, tilde, blockquote), so a runtime placeholder such as `{worktree}` needs no escaping, and there is no backslash escape. The lost-expansion and backslash-leak guards in `tests/build-mds.test.ts` are load-bearing across `git.mds` and every reference module, which share the grammar. Blank lines are kept as written. The three strips run on the compiler's OUTPUT, so they never see source syntax. `compileFile` returns a `markdown | messages` union and the build refuses a `messages` result (an `@message` host) as an aggregated error.

**KB-AP-2, learning arms.** Learning-only text sits in whole-line arms in a host or in a partial it expands: `learning:on` (kept only by the learning-on build), `learning:off` (kept only by the off build; directly after an `on` arm it is that arm's else, alone it is an off-only arm) and `learning:end`. They are legal inside a fence, a list, a define body or an agent's second frontmatter block, because MDS passes an HTML comment through untouched. A marker line is removed whole and every other line is kept byte for byte, so the blank line a paragraph needs lives inside its arm or the other variant gets a doubled one. A numbered step that loses an item gets its later numbers as on/off pairs. A second `off`, an `end` with no open arm, an unclosed arm, an arm with no content line and a malformed marker (mid-line, `<!--learning:on-->` without its spaces, wrong case) each fail the build. `tests/learning/learning-variants-arms.test.ts` also checks that no status-line sampler anchor sits inside an arm. `LEARNING_VARIANT_HOSTS` is held in both directions by the printed variant count, the files under `dist/learning-off/` and the packed tarball set, so an arm without a roster row (or a row left after its arm goes) turns one red. The markers exist because MDS 0.4.4 emits a native conditional inside a code fence or on an indented line as literal text (its lexer needs column 0), exactly where the arms must sit. They are replaced one to one, and `learning-variants.ts` deleted, once mdscript ships fence- and indent-aware conditionals (dean0x/mdscript#452) and devflow upgrades (dean0x/devflow#439).

**KB-AP-3, body start.** A command host starts its body on the line right after its `@import` block; every fence kind is passthrough, so a blank line there reaches the output.

**KB-AP-4, verbatim moves.** Prose relocated out of `git.mds` and its skill body into a reference module carries the SOURCE file's grammar assumptions into a destination parsed by another: a generated reference is sliced by heading level and the op-marker regex, so a heading that was an ordinary section in one file can become a section terminator in another. Check moved text against the destination's grammar. The incident (the SKILL.md to `ensure-traceable-issue.md` case) lives in `tracker-references`. The structural remedy is `tests/tracker/reference-structure.test.ts`: every generated reference starts with its own `## Operation: {op}` anchor (or cross-cutting anchor) and has no further UNFENCED column-0 `## ` line. A fenced `## ` (a heredoc or a template fence a provider ships on purpose, such as `manage-debt.md`'s `## Items`) is exempt through the fence-aware `collectUnfencedH2` in `tests/helpers.ts`, because demoting those headings would change what the tracker renders. Every file also clears `MIN_REFERENCE_CHARS` (owned by `tests/tracker/reference-floor.ts`, imported by `reference-reachability.test.ts`, `linear-module.test.ts` and `jira-module.test.ts`); that thinness guard belongs to the tracker test suites, while the build's own `empty-section` refuses only a fully blank section.

**KB-AP-5, converting a prompt to a host.** The method that produced `git.mds`, `release.mds` and the other agent hosts was `git mv` plus the steering block (or a scripted fence-state-machine transform) plus `cmp` against the original or golden, never a fresh body. The oracle is `tests/fixtures/golden/git-agent.md`; `GIT_AGENT_BYTES` in `tests/goldens/git-agent-golden.test.ts` is derived via `stat`, never hand-typed, and goldens are regenerated only by `npm run test:golden:update -- git-agent` in a fixture-only commit. The compiler trims trailing blank lines, so a source ending in `\n\n` compiles to one `\n`; a byte-compare against an original that ended in a blank line differs by exactly that newline.

**Frontmatter key order and extra keys.** `build-mds.test.ts` asserts `output-dir:` is the last key in every command host's frontmatter; that is a style convention, since `stripBuildKeys` removes each build key line wherever it sits. Generator hosts and reference modules are exempt: their entire first block is a dedicated steering block, stripped WHOLE with no key-level filtering, so an extra key there is harmless but pointless.

**KB-INV-10, test scoping.** Every build spawned by `tests/build-mds-generator-hosts.test.ts` or `tests/build-mds.test.ts` is scoped to a temp `DEVFLOW_MDS_ROOT`, and each file's closing self-scan (`collectSpawnScoping`, with a known-bad probe and a non-vacuity floor) fails the file if a spawn is added without it. Whole-corpus assertions (the printed census, the dist-in-sync check, the compiled-command content guards) get their tree from `buildCommittedTree()`: `src/assets/{commands,agents,mds}` are copied into a temp root and built there, memoised per test file. Real-root builds were abandoned because PID-scoping closed the writer/writer clash but the writer/reader clash survived: a real-root build silently REPAIRS a stale `dist/` while parallel workers read it, so staleness surfaces as a flake in whichever reader lost the race. Without the env var the root falls back to the script's own location, so `cwd: <tmp>` walks and rewrites the real repo while the test asserts about a tree the build never opened.

**KB-AP-10, what the staleness check proves.** `dist/` is gitignored, so the check cannot compare against reviewed bytes frozen in git. It catches "src/ changed and nobody rebuilt", a hand-edited `dist/` and stale orphans, but not a `src/` change rebuilt before review. The original reviewed-bytes claim for the generator conversion lives only in a PR body (a claim, not re-runnable evidence), so it is carried forward only as long as `dist/` holds those bytes. The byte-compare recurses into `dist/skills/` and `dist/learning-off/` too (`hashDistTree` / `hashDistSubtree`, bounded), covering all output kinds with one property; it replaced a byte-idempotence test that proved only that the build agrees with itself.
