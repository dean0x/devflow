# Memory Worker

## Rules

- **KB-INV-1** The model writes ONLY `WORKING-MEMORY.md.new`; `verify_and_swap()` assigns exactly one outcome: `updated` (the worker's own stamp on a swap copy, note format met, matching `cksum`, atomic `mv`), `conflict` (`.processing` kept) or `failed` (`.processing` left for cold-path recovery; a format refusal is KB-INV-26).
- **KB-INV-2** A CAS conflict heartbeat-touches `.processing`, which extends the cold-path liveness window; the orphan gate skips when `.processing` already exists.
- **KB-INV-3** The worker's model and effort come from `agents.memory` in `agent-models.json` (shipped row `WORKER_AGENTS.memory`), each checked on its own; only a value that passed its match reaches argv.
- **KB-INV-4** A CLI version probe (`probe_claude_version`, run before the lock, bounded by `DEVFLOW_BG_VERSION_PROBE_SECS`) picks the run: below `MEMORY_MIN_PERMISSION_VERSION` none (`result=below-floor`, queue kept, no notice); below `MEMORY_MIN_CLAUDE_VERSION` the legacy argv; otherwise the lean argv. An unreadable version gets the legacy argv, never below-floor.
- **KB-INV-5** Write-only is safe only because the staged path is empty before every run: after the lock the worker clears a folder or link there (`memory_staged_remove`) and a stale file, and if anything still stands it logs `SKIP`, ends `result=failed` and runs no LLM with the queue unclaimed; the path is re-checked before the spawn.
- **KB-INV-6** The prompt carries everything uncut and goes by heredoc stdin, never argv: the bound is the row window and `MEMORY_NOTE_CAP_BYTES` for the old note, never a cut turn; each untrusted data block sits in an outer `data-<16 hex>` tag drawn per run, under a DATA-not-instructions preamble; no valid tag, or a tag found inside a block, skips the run with the batch kept.
- **KB-INV-7** A queue with no `assistant` or `qa` row exits with no LLM run and is LEFT in place (hooks of one event run in parallel); the next run takes the whole turn.
- **KB-INV-8** The outcome literals of `compute_commits_since_note()` are a test contract, and `cksum` must be on PATH or the worker exits (a `cksum` failure on the target forces `conflict`).
- **KB-INV-9** `CLAUDE_CODE_EFFORT_LEVEL` is unset before the spawn on both argv forms, while `DEVFLOW_BG_UPDATER=1`, `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1` and `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` stay set on both.
- **KB-INV-13** The worker's write is limited to its staged file by two Edit rules in `memory_settings_json` (allow `Edit(//<staged>)`, deny `Edit(//<staged>/*)`), `disableAllHooks`, `--permission-mode dontAsk` and `--setting-sources user`; the user's own allow rules, and their ask and deny rules on Edit, apply to the run too; one canonical staged path feeds the rules and the prompt.
- **KB-INV-14** `MEMORY_MIN_PERMISSION_VERSION` is held equal between the hook and `src/cli/commands/memory.ts` by `tests/memory.test.ts`, `devflow init` states it, and it never exceeds `MEMORY_MIN_CLAUDE_VERSION` (the worker exits 1 otherwise).
- **KB-INV-15** Each run ends with one `Run:` line (keywords and digits only) from the `finish_run` EXIT trap, written only where `own_pid()` equals the `WORKER_PID` taken at start (the worker, never a subshell); only the lock holder releases the lock.
- **KB-INV-16** `memory_staged_remove` deletes a folder or link at the staged path only after it proves the exact path, the memory dir on disk, no link on the way down and a listing within `STAGED_REMOVE_MAX_LISTING`; a link is deleted itself, never followed.
- **KB-INV-17** The CLI's JSON result is reduced by `memory_result_summary` to one fixed line of shape-checked fields; the denied calls' input and the result text are never read or logged, and its file is deleted on every path out.
- **KB-INV-18** A cause only the user can fix leaves a one-time notice (`path`; `denied` after two denied runs with no successful update between them; `note` after two refused notes, KB-INV-26; `path` also when a blocked refusal marker drops a batch) that `session-start-memory` shows once as `systemMessage`; a below-floor run leaves none; a paused memory area (KB-INV-24) neither leaves nor shows one.
- **KB-INV-19** `staged_path_safe` refuses only a path the rule text cannot carry (`chars`) and one under a `.git` folder (`protected`); a checkout under `.claude/worktrees` is updated.
- **KB-INV-20** With neither `jq` nor `node` the worker logs `SKIP: neither jq nor node on PATH` right after `trap finish_run EXIT` and exits 0 (`result=skip`), reading, claiming, merging and locking nothing (else the empty extraction removes the claimed batch): the queue and any `.processing` batch stay; the guard sits outside the span `tests/memory-worker-run-line.test.ts` cuts from `own_pid() {` to the trap.
- **KB-INV-21** The orphan check and the extraction parse each queue line alone: a malformed line drops only that line (a row cut off before its newline runs into the next row, and the two are one malformed line); both parsers emit a row only for a role of `user`, `assistant` or `qa` and a `content` that is a string, null, false or absent, so jq and node log the same `Skipped N queue line(s) that hold no readable turn`; the extraction reads the batch file itself, and a row older than the `MAX_LINES` window yields only its session ID (no turn text, no skipped count); a batch whose parser exits 0 with no row is removed with no LLM run; a last row with no line break counts as a row; the jq filter uses `split`, not `gsub`, so a jq built without its regex library still yields the rows.
- **KB-INV-22** A `jq` or `node` on PATH that exits non-zero on the queue (orphan check) or the batch (extraction) has said nothing about the turns: the worker logs `SKIP`, keeps the batch and the queue (on the leftover-batch path the queue is already merged into the batch), runs no LLM and exits 0 as `result=skip`; the status tested is the parser's own, never a pipe's.
- **KB-INV-23** The recovery merge writes a complete copy (`.pending-turns.processing.merge`) from the old batch and the claimed queue (`.pending-turns.processing.claimed`) and removes the old batch only after the copy is whole. If the merge stops, the next worker finishes it before it claims new rows, so no row repeats and no false multi-session mark is set. Each original row keeps its order. A batch that ends without a line break gets one before the first queue row. A read-only batch is processed alone and the queue is kept.
- **KB-INV-24** Anything but `untracked` from the memory area probe (`queue_tracked_area <root> memory`, `DF_TRACKED_AREA_MEMORY`: `tracked` or `unknown`) ends a memory hook or worker run with one fixed log line and exit 0, before it reads or writes in `.devflow/memory/`.
- **KB-INV-25** One constant, `MEMORY_NOTE_CAP_BYTES` (in `memory-permission`), bounds the note in three places: the worker's swap copy, its read of the old note, and the SessionStart load. A note over the cap is never loaded: the session gets one fixed line and the refresh banner when it applies. `MEMORY_NOTE_TARGET_BYTES` is the prompt limit, stated to the model in bytes (a letter outside A-Z takes 2 to 4 bytes), and it sits below the cap to leave room for the worker stamp (`tests/memory-worker-note.test.ts` pins the prompt text and a two-byte-letter note within the target).
- **KB-INV-26** The swap takes only a note with the `<!-- memory-head:` prefix on line 1, no null byte, no level-two section but `## Now` and `## Progress`, and a size within the cap. The worker writes line 1 itself (`memory_stamp_line`: its HEAD, branch and any multi-session mark) onto a `.WORKING-MEMORY.md.swap` copy (0600, `noclobber`) and moves the copy over the note. The staged model output is removed once the copy exists, and also when the copy cannot be written (the run is `failed`, the note and batch stay). A refused note leaves `.processing` and a `.worker-note-once` marker; in a run with no denial the second refusal drops the batch, logs `Batch discarded after two note refusals` and leaves the `note` notice, and a marker that is not a regular file (a folder, a FIFO, or a link on its path) counts as the second at once: the batch is dropped, the log says `Batch discarded: .worker-note-once is not a regular marker`, the `path` notice is left and the blocked marker stays. So a batch gets at most two runs. A swap clears both.
- **KB-INV-27** A memory-queue row may carry a `session_id` of 1 to 64 characters from `A-Za-z0-9_-` (a curation row never does). The worker pairs a prompt with a reply only on equal IDs (no ID is `.` and pairs only with `.`); an unmatched reply shows alone and the prompt stays pending. An ID that returns after another closed it marks the batch interleaved: the stamp gets `multi: <epoch>`, carried for `MEMORY_MULTI_SESSION_SECS` after the last interleave, and `session-start-memory` adds `more than one session` to the header while it is current.
- **KB-INV-28** The worker claims the queue under `<queue>.lock`, the lock the queue trim uses (`curation_lock_acquire`, a 2 s wait), after the staged and swap paths are clear and before the merge or `mv`. Without it the worker logs `SKIP`, claims nothing, runs no LLM and exits 0. The lock is released when the claim ends, never held across the model run; the exit trap releases it on any earlier exit. `session-start-memory` takes the same lock for its stale-batch recovery (KB-INV-29).
- **KB-INV-29** The cold path of `session-start-memory` moves a stale batch back to the queue only while it holds `<queue>.lock` (a short wait; no lock, no recovery) and no link sits on the lock path. It does nothing when a queue already stands or a claimed queue stands beside the batch (the worker owns that merge); if only the merge copy remains, that copy holds the whole batch and is moved back.
- **KB-AP-1** Widening the worker's tools, adding a flag that skips or pre-approves permissions, or adding a lean flag outside the version floor: the staged-file limit goes or every Write can fail with exit 0, and an unknown flag fails every run on an older CLI (`tests/guards/no-permission-skip-in-hooks.test.ts`, list in `tests/fixtures/forbidden-argv.ts`).
- **KB-AP-5** Deleting a queue whose assistant row has not landed yet: capture-prompt and capture-turn run in parallel.
- **KB-AP-6** Reading the `Spawning claude -p` line as proof of the effort a run used: a value set in a settings file's `env` is outside the hook's reach.
- **KB-AP-8** Writing the worker's rule as `Write(path)` or its deny as `Edit(//<staged>/**)`: a `Write(path)` rule is never checked and `/**` refuses the staged file too, so every Write fails while the run exits 0.
- **KB-AP-9** Writing the `Run:` line or releasing the lock outside the `own_pid`-guarded trap, guarding it with a bare `$$`, or answering `$$` from `own_pid` in a subshell: a signalled subshell gives a second line and a lock release by a non-holder.
- **KB-AP-10** Reading `denials=unknown` or an unreported count as zero denials: a result with no array of denials (`json_array_length_file` prints `unknown`) is not zero, and only a digit count above zero is a refusal that feeds the `denied` notice.
- **KB-AP-11** Looking for a project or local Claude settings file to change the worker's run (env, rules, provider URL): only the user's settings load, by design, and widening `--setting-sources` is not the remedy.
- **KB-AP-12** Cancelling a worker subshell with any signal but SIGKILL, or a group kill with no watchdog `sleep` before it: the source check in `tests/memory-worker-run-line.test.ts` fails, and a SIGTERM can run the exit trap in a subshell.
- **KB-AP-13** Taking the model's line 1 as the stamp, or letting a refused note reach `WORKING-MEMORY.md`: the stamp drives drift detection and the multi-session mark, so only the worker writes it, and a note over the cap would never load.
- **KB-AP-14** Pairing a prompt with the next reply whatever its session ID: a reply of another session lands in the wrong turn and the multi-session mark is never set.
- **KB-AP-15** Expecting a new install to run the memory worker: memory is off for a new install and after `--reset`; the manifest reader turns a manifest with no `memory` key into on once and heals it on disk, so an older install keeps its worker.

## Overview

The memory queue (`.devflow/memory/.pending-turns.jsonl`) is drained by the detached `background-memory-update` worker, started by `memory-worker` (which owns the throttle, keyed on the `.working-memory-last-trigger` mtime, and the nohup spawn). The worker turns the queued turns into `WORKING-MEMORY.md` through a headless `claude -p` run that makes one Write, and that write is limited to its staged file by permission rules built in the sourced `memory-permission` helper. The pre-compact backup, the first-note bootstrap and the jq-less JSON fallback that every hook sources are in the sibling KB named in Related. Rules IDs KB-INV-10 to KB-INV-12, KB-AP-2 to KB-AP-4 and KB-AP-7 moved there and are retired here. The capture hooks and the link rules are in the other KBs named in Related.

## Memory worker (background-memory-update)

`memory-worker` resolves `DEVFLOW_MANIFEST`, gates its spawn on it and passes the path as `$2` (`background-memory-update <CWD> [<manifest_path>]`; the worker re-checks after spawn and falls back to `$HOME/.devflow/manifest.json`). The model writes ONLY `WORKING-MEMORY.md.new`; `verify_and_swap()` assigns one outcome:

- `updated`: the format checks of KB-INV-26 and matching pre/post `cksum` give an atomic `mv` of the swap copy, remove `.processing`, touch `.last-refresh-ok` and clear the `denied` and `note` counts.
- `conflict`: mismatch or failure (a `cksum` failure included), or a link or a non-file on the working memory path during the run (D-HOOKS-NO-SYMLINK): `.processing` kept with a heartbeat touch.
- `failed`: staged file missing or empty, a refused note (the first leaves `.processing`; the second drops the batch), a swap copy that could not be written (the staged file is removed then), or `mv` failed: `.processing` left for cold-path recovery.

**Model, effort and argv (D-MEMORY-WORKER-LEAN).** The worker opens a headless session to make one Write, so the session is cut to what that Write needs.

- **Model and effort.** `agents.memory.model` and `agents.memory.effort` in `$HOME/.devflow/agent-models.json` (set with `devflow agents`) decide the run. Each is read with `json_string_field_file` (only a JSON string counts) and checked on its own. The model is `default`, an alias (`haiku sonnet opus fable`) or a `claude-` name of the `MODEL_NAME_RE` shape (`src/core/agent-frontmatter.ts`); the effort is `default` or a level (`low medium high xhigh max`). `inherit` and external models are outside both domains, since a worker has no session to inherit from. Only a value that passed its match reaches argv: an absent, empty or non-string value silently takes the shipped one, and a string that fails logs one line naming the field, never the value. The character sets are spelled out because a range such as `A-Za-z` collates by locale on bash 3.2. `tests/agent-models-worker.test.ts` holds the hook's literals equal to `agent-models.ts` (see the `external-model-routing` KB).
- **A CLI version probe picks the run.** Before the lock is taken, `probe_claude_version` runs `claude --version` under `DEVFLOW_BG_VERSION_PROBE_SECS` (a default and a ceiling; background-and-kill like the watchdog, TERM then KILL to the process group), so a hung probe cannot extend the lock's hold. `claude_version_parsed` is the one version parser (the first `X.Y.Z` as base-10 numbers; a component over six digits is no version): the run's CLI version and both floors read through it. A version below `MEMORY_MIN_PERMISSION_VERSION` (the lowest version on which the staged-file limit below was measured) ends the run before the lock and the claim: `Run: cli=<version> argv=none result=below-floor ... floor=<floor>`, the queue kept, no notice, so its only trace is the `Run:` line. From that floor up to the lean floor the argv is the legacy one; at or above `MEMORY_MIN_CLAUDE_VERSION` the run takes the **lean** argv: `-p --model M --effort E --safe-mode --tools Write --disable-slash-commands --strict-mcp-config --mcp-config '{"mcpServers":{}}' --max-turns <cap> --permission-mode dontAsk --setting-sources user --settings <json> --output-format json` (pinned in `tests/eager-memory-refresh.test.ts`). When the probe fails, hangs or prints no version, the **legacy** argv is `-p --model M --tools Write --permission-mode dontAsk --setting-sources user --settings <json> --output-format json`: no effort is applied, MCP servers stay loaded and there is no turn cap, because one flag an older CLI does not know fails every run. The `Spawning claude -p` log line names the model, the effort (or `no effort passed`) and the form.
- **One argv array, one `exec` line.** The worker enters the project root in the main shell before the fork: a root it cannot enter logs `FAIL: could not enter the project root`, starts no claude and leaves the batch in `.processing`. `CLAUDE_ARGV` holds the flags both forms share and the lean form adds its own; one `exec` line runs it in a subshell under `set -m`, so claude keeps the subshell's PID as its process group's leader and the watchdog signals the whole group.
- **The write is limited to its staged file (`memory-permission`).** `memory_settings_json <staged>` prints the `--settings` JSON, and prints nothing for a path `staged_path_safe` refuses, so a rule is never built for an unchecked path. It holds two Edit rules and `disableAllHooks`: an allow rule `Edit(//<staged>)` for the file and a deny rule `Edit(//<staged>/*)` for every path under it, because the allow alone also matches paths under the file. Under `dontAsk` a call no rule allows is refused, never asked. The rule matches a path as it resolves on disk, so the worker resolves the project root once (`cd -P`, `pwd -P`) and every path below it, the prompt's staged path included, is built from that one canonical root. `--setting-sources user` loads the user's own settings only: their `env`, their allow rules (one that covers other paths covers the worker too) and their ask and deny rules on Edit apply to the run, while a project's or a local Claude settings file never reaches it.
- **What the lean flags buy.** `--safe-mode` turns off the user's instruction files, skills, plugins, hooks, MCP servers, custom commands and agents, while auth, model selection, built-in tools and settings `env` (the provider URL and key of a routed or keyed install) still apply. `--tools Write` leaves Write as the only tool. The turn cap is the worker's one Write and end of turn plus a margin; a run that hits the cap exits non-zero and its batch stays for the retry. `CLAUDE_CODE_EFFORT_LEVEL` is unset before the spawn because an inherited value beats `--effort`; `DEVFLOW_BG_UPDATER=1` is the capture hooks' recursion guard.
- **The prompt carries everything, uncut.** The model cannot Read, so the existing working memory (read up to `MEMORY_NOTE_CAP_BYTES`; a longer note is cut back to its last whole line, and its old stamp line is dropped from the prompt and used only for the multi-session mark) and the newest queue rows (`MAX_TURNS` turns, `MAX_LINES` rows) arrive in the prompt; the queue holds every turn whole by design, so no byte cap applies to the turns block. The prompt states the note target in bytes and asks for room for the stamp (KB-INV-25).
- **Staged-path precondition (SKIP).** After the lock the worker calls `memory_staged_remove` for a folder or link at the path, then `rm -f` for a stale file and a stale swap copy, and then checks that nothing still stands there (`path_occupied`: a file, a folder or a link, a dangling link included). If the removal is refused or something still stands (the swap path too; a link on it skips the run), it logs `SKIP: …` (with the refusal keyword), sets `result=failed`, leaves a `path` notice and exits 0 before claiming the queue: no LLM run, the batch and queue untouched. Just before the spawn the path is checked once more: a file or link there, or a link on its way, logs `SKIP` and leaves `.processing` for recovery, and only a pass clears a stale `path` notice. Write refuses an existing file that has not been read and a Write-only model cannot read one, so with the path occupied every Write errors while the run exits 0; with it empty the one Write is a create.
- **The memory area probe (`probe_memory_area`).** `session-start-memory` and `pre-compact-memory` probe in `node` mode, `memory-worker` in `git` mode after its throttle and before the touch, and `background-memory-update` on the unresolved-root path, after the switch re-check and after the `claude -p` run, each ask fresh. The worker's probe runs `queue_tracked_area <root> memory git` in a `set -m` subshell that answers by exit status (10 `untracked`, 11 `tracked`, else `unknown`), and a watchdog (`sleep`, one `kill -KILL -"$pid"`, cancelled by `kill -KILL`) cuts it after `DEVFLOW_BG_AREA_PROBE_SECS` (default 5, 1 to 60); a cut probe reads `unknown`. A pause before the run logs `SKIP: the memory area is paused ...` and exits. A pause after the run sets `result=skip` and exits with the batch left in `.processing`: no swap, stamp or denied marker. The Stop hook's own probe has no time bound.
- **The guarded removal (`memory_staged_remove <memory dir> <root> <staged>`).** It deletes a folder or a link at the staged path with one delete of exactly that path, and only after it proves, in order: `args` (all three absolute), `path` (exactly `<memory dir>/WORKING-MEMORY.md.new`), `parent` (the memory dir is `<root>/.devflow/memory`, as a string and again on disk through `cd -P`), `link` (no link on the way down from the root, `df_no_symlink_below`), `size` (a folder lists within `STAGED_REMOVE_MAX_LISTING` lines of `ls -RA`) and `rm` (`path_occupied` finds nothing there afterwards). A link goes as the link (`rm -f`), so what it names is untouched. The first fact it cannot prove becomes `STAGED_REMOVE_REFUSAL`; `STAGED_REMOVED` (`dir`, `link` or `none`) becomes the `removed=` field. A regular file, or nothing, returns 0 untouched (the caller removes a stale file itself). It runs before the spawn and again after the CLI exits: a folder or link standing there then was put there during the run, is removed the same way and the run is `failed`, or, if refused, stays and the next run stops at the pre-run guard. The checks and the delete are separate steps, so a process that swaps something in between is not stopped; such a process already runs as the user.
- **One `Run:` line per run, and the CLI result reduced to a fixed line.** `finish_run`, the EXIT trap, logs `Run: cli=<X.Y.Z|unknown> argv=<lean|legacy|none> result=<updated|conflict|failed|skip|below-floor> denials=<digits|unknown|n/a> removed=<none|dir|link>`, then removes the result file and, only when `LOCK_HELD`, the lock. It acts only in the worker process: it returns at once unless `own_pid` equals the `WORKER_PID` taken at start. `own_pid` answers `BASHPID` when set (bash 4+), else the `$PPID` a child execing `/bin/sh` reports; a failed or non-numeric read falls to `BASH_SUBSHELL` (0 gives `$$`, above 0 a value that never equals `WORKER_PID`). So a subshell never writes the line or releases the lock. The fields start as "no CLI read, no run"; the spawn sets `result=failed`, so any way out other than the end of the script is a failed run, and `verify_and_swap` sets the final result. The CLI's stderr goes to the worker log and its JSON to a `mktemp` file; if none can be made the log says `Result not captured` and the run goes on without a count. `memory_result_summary` reads only `permission_denials` (through `json_array_length_file`), `subtype`, `is_error`, `num_turns` and `api_error_status`, each held to its own shape and `MEMORY_RESULT_*` cap (`_memory_field_within`), and, only when claude started and a result file exists, logs `Result: <subtype>, is_error=.., N turn(s), N permission denial(s)[, api_status=..]` or `Result: not reported (empty|unparseable|no parser)`; a field that fails its check reads `unknown` (a status code is left out). A denial count above zero goes through `record_denied_run`, which logs `FAIL: Write denied by permission rule (N)` (with the exit code when the CLI exited non-zero) and counts the run toward the `denied` notice.
- **The one-time notice (`memory_notice_*`).** A cause only the user can fix leaves `.worker-notice-<reason>` in the memory folder: `path` when the root cannot be resolved, the staged path is refused (`chars` or `protected`) or whatever stands on it or on the swap path could not be removed; `denied` on the second denied run with no successful update between the two, and `note` on the second refused note (`memory_refusal_seen <dir> <root> denied|note` leaves `.worker-<reason>-once` after the first and sets `MEMORY_REFUSAL_COUNT` to `first`, `second` or `none`, and for `note` to `blocked` when the marker path is occupied by anything but a regular file with no link on its path; a run that ends `updated` clears both). A `blocked` count with no denied result drops the batch and leaves a `path` notice, never a `note` one, because the user must clear the marker path (KB-INV-26). The create is exclusive, only where no link sits on the way down and `path_occupied` finds neither the notice nor its `.shown` marker. `memory_notice_clear` removes them once the cause is gone: `path` after the pre-spawn checks pass, `denied` on an `updated` run. `memory_notice_text` is the one reason-to-message map. `session-start-memory` runs `memory_notice_read` and passes the message as the `systemMessage` of the session envelope, beside the context and never in it, whether or not a working memory is injected; the notice then moves to `.shown`, so a reason shows once, and one whose content does not fit its reason is moved unshown and logged.
- **The staged-path check (`staged_path_safe`).** The rule text carries no quoting, so a path with a character that means something in a rule path (`* ? [ ] \ " { }`, a control character) or a segment the rule cannot carry (not absolute, a leading or inner `//`, an empty, `.` or `..` segment) is refused as `chars`: a project path holding one gets no memory updates and one `path` notice, a known limit. `(` and `)` are carried as they are in both rules. A path under a `.git` folder is refused as `protected` and the worker skips that project with a logged reason (the only folder it skips).

**Link refusals (D-HOOKS-NO-SYMLINK).** `memory-worker` checks the throttle stamp's path first: a link on it gets no stamp and no spawned worker (`SKIP`, logged). `background-memory-update` checks the lock, queue, batch, `.last-refresh-ok` and `WORKING-MEMORY.md` paths together before it takes the lock or starts an LLM run, and skips the whole run when any has a link on its path; the existing working memory then reaches the prompt only through `df_file_below`, and `verify_and_swap` refuses the swap (`conflict`, above) when a link has appeared on the working memory's path since the run began, because `mv` would move the staged file into the folder the link names. The post-run stamps (`.last-refresh-ok` on `updated`, the batch heartbeat on `conflict`) are checked again before each `touch`, which follows a link; a refused stamp is skipped and logged.

**Leftover batch and the queue lock.** The merge or `mv` claim runs under the queue lock of KB-INV-28, so a capture hook's queue trim cannot overlap it. The merge never edits the old batch in place: it moves the queue to `.pending-turns.processing.claimed`, writes the whole `.merge` copy (batch, a line break if it lacks one, claimed rows) under noclobber at 0600, removes the old batch (that removal commits the merge) and renames the copy to the batch name. A merge that stops leaves the files it needs, and the next worker finishes it first (KB-INV-23), so no row repeats and no false multi-session mark follows. A path of the merge that is not a regular file ends the run with `SKIP`. `session-start-memory` recovers a stale batch under the same lock (KB-INV-29). Over the queue's line bound the batch is trimmed to the newest rows through a copy made by the safe-create rules of the links KB (a planted entry is removed and never opened, the batch stays untrimmed and the log says `Processing overflow: not truncated`) and renamed over it, so the batch stays 0600: the cold path moves a stale batch back into the queue.

**D-QUEUE-NO-ORPHAN-DELETE** (KB-INV-7, KB-AP-5). The orphan check reads each line alone (`jq -R` with `fromjson` under `?`, so jq 1.5+; `JSON.parse` per line in node), so a malformed line plus a user row stays a user-only queue and is kept.

**A parser that fails keeps the turns** (KB-INV-22). Both parsers test their own status (`|| _PARSER_RC=$?`), and the orphan check takes its first output line by parameter expansion (`${var%%$'\n'*}`), since a `| head` would report `head`'s status. Exit 0 with no readable row is the other case: the batch is removed (`No parseable turns`).

**Neighbours of the queue.** `compute_commits_since_note()` yields five exact outcome literals that are a test contract (no-stamp full-synthesis, invalid-SHA-format, SHA-not-ancestor-of-HEAD, none-current-as-of-HEAD, `N commit(s)… (showing newest …)`, with subjects cut by `%.100s`). `is_hex_sha <value> [min=7] [max=40]` is sourced with no forks (pre-compact uses 40-40; its bootstrap of the first note and `session-start-memory`'s bounded note read are in the sibling KB); `session-start-memory`'s `detect_refresh_failing()` counts both `.pending-turns.jsonl` and `.pending-turns.processing` through `df_file_below`, and its cold path moves a stale batch back into the queue under the queue lock (KB-INV-29), only where `df_no_symlink_below` admits the paths.

## Anti-Patterns

- **KB-AP-1, widening the worker**: with Read given or the staged path occupied every Write can fail while the run exits 0. `--allowedTools` only pre-approves and leaves every tool, listing and MCP server loaded. A flag or mode that skips permission checks leaves the allow and deny rules nothing to enforce; the guard bans those spellings in every hook script, and `tests/eager-memory-refresh.test.ts` checks both argv forms against its list. The lean flags ride only on the argv the probe admits.
- **KB-AP-8, the rule's form**: the Write tool is checked by `Edit(...)` rules, so the allow and the deny are both `Edit` rules with `//` for an absolute path (a single `/` is relative to the settings source). An allow rule on an exact path also matches the paths under it (measured), so the deny is required; `/*` denies everything under the path and spares the file, `/**` does not.
- **KB-AP-9, the trap's guard**: see the `Run:` line bullet; bare `$$` is the worker's PID in every subshell, so it guards nothing. A worker that timed out on the lock never set `LOCK_HELD`, so it releases nothing.

## Gotchas

- **`is_hex_sha` bounds are call-site specific**: the worker and the backup hook call it with different length bounds.
- **KB-INV-26: a non-file refusal marker ends the retries.** Without the `blocked` count a folder or link at `.worker-note-once` would read as no marker and the same batch would be refused on every run. A run with a denied result keeps its batch instead, since the denial may be the cause.- **KB-AP-6: the worker's effort has one blind spot.** A value set in a settings file's `env` is outside the hook's reach (it unsets only an inherited `CLAUDE_CODE_EFFORT_LEVEL`) and was not measured, so a run's effort can differ from the one its `Spawning claude -p` line names.
- **A failed or version-less probe is the legacy argv, not an error.** It costs the tokens of a full session; the `Spawning claude -p` and `Run:` lines state which argv ran.
- **KB-INV-14: the floor lives in two places and one is parsed by a test.** `tests/memory.test.ts` reads `MEMORY_MIN_PERMISSION_VERSION` from the hook with a pattern that needs the declaration alone on its line, so a reformatted or indented declaration fails the test; `workingMemoryNote()` in `src/cli/commands/memory.ts` carries the same constant. Raise the floor only after re-measuring the staged-file limit on the new lowest version (`docs/reference/platform-assumptions.md`).
- **KB-INV-13: the canonical root.** A project reached through a link needs its resolved root in the rule; a root that cannot be resolved ends the run with `SKIP` and a `path` notice. Re-deriving the staged path from `CWD` elsewhere gives a prompt and a rule that name different paths.
- **KB-INV-13: a denied Write can look like a turn-cap failure.** On the lean form, refused calls use up `--max-turns` and the CLI exits non-zero, so the log reads `FAIL: Write denied by permission rule (N), exit <code>`; the count is what names the cause.
- **KB-AP-15: the memory default has two sources.** `FEATURE_DEFAULTS.memory` (`init-seed.ts`) is false, so a new install or `--reset` leaves the worker off (the init summary names `devflow memory --enable`). `readManifest` adds `memory: true` to a manifest with no `memory` key and heals the file once; a stored non-boolean still fails the read, and raw readers (`gate-level.ts`) need the stored boolean.
- **`memory-permission` runs under `set -e`.** Both hooks that source it are `set -e`, so its helpers follow the `set -e` rule of the links KB (an explicit `return`, predicates inside `if`).
- **KB-AP-12: a kill in the worker has one of two forms, because a test reads the source.** `tests/memory-worker-run-line.test.ts` scans the code lines. A kill that cancels one subshell is `kill -KILL "$VAR"`: a SIGTERM to a subshell still holding the exit trap runs `finish_run` there, SIGKILL runs no trap. A group kill (`kill -TERM|-KILL -"$VAR"`) sits on the line after a watchdog `sleep`, as the area probe's does. Any other code line with the word `kill`, a log string too, fails the test. The trap harness slices the worker from `own_pid() {` to `trap finish_run EXIT` (that block stays whole), and its failed-read case swaps `exec /bin/sh -c` for a missing shell (the read keeps that spelling). The many-workers run needs `DEVFLOW_RUN_LINE_STRESS=1`, which only the `macos-bash32-hooks` CI job sets.
- **Test pins on the worker's line numbers.** `tests/guards/heredoc-quoting.test.ts` lists the worker's two unquoted heredocs (the turns loop and the prompt) as `background-memory-update:<line>`; lines added or removed above them move those numbers and fail the guard until its list is updated.
- **The parser cases skip off CI.** The jq cases of S31 to S33 skip when `jq` is missing (with `CI` set a gate test fails instead). S32 fakes a failing parser with a shim that exits 3 only for a call whose arguments hold `PARSER_FAIL_ON`. The `macos-bash32-hooks` job runs `S17|S31|S32|S33|S34|REL-3a` of `tests/eager-memory-refresh.test.ts` under bash 3.2; S34 skips as root.
