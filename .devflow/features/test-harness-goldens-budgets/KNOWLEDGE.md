# Test Harness - Goldens, Numeric Floors, Byte Budgets

## Rules

- **KB-INV-1** A golden mismatch means the source is wrong, never the fixture: `loadGolden` never auto-regenerates, and CI never runs `test:golden:update`.
- **KB-INV-2** A fixture regenerates in a FIXTURE-ONLY commit that also re-sets the equality baselines pinning its size (`GIT_MD_LINES`, `GIT_MD_CHARS`, `TOTAL_CHARS`, `TOTAL_LINES`, `GIT_AGENT_BYTES`); split across commits the tree is red between them.
- **KB-INV-3** `github-status-lines.txt` is FROZEN: regenerating it needs `--unfreeze` AND a fresh explicit authorisation, and every authorisation granted so far is spent.
- **KB-INV-4** The equality baselines (`GIT_MD_*`, `TOTAL_*`, `GIT_AGENT_BYTES`, `FIXTURE_BYTES`, `FIXTURE_NEWLINES`) are asserted with `toBe` and are NOT registered in `numeric-floors.json`.
- **KB-INV-5** `extractStatusLines()` is content-anchored (`gitOp`/`between`/`singleLine`/`ref` over unique text anchors), never line-offset based, and reads every operation reference only from the closed `STATUS_LINE_REFERENCE_FILES` list, enforced in both directions.
- **KB-INV-6** A status-line sample whose lines are not one contiguous slice of their file is read in pieces (contract lines and step lines of the operation's one reference), rejoined in the original order, never merged into a slice that changes a fixture byte (D-STRADDLE-SPLIT).
- **KB-INV-7** `numeric-floors.json` holds two arrays with opposite directions: floors only RISE (bar a recorded, user-accepted lowering), ceilings only get LOWERED, and the two stay disjoint; moving an entry updates the source assertion and the manifest fields together.
- **KB-INV-8** Manifest entries are hand-registered, never scanned: automatic scanning would add floors for transient numbers and make the manifest untestable as a pinning device.
- **KB-INV-9** Loaded-set budgets are priced per path: one row per provider plus its own PR-host row, because `references/pr/` installs under every tracker and a per-provider fold would price one cost three times.
- **KB-INV-10** The body-hop closure follows every op a loaded body mentions to a fixed point (bounded by `CLOSURE_STEP_LIMIT`) and is default-deny: a mention no `INFORMATIONAL_OP_MENTIONS` row explains is a hop.
- **KB-INV-11** No single Git operation loads more than `git-op-load-max`: its one reference plus every reference it can name or hop to, less the written exclusion, under every provider; an over-cap operation is condensed, the cap never raised.
- **KB-AP-1** Never fold a golden regeneration into a prose commit, and never regenerate on every run: a golden that regenerates asserts nothing about the source.
- **KB-AP-2** A budget raised to fit the artifact is not a budget: ceilings never rise (the one recorded raise is `write-fence-allowlist-size`, on explicit maintainer authorisation) and a floor falls only as a dated, user-accepted exception written into its description.
- **KB-AP-3** A ratchet entry must not arrive a commit before the fixture-only regeneration that pins its new size: the entry and the fixture land together.
- **KB-AP-4** Parallel re-derivation of an equality baseline is how derived constants rot: re-derive from the fixture that already carries the number.
- **KB-AP-5** A `LOADED_SET_WRITTEN_EXCLUSIONS` entry means something only while it is still reached: pin the exact NAMED op pair that reaches it, never a count.
- **KB-AP-6** A sample read from a generated reference reads the BUILT file: after a source edit under `src/assets/mds/`, run `npm run build` before the fixture check can even run.
- **KB-INV-12** Every compiled command has a byte ceiling per build (`command-<name>-max`, `command-<name>-curation-off-max`) with no headroom; the table is set-equal to the compiled commands and a curation-off build never exceeds its curation-on build.
- **KB-INV-13** Text moved verbatim between files is pinned by length and SHA-256, never by `git show main:` (a shallow clone reads nothing); a deliberate later edit of a moved section updates its digest in the same commit.
- **KB-INV-14** `claude-md-max-chars` caps CLAUDE.md with no headroom; it keeps one-line invariants and a plain-path pointer to `docs/reference/architecture.md`.
- **KB-INV-15** A reference-size ceiling (`code-review-levels-ref-max`, `plan-levels-ref-max`, `validate-passed-alone-ref-max`) has no headroom: an edit of its reference lowers it to the measured size in `numeric-floors.json` and its source assertion together, and a reference that must grow cuts its own text. /implement and /resolve have no reference-size ceiling yet: the last change of the planned row-adding set registers `implement-levels-ref-max` and `resolve-levels-ref-max` at the measured size (an earlier one would block the later changes).
- **KB-AP-7** Never split a moved reference on `\n## `: a `## ` line inside a code fence is text, so use `commandReferenceSections()`.
- **KB-AP-8** Never reword, drop or shadow a `resolve.mds` or `dynamic-build.mds` line the frozen status-lines fixture samples by first occurrence: only an `--unfreeze` authorisation could re-derive it.
- **KB-INV-16** A command or agent-body ceiling (`validate-body-max`) is lowered last: the cuts that pay for added text land first in their own commit with before and after byte counts per build, then the text, then the ceiling.
- **KB-INV-17** Every fenced spawn (`Agent(subagent_type="X"` or `agentType: "X"`) of /implement and /resolve is pinned by sha256 in `PINNED_FENCES`; a deliberate edit repins only the changed rows.

## Overview

Three families of pinned numbers live here. **Goldens** are committed fixtures asserting that file content stays stable ("a golden mismatch means the source is wrong, never the fixture"). **The numeric-floor manifest** (`tests/fixtures/numeric-floors.json`) is a hand-registered ratchet of pinned numbers. **The byte budgets** (`tests/tracker/byte-budget.test.ts`, priced by `tests/tracker/budget-model.ts`) cap what a spawn loads, and the command size ceilings cap what a command costs the main session. Digest pins on text moved verbatim sit beside them. The conventions they share are in `test-harness`.

## Goldens Lifecycle

**Fixtures and equality baselines:**

- `tests/fixtures/golden/git-agent.md` byte-equals the resolved `git` agent (dist-preferred). Its baselines are `GIT_MD_LINES`, `GIT_MD_CHARS`, `TOTAL_CHARS` and `TOTAL_LINES` in `tests/goldens/github-status-lines.test.ts` and `GIT_AGENT_BYTES` in `tests/goldens/git-agent-golden.test.ts`. Splitting the providers' mechanics out of the Git agent did not move the frozen status-lines fixture; folding every operation's contract into its one reference did (the ninth re-capture, below). The fixture regenerates in a FIXTURE-ONLY commit, never folded into a prose commit, and that commit also re-pins both test files; the golden test's own failure message says to move `GIT_AGENT_BYTES` in the SAME commit as the fixture, or the tree is red at that boundary.
- `tests/fixtures/golden/github-status-lines.txt` equals `extractStatusLines()` output; its baselines are `FIXTURE_BYTES` and `FIXTURE_NEWLINES`. It is **FROZEN**: regenerating it needs `--unfreeze` AND a fresh explicit authorisation. Nine have been granted and **all nine are spent**: the extractor retarget (2026-09-14), two `**Mechanics:**` pointer lines (2026-09-15), Refs #350 nine lines (2026-09-20), Refs #359 two of four granted lines (2026-09-24), Refs #352 the check-ci-status bucket-classification lines (2026-09-25), #389 line 241, the Code agent's D11 scrub path (2026-09-27), #383 four lines, the legacy escapes the MDS 0.4.4 migration removed (2026-09-28), #411 line 207, reply evidence that no longer lists ledger IDs (2026-10-03), and #451 ten deleted lines, the `**Process:**` labels and `**Mechanics:**` pointers the Git agent's operation sections no longer carry, deletions only (2026-10-12). Changes that only reach `git-agent.md`, sampler retargets that change how a sample is read without changing any sampled line, and source edits that leave every sampled line alone (the script-run rewrite of the `update-pr-evidence` and `check-merge-readiness` references, the condensing of `resolve.mds`) spend none: the fixture still re-derives byte for byte. The frozen PR-body samples (the guidance table, the Related Issues row, the D11 scrub directive) are read byte for byte from `ensure-pr-ready`'s reference and spend none.
- `tests/fixtures/golden/install-snapshot-{github,jira-hipaa,all-off}.txt` and `hook-matrix.txt` are not frozen, but move only through `npm run test:golden:update -- install-snapshot` in a fixture-only `test(snapshot):` commit; see `test-harness-prompt-install`. A new installed skill reference adds one line to each of the three (each gate-level reference did), two when its folder is new (`validate/passed-alone.md` did).

**Regeneration protocol.** `npm run test:golden:update -- git-agent` runs `scripts/update-golden.ts` (tsx); the script resolves `git.md` through `resolveAgentSource` and logs the `origin` field. A named target is required (`git-agent`, `github-status-lines`, `install-snapshot`). `npm run test:golden:update -- github-status-lines --unfreeze` regenerates the frozen fixture and is refused without `--unfreeze`; `--out-dir` exercises the script safely against a temp directory. `install-snapshot` accepts `--only <config>[,<config>]`.

**Frozen-fixture refusal re-derivation.** The `--unfreeze --out-dir` refusal test re-derives `github-status-lines.txt` byte-for-byte into a temp directory on every `npm test`.

**`extractStatusLines()` is CONTENT-ANCHORED, not line-offset based.** It locates each excerpt with unique text anchors rather than hard-coded line numbers, through these helpers:

- `gitOp(opName)` extracts a named operation section from that operation's one reference (`operationReferenceRel(op, 'github')`, read through the closed-list reader), routed through `extractOpSectionFromCorpus` in `'sole'` mode over a one-entry corpus.
- `between(src, startAnchor, endAnchor)` extracts content between two text anchors (multi-line anchors supported).
- `singleLine(src, anchor)` extracts the single line containing an anchor.
- `ref(relPath)` reads a generated reference through `compiledSkillRefsDir()`, refused for any path not on `STATUS_LINE_REFERENCE_FILES` via the type predicate `isStatusLineReference`.

`extractStatusLines(gitContent?)` accepts an optional `gitContent` so callers can supply an alternative `git.md` body.

**Generated references and the closed reference list.** `STATUS_LINE_REFERENCE_FILES` is the closed list of generated references the corpus samples: `learn-conventions.md`, `publication-gate.md`, the `pr/{op}.md` files for `check-ci-status`, `check-merge-readiness`, `fetch-review-threads`, `post-resolution-summary`, `post-review-summary`, `resolve-review-threads` and `validate-branch`, and the `tracker/github/{op}.md` files for `backlink-shipped-issues`, `create-release`, `ensure-pr-ready`, `ensure-traceable-issue`, `fetch-issue`, `fetch-issues-batch`, `gather-release-evidence`, `manage-debt`, `post-wave-report` and `setup-task`. Both directions are enforced: `ref()` refuses a path not on the list, and `extractStatusLines()` refuses to return unless every declared entry was actually read (declaring an unread entry trips the unread-entry refusal).

**D-STRADDLE-SPLIT: a sample made of several pieces is read piece by piece and rejoined in the original order, never merged into one slice that would change a fixture byte.** The Git agent carries no operation section, so every piece comes from the operation's one reference (there is no retained half in `git.md`); the pieces exist because the sampled lines are not one contiguous slice of the file:

- `manage-debt`, `learn-conventions`, `check-ci-status` and `fetch-review-threads`: a contract line or block (the D4 clause, the `**Input:**` line, the `**Output:**` header; `gitOp(op)`) and a step range (`ref(path)`) of the same reference.
- `resolve-review-threads`: three reads of `pr/resolve-review-threads.md` (steps 1-2, step 3 applying the D9 gate, step 4), in the step order a spawn executes. D9 is defined once in the marker registry and applied here, in the contract block and in step 3.
- `gather-release-evidence`: the Input line, the D4 clause and the `**Output:**` label from the contract, and steps 1, 2, 3 and 5, each one line read by its own anchor because the provider's own steps sit between them, rejoined in step order.
- `post-wave-report`: the dedup line and the compose opener are read separately and rejoined with the original single newline, because the provider-neutral step 2 sits between them.

**Safety map for `git.md` / generated-reference editors.** `git.md` is sampled only for the D4 degradation contract and the D11 scrub rules. Every operation sample, the `**Input:**`, `**Output:**` and D4 lines included, is read from that operation's BUILT reference, and the remaining samples read lines of the `dynamic-build.mds` and `resolve.mds` sources, each by first occurrence of an anchor (for `resolve.mds`: two diagram lines, the `gh/GitHub absent` edge-case row and the Tracked and manage-debt DEGRADED lines), held unique by `tests/evidence/resolve-refresh.test.ts` and `tests/dynamic/wave-flow.test.ts`. So a source edit under `src/assets/mds/tracker/` or `src/assets/mds/git/` needs `npm run build` before the fixture check can even run.

**Sanctioned post-capture source fix procedure:** source fix commit, then `npm run build`, then a fixture-only re-capture commit that carries the baseline and ratchet updates pinning its new size (see Rules).

## Numeric Floor Manifest (numeric-floors.json)

`tests/fixtures/numeric-floors.json` (DR-27a) is an occurrence-aware, hand-registered manifest of pinned numbers, held in **two arrays with opposite directions**:

- `floors` may only RISE; the one way down is a recorded exception (see "Recorded floor lowerings" below). A floor pins a minimum the corpus must keep meeting as it grows.
- `ceilings` may only be LOWERED, never raised. A ceiling pins a maximum; the rule is that a budget raised to fit the artifact is not a budget.

Both arrays share one mechanism, enforced by `tests/guards/numeric-floor-manifest.test.ts`: each entry records `id`, `floor`/`ceiling`, `pattern`, `occurrences`, `sourceFile` and `description`. To move an entry, update both the assertion in the source file AND the manifest fields together, and only in the permitted direction. Floors and ceilings stay disjoint, and entries are hand-registered, never scanned (see Rules).

**Floor entries of note.**

- `partial-count` pins `ALL_MDS_PARTIALS`; `dist-host-count` and `dist-files-count` pin the compiled-hosts and `DIST_FILES` assertions of the same file, each pattern naming its own receiver (roster definitions are in `test-harness`).
- `issue-capture-contract-size` counts the KEYS of `ISSUE_CAPTURE_CONTRACT` (the check itself ranges over `(key, op)` pairs).
- `manage-debt-archive-cap` (the 60000-character body cap, `tests/git-agent.test.ts`) has an `occurrences` field that counts: the manage-debt archive threshold, the post-wave-report cap, each summary op's `'union'` positive assertion PLUS its `sinkCorpusWithoutPrHost()` known-bad probe (the literal appears negated too, in a `.not.toContain('60000')`, and the pattern is a substring of both forms, which is why the probes count), and the containment negative arm's in-scope witness.
- `generated-reference-manifest-size` / `packed-reference-manifest-size`: the GitHub, Jira and Linear ops (`TRACKER_OPS`) plus the PR-host ops (`PR_HOST_OPS`) plus the cross-cutting documents (`GIT_CROSS_CUTTING_DOCS`) plus the two contract documents (the tool-call contract and the tracker contract). `capability-hoist-block-floor` counts the process blocks of the generated tree only (the `learn-conventions` block, one per op per provider, and the PR-host blocks), because the agent body holds none; the guard asserts that by provenance.
- `installed-reference-count-github` / `installed-reference-count-provider`: since every install carries every provider's tree, the PR-host tree, the cross-cutting documents and both contract documents, whatever the machine selected (D-INSTALL-ALL-PROVIDERS), both ids pin ONE shared constant, `INSTALLED_REFS` (`tests/mds-variants.test.ts`), equal to the build's reference manifest size.
- `min-reference-chars` (`tests/tracker/reference-floor.ts`) and `min-fenced-h2` (`tests/tracker/reference-structure.test.ts`) are harness-owned; `min-fenced-h2` ranges over `PER_OP_REFERENCES` (every Git operation, under every provider for a tracker op), not tracker ops alone, because every per-op reference is extracted the same fence-aware way, `pr/` files included.
- `git-agent-remote-io-ops` (`tests/git-agent.test.ts`) is AC-0.6b's REQUIRED_OPS remote-I/O detection count over `operationReferencesCorpus()`. It replaces a bare `> 0` non-vacuity check, which one detected op satisfies and which therefore could not have caught the detection corpus silently narrowing. The D4-evidence half of the same guard reads the same per-operation references; only the generic D4 contract stays in `git.md`.
- `issue-pr-link-pr-open-sites` (`tests/seams/pr-link-handoff.test.ts`) counts the PR-opening Git `ensure-pr-ready` spawns that pass `ISSUE_PR_LINK:` themselves (today /implement's Phase 9; the wave forwards through `PR_WAVE_BLOCK`). It is the non-vacuity floor of the relational guard that a workflow capturing the link forwards it to its PR-opening spawn, beside an exact-0 guard that no Code spawn carries `ISSUE_NUMBER`, `ISSUE_PR_LINK` or `PR_EXCEPTIONS`.
- `containment-issue-body-floor` and `containment-external-thread-floor` are two floors rather than one shared ops floor, so neither named set can pass on the other's count.
- `agent-roster-count` pins `resolveAllAgents()`'s size (the registry's agent count, the hook-spawned Tracker included), and `report-cap-roster-count` the report-cap roster derived from it.
- The prompt-doctrine rows (`gate-ownership-body-count`, `report-cap-roster-count`, `running-commands-site-count`, `spawn-no-model-agent-type-floor`) are described in `test-harness-prompt-install`. `charter-char-max` is not a floor: it is a maximum, so it sits among the ceilings.
- **Recorded floor lowerings.** A floor falls only as a deliberate, user-accepted exception, written into the entry's description as `LOWERED a -> b by #N (a deliberate exception to "a floor may only rise")` with the old value, why no coverage went, and the date (2026-10-12 for the first three groups below, 2026-10-13 for the last). The reference-manifest sizes (`generated-reference-manifest-size`, `packed-reference-manifest-size`, `installed-reference-count-github`, `installed-reference-count-provider`, one shared manifest) fell 48 to 47 when `pr/ensure-pr-ready.md` folded into the per-provider files; `capability-hoist-block-floor` fell 63 to 42 when the agent's `**Process:**` blocks and that file's block left with the operation text; `requires-closure-token-floor` fell 44 to 41 when three skill names left the corpus with the Code agent's Step 0 text; `d11-posting-ops` fell 9 to 8 and `seam-ops-with-callers` 14 to 12 (#455) when `update-pr-evidence` and `check-merge-readiness` moved from a Git spawn to `verify-evidence.cjs publish` / `readiness`: both operations stay defined and route to the same script, so one reference lost its `--body-file` posts and two operations their caller fences, while the scrub-before-post check runs against the script (`tests/evidence/update-pr-evidence.test.ts`). Where the measure itself changes, the old id is retired and a new one registered instead of moving it (`issue-pr-link-pr-open-sites` and `git-op-load-max` are such registrations).

**Ceiling entries of note.**

- The git.md-carrying rows (`budget-git-md`, `budget-loaded-set`, `budget-loaded-set-jira`, `budget-loaded-set-linear`, `budget-loaded-set-pr-host`) are re-derived DOWNWARD whenever a cut shrinks the agent or an operation's reference, each set at the measured size plus a general headroom. A commit that moves the artifact without its ceiling changes the headroom, so re-measure (`npm run build && npx vitest run tests/tracker/byte-budget.test.ts` prints every row) before quoting one; the byte-budget KB carries the derivation. Each tracker row carries the tracker contract once per spawn (`contractTerm`); Linear's is the largest.
- `budget-loaded-set-pr-host` is its own row (D-LOADED-SET-PER-PROVIDER, KB-INV-9). Formula: preloaded set + `max over PR_HOST_OPS of (chars(pr/{op}.md) + every reference that op's own reference names)`, with no separate `max_op` term since a PR-host op's own reference is already inside its one-spawn load. `PR_HOST_OPS` excludes `ensure-pr-ready`, a tracker operation with one reference per provider. It carries ONE written exclusion, `references/github-api.md` (`LOADED_SET_WRITTEN_EXCLUSIONS` in `tests/tracker/budget-model.ts`), proven load-bearing by a companion test and RECORDED (never hidden) as the `2c-ex` shape in the printed shape table.
- `git-op-load-max` (`worstCaseOpLoad()`, `opLoadRows()`) is KB-INV-11's cap, measured under every registered provider and ranging over every operation, not only the PR-host ones, because an operation's contract and steps are one file. It is the measured worst operation (Linear's `setup-task`, which hops into `ensure-traceable-issue` under `ISSUE_REQUIRED`) plus the general headroom.
- `budget-skill-md`, `mcp-contract-max-chars`, `preamble-max-lines` (scoped to the compiled `tracker/_contract.md`) and `tracker-section-max-chars` are plain ceilings; `claude-md-tracker-block-max-chars` measures the Tracker block in `docs/reference/architecture.md`, where it moved word for word.
- **Command byte ceilings (D-CMD-SIZE).** A command is the main session's standing context, re-read from cache on every turn, so `tests/guards/command-size.test.ts` holds a `COMMAND_MAX_BYTES` row per compiled command and build: `command-<name>-max` for `dist/commands/<name>.md`, `command-<name>-curation-off-max` for `dist/curation-off/commands/<name>.md`; a row's text is the `pattern` of its manifest entry, and the entry's `description` in `tests/fixtures/numeric-floors.json` names the pass that set it. They sit at the measured sizes, with no headroom, and are lowered by a pass that cuts text, never raised: a command that needs more bytes first moves a rare branch to a reference (D-CMD-REF-HAND) or condenses text a line of the same command already states, cuts first (KB-INV-16). The gate-level pass (#480) paid for the /implement and /resolve level blocks that way. The guard also holds /implement, /resolve, /plan and /code-review below the size `main` held before the trim (`MAIN_BYTES`).
- **`claude-md-max-chars`** (`CLAUDE_MD_MAX_CHARS`, `tests/docs/claude-md-tracker-section.test.ts`; D-CLAUDE-MD-RULES-ONLY): a new invariant is paid for by cutting another line.
- Maximums that are not budget rows: `charter-char-max` (the orchestrator charter's character count, 75% of the hook's 4,096-character cap), `arguments-once-max` (`$ARGUMENTS` placeholders per compiled command), `code-preload-max-bytes`, `fix-preload-max-bytes` and `refactor-preload-max-bytes` (the preloaded skill files of each Code variant, with a curation-off arm in `code-preload.test.ts` whose total is the on total less `apply-decisions`), `code-body-max`, `fix-body-max` and `refactor-body-max` (the compiled Code variant bodies, `code-operation.test.ts`), `synthesize-body-max`, `synthesize-mode-ref-max`, `curate-body-max`, `code-review-levels-ref-max`, `plan-levels-ref-max` and `validate-passed-alone-ref-max` (the Synthesize and Curate bodies, the largest Synthesize mode reference, the /code-review and /plan level references a non-`full` run reads once, and the Validate re-run reference a failed Test row reads once; `agent-references.test.ts`), `validate-body-max` (the Validate body, `validate-lint-pack.test.ts`), `ci-wait-max-seconds` (the longest one `ci-wait.cjs` call may wait, under the Bash timeout) and `compact-directive-max-chars` (the resume directive `session-start-context` Section 5 emits on every compact SessionStart; a single-quoted constant, so the pin holds the emitted text; `tracker-section-max-chars` pins a template). All lower, never rise.
- `write-fence-allowlist-size` is the one raised ceiling (KB-AP-2); see "Write-set fence" in `test-harness-prompt-install` for why the roster counts as one entry.

## Moved-Text Digest Pins

When text moves verbatim from a standing-context file into one read on demand, a guard pins the destination to what the source held: a UTF-8 length plus a SHA-256, since a `git show main:` read finds nothing on a shallow clone.

- **`tests/guards/command-reference-move.test.ts` (D-CMD-REF-HAND).** /implement's rare branches (the ticket-link and missing-test-plan asks, the exception grammar and record step, the re-validation path) live in `implement-evidence-asks.md` and `implement-revalidate.md` under `src/assets/skills/agent-references/references/commands/`; the command keeps the condition and a read by explicit path that resolves its config directory in Bash first, through the sanctioned resolution line, `SANCTIONED_RESOLUTION` in `tests/helpers.ts`, then Reads with the Read tool. The four level references (`code-review-levels.md`, `plan-levels.md`, `implement-levels.md`, `resolve-levels.md`) are hand-authored with no `MOVED` row, and a host reads one on its default path at `standard` or `lean` (/implement at the start of Phase 3, /resolve in Step 0d), not only on a rare branch. The `MOVED` table pins each section, found by `commandReferenceSections()` (`tests/helpers.ts`), which is fence-aware because the exception grammar's template fence holds a `## Evidence Exceptions` line a plain split would read as a heading. Only text with no curation arm and no Git-spawn fence moves. Every named path exists, every reference is named by a command, and no plugin lists `agent-references` in `requires:` (the closure guard does not see a path read). The guard names the reference files and the four reading hosts, so a new reader or file is a deliberate edit.
- **`tests/guards/implement-resolve-full-fences.test.ts` (#480).** Every fenced spawn (`Agent(subagent_type="X"` or `agentType: "X"`) of compiled /implement and /resolve, both builds, equals its sha256 in `PINNED_FENCES`, so a level block cannot edit a spawn (a spawn written in prose is outside it). A row is keyed by the nearest heading above the fence, its agent types joined by `+` and its ordinal. A failure names file, heading and agent type; the repin command is `REPIN_FENCES=1 npx vitest run tests/guards/implement-resolve-full-fences.test.ts --reporter=verbose`, which writes no file and prints only the rows that changed or were added (JSON-quoted headings, to paste over the row with the same key), a `// gone:` line per pinned key with no fence (delete it) and a `// unreadable:` line per fence that holds `Agent(` with no type.
- **`tests/docs/architecture-move.test.ts`.** The Architecture Overview paragraphs live in `docs/reference/architecture.md` word for word, each pinned by bold lead, length and the SHA-256 of its line as CLAUDE.md held it; CLAUDE.md carries none of them.

## Build Ownership Manifest (tests/fixtures/mds-manifest.ts)

`tests/fixtures/mds-manifest.ts` is the single definition of which files the build owns: `MDS_COMMAND_HOSTS`, `MDS_PARTIALS` (the `_partials/` directory alone), `MDS_REFERENCE_PARTIALS`, `ALL_MDS_PARTIALS` (those two together), `MDS_GENERATOR_HOSTS`, `MDS_REFERENCE_MODULES`, `DIST_COMMAND_FILES` (`MDS_COMMAND_HOSTS` mapped to `.md`), `ALL_MDS_HOSTS`, `ALL_DISCOVERED_HOSTS` (`MDS_COMMAND_HOSTS ∪ MDS_GENERATOR_HOSTS ∪ MDS_REFERENCE_MODULES`), and the curation rosters `CURATION_VARIANT_HOSTS` (commands plus agents that carry arms; `CURATION_OFF_FILES` names their files), `SETTINGS_BLOCK_HOSTS` and `SETTINGS_BLOCK_HOSTS_CURATION_OFF`. The host and partial rosters are named rather than counted, and every assertion site compares against a manifest by set-equality in both directions instead of by a count literal; the settings-block counts are test-local constants beside their assertions, not manifest rows.

## Body-Hop Closure (byte-budget.test.ts section 4b, D-BODY-HOP-CLOSURE)

Section 4 of `tests/tracker/byte-budget.test.ts` prices what an operation's own reference LITERALS name. Section 4b prices what a LOADED BODY's *prose* points a spawn at: the hop `setup-task` step 1c makes into `ensure-traceable-issue` was a real in-spawn load that no `references/...` literal marked, so nothing priced it until this section existed (D-LOADED-SET-ONE-SPAWN).

- **`MODEL_TRANSITIVE_REFS`** (`tests/tracker/budget-model.ts`) is a per-provider table of `op -> [sibling ops its body hops to]`, FLAT (never a chain), covering only hops no reference literal already prices (`setup-task` to `ensure-traceable-issue`, `gather-release-evidence` / `backlink-shipped-issues` / `associate-release` among themselves, and Linear's `post-wave-report` to `backlink-shipped-issues`, which no other provider states). `summedForProvider(provider, op, transitive?)` is the formula: an op's own load plus the own load of every hop-target; the `transitive` parameter lets the non-vacuity arm re-run the SAME formula with the table emptied.
- **`nameableFromProvider(provider, op, options?)`** is the SCAN half: it reads bodies for real (starting from the op's own load) and follows every op a body mentions to a FIXED POINT (not one hop), with a visited set for cycle termination and `CLOSURE_STEP_LIMIT = 4 * ALL_OPS.length` as a hard throw-bound. It returns a `BodyHopClosure` (`files`, `visited`, `hops`, `informational`, `scanned`, `unreadable`, `steps`). Classification order: a body naming its own op is not a hop; a mention an `INFORMATIONAL_OP_MENTIONS` row explains is not a hop; EVERY OTHER mention is a hop. It is default-deny, so a new pointer lands in `hops` whether or not anyone modelled it.
- **The always-loaded bodies** (`alwaysLoadedBodies`) are held to a stricter rule, no hop at all. The agent body declares no operation, so it is always-loaded end to end and the only op names allowed in it are the `## Operations` and loading routing-table rows (`dispatchRowOp`) and `INFORMATIONAL_OP_MENTIONS` rows.
- **`OP_MENTION_RE` / `collectOpMentions(file, body)`** read a bare op name or a backticked one (not a longer op name that merely contains it as a substring), globally per line.
- **`INFORMATIONAL_OP_MENTIONS`** is the exemption table for mentions that are prose ABOUT another op, never a load directive. Each row is `{file, target, anchor, why}`, checked four ways: `collectStaleRows` (the anchor still exists and still names the target), `collectDirectiveWorded` (`LOAD_VERB_RE`: the clause around the anchor may not say "load", "follow", "run" and the like), `collectShortWhys` (`why` at least `INFORMATIONAL_WHY_MIN_CHARS`, the same floor `single-authority.test.ts` holds its own justifications to) and `collectUnconsultedRows` (a row no live scan actually read is reported, not silently kept).
- **Seeded-reader probes P1-P9** (`describe('byte budget: body-hop closure - seeded-reader probes...')`) drive the exact same collectors over an in-memory `seededReader({...})`, never a `dist/` write. P1/P2 seed a backticked and a bare sibling-op pointer into a tracker body; P3 a pointer inside a `pr/` body, unpriced on every provider at once; P4 a pointer inside a cross-cutting reference (`learn-conventions.md`), unpriced for every op that loads it; P5 a pointer INSIDE a hop's own target, followed to the fixed point rather than one hop deep; P6 a cycle (closing `gather-release-evidence` / `backlink-shipped-issues`) terminates and still reports the half nothing prices; P7 a priced hop whose pointer text is removed is reported dead in `collectDeadTransitiveRows` AND by the scan; P8 a reworded (but still present) anchor loses its `INFORMATIONAL_OP_MENTIONS` exemption and the mention becomes a hop; P9 seeds the earlier `learn-conventions` pointer phrasing back into the always-loaded tracker contract (`tracker/_contract.md`, where the project-key rule lives and which `alwaysLoadedBodies` therefore covers) and shows it would be reported as an always-loaded hop, proving the self-contained UNTRUSTED-strings rewrite was load-bearing, not cosmetic.

## Anti-Patterns

**KB-AP-1, KB-AP-2: casual regeneration and a raised ceiling.** `npm run test:golden:update` never runs in CI, and an over-budget artifact is cut, never given a higher ceiling.

## Gotchas

**KB-INV-2, KB-AP-3: fixture and pin move together.** The ratchet entry for the new size lands in the fixture-only re-capture commit of the sanctioned post-capture procedure.

**KB-AP-8: a size pass trims the lines the fixture samples.** The anchors are diagram, edge-case and step lines, the kind a command-size pass condenses: trim around them (Safety map, above).

**KB-AP-5: a written exclusion needs a reach check.** `tests/tracker/byte-budget.test.ts` asserts the excluded file (`github-api.md`) is named by `summedFor(op)` for the exact NAMED pair of ops (`fetch-review-threads`, `resolve-review-threads`), not a count, because a count of two is equally satisfied by losing one op and gaining an unrelated one.
