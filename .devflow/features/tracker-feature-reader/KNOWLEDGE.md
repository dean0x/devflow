# Tracker Feature: reader side

## Rules

- **KB-AP-1** Never add a `- **Tracker**:` line to an operation's Output template: the line lives in the contract's github-silence bullet, because GitHub emits no tracker status line and the frozen status-lines golden catches an unconditional one.
- **KB-AP-2** Never read the remote, the hosting platform or the PR host as a tracker signal: devflow itself keeps PRs on GitHub while its tracker may be Jira; the only corroboration is the repository's own issue grammar, and it narrows, never selects.
- **KB-AP-3** Never name a provider or the transport acronym in `_mcp.mds`: it states rules in terms of capabilities and tool calls, and `provider-scope.test.ts` asserts the file stays IN scope with no exemption.
- **KB-AP-4** Never parse a DEGRADED reason with `\(([^)]*)\)`: registered reasons carry nested parentheses; use the balanced detector.
- **KB-AP-5** Never write mechanics prose that reads as a body-argument assignment (`body`, `description`, `content`, `text`, `markdown`, `adf`, `comment_body` followed by `:` or `=`): `mcp-sink-bypass.test.ts` reports it; reword, never widen the regex.
- **KB-AP-6** Never widen `validateOutputName` to admit a leading underscore: `validateContractOutputName` exists for `kind: 'contract'` only, because widening would admit `_anything.md` as a command or agent basename.
- **KB-AP-7** Never add a "tracker mechanics unavailable" stop or DEGRADED rule for an absent contract or mechanics file: every install carries every provider, so only a damaged install can cause it (the literal is RETIRED).
- **KB-AP-8** Never put a shape rule (the branch form `{type}/{KEY}-{slug}`) in the contract: the test is whether the contract would be WRONG without it, and a second copy in a file every tracker spawn reads is what the byte budget refuses.
- **KB-AP-9** Never raise a budget ceiling to fit, and never record a per-component decomposition of a cut: ceilings only lower; measure the artifact instead.
- **KB-AP-10** Never charge the tracker contract to a PR-host row or to `pr-host-max-op-load`; never re-add a largest-file term to `providerLoadedSet()` (it double-counts).
- **KB-AP-11** Never put a heading at column zero (`## `) inside a generated reference: it ends the op section for every guard reading it through `extractOpSectionFromCorpus` and the content goes silently invisible.
- **KB-AP-12** Never re-point a file sink at `--emit`, or a tool-call sink at an `&&` chain: they are different sinks with different problems.
- **KB-INV-1** The settings line is the spawn's only source of provider, `SITE` and `KEY`: exactly two lines accepted, anything else fails closed to the github line (reject, never repair).
- **KB-INV-2** Frontmatter `provider:` different from the resolved provider means `DEGRADED (tracker configuration mismatch (conventions file))` and NO tracker call.
- **KB-INV-3** The static map selects, never composes: `TRACKER` picks a hardcoded row and the conventions path is a literal in the row.
- **KB-INV-4** `references/tracker/_mcp.md` is a fixed per-spawn load under a non-`github` provider, named on exactly one line of `git.md` (the tracker bullet of `## Loading the mechanics`), and the contract wins on conflict.
- **KB-INV-5** Scrub before render: a tool-call sink posts only a body whose first line is the `redact-secrets.cjs --emit` framing with a per-invocation nonce, after the consumer verifies the received body's byte length equals the framed `<bytes>`.
- **KB-INV-6** Project keys are ASCII-upper-normalised once at the key's own boundary and shape-gated at every step with one alphabet; there is no neutral default key.
- **KB-INV-7** Issue refs render as `{ISSUE_REF}` (the conventions file's form under a non-github provider, `#{number}` under github); PR refs are always `#`-prefixed.
- **KB-INV-8** Every DEGRADED reason is registered in `tests/tracker/schema-scope.test.ts` and asserted in both directions; a retirement MOVES a row to the retired list and a union floor stops it leaving both.
- **KB-INV-9** The contract is a per-spawn term of every tracker budget row (`contractTerm`) and of no PR-host row; every git.md-carrying row sits at `min(previous ceiling, measured + the fixed headroom)`.
- **KB-INV-10** The tool-call contract allows no HTTP fallback (no `curl`, `wget`, environment credential or CLI substitute); the unique qualifying server per capability wins and two or more is a degraded run with no call.
- **KB-INV-11** `_steps.mds` is imported by all three provider modules so each reference carries the same provider-neutral step bytes by construction.

## Overview

This facet is the Git-agent side of the tracker feature: the on-demand `references/tracker/_contract.md` (provider resolution and input contract), the tool-call contract `_mcp.md` that Jira and Linear spawns load, the mechanical D11 scrub gate (`redact-secrets.cjs --emit`), the registry of DEGRADED literals and the byte budget that prices all of it. Which provider is chosen is the hub's (`tracker-feature`); how the file the Tracker agent wrote is learned is `tracker-feature-inference`; what each provider's mechanics say is `tracker-feature-providers`.

## The reader half: `tracker/_contract.md`, read on demand

The reader half was the Git agent's always-loaded preamble until `D-TRACKER-CONTRACT-ON-DEMAND` moved it, whole, into `src/assets/mds/tracker/_contract.mds`: one `## Tracker contract` section holding `### Tracker provider resolution` and `### Tracker input contract`, bounded by `PREAMBLE_MAX_LINES` (re-scoped from the agent to the contract). Its subheadings are `###` because a column-0 `## ` ends the section for every guard reading it through `extractOpSectionFromCorpus`. It declares no `@define` and imports nothing, so it adds nothing to the compile cost `_mcp.mds` documents.

`git.mds` keeps only `## Loading the mechanics` (between the degradation contract and the comment-sink scrub). Its tracker bullet is the ONE line naming the file: `references/tracker/_contract.md` once per spawn before the first tracker step, then `_mcp.md` under a non-`github` provider, then the composed `references/tracker/{provider}/{op}.md`; the first two are fixed literals and the third is the single line that composes a path from the provider token. The agent runs no resolver, names no configuration file and contains no `resolve-settings.cjs` (`tests/guards/no-config-read.test.ts` asserts it, with a positive arm on the contract and an EMPTY exemption list); no reference names the contract; and no stop or DEGRADED rule covers its absence. A PR-only spawn (check-merge-readiness) reads neither contract. `provider-scope`'s provider-map allowlist is the contract's block, from its resolution heading to the last input-contract bullet.

Provider-neutral step text moved the same way (`D-NEUTRAL-STEP-MOVE`): out of the agent's tracker operations (setup-task, fetch-issue, fetch-issues-batch, gather-release-evidence, post-wave-report) into the partial `_steps.mds` (alias `steps`, in `MDS_REFERENCE_PARTIALS`), imported by all three provider modules so `single-authority.test.ts` fails when one copy is edited in place. It is not in `_common.mds` because a module's compile cost is exponential in its define count (adding a handful of defines took `_common.mds` from tens of milliseconds to seconds). Each moved step sits at its own numeric position in the provider's `### Process` and interleaves with the steps the agent keeps, per the merged-step-order bullet. `create-release`, `backlink-shipped-issues`' step 0 and the batch GraphQL null-alias rule stay in the agent.

**The settings line.** The contract's resolution runs `node "$HOME/.devflow/scripts/resolve-settings.cjs" "{root}"` once per spawn (`{root}` = `WORKTREE_PATH` or the repository root) and accepts exactly two lines: `exit=0` last, and before it one line opening `TRACKER=<github|jira|linear> TRACKER_SOURCE=<project|personal|machine|default> TRACKER_WARN=<none|mismatch|invalid> SITE=<none|https://…> KEY=<none|…> ` followed by the script's other fields (`SETTINGS_LINE_RE` is the authority on the full shape). **Anything else** is the fail-closed line `TRACKER=github TRACKER_SOURCE=default TRACKER_WARN=invalid SITE=none KEY=none`. The script folds project.json, the narrow-only personal override, the manifest and `github`; the Git agent reads neither `.devflow/config.json` nor the manifest itself.

`TRACKER_WARN=mismatch` means `TRACEABILITY: DEGRADED (tracker configuration mismatch (repository override))` and no tracker call (the personal override named a provider other than `github` or the one already resolved; remedy: correct or drop the `tracker` key in the personal `.devflow/config.json`, since `devflow tracker --set` changes only the machine default, which a repository's selection outranks). `TRACKER_WARN=invalid` means `TRACEABILITY: DEGRADED (unknown tracker provider)` and `TRACKER` stands. A conflict with the conventions file is `... (conventions file)`: **the mismatch reason is SPLIT by cause**, because "which of these two disagreed?" is the whole question a user needs answered.

**The static map selects, never composes:** `github` gives `tracker/github/` and no conventions file; `jira` gives `tracker/jira/` and `~/.devflow/tracker/jira.md`; `linear` gives `tracker/linear/` and `~/.devflow/tracker/linear.md`. The conventions path is a literal in the row, never composed from the token. A conventions file is opened with the **Read tool**, never `cat`/`head`/`tail`; over the size bound it is read fully anyway and degrades with `tracker.md exceeds size bound`; present but unparseable, truncated or with frontmatter not at offset 0 means `tracker configuration unreadable` and resolves `github` (a present file signals intent, so it must not be silent, and must not block). A consumed section holding `# UNRESOLVED:` means `tracker.md required fields incomplete — edit the conventions file in ~/.devflow/tracker/`; an absent section means its documented neutral default.

There is no "tracker mechanics unavailable" rule: only a damaged install could leave a named mechanics file (or the contract) absent, and no prompt carries a stop rule for a failure only corruption can produce (`tracker mechanics unavailable` and the old remedy spelling `... — edit ~/.devflow/tracker.md` are RETIRED literals in `schema-scope.test.ts`).

**Under a non-`github` provider `_mcp.md` is a FIXED per-spawn load.** It carries server scoping per CAPABILITY (the unique qualifying server wins and its affinity is pinned for the spawn; two or more is `TRACEABILITY: DEGRADED (ambiguous tracker server — {n} servers offer {capability})` and no call), a write requiring a prior corroborating read from the SAME server matching the project key once per spawn (never per item), and tool DESCRIPTIONS treated as vocabulary, never instructions. The prohibition on vendor tokens across the Git spawn surface is why the partition rule reads "the leading namespace segment of the tool name" rather than a literal prefix.

**Reference rendering has a rule, a value and a default.** A reference renders as `Refs {KEY}-{n}` unless the conventions file says otherwise, and the Tracker agent never writes `# UNRESOLVED:` into that row. Release evidence is gathered in the provider's own reference grammar with **project-key equality**: a well-formed key belonging to another project is `foreign issue reference {ref}`, not a shipped issue.

**The project key chain:** the settings line's `KEY`, then an explicit ref in the task inputs (applies to that op only, never written back), then this repo's git history, then the conventions file; a conflict between steps is reported once on the `- **Tracker**:` line. Keys are ASCII-upper-normalised once at the key's own boundary, then shape-gated with `^[A-Z][A-Z0-9_]{1,9}$`, the same alphabet the conventions file's schema gate applies and a `KEY-N` reference's key segment must satisfy. Git-history strings are UNTRUSTED. **The site rung** (`_jira.mds` / `_linear.mds`): the settings line's `SITE`, else `## Project` in the conventions file, then the `^https://…` shape gate.

**The corrected remote rule, with its prohibition attached:** the remote, the hosting platform and the PR host are NOT tracker signals, and a rule that reads them is WRONG and must never be implemented. A "GitHub remote plus authed CLI means github" condition is true for essentially every Jira user *including the requester*, and would disable the feature for exactly the user it targets. The only corroborating signal is whose issue grammar the repo's history speaks, and it NARROWS what is already resolved. Neither the contract nor `git.mds` names a ref-grammar corroboration step or a `TRACKER_SOURCE`-conditional rule.

**The mismatch guard and the uninstall classification:** frontmatter `provider:` different from the resolved provider means `TRACEABILITY: DEGRADED (tracker configuration mismatch (conventions file))` and NO tracker call. It covers every path init cannot see (uninstall then reinstall, a hand edit, a dotfile-repo sync) and is why the file is preserved as user content instead of swept as an install artifact: **a stale file is safe to keep only because it can no longer be silently authoritative.**

**Where status lines and refs render.** The `- **Tracker**:` line lives in the CONTRACT (`### Tracker provider resolution`), not in any op's Output template; the rule is a clause of the github-silence bullet: under any other provider, add `- **Tracker**: {provider} ({TRACKER_SOURCE}) | DEGRADED ({reason})` beside `- **Conventions**:`, additive, exactly one rendering, `({n} unresolved)` on first use. The three issue slots in the Output templates carry `{ISSUE_REF}`; the rendering rule is the last bullet of the contract's `### Tracker input contract` (`## Reference Rendering`'s form under a non-github provider, `#{number}` under github, PR refs always `#`-prefixed because pull requests stay on the PR host). `tests/tracker/schema-scope.test.ts` pins both clauses (`RENDERING_CLAUSES`, including the positive github rendering, without which the one provider whose bytes the golden pins has no instruction for rendering its own references) and asserts every issue slot carries the token while PR slots keep their `#`. **The branch half is deliberately NOT in the contract**: `{type}/{KEY}-{slug}` with the type exact-matched against `## Issue Types` is stated by each provider's own `setup-task` mechanics and pinned per provider from the shared claim table in `tests/helpers.ts`.

## The MCP substrate: `_mcp.mds`, the generation gate and `--emit`

**The generation gate is keyed on a module's `subdir`, not on a flag.** Three collaborating pieces in `src/core/mds-variants.ts`: `MCP_BACKED_PROVIDER_SUBDIRS = ['tracker/jira', 'tracker/linear']`; `MCP_CONTRACT_MODULE` (source `_mcp.mds`, `subdir: 'tracker'`, `kind: 'contract'`); and `mcpContractIsGenerated()` / `resolveVariantModules()` / `GATED_REFERENCE_MODULE_SOURCES`. `_mcp.mds` is **not** in `VARIANT_MODULES`: `resolveVariantModules()` appends it when some registered module lands in a gated subdirectory, and `expandVariants()` and `generatedReferenceManifest()` both default to it. A conditional module-level row cannot be expressed by `as const satisfies`, so the gate is a derived registry resolver. The provider-independent `_contract.mds` is the opposite case: a `VARIANT_MODULES` row (the last, and the first UNGATED `kind: 'contract'` entry), because every install carries every provider.

The build reports deferral rather than hiding it, via `deferredReferenceModuleSources()` (the build's own predicate, exported so the build and the two count guards read ONE owner). A deferred module is neither a partial (it declares an `output-dir:`) nor a refusal (an *unregistered* reference module is still refused with the registry-naming message): `partialCount = totalCount - hosts.length - deferred.length` in `scripts/build-mds.ts`. With Jira and Linear registered nothing is deferred; the deferral line appears only when no registered provider needs the module.

**The emitted basename `_mcp` needed two narrow widenings.** `validateOutputName` refuses a leading underscore, so a registry row alone would have refused with `invalid-op-name` the moment the gate opened. `validateContractOutputName(name)` demands exactly one leading `_` then delegates (used only for `kind: 'contract'`), and `VARIANT_SECTION_MARKER_RE` is relaxed to `/^<!-- op: (_?[a-z0-9][a-z0-9._-]{0,63}) -->[ \t]*$/`, which is free because the captured name is checked against the caller's registry.

**`_mcp.mds` names NO provider and NOT the transport acronym.** It states its rules as *capabilities* and *tool calls*, so it contains neither `\bjira\b`/`\blinear\b` nor `\bMCP\b`/`\bmcp__`: the capability-first doctrine applied to its own prose, keeping `provider-scope.test.ts` at full strength. The guard asserts the file is **IN** scope, because an unscanned file is an exemption nobody wrote down.

What the contract carries: a capability table (`| Capability | Unavailable ⇒ |`) where only *identify current user* degrades-and-posts-anyway and the four dedup-rung rows fall through rather than erroring; the **no-HTTP-fallback** clause; **scrub-before-render**, permitting only a pure structural wrapper whose concatenated text nodes equal the scrubbed bytes (no re-encoding, base64, chunking, summarisation or reflowing); structured reads that are **shape-trusted, value-untrusted**; and a one-directional load chain with **THIS CONTRACT WINS** on conflict.

**`redact-secrets.cjs --emit`: the mechanical D11 gate.** A shell `&&` short-circuit cannot exist inside a tool call and an instruction is not a gate. The framing line is `D11-OK <nonce> <sha256> <bytes> <n> [type:count,…]`:

- `<nonce>`: **32 lowercase hex chars** (`NONCE_HEX_CHARS`, 16 CSPRNG bytes), per-invocation and **required**, because composed bodies contain untrusted issue text and an unframed `D11-OK` literal is forgeable by anyone who can write an issue comment. Exported so a guard pins the width from the constant.
- `<sha256>`: 64 hex of the scrubbed body. `<bytes>`: `Buffer.byteLength(body,'utf8')`, **bytes, not characters**. `<n> [type:count,…]`: the **FIRST** pass's `formatScrubLine` output minus the shared `SCRUB: ` prefix; the second pass is always 0 by construction and *that* is the gate.
- Grammar, anchored both ends: `/^D11-OK [0-9a-f]{32} [0-9a-f]{64} \d+ \d+ \[[^\]]*\]$/`.
- **A scrubbed body that itself carries a framing-shaped line (`/^D11-(OK|FAIL) /m`) is refused**, not emitted: the line-1 rule becomes a property of every body the script can emit rather than an obligation nine documents must restate, and a consumer that looked for "a `D11-OK` line" cannot be steered to a planted one. The trailing space keeps prose such as `D11-FAILURE` out of the refusal.
- **Failure framing** `D11-FAIL <reason>` with body `''` and non-zero exit. Reasons are bare tokens in the closed registry `D11_FAIL_REASONS`: `input-unreadable`, `input-too-large`, `second-pass-nonzero`, `body-contains-framing`, `nonce-unavailable`. `internal-error` and `output-unwritable` are deliberately absent (the top-level catch fires before the boundary has written anything and leaves stdout empty; `--emit` writes no file). **No path and no secret ever on stdout**; the no-body property belongs to the **result type** (`body: ''`), so the boundary writes unconditionally and cannot leak one by forgetting to suppress.
- **Exit codes:** `0` ok; `1` usage (stdout entirely EMPTY, the mode is not yet known); `2` input unreadable or over the 1 MiB limit; `3` output file write failed (FILE sink only); `4` internal; **`5` `--emit` only: a gate refused** (second pass non-zero, framing in body, nonce unavailable), distinct from 4 so a caller can tell "must not be posted" (final) from "the script broke" (retried).
- `--emit` takes **ONE** positional. Arity is exact in both modes; `--emit in out` is a usage error.

**The `<bytes>` verification clause** is the consumer's half and `_mcp.mds` states it as a **refusal**: confirm the received body's byte length equals `<bytes>`; on mismatch **DO NOT POST** and emit `TRACEABILITY: DEGRADED (redaction unavailable)`. A Bash result is clipped at a per-machine limit and **both ends survive while the middle is elided**, so the framing line and the body's tail are intact and a bare "absent framing means do not post" gate passes over a body with a hole in it. Chunking is forbidden, so a truncated body has no sanctioned recovery. `docs/reference/platform-assumptions.md` carries the limit and its drift symptom.

`tests/guards/mcp-sink-bypass.test.ts` polices the arrangement: the contract clauses against the **SOURCE** `.mds` (never the generated `_mcp.md`), the bypass regex over seven shapes including `create_comment(body: $DEVFLOW_BODY_RAW)`, and a forward arm over the LIVE generated provider corpus that must REACH every member of `MCP_BACKED_PROVIDER_SUBDIRS` by name.

## The DEGRADED literal registry

`tests/tracker/schema-scope.test.ts` holds scoped literal registries and asserts the partitions between them in both directions:

- **`LIVE_REASONS`**: the canonical tracker table, each row with an emitting site now (the contract's own `no tracker tool for {capability}` and `ambiguous tracker server — {n} servers offer {capability}`, `redaction unavailable`, the Jira mechanics' dedup, ref pre-flight, site, transition and plan-cap reasons, `trace map unavailable`, the associate-release reasons, and the rest).
- **`DEFERRED_REASONS`**: empty, kept as a declared half rather than deleted: the partition assertion is what makes it the ONLY way a row may sit outside the forward arm, so a row deleted from both halves would shrink the registry silently. Its mirror arm ranges over nothing, so it carries its own known-bad probe. Registering a provider adds no row: its spelling is admitted by `reasonSpellings` as soon as the provider is registered.
- **Two placeholders are INSTANTIATED, both token sets derived.** The canonical table states `unsupported by {provider}`; the per-provider cell is the instantiated `unsupported by jira`; both are correct and different strings. `reasonSpellings()` admits a template plus its instantiations, with `{provider}` tokens read from the module registry and `{capability}` tokens read from the tool-call contract's own capability table, so both sets are CLOSED (`unsupported by asana` and `no tracker tool for frobnicate` are still reported). `{ref}`, `{p}` and `{n}` are deliberately NOT instantiated: runtime data with no closed domain.
- **The reason collector is parenthesis-balanced** (`/DEGRADED \(((?:[^()]|\([^()]*\))*)\)/`) because two registered reasons nest a parenthesis; a naive `\(([^)]*)\)` returns a truncated reason and reports it as unregistered. The collector also **collapses whitespace**, because a reason is a one-line status string whose prose is hard-wrapped (reflowing the source would pin where a sentence happens to break).
- **Scoped exemption registries** for literals outside the canonical table, each scoped to the site that emits it and each entry asserted genuinely emitted (so none can become a dumping ground): `GITHUB_ONLY_REASONS` (github mechanics: the tech-debt archive failure and `merged-PR listing did not cover the range`), `GIT_AGENT_LEGACY_REASONS` (pre-canonical agent literals), `PR_HOST_LEGACY_REASONS` (the summary operations' retry ceilings, scoped by PATH PREFIX because `ensure-pr-ready.md` exists under `pr/` and under every provider), and `PR_HOST_REASONS` (live reasons written for the PR host, such as `cannot push to fork` and the evidence and caller-block grammar refusals). Treat each as canonical until the appendix gains it or the literal is retired; folding them together would exempt a wording anywhere the broader file appears.
- **`RETIRED_REASONS`** holds what must appear nowhere (among them `tracker mechanics unavailable` and the old single-file remedy), plus **`PHASE3_STATUS_LINES`** asserted emitted: `SECRET-EXPOSED (rotate {type} credential — the source file still holds it)` and `SCRUB: N [type:count,…]`.

Literals the contract emits, all in `TRACEABILITY: DEGRADED (…)` form: `unknown tracker provider`, `tracker configuration unreadable`, `tracker configuration mismatch (repository override)`, `tracker configuration mismatch (conventions file)`, `tracker not configured`, `ambiguous issue reference`, `tracker.md exceeds size bound`, `tracker.md required fields incomplete — edit the conventions file in ~/.devflow/tracker/`.

## The byte budget

Every *measured* figure is a row the shape table in `tests/tracker/byte-budget.test.ts` prints; the ceilings are the constants that file asserts (`BUDGET_GIT_MD`, `BUDGET_SKILL_MD`, `BUDGET_LOADED_SET`, `BUDGET_LOADED_SET_JIRA`, `BUDGET_LOADED_SET_LINEAR`, `BUDGET_LOADED_SET_PR_HOST`, `PREAMBLE_MAX_LINES`) plus the `numeric-floors.json` entries `mcp-contract-max-chars` and `pr-host-max-op-load`. **Re-run it for the current numbers**: `npm run build && npx vitest run tests/tracker/byte-budget.test.ts` prints every row. A ceiling is a regression alarm, not a target; it may be lowered after a pass that genuinely condenses the artifact, never raised. No per-component decomposition of a cut is recorded anywhere, because successive re-derivations of such components disagreed once already.

- **Every git.md-carrying row sits at `min(previous ceiling, measured + headroom)`, and the headroom (named in the `numeric-floors.json` descriptions) is fixed, not a reservation.** Any growth funds itself with a matching cut. The Git agent split took `git.md` down by moving the provider resolution and input contract to `tracker/_contract.md`, the provider-neutral step text to the references and the PR-host step bodies to `references/pr/`; every loaded-set row moved with it (the PR-host row by exactly the git.md cut, the tracker rows by less, because the contract is billed back to them). `PREAMBLE_MAX_LINES` now bounds the contract, with one line of deliberate headroom: the next rule added must retire one.
- **The loaded-set FORMULA has no largest-file term.** `providerLoadedSet()` used to add `max_op chars(tracker/{provider}/{op}.md)`, which double-counted (the file is already inside some op's own one-spawn load) and survived only because it stood in for a real unpriced cost: `setup-task` invokes `ensure-traceable-issue` under `ISSUE_REQUIRED`, and no `references/…` literal named it. `largestTrackerReference()` / `largestProviderReference()` are RECORDED ONLY (they still print as a shape-table row).
- **`D-BODY-HOP-CLOSURE` prices every operation a LOADED BODY names**, not just what a reference literal points at. `nameableFromProvider()` in `tests/tracker/budget-model.ts` starts from an op's own load, reads every body inside it and follows every operation name a body mentions into that op's own load, to a fixed point (bounded by `CLOSURE_STEP_LIMIT`, a visited set preventing cycles). `MODEL_TRANSITIVE_REFS` is the per-provider table of known hops (`setup-task` to `ensure-traceable-issue`; `gather-release-evidence` and `associate-release` to `backlink-shipped-issues` on all three providers; Linear's `post-wave-report` to `backlink-shipped-issues`). `INFORMATIONAL_OP_MENTIONS` is the CLOSED exemption table for a mention that names an operation without loading it, DEFAULT-DENY: a mention no row explains is priced as a hop. So the worst tracker spawn is `setup-task` plus the `ensure-traceable-issue` mechanics its step 1c loads, and Linear is the largest row because its `setup-task` and `ensure-traceable-issue` mechanics are each the longest of the three.
- **The contract is a per-SPAWN term of every tracker row and of no PR-host row.** `contractTerm(provider)` is a sum over `contractTermRels(provider)` (`tracker/_contract.md` on every tracker row, plus `tracker/_mcp.md` under a tool-call provider), added once in `providerLoadedSet`; the GitHub row therefore carries `_contract.md`, bytes that used to sit inside the always-loaded `git.md`. It stays out of `ownLoadForProvider`, the PR-host row and the per-operation PR-host cap: `ensure-pr-ready` is both a PR-host and a tracker operation, and charging it the contract on the PR-host side would put it over the lower-only `pr-host-max-op-load` (zero headroom), so its full cost is priced through the tracker rows where it is already a candidate. `MODEL_CROSS_CUTTING_ASSERTED` lists both contracts, `alwaysLoadedBodies()` carries them under the no-hop rule, and `contractBlock()` / `loadingBlock()` are the slices the line and ordering assertions read.
- **Each provider and PR-host has its own row** (`D-LOADED-SET-PER-PROVIDER`): the GitHub row keeps `bytes(_mcp.md)` at 0 BY CONSTRUCTION (pricing a tool-call contract there would bill every GitHub user for bytes they never receive, by raising a ratcheted ceiling), and the PR-host row is scoped to the PR-host operations (`D-LOADED-SET-SCOPE`: the GitHub row is scoped to TRACKER ops). Trimming `_mcp.md` is the sanctioned first response to a tool-call row going red, condensing the jira or linear mechanics the second; neither is "give the provider more room".
- **One written exclusion, declared rather than filtered inline:** `LOADED_SET_WRITTEN_EXCLUSIONS` names exactly `references/github-api.md`. The PR-host row's `2c-ex` shape RECORDS the same maximum with the file charged, an equality pin (`GITHUB_API_MD_CHARS`) holds its size, and an arm asserts the unexcluded figure would NOT fit under the ceiling, so the exclusion is load-bearing rather than a rounding convenience.
- **Where a cross-cutting paragraph goes matters.** Content added to an op inside a worst spawn's one-spawn load moves a ceiling; the same content in an op outside every worst spawn moves nothing. Check the printed table before choosing.

## Anti-Patterns

- **KB-AP-1.** The first draft added the line to `setup-task`'s `### Traceability` template and the frozen `github-status-lines.txt` caught it: the fixture was right on the merits, since the GitHub path emits **no tracker status line at all**.
- **KB-AP-2.** Devflow deliberately keeps PR hosting on GitHub while the tracker is Jira, so a remote-based rule disables the feature for the user it targets.
- **KB-AP-6.** The widenings were planted build breaks defused one subtask early; leave `validateOutputName` alone.
- **KB-AP-8.** The contract is wrong without the rendering rule and silent without the branch rule; the branch rule is pinned per provider.
- **KB-AP-12.** The file-sink recipe uses a shell `&&` chain as the gate (in the Tracker agent and the Git agent's comment-sink scrub); framed stdout exists only for sinks with no such boundary.

## Gotchas

- **KB-AP-5: the bypass regex reads `word:` as an argument assignment, and prose is full of them.** A sentence like "the detector must read the text: a status-shaped rule..." is reported as a posting mechanic assigning an ungated body. Write mechanics, not prose that looks like a call ("read that error text and not the status" costs nothing). Do not widen the regex: the widening would exclude the real shapes too.
- **KB-AP-4: two registered reasons nest a parenthesis** (`tracker configuration mismatch (repository override)` and the `(conventions file)` form). Any consumer of a DEGRADED reason must use the balanced detector; this is the one behavioural ripple of the mismatch split outside the two emitting sites.
- **Two `gh`-shaped traps for anyone editing the Git agent's cross-cutting text:** a `` `gh` `` code span anywhere there fails `git-agent.test.ts`'s provider-detector guard (state the prohibition without naming the CLI), and a mid-line `## Operation: <name>` literal is read by the op-roster scan as a real operation (name it as "the `learn-conventions` operation").
