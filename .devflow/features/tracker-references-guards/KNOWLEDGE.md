# Tracker References: Guards, Corpora and Goldens

## Rules

- **KB-INV-1** Every corpus extraction names its mode ([DR-18]): `'sole'` throws when the anchor matches more than one corpus file; `'union'` concatenates and returns a match count.
- **KB-INV-2** After a contract/mechanics split, classify every guard literal individually and widen `'sole'` to `'union'` only where the literal provably moved. Each widening carries a `sinkCorpusWithoutPrHost()` (or `sinkCorpusWithout(prefix)`) known-bad probe proving it is load-bearing.
- **KB-INV-3** Guards that decide which ops are the subject (the remote-I/O sweep behind `git-agent-remote-io-ops`) read the operation-reference corpus, `gitOperationReferenceCorpus()` (the git-agent suite's `operationReferencesCorpus()`): every operation once, in its one reference, GitHub provider. Literal-presence guards (a fixed op, "can it reach this text?") read the full `gitAgentSinkCorpus()`.
- **KB-INV-4** `extractOpSectionFromCorpus` is fence-aware: a `## ` inside a fenced block does not end the op section, a column-0 `## ` outside one does.
- **KB-INV-5** An operation's degradation notes are inside its one reference, which the spawn loads to run the op, so a clause there is a contract; the remote-I/O guard reads that corpus for both its detection and its D4-evidence halves, while the generic D4 contract that governs every op stays in `git.md`.
- **KB-INV-6** The D10 `gh repo view` scope property is a successor pair, not a corpus-wide search: `publication-gate.md` is named from exactly `['post-resolution-summary', 'post-review-summary']` through their own references and never from `git.md`, and `gh repo view` appears only in that file and those two references.
- **KB-INV-7** Every shipped recipe that posts a body posts the scrubber's output: the `d11-posting-ops` floor spans `git.mds` and the generated references, tracker and PR-host, and `KNOWN_GITHUB_API_INLINE_BODIES` stays empty. `update-pr-evidence`'s posts are the script's, so its scrub-before-post is held by running `verify-evidence.cjs publish` (KB-INV-11).
- **KB-INV-8** One normative sentence has one owner: single-authority registries pin every shared literal to the file that owns it, and the three generated copies of a neutral step stay byte-identical.
- **KB-INV-9** Non-vacuity floors rise with the roster; a provider adds its whole roster at once, so a floor moves by a module rather than by a file. A floor falls only through a dated, user-accepted note beside it in `numeric-floors.json`.
- **KB-INV-10** `tests/fixtures/golden/github-status-lines.txt` is frozen and `STATUS_LINE_REFERENCE_FILES` is a closed list (its reader, `statusLineRefReader().read`, refuses an undeclared path); each authorisation to re-capture is one-time, and every authorisation to date is spent.
- **KB-INV-11** A script-pointer reference (`update-pr-evidence`, `check-merge-readiness`) restates nothing its script owns, and the script is held by running it under the gh PATH shim `tests/evidence/pr-shim.ts`: no gh write after a failed scrub, only the contract's block on stdout. `check-merge-readiness`'s prose ladder, a model and the script's `readinessVerdict` agree arm for arm.
- **KB-AP-1** Blanket-widening a guard corpus to a joined union just to turn it green, without a probe that fails when the moved tree is dropped.
- **KB-AP-2** Widening a detection guard to the full union even when it passes: an op that is remote-I/O under ONE provider is then detected through that provider's mechanics, silently changing the subject of a guard about the operations themselves.
- **KB-AP-3** Editing one provider's copy of a `_steps.mds` step in place, or stripping a gated step's condition from one provider: the single-authority `NEUTRAL_STEPS` arm fails both.
- **KB-AP-4** Letting a shared step open a loop ahead of a provider's hoisted identity lookup: the capability-hoist guard's known-bad probe reports it, which is why `backlink-shipped-issues`' loop bound stayed in the agent.
- **KB-AP-5** Moving text a status-lines sample reads without turning that sample into a straddle sample, or leaving a sampled line with no successor (a pointer that would point at its own file): the fixture then needs a fresh authorisation.
- **KB-AP-6** Naming a Principle-8 or D11 containment obligation from an op without stating it in that op's own reference: a control cited by name is not a control that lives there.

## Overview

The guards that keep the contract/mechanics split honest read two corpora: `dist/agents/git.md` (routing and shared rules; it declares no operation) and the generated reference tree (one reference per operation). Their central discipline is corpus classification: after a split, a literal is readable from exactly one corpus, `git.md` or a reference, and a guard must be pointed at the corpus where the literal provably lives. The hub is `.devflow/features/tracker-references/KNOWLEDGE.md`; the ceilings are `.devflow/features/tracker-references-byte-budget/KNOWLEDGE.md`; the registry and overlay are `.devflow/features/tracker-references-build-install/KNOWLEDGE.md`. General harness conventions (`extractOpSectionFromCorpus`, `collectUnfencedH2`, `gitAgentSinkCorpus`, goldens lifecycle, `walkFiles`) are owned by `.devflow/features/test-harness/KNOWLEDGE.md`.

**The classification rule shaped every guard.** The original tracker split moved only `fetch-issues-batch` step 2 and left `fetch-issue` step 1, specifically so their retained literals could stay `'sole'`-scoped. The PR-host split did the same: every guard it re-pointed from `'sole'` to `'union'` carries its own `sinkCorpusWithoutPrHost()` probe. The one-reference move made the single-authority read direct: `operationReferencesCorpus()` holds each operation once, so a `'sole'` read of an op's contract or steps is a single-authority read, and `'union'` remains for literals that span providers or the PR-host tree. That is the lens for reading every `extractOpSectionFromCorpus(..., { mode })` call in `tests/git-agent.test.ts`.

**Verification order at PR time.** Byte budget, including the body-hop closure's bidirectional check → single-authority and reachability (each scanning the PR-host tree alongside the provider trees) → the D11, D10, Guard-2 and AC-0.6b corpus guards in `tests/git-agent.test.ts` → the installer overlay tests (both `tracker/` and `pr/` converge and swap atomically) → packaging (the tarball carries the full manifest).

## The corpora

- `gitAgentSinkCorpus()` — the full union of `git.md` and every generated reference (all three providers); used by literal-presence guards.
- `gitOperationReferenceCorpus(provider = 'github')` (`tests/helpers.ts`) — one entry per `GIT_OPERATIONS` member, each the one reference the agent tells a spawn to read, so no two entries share an operation anchor; git-agent.test.ts reads it through `operationReferencesCorpus()` as the detection-scoped corpus for guards that decide which ops are the subject, and the status-lines sampler and most single-op suites read it too.
- `sinkCorpusWithoutPrHost()` — the known-bad probe corpus: drop the PR-host tree and the widened guard must turn red (`sinkCorpusWithout(prefix)` does the same for any tree and throws when nothing is dropped).
- `seedPrHostFile(op, transform)` — returns the corpus with one PR-host file's content transformed in memory, for probes.
- Mode is explicit at every call. `'sole'` throws on a multi-file anchor match; `'union'` returns a count.

`extractOpSectionFromCorpus` is fence-aware, which is the structural remedy for text moved byte-identically across a grammar boundary: a `## ` heading inside a generated reference is safe as a real `##` line only inside a fenced code block; outside any fence it terminates the op's section for every union-mode guard. Every PR-host `### Process` heading and the compose-fence `## ` lines inside the two summary operations' templates follow this rule exactly as the tracker references do. `tests/tracker/reference-structure.test.ts` holds the fence-aware boundary over both trees and the contract-first order over every operation reference under every provider (`collectContractFirstDefects`: `**Input:**` before `**Output:**`, the template's fence closed, then the first `###` outside a fence).

## The guard suites

- **`tests/tracker/single-authority.test.ts`** keeps one normative sentence to one owner. `SHARED_LITERAL_REGISTRY` and `MCP_SHARED_LITERAL_REGISTRY` pin shared literals, each with a rationale of at least `MIN_RATIONALE_CHARS` (`collectUnderJustified`). §5 `TRACKER_CONTRACT_LITERAL_REGISTRY`: every registry sentence lives in `_contract.md` and in no other generated reference or the agent. §6 `NEUTRAL_STEPS` (`D-NEUTRAL-STEP-MOVE`): each `_steps.mds` define is expanded by every provider module and spelled out in none, the three generated copies are byte-identical (`collectDivergentCopies`), and each gated step's condition is present in all three (`collectDroppedConditions`, AC-526), each with a known-bad probe — a copy edited in place in one provider, a condition stripped from one provider's copy. The project-key alphabet scan reads each provider's own mechanics outside `ensure-pr-ready`'s PR-link paste gate, which names every provider's grammar on purpose (`withoutPasteGate`, with its own probe). `providerReferenceCorpus()` walks `MECHANICS_TREES` (`tracker/` AND `pr/`), with a non-vacuity arm proving through `readsPrHostTree` that the `pr/` half was read and a known-bad probe walking the real tree without `pr/` that requires the check to fail.
- **`tests/tracker/reference-reachability.test.ts`** — structural parity for both the provider trees and `PR_HOST_OPS` (its own two-directional reachability pair: `collectPrHostNames`, `anchorsOnLineOne`, `reachableSetFrom`), `gather-release-evidence` batch-first, full-manifest reachability in both directions (every generated file is nameable by something the agent reads, every name resolves), and the loading-section arms (`contractsNamedByTheLoadingSection`, `collectLoadingPlacementDefects`, `collectMissingContractRules`, `collectHopRuleDefects`): one load instruction and it is the template, the two contracts are fixed loads no operation file names, AC-519 no stop rule for a missing contract, AC-524 the one-reference rule and the reference table stay in the agent, and the hop rule lets a step run or follow another operation's reference. AC-102 holds that each operation reaches exactly one reference (its table row or the templated tracker line, equal to `operationReferenceRel`) and each file declares one `## Operation:` anchor; AC-101 that the agent body carries no operation section, `**Input:**` or `**Output:**`. It also holds that every "same logic as `{op}`" in a `pr/` file names that op's `pr/` file.
- **`tests/guards/capability-hoist.test.ts`** — session-scoped capabilities must be hoisted before a loop; per-item capabilities inside a bounded loop are the loop's payload (`D-CAPABILITY-PROBE-SCOPE`, `PER_ITEM_PAYLOAD`). Its non-vacuity floor `capability-hoist-block-floor` counts the `### Process` blocks of the generated tree (`learn-conventions`, one block per tracker op per provider, one per PR-host op), so it moves by a module rather than a file, and asserts by provenance that none comes from `git.md`. The moved neutral steps expand inside each provider's existing `### Process` block, which is why that split left the floor unchanged; known-bad probe 5 reports a shared step that opens a loop ahead of the hoisted lookup. `LOOP_MARKERS`' fan-out justification cites `references/pr/{fetch,resolve}-review-threads.md`.
- **`tests/guards/provider-scope.test.ts`** — the provider-token scope over the Git spawn surface, a widened corpus scanning `dist/skills/git/references/pr/` for a stray jira or linear literal (a hostile literal there would be read by every provider's users), and `ALLOWLISTED_PROVIDER_REGIONS`: the tracker contract's block and `ensure-pr-ready`'s PR-link paste gate (the github copy plus `_ops_steps.mds`; the Jira and Linear copies each `confines` only the other provider's token, since a provider's own reference names its own). It also holds that no `tracker/github/{op}.md` names the tool-call contract.
- **`tests/git-agent.test.ts`** — the D11, D10, Guard-2 and AC-0.6b guards. The conventions-commit placement guard reads `setup-task`'s steps from each provider reference (`PROVIDER_SETUP_TASK_PATH`) and asserts they are absent from `git.md` — the union is load-bearing. AC-101 there asserts the agent body declares no operation section.
- **`tests/guards/requires-closure.test.ts`** — the bidirectional `requires:` closure over commands ∪ agents ∪ skill bodies and `TEMPLATE_SKILL_REFS`, the classified exception for the Review agent's focus-templated skill reference.
- **`tests/guards/report-cap.test.ts`** and **`tests/fixtures/agent-config.ts`** — Git's frontmatter row and report-cap roster membership (hub KB).
- **`tests/evidence/update-pr-evidence.test.ts`**, **`merge-readiness-script.test.ts`** and the shim **`pr-shim.ts`** — the two script-pointer ops. The first holds that the `update-pr-evidence` reference points at the script and restates nothing it owns (known-bad probes: a gh call, `--body-file`, a scrubber chain or a marker put back) and that the contract's Output statuses are the script's; it then runs `publish` for real against a stateful `gh` fake first on PATH, which logs every call with the bytes of any `--body-file` (exact block in every scenario, no gh write after a failed scrub) and checks in the source that each write follows its scrub. The second runs `readiness` under the same shim against the contract's Output template. `tests/evidence/merge-readiness.test.ts` holds the prose ladder, a model and `readinessVerdict` to the same arms, and that the script's CI classification is `ci-wait.cjs`'s.
- **`tests/tracker/compliance-gate.test.ts`** — operations never decide compliance: a caller gates and passes a mechanism input (`ISSUE_REQUIRED`, `APPLY_CONVENTIONS`), and the whole op surface (`git.md` plus every generated reference) holds zero condition-shaped compliance mentions.

## Floors

Registered under `floors` in `tests/fixtures/numeric-floors.json` (floors rise; a fall needs a dated, user-accepted note): `generated-reference-manifest-size` and `packed-reference-manifest-size` (build and tarball scope), `installed-reference-count-github` and `installed-reference-count-provider` (one shared `INSTALLED_REFS`, since an install no longer depends on the machine's provider), `min-reference-chars`, `capability-hoist-block-floor`, `git-agent-remote-io-ops` (AC-0.6b, asserted over the operation-reference corpus with zero headroom), `d11-posting-ops` (zero headroom, over the corpus spanning `git.mds` and the generated references), `report-cap-roster-count`, `manage-debt-archive-cap` and `requires-closure-token-floor`, plus `seam-ops-with-callers` (`tests/seams/command-agent-input.test.ts`: operations with a live caller fence). `d11-posting-ops` and `seam-ops-with-callers` each fell once, by a dated, user-accepted note naming the old value, when `update-pr-evidence` and `check-merge-readiness` became script pointers: `update-pr-evidence`'s reference holds no `--body-file` post, and no command spawns either op. The manifest-size, packed-size, installed-count and `capability-hoist-block-floor` values sit below their earlier values because `pr/ensure-pr-ready.md` is not emitted and the agent carries no `**Process:**` label; each carries a dated, user-accepted note naming its old value.

## Goldens and the status-lines fixture

`tests/fixtures/golden/github-status-lines.txt` is sampled by `extractStatusLines()` against the closed `STATUS_LINE_REFERENCE_FILES` list in `tests/helpers.ts`. Re-captures have been made only under explicit, one-time user authorisations and every one to date is spent; a further one needs a fresh authorisation. `extractStatusLines()` still equals the frozen fixture byte for byte with zero residual lines. When a split moves a line a sample reads, the sample becomes a `D-STRADDLE-SPLIT` sample: each moved line is read by its own anchor and rejoined in its original order, and the moved-to file joins `STATUS_LINE_REFERENCE_FILES` (the neutral-step move did this for `gather-release-evidence` steps 1, 2, 3 and 5 and `post-wave-report` step 2, which is why it needed no authorisation). A sampled line with no successor is the exception: the agent body declares no operation section, so the `**Process:**` labels and `**Mechanics:**` pointers that the `manage-debt`, `check-ci-status` and `gather-release-evidence` samples read have nowhere to move (each operation's contract and steps are one reference, so the pointer would point at its own file). The ninth authorisation covered exactly those deletions, nothing added, and is spent. `gitOp(op)` reads each sampled operation through `statusLineRefReader()` from its one reference, so `STATUS_LINE_REFERENCE_FILES` lists the GitHub copy of every sampled operation, and the PR-body guidance and D11 scrub directive lines are sampled byte for byte from `ensure-pr-ready`'s reference. The `git-agent.md` golden (`tests/fixtures/golden/git-agent.md`) is regenerated in its own fixture-only commit via `npm run test:golden:update -- git-agent`, and the install-snapshot goldens gain a line when the installed tree gains a file and lose one when it loses a file.

## Anti-Patterns

- **KB-AP-1, KB-AP-2** The probe is what separates a relocation from a cosmetic widening. Dropping the PR-host tree from the corpus must turn the guard red, or the guard never needed the tree. Over the full union a detection guard's subject set changes silently, so detection reads the narrower corpus even though the wider one would pass.
- **KB-AP-3** The three provider copies carry the same bytes by construction; an in-place edit in one provider breaks the construction, and a stripped condition leaves a gated step ungated in one provider only.
- **KB-AP-4** The capability-hoist guard's probe verbs are session-scoped only; the loop bound is the loop's payload and not a hoist violation, but a loop line ahead of the hoisted identity lookup is.
- **KB-AP-5** A moved line a sample reads should become a straddle sample read through its own anchor instead of being regenerated into the golden.
- **KB-AP-6** A control cited by name in one section is not a control that lives there. `post-wave-report`'s non-reproduction clause and `post-resolution-summary`'s op-local clause both illustrate it.

## Gotchas

- **KB-INV-3, KB-INV-5** The AC-0.6b guard's detection half reads the one-reference corpus on purpose: widened to the full union, an op is detected through any provider's mechanics. Its D4-evidence half reads the same corpus because an op's degradation notes are in the reference the spawn must load to run it, while the generic D4 contract stays in `git.md`.
- **KB-INV-6** The scope property is held at both ends: each summary op's D10 naming sentence is in its own `pr/` reference (the exact-set assertion over the operation references), and the agent body is asserted to name the gate nowhere.
- **KB-INV-7** `KNOWN_GITHUB_API_INLINE_BODIES` (`D-INLINE-BODY-EXCLUSIONS`) is an empty array; the guard mechanics (`joinContinuations`, `INLINE_BODY_SHAPES`, `inlineBodyCorpus`) are owned by the test-harness KB.
- **KB-INV-10** The `git-agent.md` and install-snapshot goldens are the ones a split regenerates, in a fixture-only commit; the status-lines fixture is not among them.
- **KB-INV-9** `check-ci-status` stays defined though no command spawns it. `ci-wait.cjs` replaced the Git CI re-spawn, so no command fence names it; it stays for two non-command readers. Its Output `**Status**:` enum is the authority `ci-wait.cjs` is pinned to (`tests/evidence/merge-readiness.test.ts`), and `check-merge-readiness` step 3 names its PR-host reference for the classification (the `readiness` script classifies with `ci-wait.cjs`'s own `classifyChecks`). Removing it would lower `capability-hoist-block-floor` (a floor falls only through an accepted note), break PR-host roster parity and ci-wait enum parity, and force a status-lines fixture re-capture. In the agent's `## Output` exempt list its `**Status**:` is classified as "the enum `ci-wait.cjs` is pinned to", not as a field a command reads (`tests/guards/report-cap.test.ts` asserts the operation is still routed in the agent's tables and that classification). No command spawns `check-merge-readiness` either: `/resolve` runs `verify-evidence.cjs readiness` inline.
