# Curation-aware Install & Language-focus Stamp

## Rules

- **KB-AP-1** `FileCopyOptions.curation` has no default, and `init` passes the SETTLED `curationEnabled`, never the raw seed or a repository's narrowing: the variant follows the machine switch alone, and the copied files and the manifest must agree.
- **KB-AP-2** Never express "curation off" by removing `apply-decisions` from a plugin's `skills` or `requires`: the closure guard reasons over the curation-on superset, and a plan-level removal would report the skill as a deselection (`removedSkills`). The exclusion is the install-time `CURATION_GATED_SKILLS` condition on an untouched plan.
- **KB-AP-3** Never re-stamp the language list after each converge write or derive it from `manifest.plugins` in a toggle: the stamped copy always differs from source (rewritten every `devflow init`), and a selective uninstall leaves `manifest.plugins` stale (resurrects a removed language). The converge CARRIES the installed list; install and uninstall are the only writers.
- **KB-AP-4** Never put prompt text, an out-of-pattern name, or a duplicated stamp line on the stamp: `applyLanguageStamp` refuses over `MAX_STAMPED_FOCUSES`, any name outside the focus-name pattern, and a file with no stamp line or several.
- **KB-AP-5** The converge never throws and never stops a run: every failure is a warning and `converged: false`; a damaged stamp line is a warning to run `devflow init`, never a stop rule.
- **KB-AP-6** Never read a missing `dist/curation-off` as a no-op: after `build:cli` alone `convergePromptVariants` warns to run `npm run build:mds` and reports `converged: false`, and with compliance off the install itself refuses before any write (remedy `npm run build:mds`).
- **KB-AP-7** The converge never installs an uninstalled plugin's prompt: a roster entry with no installed copy is left alone (`notInstalled`).
- **KB-AP-8** Never drop a build-manifest host the roster cannot hold (`readRoster` `refused`, name fails `ROSTER_NAME_RE`) as if it were converged: each is a warning and a failed converge, and with compliance off an armed refused host leaves `posting` unknown.
- **KB-AP-9** Never call a removed single-axis converge or hand-build the record: callers use `convergeVariantAxes` (init, `devflow curation`, `devflow compliance`) or `convergePromptVariants` with explicit `{curation, compliance}` switches.
- **KB-INV-1** The curation switch picks variants machine-wide: a repository that narrows curation in `project.json` never reaches the installer; curation-on files keep their run-time gate. Posting steps are likewise a compile-time variant keyed on the machine compliance switch alone, so a repository key cannot restore them.
- **KB-INV-2** `resolveSkillSource` is the one spelling of the shadow decision, shared by the install loop and the converge; it stat-checks the shipped source FIRST and throws if absent, even under a valid shadow.
- **KB-INV-3** A converge write is byte-compared with the installed file and written only when different, atomically (`writeFileAtomicExclusive`); a steady-state run moves nothing.
- **KB-INV-4** An installed agent keeps its `model:` and `effort:` across a variant rewrite (`carryAgentOverrides`); `reapplyAgentMapping` stays the authority and the carry only closes the shipped-model window.
- **KB-INV-5** The `/code-review` stamp is computed from the EFFECTIVE selection (what is on disk), never the plugins one run copies, and only `code-review.md` carries it (`LANGUAGE_STAMPED_COMMANDS`).
- **KB-INV-6** A shadow of `apply-decisions` is dormant under curation off: kept in `~/.devflow/skills/`, never installed, never deleted, applied again on enable.
- **KB-INV-7** A curation toggle across a CLI version skew records the switch but converges nothing (`variantToggleSkew`); both curation mismatches are safe by design. `devflow compliance --enable/--set` across a skew still converges the compliance skill and rule, and a skewed disable exits non-zero.
- **KB-INV-8** The install record (`installedVariants`) is written only after a clean converge, by `installRecordFor(converged, switches)` (the one pure decision init uses for the record and the posting notice); `recordInstalledVariants` re-reads the manifest switches inside the lock and, if they changed during the run, writes nothing and removes an old record, so status reads unknown.

## Overview

The build emits an off variant of every command and agent that carries an arm into `dist/curation-off`, `dist/compliance-off` or `dist/curation-compliance-off` (both-off) `/{commands,agents}/`, plus the manifest `dist/variant-axes.json` (the marker splitter, `src/core/curation-variants.ts`, belongs to the `curation-capture-system` KB). The build removes the retired off tree `dist/learning-off` whole (`LEGACY_OFF_OUTPUT_DIR`, `pruneLegacyOffTree`), because no host writes there now. The install follows the machine's curation switch (`features.curation` in `~/.devflow/manifest.json`; the mirror key `features.learning` always holds the same value, see the hub KB) and nothing else: the installed agents are machine-wide, so one repository's narrowing cannot pick them without changing every other repository's prompts (`D-LEARNING-VARIANT-INSTALL`). The compliance axis works the same way with its own machine switch (`features.compliance`), and the converge also records which variants the prompts hold. A separate mechanism stamps the installed `/code-review` with the language focuses on disk (`D-LANGUAGE-FOCUS-STAMP`); both live in `src/targets/claude-code/` and reach installed files after the copy.

## Curation-aware Install and Converge (`curation-install.ts`)

Three pieces carry it:
- **Source order.** `FileCopyOptions.curation` is REQUIRED with no default, because a caller that forgot it would install the wrong variant with no error. `init` passes the SETTLED `curationEnabled` (after flag, prompt and seed). `FileCopyOptions.compliance` is required for the same reason and `init` passes the settled compliance switch. Commands resolve over `commandSourceDirs({curation, compliance}, root)` and agents over `agentSourceDirs(root, {curation, compliance})` (`VariantSwitches`): with an axis off the off-variant directories come first, and a host with no arm falls through to its one compiled file. With compliance off (the default), `requireComplianceVariantFiles` first refuses the install before any write when `dist/variant-axes.json` is absent or invalid, or when a compliance-armed host lacks the file built for the machine's exact switches (a both-off machine needs the both-off file, never the curation-off one), or when the copy's own source list would take another file; it checks the file the copy would take.
- **Skill condition.** The skill loop runs over `omitCurationGatedSkills(skillsMap, curation)`, so `apply-decisions` is not installed with curation off. The full-install pre-clean walks the UNFILTERED `skillsMap`, so a full install also drops a leftover copy; a partial install leaves removal to the converge. The registry still owns and requires the skill and `resolveSkillInstallPlan` is untouched, so a curation-off machine never reports it as a deselection nor its shadow as inactive. Only skills and rules have shadows; commands and agents have none, so an off variant has nothing to collide with.
- **`resolveSkillSource(skill, devflowDir, packageRoot?)`** (`installer.ts`, returns `ResolvedSkillSource = { dir, shadow }`) stat-checks the shipped source FIRST and throws when it is absent, even under a valid shadow (a packaging failure a shadow must not mask), then `validateSkillShadow`: a valid shadow wins, an invalid one is reported and the shipped source installs.

**`convergeVariantAxes({claudeDir, devflowDir, manifest, plugins, warn, packageRoot?})`** makes an ALREADY-installed tree match both machine switches. It never throws and composes three converges, each isolated so a failed one never skips the next: `convergePromptVariants` (commands and agents, explicit `{curation, compliance}` switches), the `apply-decisions` skill (`convergeSkills`), and `convergeFromManifest` (the compliance skill and rule). Every failure is a warning and `converged: false`, and a non-absolute `claudeDir` is warned and skipped. A curation failure only warns because either mismatch is safe — an on variant is still gated at run time and an off variant loads no decisions. With compliance off the result also carries `posting` (`clear`, `left` with the files, or `unknown`): fail closed, so the compliance command exits non-zero while init and curation warn.
- *Roster*: the `.md` files under the three off trees (`dist/curation-off`, `dist/compliance-off`, `dist/curation-compliance-off`, `{commands,agents}`) whose name matches `ROSTER_NAME_RE` (`^[a-z0-9][a-z0-9-]*\.md$`, sorted, at most `MAX_CURATION_ROSTER` per kind), joined with the hosts of the build manifest `dist/variant-axes.json` (read only with compliance off); never a list typed in the installer, so a new arm converges with no edit here. A manifest host whose name the pattern rejects is `refused` (see the Gotchas). A missing tree (only `build:cli` ran) warns to run `npm run build:mds` and leaves the installed prompts as they are.
- *Rewrites only installed files*: a roster entry with no installed copy is left alone (`notInstalled`) — a `--plugin` install carries one plugin's files and a toggle must not add another plugin's. The wanted bytes are the variant (off: the roster file; on: the first existing file over the normal source order) wearing the installed copy's state (`withInstalledState`). An agent carries its installed `model:` and `effort:` (`carryAgentOverrides` in `agent-models.ts`, `D-AGENT-OVERRIDE-CARRY`: the two lines `devflow agents` and the proxy put there; the source comes back unchanged when either side has no well-formed frontmatter or the carried model/effort fail their guards). `code-review` carries its language stamp (`stampForConverge`). The result is byte-compared with the installed file and written only when different, atomically (`writeFileAtomicExclusive`), so a steady-state run moves nothing and a no-op converge rewrites no agent. `reapplyAgentMapping` stays the authority; the carry only shuts the window in which a rewritten agent would sit on its shipped model.
- *Skill*: with curation off it removes the `devflow:apply-decisions` directory when present; with curation on it installs only when `skillsOf(plugins)` holds the skill (else `not-selected`), from `resolveSkillSource` (shadows and `packageRoot` honoured), skipping when the two trees hold the same files and bytes, otherwise a staged swap. Staging sits at `{claudeDir}/.devflow-curation-<pid>-<ts36>.tmp`, never under `skills/` (a stranded directory there would look like a second skill); the old directory is displaced to `.old` and restored if the rename fails. Each file and each gated skill is tried separately, and a failed prompt never skips the skill. `CurationSkillState = installed | removed | unchanged | not-selected | failed`.

**Callers.** `init` calls `convergeVariantAxes` right after `installViaFileCopy` with `plugins: effectivePlugins` and the settled switches, routing warnings (and a thrown error, defensively) into `installWarnings`, then calls `describePostingLeft` on `posting`; `reapplyAgentMapping` runs later in init (preflight ordering is in the init-seed KB). Init writes the manifest record from `installRecordFor(converged, switches)`, and prints the one-time posting notice only when the record was written and `postingNoticeDue` holds. `devflow curation --enable/--disable` and `devflow compliance`: the command writes the machine switch first (exit 1 when Devflow is not installed or the switch cannot be recorded), then calls `applyVariantToggle`, which SKIPS with a "run `devflow init`" message when there is no readable manifest or the manifest's version differs from the running CLI's (`variantToggleSkew`: the installed prompts are not ones this package would rewrite; the switch itself is already recorded). Otherwise it converges over the registry filtered by `manifest.plugins`, records the variants after a clean converge, and runs `reapplyAgentMapping` only when the converge rewrote an agent. The compliance command, on a skip, still runs `convergeFromManifest` for the skill and rule (they do not depend on the installed version). `describeVariantConverge` prints one `Installed prompts: …` line only when something changed. Re-init without a curation flag keeps the prior manifest value; only `--curation` / `--no-curation` or `devflow curation` flips it.

## Language-focus Stamp (`language-stamp.ts`, `D-LANGUAGE-FOCUS-STAMP`)

`/code-review` spawns a language focus only when its file-type trigger fires AND the focus appears on the one line `Installed language focuses: <list>` of the installed command; the installer writes that line, replacing a run-time `test -f` probe of Claude Code's directory.
- *Carrier*: shipped as `Installed language focuses: (none)` in `code-review.mds` (Step 1.2, outside every curation arm so both variants carry it, no interpolation braces) and found again by an anchored multiline match; exactly one match is required. Only `code-review.md` carries it (`LANGUAGE_STAMPED_COMMANDS`); `/dynamic-build` spawns every focus and has no stamp. A default install, with no language plugin, leaves code-review byte-identical to the build.
- *List*: `installedLanguageFocuses(effectivePlugins)` is plumbing only (which focuses a diff gets stays a prompt rule). It comes from the EFFECTIVE selection (`FileCopyOptions.effectivePlugins`: the full selection on a full install, the prior manifest's plugins merged with X on `--plugin=X`), because the stamp describes what is on disk.
- *Writers*: (1) `installViaFileCopy` calls `restampInstalledCommands({claudeDir, effectivePlugins, warn})` after the command copy and command sweep, on every install shape and even when code-review's own plugin is not in the run (`--plugin=devflow-typescript` copies no command yet must update an installed code-review; an absent command stays absent). It compares against the bytes on disk at write time, so neither the same-run copy nor the pre-clean can defeat it; `init.ts` is untouched. (2) The uninstall's `runSelectivePhaseForScope` re-stamps right after `removeSelectedPlugins` from `installedPlugins` minus the selected plugins (a language plugin owns a skill and no command, so otherwise the removed skill's name would stay on the line), under the legacy-local `mayChange` guard. (3) The converge CARRIES the stamp rather than re-stamping (`stampForConverge` calls `carryLanguageStamp` inside the write path, before the byte comparison). So install and uninstall are the only writers of an existing list and a toggle never changes it. A copy with no well-formed list to carry (installed before the stamp existed) is stamped from the converge's selection instead of being handed the shipped `(none)`.
- *Safety*: `applyLanguageStamp` returns a Result and refuses more than `MAX_STAMPED_FOCUSES` focuses, any name outside `FOCUS_NAME_RE` (`^[a-z][a-z0-9-]{0,31}$`; no prompt text can ride in on the list) and a file with no stamp line or several; `carryLanguageStamp` copies only a single well-formed line. A damaged or missing line is a warning to run `devflow init`, never a stop rule, and nothing here throws.
- *Edges*: a selective uninstall does not rewrite `manifest.json`, so `manifest.plugins` still lists the removed language plugin and a later `init --plugin=X` or full re-init re-installs that skill AND stamps it, consistent with disk; with no readable manifest the re-stamp falls back to the whole registry minus the selected plugins; `uninstall --dry-run` does not list the re-stamp (a rewrite, not a removal).

## Anti-Patterns

- **KB-AP-1** The option is required precisely because a forgetful caller installs the wrong variant silently. Passing the raw seed would let the copied files and the written manifest disagree; gating on a repository's narrowing would change every other repository's prompts.
- **KB-AP-2** The skill stays in the registry's `skills` / `requires` (the closure guard `tests/guards/requires-closure.test.ts` reasons over curation-on); the gate is `CURATION_GATED_SKILLS` applied at install time and in the converge.
- **KB-AP-3** The stamped copy always differs from shipped source, so re-stamping after every converge write would rewrite it on every `devflow init`. A selective uninstall leaves `manifest.plugins` stale, so a manifest-derived stamp in a toggle would resurrect the removed language. `stampForConverge` therefore carries; the only two writers are install and uninstall.

## Gotchas

- **KB-AP-6** After `npm run build:cli` alone there are no variants: `convergePromptVariants` warns and leaves prompts as they were. `installViaFileCopy` with compliance off (the default) refuses before any write when `dist/variant-axes.json` or the exact-axes off file of a compliance-armed host is absent; only a machine with compliance on can still reach the curation-on files this way. The on-variant fallback for a host with no arm reads the all-on source order (`onSourceDirs`).
- **KB-AP-8** A refused host is a manifest entry the build accepts under a wider name than `ROSTER_NAME_RE`. It never reaches `convergeFile`, so it is never rewritten; the failed converge keeps the install record unwritten, and the posting question stays open when the host is compliance-armed with compliance off.
- **KB-INV-7** `devflow curation --enable/--disable` after a CLI upgrade and before `devflow init` records the switch but converges nothing; the installed prompts stay on the old variant until init. An on variant keeps its run-time gate and an off variant loads no decisions, so neither curation mismatch is harmful. A compliance-off skew is different: posting steps remain installed until init, so `devflow compliance --disable` exits non-zero with that message, while an enable across a skew is a warning and exit 0.
- **KB-INV-8** The record is a claim about the installed files, so it follows the converge, not the switch: an unclean converge leaves the field out (unknown, remedy `devflow init`), and a switch that moved while the converge ran removes a stale record rather than recording switches that no longer hold. An unknown record counts as posting for the one-time notice.
- **KB-INV-6** Under curation off the `apply-decisions` shadow stays in `~/.devflow/skills/` unapplied and undeleted, and a curation-off machine reports the skill neither as a deselection (`removedSkills`) nor its shadow as inactive; both come back on enable.
- **KB-AP-7** A `--plugin` install carries one plugin's files, so a toggle must rewrite only prompts that are already installed.
