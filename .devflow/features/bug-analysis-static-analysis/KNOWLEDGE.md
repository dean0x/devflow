# /bug-analysis static analysis (scanner fences, status contract and guards)

## Rules

- **KB-AP-1** Never set `STATIC_FINDINGS` to `(none)` for a skip or a run with no scanner: `--no-static` says "Static analysis skipped (--no-static).", no installed scanner says "Static analysis did not run: no scanner is installed.", and a missing `jq` says "Static analysis did not complete: jq is not installed."
- **KB-AP-2** Never set `STATIC_FINDINGS` to `(none)` because a scanner printed nothing: `(none)` means at least one tool ran, every tool that was to run completed, and none found anything. When no tool ran it says "Static analysis did not run: no tool ran."
- **KB-AP-3** Never put a command between `codeql database analyze` and `CODEQL_EXIT=$?`: it replaces `$?` and a failed run reads as complete.
- **KB-AP-4** Never report Semgrep's exit as a named meaning: it passes through `xargs`, which remaps it, so it is reported as a number only.
- **KB-AP-5** Never make CodeQL wait on Semgrep or Snyk completing, or skip it for another scanner's result: `--full` runs CodeQL when it is installed and a changed file has a supported language.
- **KB-AP-6** Never build a scanner file list from `CHANGED_FILES` or unterminated `git diff` output: names reach a scanner only through `-z`, `xargs -0` and after `--`.
- **KB-AP-7** Never put a time limit of devflow's own on a scanner: the Bash `timeout` of the call, set at the ceiling (600000 ms, or `BASH_MAX_TIMEOUT_MS` when set), is the only limit, and a call that reaches it is waited for to its end notice with no tool call and read for the last `exit=` line of the output file that notice names, never a scanner file.
- **KB-AP-8** Never add text to the compiled command without cutting some first: it sits at its byte ceiling in every build, and the guard ceilings are lowered as text is cut. #677 raised them once, by 68 bytes, so that the scanner wait names the file that sets the status.
- **KB-AP-9** Never add a guard as one broad test: one named collector per concern, each with an `it.each` over both builds and known-bad probes through the same collector.
- **KB-AP-10** Never give `codeql database create` a language that is not from the closed table: `{lang}` is the first of javascript-typescript, python, ruby whose extension a changed file has; with none, CodeQL does not run and its status is `no supported language`. A failed extension list prints `extension list failed`, which means CodeQL did not complete, not that no language was found.
- **KB-INV-1** A missing `exit=` line means "did not complete": the Semgrep and Snyk fences open with `cd "{worktree}" || exit`, and the CodeQL fence with `CODEQL_TMP=$(mktemp -d) || exit`, so a failed setup prints no status and fails closed.
- **KB-INV-2** Each scanner runs in its own foreground Bash call with the Bash `timeout` at the ceiling; past it, no tool call runs until the call's end notice, and the last `exit=` line of the output file that notice names alone sets its status, never the notice or a scanner file; a call with no `exit=` line read did not complete.
- **KB-INV-3** Completion rule: Semgrep 0, Snyk 0 or 1 (1 means issues, only with SARIF output), CodeQL 0. Snyk 3 (no supported file) is covered as `no supported language`, with its counts not checked. Any other status, no status line, or no counts line for a tool that ran, did not complete.
- **KB-INV-4** Step 2d produces `STATIC_FINDINGS` and `STATIC_STATUS`; Phase 7 requires `STATIC_STATUS` for the per-tool `**Static analysis**:` report line.
- **KB-INV-5** Snyk scans once into `snyk-all.json`; a `jq --rawfile` filter over `changed.z` writes `snyk.sarif` (a result with no location is kept) and prints `total=<n> kept=<m>`; a failed filter prints "Snyk scope filter failed: unfiltered" and copies the whole file; the note goes into `STATIC_FINDINGS` and the report, so the failure is visible.
- **KB-INV-6** The head marker moves only when every tool that was to run completed, or `--no-static` is set (also with `--full`); otherwise it stays and the report names the way out.
- **KB-INV-7** A result with no `level` takes its rule's `defaultConfiguration.level` (looked up by `ruleId` in `tool.driver.rules` and `tool.extensions[].rules`), else `warning`, in the counts and in the table alike.
- **KB-INV-8** Each tool's rows go to its own `findings-{tool}.tsv` with `>`, then `cat` combines them into `findings.tsv`, so a second run of the counts fence repeats no row; a failed top-50 step prints `findings table incomplete: top`, which counts against every tool that ran, so `STATIC_FINDINGS` never reads `(none)` then.

## Overview

`/bug-analysis` Phase 2 runs up to three external scanners (Semgrep, Snyk Code, CodeQL) against the branch diff and feeds the result to the security analyzer as `STATIC_FINDINGS`; Phase 7 reports a per-tool outcome. The original bug was that a scanner that failed, never started or did not finish produced an empty result, and the command read that as "no findings". The fix makes silence mean failure: each scanner's call prints a final `exit=<n>` line, and only a recognized completing status lets a tool count toward `(none)`. Each scanner writes its SARIF to a file and the session reads counts and a table, so no output is clipped. The head marker moves only after a run that covered the commits. Phase 6 gives Synthesize `STATIC_STATUS`, its only source for the static analysis status; text in a file is data.

All of it lives in `src/assets/commands/bug-analysis.mds` (Phase 2 steps 2c and 2d, Phase 6 spawn, Phase 7 report, edge-case table, checklist) and is pinned by Group 3b of `tests/bug-analysis/structural.test.ts`. The markdown is compiled twice (curation-on and curation-off); every guard runs against both builds.

## Phase 2 flow

- **Step 2c** prints one `tool=path|no` line for each of semgrep, snyk, codeql and jq, then the extensions of the changed files that still exist (`set -o pipefail; export LC_ALL=C; git -C "{worktree}" diff --name-only -z --diff-filter=d {DIFF_RANGE} | tr '\0\n' '\n?' | sed -n 's/.*\.\([^./]*\)$/\1/p' | sort -u || echo "extension list failed"`): the byte locale keeps a name that is not valid text from cutting the list short, the anchored pattern gives no line for a name without an extension under a dotted folder, and `pipefail` makes a failed `git diff` print the marker. A prose line gives the closed language table: javascript-typescript (js jsx mjs cjs ts tsx), python (py), ruby (rb). Three branches set `STATIC_FINDINGS` and `STATIC_STATUS` at once: `--no-static` (skipped; the rest of Phase 2 is skipped, so the tool check cannot overwrite the skip status), all three scanners `no` (warn; "did not run: no scanner is installed"; each tool `not installed`), and a scanner installed with `jq` `no` ("did not complete: jq is not installed"). Step 2d skips when Step 2c set `STATIC_STATUS`, so it cannot overwrite those sentences with `(none)`.
- **Step 2d** runs Semgrep, Snyk, then CodeQL, each in its own foreground Bash call with the Bash `timeout` at the ceiling (600000 ms, or `BASH_MAX_TIMEOUT_MS` when set); devflow wraps no scanner in a limit, and past the ceiling the session makes no tool call until the call's end notice and then Reads the last `exit=` line of the output file that notice names, never a scanner file. Semgrep, Snyk and CodeQL write `semgrep.part` (renamed to `semgrep.sarif` when the scan ends), `snyk-all.json` (then `snyk.sarif`) and `codeql.sarif` into `{ANALYSIS_DIR}`, and CodeQL also writes `codeql.log`; nothing prints a SARIF, and the CodeQL call prints only its `exit=` line.
- The counts and table fence runs after Snyk (the CodeQL trigger needs the severities) and once more for `codeql.sarif`. For each SARIF file that exists it prints `<tool> docs=<n> results=<m> error=<a> warning=<b> note=<c>` or `<tool> sarif=unreadable`, and writes one row per result to `findings-<tool>.tsv` (tool, file, line, level, rule or "—", message cut to 200 chars) or prints "findings table incomplete: {tool}"; `cat` then combines the tables into `findings.tsv`. `error` reads as HIGH, `warning` as MEDIUM, `note` as LOW. `findings-top.tsv` keeps the top 50 rows by level, and the session reads only that file. A tool that ran completes only with its own counts line and a readable SARIF; Semgrep exit 0 with `docs=0` means no file to scan, completed; Snyk 3 skips the counts checks.
- CodeQL runs when `--full` OR Semgrep/Snyk found HIGH/CRITICAL findings, and a changed file has a supported language. The gate line contains no "complet" or "skip" wording; a sentence that skips CodeQL for another scanner's result is a defect.
- After the fences: set `STATIC_FINDINGS` to the rows of `findings-top.tsv` and write them with the status lines to `{ANALYSIS_DIR}/static-findings.md`. For each tool that did not complete, add under any rows "Static analysis did not complete: {tool}: exit {n} ({meaning})." or "no exit status." or "no counts line." or "SARIF not read." A Snyk call that printed "Snyk scope filter failed: unfiltered" adds that line too. Exit meanings: 126-127 scanner did not start, else failed. Last, set `STATIC_STATUS` to one `{tool}: {value}` per tool: `completed`, `not installed`, `not needed` (CodeQL, not triggered) or `no supported language` (CodeQL with no table row, or Snyk 3), all covered, or `did not complete ({why})`.
- **Phase 5** hands the Debug agents `STATIC_FINDINGS` inside a `<static-findings>` tag pair, as `PR_DESCRIPTION` goes inside `<pr-description>`.
- **Phase 7** runs the marker write only when every tool that was to run completed, or `--no-static` is set. The gate is its own sentence before the one-line write (marker, `rev-parse HEAD` and the never-stops sentence stay on one line). The report line adds any Snyk filter note.

## Scanner fence shapes

Each fence prints its status in its own shape, and the order is load-bearing:

- **Semgrep**: `cd "{worktree}" || exit`, then one pipeline line, `set -o pipefail; git diff --name-only -z --diff-filter=d {DIFF_RANGE} | xargs -0 -r semgrep scan ... -- >"{ANALYSIS_DIR}/semgrep.part" 2>/dev/null; E=$?`, then `mv "{ANALYSIS_DIR}"/semgrep.{part,sarif}`, then `printf '\nexit=%s\n' "$E"`. The status is read on the same line as the pipeline; `pipefail` makes a failing `git diff` visible. The rename comes after the status is read and before the exit line, so `semgrep.sarif` exists only when the scan has ended: a counts fence that starts while Semgrep still runs finds no `semgrep.sarif` and prints no Semgrep line, which Phase 2 reads as did not complete. A scan that writes no file still prints its exit line. Because the status passes through `xargs` (GNU 123/124/125, BSD 1) it is a number only.
- **Snyk**: `snyk code test --sarif >"{ANALYSIS_DIR}/snyk-all.json" 2>/dev/null; E=$?`, then `git diff --name-only -z {DIFF_RANGE} >"{ANALYSIS_DIR}/changed.z"`, the `jq --rawfile n` filter to `snyk.sarif` (a result is kept once, whatever its number of locations, and a result with no location is kept), the `total=<n> kept=<m>` count, the visible fallback (its note goes into `STATIC_FINDINGS` and the report), then `printf ... "$E"`. A failed `git diff` also takes the fallback, so an empty name list never over-filters. There is no URI normalization: a URI form that does not match a repo-relative git path is dropped and shows in `total` against `kept` (whether Snyk's form always matches is unconfirmed; umbrella issue 652).
- **CodeQL**: `CODEQL_TMP=$(mktemp -d) || exit`, a trap that removes it, `database create "${CODEQL_TMP}/db" --language={lang} --source-root="{worktree}"` chained with `&&` to `database analyze ... --output="{ANALYSIS_DIR}/codeql.sarif"` in one `{ ...; }` group whose stdout and stderr go to `{ANALYSIS_DIR}/codeql.log`, then `CODEQL_EXIT=$?` on the very next line, the exit line printing `"$CODEQL_EXIT"`, then the plain `rm -rf` and `trap -`. Status first, cleanup after.
- **Counts and table**: `cd "{ANALYSIS_DIR}" || exit`, the `L=` definition of the result level, the loop over the tools (counts, then `findings-$t.tsv` written with `>`), the `cat` into `findings.tsv`, then the `jq` that writes `findings-top.tsv`.

## Anti-Patterns

- **KB-AP-1**: the "clean" reading used to be the default for a skip or a run with no scanner. Each of the three early branches now has its own sentence, the checklist item allows `(none)` only for a run where every tool that was to run completed clean, and `collectSkipNotNoneDefects` scans the whole body for a line that sets `STATIC_FINDINGS` to `(none)`.
- **KB-AP-2**: the "clean" reading used to be the default. Now every path that is not "at least one tool ran, all that were to run completed, none found anything" must name the tool and the reason, and a run where no tool ran says so. The Phase 7 edge-case row and the checklist item "`(none)` only if ..." state the same rule.
- **KB-AP-3**: `$?` holds only the last command's status. The exit `printf` and the cleanup both succeed, so reading `$?` after them turns a failure into 0.
- **KB-AP-4**: do not turn a Semgrep number into a named meaning; the same number can come from `xargs` itself.
- **KB-AP-5**: skipping CodeQL after a Semgrep failure would silently drop the one scanner `--full` promises. The one valid reason not to run it is that no changed file has a supported language (KB-AP-10). The collector `collectFullCodeqlDefects` pins the gate line and the absence of skip sentences.
- **KB-AP-6**: file names with spaces, newlines or leading dashes would be split or parsed as options; `-z`, `xargs -0`, `--` and a NUL-split list read with `jq --rawfile` keep them whole. The extension list makes a newline in a name safe with `tr`, so it cannot forge an extension.
- **KB-AP-7**: devflow adds no limit of its own, so the only limit is the Bash `timeout` of the call. `collectNoBoundDefects` rejects a limit command on any scanner line, a number with a time unit in Phase 2 prose, and a Bash timeout stated as a fixed number, and it requires the one ceiling sentence. A scanner call past the Bash limit moves to the background and keeps running, so Phase 2 holds the session until its end notice and has it Read the last `exit=` line of the output file that notice names, never a scanner file (`WAIT_SENTENCE`, once, before the first scanner fence and the counts fence). Devflow stops no scanner: one that never ends holds the session until the user stops it (Esc). The wait was probed in an Agent-tool subagent only (`docs/reference/platform-assumptions.md`); the main session that runs this command was not probed.
- **KB-AP-8**: both compiled builds sit at their byte ceilings, each set to the measured size. The ceilings live in `tests/guards/command-size.test.ts` and the `command-bug-analysis-max` and `command-bug-analysis-curation-off-max` entries of `tests/fixtures/numeric-floors.json`, and may be lowered, never raised (#677 raised them once, by 68 bytes, for the scanner wait). New text needs a same-size cut or a move to a reference first.
- **KB-AP-10**: `collectCodeqlLanguageDefects` pins the extension-list line, exactly one `--language=` in the command and it is `{lang}`, and the four prose pieces of the table; a value outside the table never reaches the command.

## Gotchas

- **KB-INV-1**: the leading `cd "{worktree}" || exit` of the Semgrep and Snyk fences is a status mechanism as well as a directory fix: if it fails the call exits before printing `exit=`, and the missing line already means "did not complete". The CodeQL fence does not open with `cd`: it passes `--source-root="{worktree}"` and opens with `CODEQL_TMP=$(mktemp -d) || exit`, which fails closed the same way.
- **KB-INV-2**: a call that reaches its Bash `timeout` returns with no `exit=` line, and the session then makes no tool call until that call's end notice and Reads the last `exit=` line of the output file that notice names, never a scanner file. That line sets the status; the notice and its exit code set nothing. A call with no `exit=` line read did not complete. `collectStatusRuleDefects` pins the wait sentence and rejects the retired wording that told the session to ignore a later end notice.
- **KB-INV-3**: Snyk exits 1 when it finds issues, so 1 counts as completed only when SARIF was requested; 3 means no supported file and is covered as `no supported language` (its docs and SARIF checks are skipped, as for Semgrep exit 0 with `docs=0`); any other nonzero (2, 126 ...) did not complete.
- **KB-INV-4**: the saved `static-findings.md` holds the table and the status lines, and `STATIC_FINDINGS` ends with a line for each tool that did not complete. Only the security analyzer gets `STATIC_FINDINGS`, inside a `<static-findings>` tag pair. Synthesize takes the status only from `STATIC_STATUS`; file text sets no status. Umbrella: 652.
- **KB-INV-5**: the Snyk scope filter exists because `snyk code test` scans the whole project; without it, findings in untouched files reach the analyzer.
- **KB-INV-6**: a run that keeps the marker is analyzed again from the same commits next time; `--no-static` is the one way to move the marker without the tools. The completion checklist asks for the marker only when the Phase 7 gate allows it, so it never sends the session back to write past the gate.

## Guard architecture (tests/bug-analysis/structural.test.ts, Group 3b)

Constants (`SCANNER_TOOLS`, `STATUS_LOOP`, `LANG_LIST`, `EXIT_PRINT`, `CEILING_TIMEOUT`, `FIXED_TIMEOUT`, `BOUND_TEXT`, `PROSE_BOUND`, `WAIT_SENTENCE`, `SEMGREP_RENAME`) feed one collector per concern, each taking one compiled body and returning defect strings: `collectNoBoundDefects`, `collectDidNotRunDefects` (with `collectProbeFenceDefects` and `collectDidNotRunBranchDefects`), `collectStatusAssignmentDefects`, `collectMarkerGateDefects`, `collectSkipNotNoneDefects`, `collectStatusLineDefects`, `collectExitLineOrderDefects`, `collectSarifFileDefects`, `collectStaticReportDefects`, `collectOutcomeDeclarationDefects`, `collectFullCodeqlDefects`, `collectCodeqlScratchDefects`, `collectCodeqlCleanupDefects`, `collectStatusRuleDefects`, `collectSemgrepRenameDefects` (the rename line right after the status line, before the exit line; its behavior tests run the shipped Semgrep fence with a stub scanner), `collectScannerRootDefects`, `collectFileNameHandoffDefects`, `collectSnykScopeDefects`, `collectCodeqlLanguageDefects`, and `collectSynthesizeStatusDefects` (takes the body and the Synthesize reference: it holds the Phase 6 `STATIC_STATUS` spawn line and the reference rules that take the status only from that input).

- Every guard is an `it.each` over `[curation-on, curation-off]`; a null build fails with "run `npm run build:mds`".
- Known-bad probes go through the same collector that owns the message. The describe-level `seed` asserts the target occurs exactly once (string or RegExp) and that the text changed, so no probe is inert; `probe(collect, body)` never touches the committed tree.
- Guards pin counts of scanner lines, exit lines and fences so a guard cannot pass on nothing; an empty-input call (`collect...('')`) is asserted to report defects.
- Behavior tests run the shipped fences with bash in a scratch folder or repo: the Snyk fence (a stub `snyk` on PATH; several locations, no location, an untouched file, null `results`, awkward names, invalid JSON and a bad range taking the fallback), the counts and table fence (concatenated, invalid and more-than-50-result SARIF, a result with no level, and a second run that repeats no row), and the extension list (the shipped line sets its own locale, and a name with no extension under a dotted folder gives no line; the `pipefail` marker is pinned as text). They skip with a printed reason when `jq` is not installed, and throw if a fence changes shape, so reshaping a fence means updating `shippedSnykFence`, `shippedCountsFence` or `shippedExtensionList`.
- Three pins read one line or one fence, not a whole phase: the CodeQL cleanup (`collectCodeqlCleanupDefects`: the trap before the create line and the plain `rm -rf` after the exit line, in the CodeQL fence only), the Debug spawn's one exact `STATIC_FINDINGS` line, inside its tag pair, that gives the findings to the security analyzer only (`collectSecurityOnlyFindingsDefects`), and the three consecutive severity-mapping lines of the Debug agent (`collectDebugSeverityDefects`, source `src/assets/agents/debug.mds`).
- The outcome-declaration guard stays on the `**Produces:**`/`**Requires:**` lines and the `**Static analysis**:` report line, not on prose, so rewording prose does not break it.
