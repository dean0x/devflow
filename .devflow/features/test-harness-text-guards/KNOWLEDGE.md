# Test Harness - Curation, Decisions, KB-Shape, Review-Gating and Corpus-Wide Text Guards

## Rules

- **KB-INV-3** `DECISIONS_CONTEXT` goes only to agent types whose source lists it among their inputs, and the `CURATION=off` gate sentence precedes the ledger-locate call and index read in every host.
- **KB-INV-5** Each curation variant equals the compiled host resolved on or off by an INDEPENDENT line scanner (not the build's splitter), and no `<!-- curation:... -->` marker survives in any `dist/**/*.md`.
- **KB-INV-9** No curation-ledger ID reaches committed text (`no-ledger-citations`): ledger IDs are machine-local, so committed text states a decision in words.
- **KB-AP-7** `heredoc-quoting` exclusions are pinned as `file:line`: a comment added above an excluded heredoc moves it, so re-pin in the same change.
- **KB-AP-8** The percent-based auto-compact override is out of scope in every spelling and letter case anywhere under `src/`.
- **KB-AP-9** A prompt scan must not read a stale build: `no-config-read` and `claude-dir` fail when a compiled prompt is older than its own host (a command also against the command partials). A shared agent-partial edit is not detected, so run `npm run build:mds` after it.
- **KB-INV-23** Validate's per-file re-run rule is one paragraph of `## Validation Order`, outside the byte-identical `## Running commands` block, which never names PASSED-ALONE, the `Passed alone:` line or the fallback sentence; the rule is the one stated exception to that block's never-re-run rule, and its wait for a re-run past its timeout is the block's own wait for a run past its timeout.
- **KB-INV-24** The re-run procedure lives in the agent-references file `validate/passed-alone.md`; the body keeps a stub that decides the gate alone, with the Read line (through the sanctioned directory line) after the trigger and before the conditions. An unread reference accepts no path, so every failure is REAL.
- **KB-INV-25** The labels are PASSED-ALONE and REAL only, PASSED-ALONE needs a 40-hex BASE_SHA, a re-run is never BLOCKED, and a label never appears in Failures, Parsed References or `details`.
- **KB-AP-17** `validate-passed-alone` pins are substring includes: a negated, appended or contradicted clause around a pinned phrase still passes, so read a reworded rule by eye; the probes only prove removal.
- **KB-AP-18** The label-word check is a banned-word regex over one synonym stem, so a new third label word passes it; add a word to the regex when a review finds one.

## Overview

These guards hold the curation variants, the decisions seam, the feature-knowledge shape and delivery, the handoff and quiet-form wording, Validate's passed-alone re-runs, `/code-review` gating, compaction and import audit, and the text scans that run over the whole prompt corpus. They were split out of `test-harness-prompt-install` (which keeps the prompt doctrine guards and the install-level regression net) with the Rules bullets that only they need; each bullet keeps its original ID. Each guard follows the Guard Conventions in `test-harness`: a named collector, known-bad probes driven through that same collector, loud corpus reads.

## Curation, Decisions, KB-Shape and Review-Gating Guards

- **Curation variants (`tests/curation/`).** `curation-variants.test.ts` holds the splitter (`src/core/curation-variants.ts`): exact-byte assertions on every happy arm and one known-bad probe per refusal kind (nesting, second `off`, unopened `end`, unclosed arm, empty arm, stray or malformed marker, and the retired `<!-- learning:... -->` spelling, which the splitter refuses as `legacy-marker`). `curation-variants-build.test.ts` builds a FIXTURE host with arms under a throwaway `DEVFLOW_MDS_ROOT` and holds the real `dist/curation-off/` to `CURATION_VARIANT_HOSTS` in both directions, with no marker in any `dist/**/*.md`. `curation-variants-arms.test.ts` holds the arms the prompts really carry: each variant equals the compiled host resolved on or off by an INDEPENDENT line scanner; an on arm is curation text and an off arm never is, bar an on/off pair differing only in a list or step number; nothing under `dist/curation-off` holds a curation token except the pinned settings-grammar line; an off agent's frontmatter is its on frontmatter minus the `apply-decisions` preload; no status-line sampler anchor sits inside an arm. The install side (`curation-variants-install.test.ts` against temp trees and the real installer, `-install-e2e.test.ts` driving the built CLI under `sandboxEnv`, HOME seeded with `~/.claude` and the first assertion on installed bytes) is mutation-checked; `requires-closure` reasons over the on variant, `provider-scope` scans `dist/curation-off/{agents,commands}`, and `code-preload.test.ts` has an off arm.
- **Decisions seam (`tests/decisions/decisions-seam.test.ts`, D-DECISIONS-DECLARED-ONLY).** `DECISIONS_CONTEXT` goes only to agent types whose source lists it among their inputs (computed from `resolveAllAgents()`, never typed): every Code-family spawn passes it with no exemption by operation, a site that passes it names a declared type, and every unfenced prose sentence giving it away names a declared receiver, with a literal classification table whose stale rows fail. Spawn sites come from `collectCodeSpawnSites(file, text, agentType?)`, which with no type reads the whole Code family and otherwise validates the type name and reads five shapes (fenced spawn, one-line prose spawn, "Spawn a T agent" prose, a workflow template literal with other options allowed, and the engine partial's pseudo-form `T(agentType:"T", ...)`), so that pseudo-form counts as a Code site in dynamic-build for the compliance-lens and OPERATION guards.
- **Feature-knowledge delivery and shape.** `tests/guards/feature-knowledge-delivery.test.ts` (D-KB-DELIVERY-TIERS, D-KB-LEGACY-FALLBACK): each selected KB reaches an agent as a `--- Feature knowledge: {slug} ---` block (`KB:` path, `Rules:` bullets with IDs, `Headings:` index); the `LOAD_HOSTS` (the commands calling `knowledge_load()` plus `release`) carry the format, the Bash heading listing and the legacy `Rules ({section name}):` label and never the word "Grep"; a spawn line keeps the input name `FEATURE_KNOWLEDGE:` and names its tier's variable (`FEATURE_KNOWLEDGE_RULES` for Evaluate and Harden; none for Validate, Git, Test, Fix, Refactor). `tests/guards/kb-shape.test.ts` (D-KB-RULES-SHAPE) holds the wording in the `feature-knowledge` skill, the Knowledge agent and the write-back prompt: Rules first after the title, stable `KB-AP-n`/`KB-INV-n` IDs, a 30,000-character target and 40,000 ceiling, index lines of at most 300 characters and descriptions of at most 220, "curate, never truncate", the legacy fallback and the refresh rule stated once. The charter's Feature knowledge bullet is held by `collectCharterKnowledgeDefects` in `tests/helpers/charter-guards.ts`, which `agent-name-guards.test.ts` runs on the source and `charter-render.test.ts` on every render.
- **Handoff and quiet form.** `tests/guards/handoff-sections.test.ts` (D-HANDOFF-CAP): `## Phase {N} Implementation Summary` sections of at most 8,192 bytes, each written once by the Code agent that finished the phase; the Code agent, `/implement`'s Handoff Protocol and the dynamic commands' shared convention must agree. `tests/guards/validate-quiet-form.test.ts` (D-VALIDATE-QUIET-FORM): the Validation Order table's Quiet form column per row, one fallback sentence (`FALLBACK`: after a failed Test row, re-run each failed test file alone, once, verbose, never the suite; the one exception to the never-re-run rule under Running commands) OUTSIDE the byte-identical `## Running commands` block, and one quiet-form bullet in each of the language rules. The block-intrusion check reports the block if it carries the words `failed Test row`.
- **Validate's passed-alone re-runs.** `tests/guards/validate-passed-alone.test.ts` drives every arm through the named collector `collectPassedAloneDefects(body, readReference, skillMd)`, and every probe changes a real text and runs that same collector. After a failed Test row, Validate re-runs each of the first 20 failed test files alone, once, and runs them one at a time. A re-run that passes its explicit Bash timeout moves to the background; the end notice re-invokes Validate, which never polls, reads the call's own last `EXIT=` line, then its log. After one re-run passes its timeout and is read, the rest are REAL and are not re-run; a re-run that does not start, or has no `EXIT=` line read, is REAL. It labels a file PASSED-ALONE (a timeout, spawn or resource cause that the test runner reports; a file outside the changed set, which is the branch diff plus the working tree; a tracked and checked path; a re-run of only that file with no name filter and `EXIT=0`; tests that ran and passed; only with a 40-hex BASE_SHA) or REAL (everything else). An assertion failure is REAL, also when its message names a timeout, so a child-process timeout that a test reports as an assertion stays REAL (the repair is tracked in #332). PASS needs PASSED-ALONE files to explain every failure. Only Validate's own report shows the `Passed alone:` line, not the /implement summary or the PR body. The body holds the trigger and the label conditions; the reference `references/validate/passed-alone.md` holds the numbered checks; `SKILL.md` lists it in its Files row (`| validate/passed-alone.md | Validate | A Test row failed |`). The collector reads five things. (1) `BODY_CLAUSES` are substring pins in `## Validation Order`, one per clause of the trigger, the Read line, the conditions, the REAL default and the PASS rule. (2) `REFERENCE_CLAUSES` are substring pins on the reference, one per rule sentence, and steps 3, 5 and 9 of the reference equal `FAIL_CLOSED_STEPS` byte for byte, because they hold the fail-closed rules and the reference has no byte headroom. (3) Structural checks: `TRIGGER`, `READ_LEAD` and the conditions sit in ONE paragraph in that order (a blank line splits the Read from its trigger; a Read after the re-runs would let a log path reach a command unchecked); the `Passed alone:` line sits in `## Output` between the commands table and `### Failures` and keeps its bound (`OUTPUT_LINE_BOUND`); the path in the body's Read line is the one reference path and the file exists there; a Read worded to re-run every path it does not reject (fail-open) is reported. (4) Wording: a name filter is allowed only after the word "no", the reference names no `devflow:` token, and a banned label word fails (KB-AP-18). (5) The wait and the limit: `WAIT_RULE`, `NO_RESULT_RULE` and `COUNT_BOUND_RULE` pin the wait sentences whole, and `SWAPS` negates "wait" and "never poll" in them; `CEILING_RULE` pins the re-run's Bash timeout at the ceiling (600000 ms, or `BASH_MAX_TIMEOUT_MS` when set), never a fixed number, and `GO_RULE` pins the go rule's result (a file is REAL when its directory holds a changed file); the body and the reference name no form of a wrong limit that `WRONG_LIMIT` matches; a second collector, `collectWrongLimitSiteDefects(docs, knowledge)`, applies the same check to the Validation step of `docs/commands.md` and to this entry, and a third, `collectDocsWaitDefects(docs)`, holds the wait sentence of that Validation step. Each removal probe's `seed()` fails the test when its text did not change, so a pin whose phrase was reworded fails loudly instead of passing as a no-op. Neighbours: `report-cap` names the `Passed alone:` line among the exempt fields and has a probe that drops it from the cap line; `validate-lint-pack` holds `validate-body-max` and `agent-references` holds `validate-passed-alone-ref-max` (both lowered, never raised); `claude-dir` `SITE_ROWS` carries a row for the Validate body's reference-path line, as it does for the Synthesize and Curate bodies.
- **`/code-review` gating and the language stamp.** `tests/guards/code-review-diff-gating.test.ts` (D-DIFF-CLASS-GATE, D-DIFF-FILE-ONCE, and the prompt side of D-LANGUAGE-FOCUS-STAMP, in both curation variants): classification order and both fail-safes, exact reduced focus sets, one `diff.patch` per worktree written by redirect, `DIFF_FILE`/`DIFF_RANGE` spawn keys, every `git ... diff` either the `--name-only` listing or a redirect into a patch file, no `test -f` probe in any compiled command, and `/dynamic-build` carrying none of it. The installer side is `tests/installer/language-stamp.test.ts` (injected temp dirs: the pure `installedLanguageFocuses`, the line rewrite, install, partial install, the `uninstall --plugin` re-stamp, and the converge CARRYING the installed stamp rather than re-stamping) and `language-stamp-e2e.test.ts` (built CLI under `sandboxEnv`); `skill-references` holds the stamp paragraph's canonical focus names (`language-gate-focuses`, equal to what `renderLanguageStamp(installedLanguageFocuses(DEVFLOW_PLUGINS))` writes) and `claude-dir` holds `/code-review` to its one gate-level read.
- **Compaction and import audit.** `tests/guards/no-autocompact-pct-override.test.ts`: the percent-based auto-compact override is out of scope in every form, so no spelling of its name (any letter case) appears anywhere under `src/`, with a reach arm naming a sentinel per surface class. `tests/session-start-compact.test.ts` holds Sections 5 and 6 of `session-start-context` (the resume directive, pinned by `compact-directive-max-chars`, and the CLAUDE.md import-audit fast path and stamp) through PATH farms of recording `jq`/`node` wrappers; `tests/core/claude-md-audit.test.ts` holds the audit script and its facade.

## Corpus-Wide Text Guards

- **`tests/guards/no-ledger-citations.test.ts`**: no curation-ledger ID (the ADR or PF prefix followed by three digits) reaches committed text, because the ledger is gitignored and numbered per machine. It reads the worktree as git lists it (tracked plus untracked-unignored files; binary files skipped). A FULL BAN reports an ID anywhere in `src/**`, `scripts/**`, the root `vitest*.config.ts` files, `docs/**`, the root prose (`CLAUDE.md`, `README.md`, `CONTRIBUTING.md`, `.devflow/conventions.md`, `.release/RELEASE-FLOW.md`), `.devflow/features/index.md`, every feature `KNOWLEDGE.md` and `tests/fixtures/numeric-floors.json`. In `tests/**/*.ts` only commentary is read (comments, `describe`/`it`/`test` titles and `expect(value, message)` messages, pulled out by a strings-first lexer so a `//` inside a string is never a comment): an ID in a citation shape (after `applies`, `avoids`, `per` or `see`, in parentheses or brackets, or possessive) is always reported, and any other ID is reported unless the same file holds it as data outside its commentary. `CHANGELOG.md`, the golden and install-snapshot fixtures and `.devflow/curation/**` are excluded; placeholders carry no three digits and pass. Seeded probes drive the same `collectLedgerViolations` collector the live arms use (a red probe per full-ban root and per test-arm shape; green probes for placeholders, data, Jira-style keys, longer numbers, strings, regex literals and excluded paths), and reach checks (`SCANNED_AREAS`, each `ROOT_PROSE` file, an extractor check on real comments, titles and messages) fail an arm that would pass over nothing.
- **`tests/guards/claude-dir.test.ts`** (D-CLAUDE-DIR-PROMPTS): an allowlist over the full prompt corpus (compiled commands, agents, references, skills, rules, curation-off builds, the compaction line). Per file, each sanctioned resolution line (the installer's rule: `CLAUDE_CONFIG_DIR` when absolute, else `$HOME/.claude`) and each file-scoped rule prose is removed; the residue is reported for the variable name, a path into the home Claude directory (a project-local `.claude/` path is a negative control), an unrooted install path, and a `d=` or `for d in` reassignment. Each `$d/` use needs the sanctioned line earlier on the same line, because each Bash call is a fresh shell. A new read site needs a `SITE_ROWS` row; new rule prose needs a file-scoped `ALLOWED_RULE_PROSE` entry. /plan's two reads are held by `collectPlanDirReadDefects`. Its dist currency check compares each compiled prompt with its own host only (KB-AP-9). It adds liveness checks and a behavioural run of the sanctioned line. `tests/skill-references.test.ts` Format 3 holds that compiled commands name no skill by install path (non-vacuity: an extractor probe and the stamp paragraph); its companion-skill check holds all five catalog intent rows, "(none)" included, to the compiled command both ways (`collectCompanionDrift`).
- **`tests/guards/docs-root.test.ts`** (D-DOCS-ROOT): every `.devflow/docs` path in a compiled command is rooted at `{worktree}` (`_partials/_docs_root.mds`), relative only in an agent field that travels with `WORKTREE_PATH`, or a named live exemption; `tests/commands/partials-root.test.ts` runs the resolution on real git.
- **`tests/guards/settings-atomic-write.test.ts`** (D-SETTINGS-ATOMIC): every `settings.json` write under `src/` goes through `writeSettingsFileAtomic`.
- **`tests/guards/no-config-read.test.ts`**: no prompt reads `project.json` or `config.json` itself; the scan covers compiled commands, agents, references, skills, rules, the ambient charter and every directive a hook emits, and it fails when a compiled prompt is older than its own host rather than scan a stale build (KB-AP-9).
- **`tests/guards/heredoc-quoting.test.ts`**: an unquoted `<<EOF` heredoc scan over the prompt corpus; its frozen exclusions are `file:line`, so a comment added above an excluded heredoc moves it and the guard reports both a "new" heredoc and a stale exclusion.
- **`tests/hook-log-paths.test.ts`** (D-LOG-DIR-CAP, hook side): `devflow_log_dir` and the debug trace's folder creation prune to the cap under a temp HOME; the shell cap is pinned equal to `MAX_HOOK_LOG_DIRS`.

## Gotchas

**KB-AP-7: frozen pins.** `heredoc-quoting` names its excluded heredocs by file and line, so any edit above one re-sets the pins in the same change.

**KB-AP-17: substring pins accept the wrong sentence.** `BODY_CLAUSES` and `REFERENCE_CLAUSES` are `includes` checks, and a removal probe only proves that deleting the phrase is reported. A rewrite that keeps a pinned phrase but negates it ("never re-run" turned into "re-run"), appends a contradicting clause, or moves it into the wrong sentence passes every pin. The guards that do check shape (one paragraph and order, the Output line between the table and `### Failures`, the name-filter wording, the fail-open Read) each cover one known way this goes wrong; a new way needs a new check, not a new pin. Editing a pinned sentence on purpose means editing its clause entry in the same change, because the removal probe's `seed()` fails when the old phrase is gone.

**KB-AP-18: the label check bans one stem.** The body and the reference are scanned with a regex for a single synonym of the unwanted third label; a different new label word passes. The label set is held by the rule sentences (PASSED-ALONE needs all of the listed conditions, else REAL), so a review that finds a third label word adds it to the regex and a probe, rather than trusting the scan.

**KB-INV-23 to KB-INV-25: the sentence is shared between guards.** `FALLBACK` in `validate-quiet-form` and `TRIGGER` in `validate-passed-alone` are the same opening sentence, so rewording it moves both pins. The Read line's `$d/skills/devflow:agent-references/references/...` path is matched by `NAMED_PATH` and counted by `claude-dir` `SITE_ROWS`; a second reference read from the Validate body needs a row there and its own SKILL.md Files row. The reference itself must not name a `devflow:` token (the body's Read line is the only place the install path is spelled), and a full run and a re-run past their timeout are both waited for and read, with the same end: a full run with no `EXIT=` line read is BLOCKED, and a re-run that does not start or has no `EXIT=` line read is REAL, never BLOCKED. The reference states both outcomes (step 3 for the full run, step 8 for the re-run); the body's Validation Order paragraph states only the re-run's, and the `## Running commands` block states the full run's.
