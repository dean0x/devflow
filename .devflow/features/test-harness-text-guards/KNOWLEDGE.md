# Test Harness - Learning, Decisions, KB-Shape, Review-Gating and Corpus-Wide Text Guards

## Rules

- **KB-INV-3** `DECISIONS_CONTEXT` goes only to agent types whose source lists it among their inputs, and the `LEARNING=off` gate sentence precedes the ledger-locate call and index read in every host.
- **KB-INV-5** Each learning variant equals the compiled host resolved on or off by an INDEPENDENT line scanner (not the build's splitter), and no `<!-- learning:... -->` marker survives in any `dist/**/*.md`.
- **KB-INV-9** No learning-ledger ID reaches committed text (`no-ledger-citations`): ledger IDs are machine-local, so committed text states a decision in words.
- **KB-AP-7** `heredoc-quoting` exclusions are pinned as `file:line`: a comment added above an excluded heredoc moves it, so re-pin in the same change.
- **KB-AP-8** The percent-based auto-compact override is out of scope in every spelling and letter case anywhere under `src/`.
- **KB-AP-9** A prompt scan must not read a stale build: `no-config-read` and `claude-dir` fail when a compiled prompt is older than its own host (a command also against the command partials). A shared agent-partial edit is not detected, so run `npm run build:mds` after it.

## Overview

These guards hold the learning variants, the decisions seam, the feature-knowledge shape and delivery, the handoff and quiet-form wording, `/code-review` gating, compaction and import audit, and the text scans that run over the whole prompt corpus. They were split out of `test-harness-prompt-install` (which keeps the prompt doctrine guards and the install-level regression net) with the Rules bullets that only they need; each bullet keeps its original ID. Each guard follows the Guard Conventions in `test-harness`: a named collector, known-bad probes driven through that same collector, loud corpus reads.

## Learning, Decisions, KB-Shape and Review-Gating Guards

- **Learning variants (`tests/learning/`).** `learning-variants.test.ts` holds the splitter (`src/core/learning-variants.ts`): exact-byte assertions on every happy arm and one known-bad probe per refusal kind (nesting, second `off`, unopened `end`, unclosed arm, empty arm, stray or malformed marker). `learning-variants-build.test.ts` builds a FIXTURE host with arms under a throwaway `DEVFLOW_MDS_ROOT` and holds the real `dist/learning-off/` to `LEARNING_VARIANT_HOSTS` in both directions, with no marker in any `dist/**/*.md`. `learning-variants-arms.test.ts` holds the arms the prompts really carry: each variant equals the compiled host resolved on or off by an INDEPENDENT line scanner; an on arm is learning text and an off arm never is, bar an on/off pair differing only in a list or step number; nothing under `dist/learning-off` holds a learning token except the pinned settings-grammar line; an off agent's frontmatter is its on frontmatter minus the `apply-decisions` preload; no status-line sampler anchor sits inside an arm. The install side (`learning-variants-install.test.ts` against temp trees and the real installer, `-install-e2e.test.ts` driving the built CLI under `sandboxEnv`, HOME seeded with `~/.claude` and the first assertion on installed bytes) is mutation-checked; `requires-closure` reasons over the on variant, `provider-scope` scans `dist/learning-off/{agents,commands}`, and `code-preload.test.ts` has an off arm.
- **Decisions seam (`tests/decisions/decisions-seam.test.ts`, D-DECISIONS-DECLARED-ONLY).** `DECISIONS_CONTEXT` goes only to agent types whose source lists it among their inputs (computed from `resolveAllAgents()`, never typed): every Code-family spawn passes it with no exemption by operation, a site that passes it names a declared type, and every unfenced prose sentence giving it away names a declared receiver, with a literal classification table whose stale rows fail. Spawn sites come from `collectCodeSpawnSites(file, text, agentType?)`, which with no type reads the whole Code family and otherwise validates the type name and reads five shapes (fenced spawn, one-line prose spawn, "Spawn a T agent" prose, a workflow template literal with other options allowed, and the engine partial's pseudo-form `T(agentType:"T", ...)`), so that pseudo-form counts as a Code site in dynamic-build for the compliance-lens and OPERATION guards.
- **Feature-knowledge delivery and shape.** `tests/guards/feature-knowledge-delivery.test.ts` (D-KB-DELIVERY-TIERS, D-KB-LEGACY-FALLBACK): each selected KB reaches an agent as a `--- Feature knowledge: {slug} ---` block (`KB:` path, `Rules:` bullets with IDs, `Headings:` index); the `LOAD_HOSTS` (the commands calling `knowledge_load()` plus `release`) carry the format, the Bash heading listing and the legacy `Rules ({section name}):` label and never the word "Grep"; a spawn line keeps the input name `FEATURE_KNOWLEDGE:` and names its tier's variable (`FEATURE_KNOWLEDGE_RULES` for Evaluate and Harden; none for Validate, Git, Test, Fix, Refactor). `tests/guards/kb-shape.test.ts` (D-KB-RULES-SHAPE) holds the wording in the `feature-knowledge` skill, the Knowledge agent and the write-back prompt: Rules first after the title, stable `KB-AP-n`/`KB-INV-n` IDs, a 30,000-character target and 40,000 ceiling, index lines of at most 300 characters and descriptions of at most 220, "curate, never truncate", the legacy fallback and the refresh rule stated once. The charter's Feature knowledge bullet is held by `collectCharterKnowledgeDefects` in `agent-name-guards.test.ts`.
- **Handoff and quiet form.** `tests/guards/handoff-sections.test.ts` (D-HANDOFF-CAP): `## Phase {N} Implementation Summary` sections of at most 8,192 bytes, each written once by the Code agent that finished the phase; the Code agent, `/implement`'s Handoff Protocol and the dynamic commands' shared convention must agree. `tests/guards/validate-quiet-form.test.ts` (D-VALIDATE-QUIET-FORM): the Validation Order table's Quiet form column per row, one fallback sentence (re-run only the failing test verbosely, never the suite) OUTSIDE the byte-identical `## Running commands` block, and one quiet-form bullet in each of the language rules.
- **`/code-review` gating and the language stamp.** `tests/guards/code-review-diff-gating.test.ts` (D-DIFF-CLASS-GATE, D-DIFF-FILE-ONCE, and the prompt side of D-LANGUAGE-FOCUS-STAMP, in both learning variants): classification order and both fail-safes, exact reduced focus sets, one `diff.patch` per worktree written by redirect, `DIFF_FILE`/`DIFF_RANGE` spawn keys, every `git ... diff` either the `--name-only` listing or a redirect into a patch file, no `test -f` probe in any compiled command, and `/dynamic-build` carrying none of it. The installer side is `tests/installer/language-stamp.test.ts` (injected temp dirs: the pure `installedLanguageFocuses`, the line rewrite, install, partial install, the `uninstall --plugin` re-stamp, and the converge CARRYING the installed stamp rather than re-stamping) and `language-stamp-e2e.test.ts` (built CLI under `sandboxEnv`); `skill-references` holds the stamp paragraph's canonical focus names (`language-gate-focuses`, equal to what `renderLanguageStamp(installedLanguageFocuses(DEVFLOW_PLUGINS))` writes) and `claude-dir` holds `/code-review` to its one gate-level read.
- **Compaction and import audit.** `tests/guards/no-autocompact-pct-override.test.ts`: the percent-based auto-compact override is out of scope in every form, so no spelling of its name (any letter case) appears anywhere under `src/`, with a reach arm naming a sentinel per surface class. `tests/session-start-compact.test.ts` holds Sections 5 and 6 of `session-start-context` (the resume directive, pinned by `compact-directive-max-chars`, and the CLAUDE.md import-audit fast path and stamp) through PATH farms of recording `jq`/`node` wrappers; `tests/core/claude-md-audit.test.ts` holds the audit script and its facade.

## Corpus-Wide Text Guards

- **`tests/guards/no-ledger-citations.test.ts`**: no learning-ledger ID (the ADR or PF prefix followed by three digits) reaches committed text, because the ledger is gitignored and numbered per machine. It reads the worktree as git lists it (tracked plus untracked-unignored files; binary files skipped). A FULL BAN reports an ID anywhere in `src/**`, `scripts/**`, the root `vitest*.config.ts` files, `docs/**`, the root prose (`CLAUDE.md`, `README.md`, `CONTRIBUTING.md`, `.devflow/conventions.md`, `.release/RELEASE-FLOW.md`), `.devflow/features/index.md`, every feature `KNOWLEDGE.md` and `tests/fixtures/numeric-floors.json`. In `tests/**/*.ts` only commentary is read (comments, `describe`/`it`/`test` titles and `expect(value, message)` messages, pulled out by a strings-first lexer so a `//` inside a string is never a comment): an ID in a citation shape (after `applies`, `avoids`, `per` or `see`, in parentheses or brackets, or possessive) is always reported, and any other ID is reported unless the same file holds it as data outside its commentary. `CHANGELOG.md`, the golden and install-snapshot fixtures and `.devflow/learning/**` are excluded; placeholders carry no three digits and pass. Seeded probes drive the same `collectLedgerViolations` collector the live arms use (a red probe per full-ban root and per test-arm shape; green probes for placeholders, data, Jira-style keys, longer numbers, strings, regex literals and excluded paths), and reach checks (`SCANNED_AREAS`, each `ROOT_PROSE` file, an extractor check on real comments, titles and messages) fail an arm that would pass over nothing.
- **`tests/guards/claude-dir.test.ts`** (D-CLAUDE-DIR-PROMPTS): an allowlist over the full prompt corpus (compiled commands, agents, references, skills, rules, learning-off builds, the compaction line). Per file, each sanctioned resolution line (the installer's rule: `CLAUDE_CONFIG_DIR` when absolute, else `$HOME/.claude`) and each file-scoped rule prose is removed; the residue is reported for the variable name, a path into the home Claude directory (a project-local `.claude/` path is a negative control), an unrooted install path, and a `d=` or `for d in` reassignment. Each `$d/` use needs the sanctioned line earlier on the same line, because each Bash call is a fresh shell. A new read site needs a `SITE_ROWS` row; new rule prose needs a file-scoped `ALLOWED_RULE_PROSE` entry. /plan's two reads are held by `collectPlanDirReadDefects`. Its dist currency check compares each compiled prompt with its own host only (KB-AP-9). It adds liveness checks and a behavioural run of the sanctioned line. `tests/skill-references.test.ts` Format 3 holds that compiled commands name no skill by install path (non-vacuity: an extractor probe and the stamp paragraph); its companion-skill check holds all five catalog intent rows, "(none)" included, to the compiled command both ways (`collectCompanionDrift`).
- **`tests/guards/docs-root.test.ts`** (D-DOCS-ROOT): every `.devflow/docs` path in a compiled command is rooted at `{worktree}` (`_partials/_docs_root.mds`), relative only in an agent field that travels with `WORKTREE_PATH`, or a named live exemption; `tests/commands/partials-root.test.ts` runs the resolution on real git.
- **`tests/guards/settings-atomic-write.test.ts`** (D-SETTINGS-ATOMIC): every `settings.json` write under `src/` goes through `writeSettingsFileAtomic`.
- **`tests/guards/no-config-read.test.ts`**: no prompt reads `project.json` or `config.json` itself; the scan covers compiled commands, agents, references, skills, rules, the ambient charter and every directive a hook emits, and it fails when a compiled prompt is older than its own host rather than scan a stale build (KB-AP-9).
- **`tests/guards/heredoc-quoting.test.ts`**: an unquoted `<<EOF` heredoc scan over the prompt corpus; its frozen exclusions are `file:line`, so a comment added above an excluded heredoc moves it and the guard reports both a "new" heredoc and a stale exclusion.
- **`tests/hook-log-paths.test.ts`** (D-LOG-DIR-CAP, hook side): `devflow_log_dir` and the debug trace's folder creation prune to the cap under a temp HOME; the shell cap is pinned equal to `MAX_HOOK_LOG_DIRS`.

## Gotchas

**KB-AP-7: frozen pins.** `heredoc-quoting` names its excluded heredocs by file and line, so any edit above one re-sets the pins in the same change.
