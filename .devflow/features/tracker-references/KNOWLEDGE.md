# Tracker References

## Overview

`src/assets/agents/git.mds` — the always-loaded, per-spawn-billed Git agent prompt (PF-026) — is a **provider-independent contract**; the per-provider mechanics and the PR-host mechanics live in generated skill references that only the operations needing them load. Three tracker providers are registered: `github`, `jira` and `linear`. A second, orthogonal axis sits beside the provider one: eight PR/review operations (`PR_HOST_OPS`) whose mechanics are provider-INDEPENDENT — pull requests, PR reviews and PR checks stay on GitHub under every tracker, so those bodies are generated once, under `references/pr/`, and installed under every provider unconditionally. This KB owns the reference tree itself — what the build emits, what an install carries, what the byte budget gates and how the installer converges it. The provider-SELECTION dimension built on top of it — how a provider is chosen, the background Tracker agent, hook Section 3, `--emit` and the reader-side preamble — is owned by `.devflow/features/tracker-feature/KNOWLEDGE.md`.

**The build and the install are different sets, and confusing them is the standing trap.** The build compiles every provider plus every provider-independent tree: 42 generated references (`generatedReferenceManifest()` — 10 GitHub tracker ops + 10 Jira + 10 Linear + 8 PR-host ops + 3 cross-cutting documents + the tool-call contract), and the tarball ships all of them. An install carries `{github tracker} ∪ {pr-host} ∪ {cross-cutting} ∪ {selected provider}` — `installedReferenceManifest({provider})`, 21 paths for `github` and 32 for `jira`/`linear`, with the tool-call contract `tracker/_mcp.md` landing **iff** the provider is MCP-backed. A third number is the one the byte budget gates: the per-SPAWN loaded set, which is neither of the first two, and which now has a fourth row (the PR-host spawn) beside the three tracker-provider rows.

The system has five moving parts that must be understood together: (1) the contract in `git.mds` plus the provider-resolution preamble that is the *single* place a provider token is resolved; (2) the MDS build machinery (`VARIANT_MODULES`, `expandVariants`, `splitVariantSections`) that fans reference modules out into per-op files — five modules now, one of them provider-independent; (3) the byte-budget guard that makes the split's payoff a tested property rather than an assumption, with its own ceiling row for the PR-host path; (4) the single-authority and reachability guards that keep one normative sentence to one owner and every generated file nameable by something the agent reads, now scanning the PR-host tree alongside the provider trees; (5) the installer's converge-not-merge overlay that gets the selected provider's files — and the PR-host tree, under every provider — into a user's `~/.claude/skills/devflow:git/references/` tree atomically.

Devflow-wide prompt diet is tracked in issue **#342** (related #326, #333) — broader per-spawn budget work beyond this feature's scope. Issue **#326** is the PR-host split described throughout this KB; it is DONE, and every ceiling, floor and guard below is its end state.

## System Context

`git.md` is compiled from `src/assets/agents/git.mds` (`output-dir: dist/agents`) and is re-sent on every Git agent spawn — a single `/resolve` run spawns it 7+ times, so every character in it is a per-run multiplier (PF-026). Before any split it was 992 L / 65,677 ch (66,180 bytes), interleaving each operation's provider-neutral **Input:**/**Output:**/**Degradation (D4):** contract with its GitHub-specific `gh` invocations, header names and rate-limit detectors. That interleaving was also the root of two other defects: PF-023's ~30 filename-composition sinks instead of one provider-resolution convergence point (GAP-10), and the D4/D11 cross-cutting invariants declaring themselves provider-independent while their concrete detectors were GitHub-only (GAP-03 — two authorities on the secret-redaction path). After both splits (the tracker-op split and #326's PR-host split), `dist/agents/git.md` measures 45,103 ch / 801 lines, against a ceiling of 45,150.

The split generalizes to a named decision, **ADR-025**: when a monolithic prompt is split into a provider-independent contract and per-provider mechanics, classify every guard literal individually and widen only where the literal provably moved — never blanket-widen a whole guard suite to a joined corpus just to turn it green. That rule shaped the original tracker split (`fetch-issues-batch` moved only its step 2, `fetch-issue` kept its step 1, specifically so their retained literals could stay `'sole'`-scoped) and shaped #326 identically: every guard `#326` re-pointed from `'sole'` to `'union'` carries its own known-bad probe (`sinkCorpusWithoutPrHost()`) proving the widening is load-bearing rather than cosmetic. That rule is the lens for reading every `extractOpSectionFromCorpus(..., { mode })` call in `tests/git-agent.test.ts`. **ADR-027**'s merge-gate amendment records the ceiling's side of it: the phase-named pair (`budget-git-md` / `budget-git-md-p3`) was kept at that merge as a deliberate, time-boxed exception to ADR-003, with #326 named as its exit — which is why #326 collapses it into one number.

## Component Architecture

### 1. The contract/mechanics split — tracker ops and PR-host ops

Per tracker operation, `git.mds` retains: the `## Operation: {name}` heading, prose, `**Input:**`, `**Degradation (D4):**` (where present), `**Output:**` (including any `### Handoff Values` block), and a one-line `**Mechanics:**` pointer. All ten tracker pointers are the same 56-character line — `**Mechanics:** load this operation's provider reference.` — condensed to it from a 147-character per-op variant, since the *where* and the *when* both belong to `## Tracker input contract` and restating them per op bought nothing but per-spawn characters. (An eleventh `**Mechanics:**` line, `learn-conventions`'s, is deliberately long-form: it names `references/learn-conventions.md` directly and carries the load condition that no other op has — load ONLY when `.devflow/conventions.md` is absent.) The op's `### Process` mechanics body moves to `references/tracker/github/{op}.md`, generated from `src/assets/mds/tracker/_github.mds`.

Ten ops split this way (`TRACKER_GITHUB_OPS` in `src/core/mds-variants.ts`): `setup-task`, `fetch-issue`, `fetch-issues-batch`, `manage-debt`, `create-release`, `gather-release-evidence`, `backlink-shipped-issues`, `ensure-traceable-issue`, `post-wave-report`, `ensure-pr-ready`. Not every op moves wholesale — `create-release` moves only its `## Closed Issues` enrichment bullet; `gather-release-evidence` moved as **two separate commits** ([DR-17]).

**Eight further operations split the same way but along the OTHER axis (#326): the PR-host split.** `PR_HOST_OPS` — `ensure-pr-ready`, `validate-branch`, `post-review-summary`, `check-ci-status`, `fetch-review-threads`, `resolve-review-threads`, `post-resolution-summary`, `check-merge-readiness` — generates once from `src/assets/mds/git/_pr.mds` into `references/pr/{op}.md` (`PR_HOST_DESTINATION_ROOT = 'pr'`), installed under **every** provider unconditionally, never fanned per provider. The reason is provider-independence itself: pull requests, PR reviews and PR checks stay on GitHub whatever the issue tracker is, so filing them under `tracker/github/` would make a jira or linear user's PR mechanics read as their tracker's, and fanning them across three provider directories would ship three identical trees. `ensure-pr-ready` is a member of **both** rosters by design, and the two halves do not overlap: the PR skeleton (branch/commit/push, create, retitle, and step 4b's PR-host half — the open-PR lookup and the scrub-then-edit) is a PR-host fact and lives in `references/pr/ensure-pr-ready.md`; step 4b itself — the issue-number lookup and the link line it renders — is a tracker fact and lives in `references/tracker/{provider}/ensure-pr-ready.md`, which publishes that line through the PR-host half. The operation carries one pointer to each — `**PR mechanics:** load references/pr/ensure-pr-ready.md` followed by `**Mechanics:** load this operation's provider reference.` `PR_HOST_OPS` has exactly 8 entries, which is `MIN_VARIANT_PAIRS` exactly — not a coincidence: the module cannot be grown an operation at a time (dropping one fails the build on purpose per GAP-42/PF-018).

Each PR-host op's `git.mds` section keeps its contract (`**Input:**`, `**Output:**`, `**Degradation (D4):**`) and gains a `**PR mechanics:** load references/pr/{op}.md` pointer where its old `### Process` block used to be. `ensure-pr-ready` carries two pointers (both `**PR mechanics:**` and `**Mechanics:**`); the other seven carry one. The preamble's "Load the mechanics" bullet (`## Tracker input contract`) states the second pointer vocabulary explicitly: an operation whose section carries a `**PR mechanics:**` pointer reads the file that pointer names — PR-host steps, a fixed literal, the same file under every provider — and it MUST NEVER spell `references/pr/` on that convergence-point line the way the tracker vocabulary spells `references/tracker/{provider}/`; the PR-host pointer is per-op literal text, not composed from the provider token, because the file is the same file under every provider. "Merged step order" was widened to say a loaded reference's steps carry the operation's own step numbers and interleave with the steps stated in `git.mds` — **with two references loaded it is still one sequence** (an op can load both a tracker reference and a PR-host reference in the same spawn, e.g. `ensure-pr-ready`). One op loads two PR-host files: `check-merge-readiness`' step 3 reuses `check-ci-status`'s classification and names `references/pr/check-ci-status.md` for loading, and the budget model charges both files to it. `tests/tracker/reference-reachability.test.ts` holds both rules: every "same logic as `{op}`" in a `pr/` file names that op's `pr/` file, and no step label is supplied by two files loaded for the same op under any provider.

**Written exclusions — controls that stay in the agent by rule, not by oversight.** `## Comment-sink scrub (D11)` is the first, and `git.mds` states it itself: the section never moves, and only the concrete D11 sink calls (`gh pr comment`, `gh pr create --body-file`, `gh pr edit --body-file`, the GraphQL mutation) relocate into the PR-host bodies that own each sink. A control a spawn can decline to load is no longer guaranteed to run before the write, and PF-027 requires an append-only sink's containment control to precede it. The other three are stated once in `src/assets/mds/git/_pr.mds`'s own header:
- The two summary operations' sentence naming `references/publication-gate.md` — D10's scope property [DR-20](i) is asserted over `git.md` **alone**, so the naming line stays in the agent even though the step order it instantiates moved.
- `post-resolution-summary`'s op-local non-reproduction clause — stays a distinct paragraph in `git.mds` immediately after the `**PR mechanics:**` pointer (Principle 8's containment obligation must be readable from the operation's own section, not only from the generated body).
- `resolve-review-threads`' step 3, the D9 gate application — the D9 predicate has one authority, and `references/decision-markers.md` is where the reference tree states it; step 3 interleaves numerically between the PR-host body's steps 1–2 and its step 4, making `resolve-review-threads` the first **three-part** straddle (reference / agent / reference, in step order — see the fixture Gotcha below).

Moved, by contrast: `ensure-pr-ready`'s op-local scrub-then-sink statements — step 4a's create and step 4b's PR-host half (the open-PR lookup and `gh pr edit --body-file`) — which sit in `references/pr/ensure-pr-ready.md` beside the calls they gate; the D11 section still governs both from the agent, and the provider reference's step 4b only resolves the issue and renders the link line.

Headings below each PR-host section's own `## Operation:` anchor are `###` by grammar, not by taste: a column-0 `## ` line outside a fence terminates the section for every guard that reads it through `extractOpSectionFromCorpus` (PF-063) — the `## ` lines inside the two summary operations' compose fences are indented payload and stay exactly as authored.

**Principle 8 (#328).** The cross-op non-reproduction rule — no comment-posting operation (`post-review-summary`, `post-resolution-summary`, `post-wave-report`, `backlink-shipped-issues`) may reproduce verbatim `<external-thread>` or `<untrusted-issue-body>` content — is stated as its own sub-bullet under Principle 8's marker-neutralisation bullet in `git.mds` (`## Principles`, near the file's end), naming all four operations by name. This sits **beside**, not instead of, `post-resolution-summary`'s op-local clause: the global sub-bullet is the one place a reader confirms the rule spans every posting op, and the op-local clause is what keeps it readable from that op's own section per PF-027's rule.

### 2. The provider-resolution preamble

The preamble — `## Tracker provider resolution` and `## Tracker input contract` — sits between the D4 block and `## Comment-sink scrub (D11)` in `git.mds`, currently **35 lines** (ceiling 36, `PREAMBLE_MAX_LINES`). It is the *single* convergence point PF-023 requires (GAP-10): a static path map (`github → tracker/github/`, `jira → tracker/jira/`, `linear → tracker/linear/`), reject-never-repair token normalisation, and "select, never concatenate" — the validated token only *selects* a hardcoded directory, it is never joined into a path. Resolution reads the per-repo `tracker` key in `.devflow/config.json`, which only narrows, together with the manifest's provider, and defaults to `github`.

`## Tracker input contract` (also in the preamble region) carries: the capability-hoist rule; the Read-tool rule for `tracker.md` (PF-035); the size bound; the **single** load-instruction sentence — the only line in `git.md` that composes a `references/tracker/{provider}/{op}.md` path — now paired, in the same bullet, with the PR-host pointer vocabulary's own sentence (a fixed literal, never composed); and the **merged step order** rule, widened for two-reference ops. An operation with no `**Mechanics:**` or `**PR mechanics:**` pointer loads nothing and degrades nothing.

The D4/D11 **legend** (`## Operations` table footer in `git.md`) keeps only the D4 and D11 rows. D1–D3/D5–D10 moved to `references/decision-markers.md`, a `kind: 'named'` cross-cutting document.

### 3. Handoff Values — the producer side of the issue-capture contract

`setup-task` and `fetch-issue`'s Output blocks each end with a `### Handoff Values` block (PR link line, branch token, issue ID) — unaffected by #326. `code.md` re-checks `ISSUE_PR_LINK`'s shape against the resolved provider before pasting it (Responsibility 7). `fetch-issues-batch`'s mechanics project each issue's `state` (`OPEN`/`CLOSED`) into a `**State**: {state}` line.

### 4. The build side (owned in detail by `feature-knowledge-system`; tracker-specific parts here)

`src/core/mds-variants.ts` defines the registry: `VariantModule { source, subdir, kind, ops }`, a closed `VARIANT_MODULES` array with **five** entries —
- `_github.mds` (`subdir: 'tracker/github'`, `kind: 'fanout'`, `ops: TRACKER_GITHUB_OPS`) — one file per tracker op;
- `_jira.mds` (`subdir: 'tracker/jira'`, `kind: 'fanout'`, `ops: TRACKER_OPS`) and `_linear.mds` (`subdir: 'tracker/linear'`, same ops) — the two MCP-backed providers;
- `_pr.mds` (`subdir: PR_HOST_DESTINATION_ROOT = 'pr'`, `kind: 'fanout'`, `ops: PR_HOST_OPS`) — the provider-independent PR/review split, source `src/assets/mds/git/_pr.mds`;
- `_references.mds` (`subdir: ''`, `kind: 'named'`, `ops: GIT_CROSS_CUTTING_DOCS`) — the fixed, individually-named cross-cutting document set.

`kind` now has **three** members. `'fanout'` (default) is checked against `MIN_VARIANT_PAIRS = 8`; the PR-host module clears it exactly, at the floor. `'named'` is exempt from the count floor (`GIT_CROSS_CUTTING_DOCS`). `'contract'` — the third kind, added for `MCP_CONTRACT_MODULE` — is a single cross-cutting CONTRACT document whose emitted basename carries a mandatory leading underscore (`validateContractOutputName`), distinguishing `tracker/_mcp.md` from the provider directories beside it; like `'named'` it is exempt from the pair floor, for the same reason nothing ranges over it, but it is its own kind rather than a flag on `'named'` because the NAME RULE differs.

`expandVariants(modules = resolveVariantModules())` is pure/total (`Result`, never throws). `splitVariantSections(body, ops)` splits one module's compiled output on `<!-- op: NAME -->` markers, bidirectionally, plus `empty-section` (GAP-44).

`MCP_CONTRACT_MODULE` (`_mcp.mds` → `tracker/_mcp.md`) sits outside `VARIANT_MODULES` behind a generation gate (`GATED_REFERENCE_MODULES`, `resolveVariantModules()`): emitted **only** when a registered module lands in `tracker/jira` or `tracker/linear`.

**`src/assets/mds/tracker/_common.mds` is the home for anything shared.** It is a partial with no `output-dir:`, living outside `_partials/`, and it holds the compliance-step gate, the compliance issue policy, the `**State**:` batch line, the bare-number rule and the four ref pre-flight heads that 14 call sites across the three provider modules share.

### ⚠ `_mcp.mds` IS AT A COMPILER CLIFF — read this before adding a define there

Compiling a provider module against `_mcp.mds` costs, MEASURED with control defines whose entire body is one character (so it is the define COUNT against that module's size, not the content):

| defines in `_mcp.mds` | cost |
|---|---|
| 9 (as shipped) | 3.3 s |
| 10 | 4.9 s |
| 11 | 8.3 s |
| 12 | did not finish in 12 s |

Both `_jira.mds` and `_linear.mds` pay it, so twelve defines in `_mcp.mds` makes `npm run build:mds` not terminate in any practical time. The same five defines in `_common.mds` cost 1.2 s in total. **Anything further that wants hoisting goes to `_common.mds`, or `_mcp.mds` shrinks first.** `_pr.mds` is an import-free fanout module — one `@define` per op, eight in all, and no `@import` — so it is unaffected by the cliff: it never compiles against `_mcp.mds`, and with nothing imported its defines capture only one another (PF-073's cost is exponential in a module's own define count and multiplied by whatever it imports; the import-free `_common.mds` measures 0 ms).

Anything that ENUMERATES partials must use `ALL_MDS_PARTIALS` (`MDS_PARTIALS` ∪ `MDS_REFERENCE_PARTIALS`) — a third enumerator fails the same way `tests/packaging.test.ts` and `tests/build-mds-generator-hosts.test.ts` were both re-pointed for.

`compiledSkillRefsDir()` (`src/core/assets.ts`) is the one owner of where generated references land in `dist/`; `dist/skills/git/references` is `ALLOWED_OUTPUT_DIRS`' `HostVariant: 'skill-refs'` entry (`D-SKILLREFS-ALLOWLIST`).

### 5. The byte budget (`tests/tracker/byte-budget.test.ts`, model in `tests/tracker/budget-model.ts`)

Every ceiling is derived in a comment and registered in `tests/fixtures/numeric-floors.json`'s `ceilings` array (may be **lowered**, never raised). A ceiling here is a **regression alarm, not a target**: after a pass that genuinely condenses the artifact, the ceiling is re-derived downward to sit just above the new measurement. Lowering one re-pins the constant *and* its `numeric-floors.json` entry (value + `pattern` + `occurrences`) in the same commit.

```
BUDGET_GIT_MD            = 45_150  // the ONE gate on dist/agents/git.md
BUDGET_SKILL_MD          =  6_600  // skills/git/SKILL.md
BUDGET_LOADED_SET        = 67_200  // worst-case one-spawn load, GitHub tracker path
BUDGET_LOADED_SET_JIRA   = 76_500  // … jira tracker path (adds tracker/_mcp.md)
BUDGET_LOADED_SET_LINEAR = 78_700  // … linear tracker path
BUDGET_LOADED_SET_PR_HOST = 59_100 // … a PR-host spawn (pr/{op}.md), same on every provider
PREAMBLE_MAX_LINES       =     36
```

**`BUDGET_GIT_MD` is now the ONE ceiling on `dist/agents/git.md`.** It supersedes the phase-named companion ceiling `budget-git-md-p3` (58,870), which was kept registered alongside `budget-git-md` (55,750) through PR #351 so the live gate could be read as a delta from a pinned base — the split no longer exists, and the two-name scheme (`budget-git-md` as design-time base, `budget-git-md-p3` as the live file gate, `PREAMBLE_CHARS_P2` as the operand between them) is gone. #326 re-derived the single surviving ceiling downward, 55,750 → 45,150, by moving the eight PR-host operations' `**Process:**` bodies out of the agent and into `references/pr/{op}.md` — that move is the whole of the re-derivation. `git.md` measures 45,103 against it (47 ch headroom). Re-measure rather than trust a transcription: `npm run build && node -e "process.stdout.write(String(require('fs').readFileSync('dist/agents/git.md','utf8').length))"`.

**Each loaded-set row fell by the same amount `git.md` fell**, since every term but the preloaded set is unchanged by the PR-host move: GitHub 80,200 → 67,200 (measured 67,158), Jira 89,500 → 76,500 (measured 76,462), Linear 91,700 → 78,700 (measured 78,645). Linear's row is still the **largest of the three tracker rows**, for the same recorded reason as before — `backlink-shipped-issues`' dedup ladder, of which three of four rungs are unreachable on a stock server (OD-12). Largest is not binding: every row carries `git.md`, so an addition to the always-loaded agent is bound by the row with the least headroom — the PR-host row, then Jira's.

**`BUDGET_LOADED_SET_PR_HOST = 59,100`** (measured 59,068, `post-review-summary`'s PR-host body plus `references/publication-gate.md`; 32 ch headroom) is the fourth row, gated by `D-LOADED-SET-PER-PROVIDER`'s same reasoning applied a fourth time: `references/pr/` is installed under every tracker at the same cost, so a PR operation's cost is priced once rather than folded into (and tripled across) the three provider rows, and it cannot ride the GitHub row, which `D-LOADED-SET-SCOPE` scopes to TRACKER ops only. Its formula has no `max_op` term of its own — a PR-host op's own mechanics file is already inside its one-spawn load, so a separate largest-file term would double-count it. **`LOADED_SET_WRITTEN_EXCLUSIONS = ['github-api.md']`** (declared in `budget-model.ts`) excludes `references/github-api.md` (21,166 ch, `GITHUB_API_MD_CHARS`, pinned by equality) from this row: `fetch-review-threads` and `resolve-review-threads` loaded that file long before #326 existed, and the split only moved the line that names it — charging it here would bury the `pr/` bodies the row exists to measure under a term four times their size. The exclusion is proven load-bearing, not a rounding convenience, by a dedicated arm asserting the unexcluded figure would exceed the ceiling; the recorded (never gated) row `2c-ex` — the same maximum with the exclusion's file charged — reads **77,709**.

The loaded-set formula (`D-LOADED-SET-SCOPE`) for a TRACKER provider row is unchanged in shape: `bytes(git.md) + bytes(git SKILL.md) + bytes(worktree-support SKILL.md) + bytes(_mcp.md [0 on the GitHub path]) + max_op bytes(tracker/{provider}/{op}.md) + max over TRACKER ops of (sum of every reference that op's load instructions can name in one spawn)`. `nameableFrom(op)` — the scan half of the bidirectional formula↔nameable-set check — grew a **one-hop rule (#326)**: if an op is a PR-host op, the function reads its `references/pr/{op}.md` body and adds every literal `references/…` mention found *inside that body* to the nameable set (`collectPointerSites`, `readReferenceFromDisk`, injectable for the known-bad probe). This exists because `fetch-review-threads`' only mention of `github-api.md` moved out of `git.mds` and into its PR-host reference — without the hop, the model would sum a file the scan can no longer see the op name, and direction 1 of the bidirectional check would go red for a reason that is not a regression. The hop does **not** recurse (one hop, fixed depth, never a loop bound to raise).

`learn-conventions.md` and `publication-gate.md` are **named rows** of the shape table. `decision-markers.md` (1,681 ch) is an **on-demand glossary lookup, not a per-spawn load** (`D-CROSS-CUTTING-ON-DEMAND`).

**Every figure is PRINTED by the shape table — re-run `npx vitest run tests/tracker/byte-budget.test.ts` rather than trusting a transcription** (PF-057). The table now carries nine shapes: (1) the always-loaded preloaded set, (2) per-op split GitHub path — shipped, (3) per-provider single file — disqualified against (2), (4) per-op without `_mcp.md` — identical to (2) in this phase, (2-jira)/(2-linear) the per-provider rows, (2c) the PR-host spawn — gated, (2c-ex) the PR-host spawn with the written exclusion charged — recorded only, (2b) shape 2 with the cross-cutting glossary as if mandatory — recorded only.

## Component Interactions

Build order: `scripts/build-mds.ts` reads `VARIANT_MODULES`, calls `expandVariants()`, compiles each module host once, and calls `splitVariantSections()` to emit one file per pair under `compiledSkillRefsDir()`. `git.mds` itself compiles separately to `dist/agents/git.md`, carrying only the contract text plus `**Mechanics:**`/`**PR mechanics:**` pointers and the preamble's single load-instruction line.

Verification order at PR time: byte-budget → single-authority and reachability (now scanning the PR-host tree alongside the provider trees) → the D11/D10/Guard-2/AC-0.6b corpus guards in `tests/git-agent.test.ts` (each with an explicit `'sole'`/`'union'` mode per [DR-18], now with `gitPlusPrHostCorpus()` and `sinkCorpusWithoutPrHost()` as the #326-specific corpora — see Gotchas) → the installer overlay tests (prove `tracker/` and `pr/` both converge and swap atomically) → packaging (proves the tarball carries all 42 files).

Runtime order in a Git agent spawn: preamble resolves `TRACKER_PROVIDER` once → an op's `**Mechanics:**` pointer (if present) triggers a Read of `references/tracker/{provider}/{op}.md`, and its `**PR mechanics:**` pointer (if present) triggers a Read of `references/pr/{op}.md` — an op like `ensure-pr-ready` can trigger both in the same spawn → the op executes using contract text (from `git.md`) plus whichever mechanics loaded, merging every loaded reference's step numbers into the op's own numeric sequence → any body-posting step passes through the always-inline D11 scrub before the provider-specific post command.

## Integration Patterns — adding a provider

What a fourth tracker provider costs, and what it does not:
- The preamble resolves a provider from the per-repo config key, repo ref-grammar corroboration and the manifest, defaulting to `github`; a new provider needs no preamble change, only a registry entry.
- A provider module slots into `VARIANT_MODULES` as another `kind: 'fanout'` entry over `TRACKER_OPS` — no build-side change beyond the entry, and `installedReferenceManifest` picks it up without edit. Shared lines go in `_common.mds`, never `_mcp.mds` (see the cliff above).
- `tracker/_mcp.md` is generated iff a registered module lands in `tracker/jira` or `tracker/linear`, and installed iff the SELECTED provider is one of them.
- **`references/pr/` is unaffected by a new provider, by design (ADR-026).** `installedReferenceManifest`'s wanted set is `{'', PR_HOST_DESTINATION_ROOT, PR_HOST_TRACKER_SUBDIR, providerSubdir}` — `pr/` and `tracker/github/` (`PR_HOST_TRACKER_SUBDIR`) are both **stated floors**, present for every provider whatever the selection, because pull requests stay on GitHub whatever the tracker is. A fourth provider adds its own `tracker/{id}` directory to the union; it does not touch `pr/`.
- **The `## Operations` contract table is provider-neutral**, and its three tracker cells read "tracker issue(s)". `create-release` and `fetch-review-threads` still name GitHub: PR and release hosting stay there under every provider, so those are not tracker facts. `src/assets/skills/git/SKILL.md`'s `X-RateLimit-Remaining` threshold was KEPT, deliberately.
- **`backlink-shipped-issues`' entry gate defers to the resolved provider's anchored reference grammar**, in `_github.mds`'s `backlink_shipped_issues` define. Placed above the range `STATUS_LINE_REFERENCE_FILES` samples in that file, which is why the frozen fixture stayed byte-identical to that addition.
- **A prunable flat cross-cutting root** — `sweepOrphanedReferences` is scoped strictly to the `CONVERGED_SUBTREES` (`tracker/`, `pr/`); the references root holds hand-authored documents beside generated ones and is never pruned, only overlaid.
- Devflow-wide prompt diet, tracked in issue #342 (see Overview) — this feature's byte-budget ceilings are a per-agent instance of that broader effort, not the effort itself.

## Anti-Patterns

- **Blanket-widening a guard corpus to green instead of classifying each literal** (ADR-025). Every guard `#326` re-pointed from `'sole'` to `'union'` carries a `sinkCorpusWithoutPrHost()` known-bad probe proving the widening is load-bearing: dropping the PR-host tree from the corpus must turn the guard red, or the widening was cosmetic rather than a genuine relocation.
- **Moving text verbatim without checking the destination's reserved tokens** (PF-063). A `##` heading is a section inside `SKILL.md`; inside a generated reference it is a section **terminator** for `extractOpSectionFromCorpus` UNLESS it sits inside a fenced code block. This is why every heading below a PR-host section's own `## Operation:` anchor is `###`.
- **A one-element or two-element variant/pair list.** `MIN_VARIANT_PAIRS = 8` exists because a roster short enough to hand-enumerate is satisfied by any implementation that returns something (GAP-42/PF-018); `PR_HOST_OPS` has exactly 8 for this reason — it cannot be grown one operation at a time.
- **Raising a byte-budget ceiling to fit whatever the artifact grew into.** `numeric-floors.json`'s `ceilings` array may only be **lowered**. `BUDGET_GIT_MD`'s current 47 ch of headroom is deliberately thin — the next content addition to `git.mds` must fund itself with a cut elsewhere, not spend slack. Re-measure before quoting a headroom figure; the exact number narrows on every commit that touches `git.md`, the contract, or a provider reference.
- **Folding the PR-host cost into a per-provider row instead of giving it its own.** `BUDGET_LOADED_SET_PR_HOST` exists precisely because folding would price one cost three times over (once per provider row) while leaving "what does a PR spawn cost?" unanswerable from any single row.
- **Renaming `rm(target)` then `rename(tmp, target)` for an atomic swap.** Displace to `.old` first, rename the new tree in, then drop the backup.
- **Reusing a fixed staging directory name across runs.** Staging paths must stay process-unique (pid + timestamp).
- **Treating "every top-level directory the manifest names" as the prune scope.** `CONVERGED_SUBTREES` is an explicit list (`tracker`, `pr`), not derived from the manifest — a subtree the manifest stops naming ENTIRELY would drop out of a derived set and keep its whole installed tree, exactly the retirement case the prune exists for.

## Gotchas

- **`extractOpSectionFromCorpus` is fence-aware since 2026-09-15 — PF-063's structural remedy.** A `## ` heading inside a generated reference is safe to ship as a real `##` line only when it sits inside a fenced code block; a heading OUTSIDE any fence still terminates the op's section for every union-mode guard. Every PR-host `### Process` heading and the compose-fence `## ` lines inside `post-review-summary`/`post-resolution-summary`'s templates follow this rule identically to the tracker references.
- **Every corpus extraction names its mode explicitly** ([DR-18]) — `'sole'` throws when the anchor matches more than one corpus file; `'union'` concatenates and returns a match count. #326 added a SECOND detection-scoped corpus: `gitPlusPrHostCorpus()` (`git.md` ∪ the PR-host tree, nothing else) for guards that decide **which ops are the subject** (AC-0.6b's remote-I/O sweep). Widening a detection guard to the full `gitAgentSinkCorpus()` union is wrong even when it would pass — over the full union, `setup-task` is detected as remote-I/O through its TRACKER mechanics, silently changing the subject of a guard about the agent's own degradation contract. Literal-PRESENCE guards (a fixed op, asking "can this op reach this text?") correctly read the full union and are held non-vacuous by `sinkCorpusWithoutPrHost()` instead.
- **`planOverlayUnits` classifies three unit kinds, by registry shape and by name.** `tracker/{provider}` — exactly two segments, `tracker` first (`isProviderSubdir`) — is a provider unit, and `pr/` (`PR_HOST_DESTINATION_ROOT`) is the PR-host unit: both are directories the unit owns outright, and both are swapped whole behind a `.old` backup. Every other directory — the references root, and `tracker/` itself, which holds `_mcp.md` beside the provider directories — is a flat cross-cutting set, promoted one rename per document. The PR-host unit's staging tree and backup sit under `tracker/` (`tracker/.pr-host.pr.{token}.tmp`, `tracker/.pr-host.pr.old`), so a crash that strands either is removed by the next run's prune. A new directory the registry emits takes the flat arm until it is classified.
- **`CONVERGED_SUBTREES = [TRACKER_DESTINATION_ROOT, PR_HOST_DESTINATION_ROOT]`** (D-CONVERGED-SUBTREES) is the whole rule for what the prune converges: a directory converges exactly when every file in it is generated. The same list gates the full-install pre-clean: `overlayOwnedSkillPaths` keeps a nested directory whole only when its top segment is listed, so a directory missing from the list fails safe — kept file by file — rather than keeping stale files forever. A listed root that is a symlink or otherwise not a real directory is refused and reported (`D-CONVERGED-ROOT-REAL`): no unit stages, promotes or backs up through it, and its prune is skipped; every unit stages under `tracker/`, so a faulted `tracker/` refuses them all. `pruneConvergedSubtrees` merges the per-subtree sweeps (`prunePreservingRecoveryCopies`, now parameterised over `(referencesTarget, subtree, manifest, overlayFailures)`) into one `SweepResult`; every removed/failed name in the merged result is prefixed with its own subtree (`pr/stale.md` vs `tracker/probe-provider`), so two identically-named orphans in different subtrees never collapse into one indistinguishable report line. A stranded recovery copy (`restore-failed`) skips the prune **only for the subtree it sits under** — a backup stranded under `tracker/` says nothing about whether `pr/` can converge.
- **A control cited by name in one operation's section is not the same as a control that LIVES in that operation's section.** `post-wave-report`'s non-reproduction clause and `post-resolution-summary`'s op-local clause both illustrate the same rule PF-027 states: a containment obligation an op is *named as carrying* must be *readable from that op's own section*, whether that section lives in `git.mds` or is the op-local paragraph `git.mds` still carries after #326's move.
- **MDS escape asymmetry when moving `**Process:**` text source-to-source**: braces are escaped in prose (`DEGRADED (\{reason\})`) but raw inside a column-0 fence — moving text between an agent host and an MDS define without re-checking escaping is the single most error-prone step of this kind of split. `_pr.mds` carries the same escaped-brace literals `_github.mds` does, for the same reason.
- **The single-naming-line assertion is about the TRACKER pointer only.** Exactly one line in `dist/agents/git.md` may name a `references/tracker/{provider}/` path composed from the provider token; the PR-host pointer vocabulary (`**PR mechanics:**`) is deliberately excluded from that count, because it is a fixed literal under every provider and composes nothing — widening the single-naming-line rule to cover it would conflate "one convergence point for a composed path" (PF-023's actual requirement) with "one pointer vocabulary total", which is not what PF-023 asks for.
- **`tests/fixtures/golden/github-status-lines.txt` has been re-captured three times under explicit, one-time user authorisation, and every authorisation is spent** — a fourth needs a fresh one. `#326`'s move RETARGETED the extractor (`STATUS_LINE_REFERENCE_FILES` gained six `pr/` entries; `resolve-review-threads`, `check-ci-status` and `fetch-review-threads` each became `D-STRADDLE-SPLIT` samples across the agent/reference boundary, and `resolve-review-threads` is the first **three-part** straddle: `pr/resolve-review-threads.md` steps 1–2, `git.md`'s own step 3 — the D9 gate application, which never moved — then `pr/resolve-review-threads.md`'s step 4, sampled in that step order) **without spending a fourth authorisation**: the fixture's bytes are unchanged, because the retarget moved WHERE each sampled slice is read from, never WHAT bytes are in it. Verified both ways in the commit that made the move (`git show main:…/github-status-lines.txt | cmp -` against the working fixture, and `update-golden github-status-lines --unfreeze --out-dir <tmp>` re-derived into a scratch directory and compared). The freeze stands at the third re-capture (2026-09-20); any future genuine re-capture still needs its own explicit authorisation. `STATUS_LINE_REFERENCE_FILES` in `tests/helpers.ts` remains a closed list; `ref()` refuses an undeclared path.
- **Every shipped recipe that posts a body posts the scrubber's output (#340, #341).** The D11-posting-op floor (`d11-posting-ops` in `tests/git-agent.test.ts`) is **8**, with zero headroom, over the corpus that now spans `git.mds` and the generated references (tracker AND PR-host). `KNOWN_GITHUB_API_INLINE_BODIES` (`D-INLINE-BODY-EXCLUSIONS`) stays an empty array. The guard mechanics (`joinContinuations`, `INLINE_BODY_SHAPES`, `inlineBodyCorpus`) are owned in detail by the `test-harness` KB.
- **The review-methodology skill holds no posting recipe.** Its former inline PR-comment function is replaced by a pointer to the Git agent's `post-review-summary` operation, where D10 and D11 already live.
- **`SKILL.md` has headroom against `BUDGET_SKILL_MD`.** The Extended References table deliberately does **not** gain a row for the flat cross-cutting documents or for `pr/` (`D-EXTREF-SCOPE`) — each is named from the agent at its point of use, and a table row would cost real per-spawn characters in the one file preloaded on every Git spawn for documentation that already exists elsewhere.
- **`gh repo view` scope property is stated as a successor pair, not a corpus-wide search** ([DR-20]): the literal lives once in `publication-gate.md`, an op-agnostic file; the shipped assertion is *"named from exactly `['post-resolution-summary', 'post-review-summary']`"* **and** *"`gh repo view` appears only in that file"* — unaffected by #326, since neither summary op's D10 naming sentence moved out of `git.mds`.
- **The capability-hoist guard's probe verbs are session-scoped only** (`D-CAPABILITY-PROBE-SCOPE`, `PER_ITEM_PAYLOAD` constant) — per-item capabilities inside a bounded loop are the loop's payload, not a hoist violation; only session-scoped capabilities must be hoisted before the loop. Its non-vacuity floor (`capability-hoist-block-floor`) is **57** (18 `git.md` process blocks + 1 `learn-conventions` + 30 tracker-provider blocks + 8 PR-host blocks).
- **AC-0.6b's remote-I/O detection floor is `git-agent-remote-io-ops = 14`**, asserted over `gitPlusPrHostCorpus()` rather than `git.md` alone — a `git.md`-only read silently narrows the detected set (to 13), because `post-resolution-summary`'s `gh` indicators all moved with its body into `references/pr/post-resolution-summary.md`. The D4-evidence half of the same guard stays `git.md`-only on purpose (PF-027 — a degradation clause a spawn can decline to load is not a contract), so the guard's two halves deliberately read different corpora.
- **`references/github-api.md`** (21,166 ch, pinned by equality as `GITHUB_API_MD_CHARS` in `tests/tracker/byte-budget.test.ts`) states its D4 STOP-and-report rule exactly once and fails closed on a malformed rate probe.
